# 装载等价专项：官方 TS / UGC JSON 统一装载契约

## 一、北星（一句话）

所有玩法规则都是载入式的：官方可用 TypeScript 表达玩法包、UGC 只能用纯 JSON 玩法包，但两者经**同一装载契约**进入注册表、装载后 Def 快照地位等价——官方 TS 机制不被当作"源码特权"，UGC JSON 能覆盖官方机制、装载后即成新玩法层。

## 二、现状实锤（已核查）

- 基类层已符合：38 个 JSON 目录 + TS 装载机器，零 TS 对象字面量承载内容。
- 玩法层是债：官方核心机制 `src/play/core-mechanics/defs/*.ts`（3876 行、57 个 export const）由 `load.ts:476` 硬编码 import 装载；`action-turn/playpack.json`（1849 行、可加载可运行）不是生产路径。
- 三个精确缺口：① `playpack-codec.ts` 拒绝 `play` 治理元数据（numericOwnership/sourceTrace 等），JSON 包过不了玩法层 Linter 的逐 Def 校验；② `loadCoreMechanics` 写死官方 TS 包，无参数接受外部包；③ `playpack-compiler` 产物停在 CompiledPlaypack，无桥到 PlaypackLoader。
- 表达力：`expr.ts` 构造器全是纯函数（JSON 可等价），`playpack-codec` 接受 when/effects/let/forEach/q/while/emit，action-turn JSON 已证明可表达 AP 分配/查询/分支/容器——等价基本成立，缺机器审计。
- 权威文档：D-073（装载后即新玩法层）、D-075/D-077（上传最强装载）、D-062（声明式 playpack 为机制权威形态）已存在；`06_UGC系统.md` 头注已写"官方 TS / UGC JSON 只差表达手段，不差装载权限"；缺 L0 独立条款与 D-019 措辞协调。
