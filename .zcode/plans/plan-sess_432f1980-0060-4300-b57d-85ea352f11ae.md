# 建筑组分支楼层 + 地图 AI 素材管线实施计划

## 目标

把地图美术流程落成可执行闭环：

```text
项目所有者选定整张底图
→ 编辑器/声明文件确定建筑场景框
→ 建筑组固定外壳范围
→ 在同一建筑组分支内创建楼层
→ 每个楼层只生成/重绘自己的局部图幅
→ 一键裁剪、合成、纯化、登记
→ 表现层按外部/悬停/已进入状态显示
```

不把建筑楼层并入主地图层级，不根据 `height` 合并不同建筑或主地图图层。

## 已确定的设计原则

1. `MapLayer` 继续表示主地图表现层；不把建筑内部楼层伪装成全局 layer。
2. `BuildingGroup` 是主层级之外的空间分支，拥有自己的 shell 与 floor 分支。
3. 场景框是建筑组的定位输入；楼层图幅严格来自建筑组框选范围，而不是整张地图。
4. 建筑内部楼层的高度/序号只在所属建筑组命名空间内有意义。
5. AI 只负责生成候选图；区域、外壳边界、楼梯/入口锚点由人确认，工具做确定性裁剪、mask、合成和校验。
6. 地图背景统一使用纯 `top-down plan view`。本轮不再沿用会诱导立面/等轴投影的旧组件提示词；组件管线既有契约不在本批次改动。
7. 任何文字都禁止：无中文、英文、数字、招牌、logo、glyph、道路标签、UI 元素、水印。
8. 车辆、人物、动物等可移动对象禁止出现在底图；动态对象以后由组件/运行时放置。
9. 整图底图和建筑楼层图幅都保留原始参考与作者编辑中间产物，最终 ship 只使用处理后的资产。
10. 保留当前 `compileMap → PrefabDef` 的表现/拓扑分离；建筑组表现数据不进入 `PrefabDef`。

**实现内容**

1. 将 `map-backdrop-pipeline.py` 变成真实、可验证的地图资产编排器：
   - `generate`：生成/留档整图候选 prompt 与 raw 输入契约；支持 `room`、`large-map`、`combined-district` 预设。
   - `select`：把项目所有者选定的图登记为 canonical source，不隐式覆盖原图。
   - `declare-regions`：读取建筑组/场景框声明，校验 frame、锚点和楼层命名空间。
   - `extract`：按声明确定性裁切 shell / floor reference / mask，不使用固定 4×4 sheet 假设。
   - `compose-floor`：把局部作者重绘结果回贴到对应建筑/楼层输出，验证 mask 外像素不变。
   - `purify`：统一在全部局部重绘完成后处理最终合成图；保护边界和锚点不被吞边。
   - `ship`：输出独立表现资产与脱敏 manifest，保留源图坐标、buildingId、floorId、frame、anchor、处理参数。
2. 新增稳定的区域声明格式，例如：

```json
{
  "schemaVersion": "1.0",
  "mapId": "high-school-district",
  "source": { "image": "selected-base.png", "pixelWidth": 4096, "pixelHeight": 4096 },
  "buildings": [
    {
      "id": "building:school-a",
      "frame": { "x": 0.12, "y": 0.18, "width": 0.28, "height": 0.34 },
      "shell": { "source": "frame", "image": "shell-reference.png" },
      "floors": [
        { "id": "floor:1", "ordinal": 1, "height": 0, "frame": "same-as-building" },
        { "id": "floor:2", "ordinal": 2, "height": 2, "frame": "same-as-building" }
      ],
      "anchors": ["entrance:main", "stair:1-2"]
    }
  ]
}
```

3. 将楼层图幅定义为建筑组 frame 的局部输出：
   - 外部源坐标使用整图像素坐标；
   - 对外 manifest 同时记录归一化 frame；
   - 楼层图输出尺寸等于框选范围，不再正方形化、不拉伸整图；
   - floor reference、author-pass、final 三者尺寸固定一致。
4. 加入机械 QC：
   - frame 越界/零面积拒绝；
   - mask 外像素必须保持不变；
   - shell/floor 的入口和楼梯锚点必须存在；
   - 输出图中禁止文字和可移动对象（能做的图像统计检查 + manifest 警告，最终视觉审查仍由人完成）；
   - 视角 prompt 必须含 `top-down plan view`，禁止 `isometric` / `three-quarter` / `front face` / `side face`。
5. 为 `large-map` 与 `room` 预设分别写完整 prompt；新增合一版 `combined-district`，明确校园与门口街道的空间连接，而不是让两张图在运行时强行拼接。
6. 修正当前 `stage_generate` 只打印命令、不执行调用的语义：保留 dry-run/print-only 模式，但真实执行必须显式选择并报告失败；不把未生成的 raw 当作已交付资产。
7. 将当前大地图 prompt 中的 `signage`、`road signs` 等易诱发文字的词替换为 `blank storefront fascia`、`unmarked geometric facade panels` 等。

**批次 1 交付物**

### 批次 2：MapData 建筑组 canonical 契约（依赖批次 1 的字段冻结）

**独占可写范围**

- `src/play/map/types.ts`

**禁止修改**

- editor-shell UI 和渲染实现

- 角色/组件资产管线

**实现内容**

1. 新增表现侧 canonical 类型：
   - `MapRect`
   - `MapBuildingGroup`
   - `BuildingShellRef`
   - `BuildingFloorRef`
   - `BuildingPortalRef`
2. `MapBuildingGroup` 至少包含：
   - 唯一 `id`
   - 整图归一化 `frame`
   - shell 引用
   - floor 分支
   - 入口/楼梯/电梯锚点
3. `MapLayer` 不承担建筑楼层身份；若保留兼容字段，显式标记其为 main scope。
4. 建筑内部 floor 使用建筑命名空间：
   - 相同 `height` 可出现在不同建筑；
   - 同一建筑内参与透视的 height/ordinal 按本建筑校验；
   - 主地图 layer 与建筑 floor 不隐式合并。
5. 规范化、序列化和旧数据兼容：
   - 旧 v1/v2 无 buildingGroups 时行为完全不变；
   - 新字段 roundtrip 保真；
   - 不根据旧 `height` 猜建筑归属；
   - `compileMap` 继续剥离 shell/floor/frame/presentation 状态。
6. 新增诊断码与性质测试：重复建筑 ID、frame 越界、楼层 scope 错误、跨建筑引用、门户端点错误、不同建筑相同高度合法、建筑楼层与主 layer 高度相同合法、编译不泄漏表现字段。

### 批次 4：表现层建筑视图状态与门户运行时（依赖批次 2/3）

**独占可写范围**

- 当前实际 UI/表现消费层中负责地图视图的模块
- 对应表现层测试
- 不直接修改 AI 资产工具和 MapData 契约

**实现内容**

1. 用明确的运行时状态区分：
   - `playerScope`
   - `hoveredBuildingId`
   - `previewFloorId`
   - `lockedBuildingId`
   - `lockedFloorId`
2. 显示优先级：

```text
occupied section
> transition lock
> hover section
> exterior shell
```

3. 玩家在外部时：所有建筑显示 shell；悬停只替换目标建筑为匹配楼层 section。
4. 进入建筑后：锁定该建筑和楼层，鼠标移出不恢复 shell。
5. 楼梯/电梯切换只更新当前建筑的 floor section，不影响其他建筑或主地图层。
6. 退出建筑后恢复 shell。
7. 入口、楼梯、电梯状态和视图锁定必须由门户事件驱动，不能由鼠标位置直接改变玩家空间状态。
8. 增加状态机性质测试：悬停非目标建筑不切全图、进入后移出仍保持剖面、跨层只更新当前建筑、退出恢复外壳。
