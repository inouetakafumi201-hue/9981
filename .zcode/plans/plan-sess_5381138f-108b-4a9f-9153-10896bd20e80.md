## 执行任务（tasks）——按依赖分层，全部主控专做

**层A：引擎层方向语义修通（独立，先做）**
- A1. `metrics.ts:29` 建邻接改为消费 `direction` 而非 `directed`：`one-way-down` 视作 b→a 反向禁用、`one-way-up` 视作 a→b 正向（仅单向语义的端点选择差异），bidirectional/unidirectional 语义不变。让 `dist/spread/shortestPath/radius` 用上四值。
- A2. `Link.direction` 已是透传字段（types.ts + prefab-ops.ts 已做），本轮只补守卫：`engine-layer-map.property.test.ts` Property 6 加「one-way-down 的 dist 反向为 null、正向可达；one-way-up 相反」断言，锁定 metrics 不再布尔降维。
- A3. 基类层扩值两态→四态（`scenes/index.json` transition_directionalities + `family-contracts.ts` TRANSITION_DIRECTIONALITIES 扩到四 token）——**作为交接项写进 tasks，标「提交基类层线做，不在本 spec 执行」**，同时把任务 A1 的 metrics 改动对齐到四 token 语义（白盒侧接线即可）。

**层B：单调重定义统一（独立，核心修复）**
- B1. `package-mapping.ts` `checkChangeAuthorization`「未声明覆盖」分支（L155 的 `!declaredOverrides.has(id)`）改为「同 key 即重定义、不作为冲突拒绝」：同 key 且包未声明 overrideIntent 时不再报 `REF_OVERRIDE_NOT_DECLARED`。保留 `REF_OVERRIDE_TARGET_MISSING`/`REF_REMOVAL_TARGET_MISSING`（它们守的是 add/replace/remove 操作与声明的一致，与 D-073 无关）。
- B2. `definition-registry.ts:136-143` 已 Map.set 后装覆盖，无需改；只加守卫测试锁「同 key 激活=覆盖」。
- B3. 清理 `playpack.ts:110-112` 已死分支（findConflicts 恒空），一并把 `playpack-runtime.ts:150` PoolDef 撞名确认是与 def key 语义不同（保留）。
- B4. 守卫测试：新增「UGC 端口同 key 后装不再 REF_OVERRIDE_NOT_DECLARED，且激活后为后装覆盖」；确认 P10-atomic-activation-rollback 原子性不受影响（激活失败时注册表不变——definition-registry 只动候选，不改 active）。

**层C：载器接线登记为待裁决 + 守卫（不做机制推导）**
- C1. `reconciliation-design.md` 把「基类层 seat_binding/agent.bind + container.class.stationary 不建 category:'carrier'」登记，Q-04 未决不推导。列出裁决选项（载类补 carrier 语义 / agent.bind↔container.enter 收纳对齐），交接至 L2 线。
- C2. 守卫：新增测试锁「非 carrier 面 holds 活体被 `container.enter` 拒绝 `E_OP_NOT_ACCEPTED`」+「`category:'carrier'` 的容器可进活体」+「Q-04 未决时 `item-vehicle-rules` 仍拒 `SOURCE_PROMOTION_REQUIRES_DECISION`」（保持既有行为，防白盒封顶前机制漂移）。

**层D：地图锚点待对齐 + 守卫（不动语义）**
- D1. 守卫测试（在 `engine-layer-map.property.test.ts` Property 4）：锁「同 key 不可替换 / 异 key 不互排 / 释放后可重装 / LLM 地图拒绝」，全都有（本轮已有），无需新代码，只补注释对齐 UGC §7.6。
