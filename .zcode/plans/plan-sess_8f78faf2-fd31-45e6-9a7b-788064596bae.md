## 目标
为 sprite-forge 组件管线实装「批量生成」：定义增量登记素材清单格式，给 `sprite-component.py` 加非破坏式批量模式（循环读清单 → 调出图 API → 品红纯化 → 切格 → proper-pixel-art → 成品质量闸门，带失败跳过与续跑），加速率防护，再用 ~10 个组件做小规模验证，统计成功率/失败模式并核验成品符合 `docs/表现系统/05_组件生成风格规范.md`。

## 关键基线（已勘探确认）
- 现有 `sprite-component.py` 是纯单组件：flat argparse，一次一调，无 loop/无速率防护/无重试。质量闸门 `_validate_frames`（帧数匹配/最小 8px/非品红内容 ≥2%）在失败时 `SystemExit(1)` 且保留 `raw.png/sheet.png`。后处理 `pixelate_frame` 直接调 `proper_pixel_art.cli -s 1`，不调 `sprite-pixelate.py`。无任何批量入口。
- `manifest.json` 是开发期单组件留档，引擎不读、不编译进 MapData；无任何聚合登记。批量格式在 `挂素材MVP任务清单.md` 第 135 行预定义为「类型 / 描述 / 状态数 / 语境 map|ui」，尚无人落地。
- 任务六（§七）列的示例素材里，武器图标/状态图标/货币图标是 `sprite-component.py` 能出的；角色 3 张走角色管线、场景 2 张走地图导出，都不归本脚本。

## 决策
1. **扩展现有脚本、非破坏式**：在 `sprite-component.py` 内加 `--registry` 批量分支；无 `--registry` 时走原单组件逻辑（行为、打印、退出码逐字不变）。把当前 `main()` 单组件主体抽成 `generate_one(...)`，单组件模式与批量模式共用同一套已验证的纯化/切格/闸门/像素化逻辑（单一事实源，避免两份管线）。这遵从用户「扩展现有组件脚本…增加批量模式」的字面要求，且零回归风险。
2. **失败分类**：`generate_one` 按阶段抛 `BatchItemError(stage, error_type, error)`：`api.{429,5xx,timeout,parse}`、`purify`、`slice.{no_bands}`、`gate.{count_mismatch,frame_too_small,content_too_low}`、`pixelate`、`write`。单组件模式捕获后复刻原 `SystemExit(1)`+保留素材的提示；批量模式捕获后记入失败清单继续。这样『失败可识别可修正』直接落到可读分类上。
3. **速率防护**：`--delay`（请求间隔，默认 3s）在每次 `call_backend` 前 `time.sleep`。`_call_gpt/_call_gemini` 增最小 429 处理：遇 429 先退避（基线 30s）重试 1 次，仍失败再按既有的 `SystemExit`/`BatchItemError` 抛。仅用 `time.sleep`，无新依赖，符合 repo 现状（全无防护）。
4. **断点续跑**：默认跳过已存在 `manifest.json` 的条目（已有成品，避免重复计费），`--force` 强制重生成。省的是钱与时间。
5. **离线可验证**：`--dry-run`（解析+schema 校验+`build_prompt` 打印、不发任何 API、不写盘）；并现成可对 `run/assets` 已有 `raw.png`（test-key / crate-nc-v5）离线重跑纯化→切格→闸门→像素化，整条循环不花钱即可验通。

## 注册清单格式（新建 `run/assets/batch-registry.json`）
JSON，带 `kind:"wakeup-batch-manifest"` 鉴别符（承袭 manifest.json 的 `kind:` 约定）：
```json
{
  "kind": "wakeup-batch-manifest",
  "version": 1,
  "defaults": { "context": "map", "provider": null, "cell": 64, "colors": 32 },
  "entries": [
    { "name": "ui-knife", "type": "weapon-melee", "desc": "rusty combat knife, top-down", "context": "ui" },
    { "name": "crate-supply", "type": "environment", "desc": "wooden supply crate", "states": ["closed","open","broken"] }
  ]
}
```
字段：`name`（出图目录名，必须唯一）、`type`（8 类之一）、`desc`、`states?`（字符串数组，数组长度即「状态数」，省略=`["single"]`；元素即帧文件名）、`context?`（`map`|`ui`，默认 `map`）、可选 `provider/reference/cell/colors/out_override`（逐条覆盖 defaults）。解析时校验：name 唯一、type 在 8 类、context 合法、states 长度 1-9（与现有 `pick_grid` 表一致）。违规行连同理由一次性列出、在发任何 API 前失败。

## `sprite-component.py` 改动清单
- 抽 `generate_one(*, type, desc, states, context, out_dir, provider, reference, cell, colors) -> dict`：把现 `main()` 第 587-672 行主体搬入；失败统一抛 `BatchItemError(stage, error_type, error)`，各阶段用 except 分区捕获并加 stage 标签（`call_backend` 的 429/5xx/timeout/parse 在 `_call_*` 内部分类）。
- 新增 argparse：`--registry FILE / --delay INT (def 3) / --dry-run / --force / --report-dir FILE (def run/assets)`。
- `main()` 改为分发：无 `--registry` → 单组件模式（调 `generate_one`，捕获 `BatchItemError` 后按现有打印 + `SystemExit(1)`，行为不变）；有 `--registry` → 批量模式。
  - 加载 + 校验 `batch-registry.json`；按 `name` 生成 `out_dir = run/assets/<name>`（除非 `out_override`）；命中已有 `manifest.json` 且非 `--force` 则跳过并记 `skipped`。
  - 循环：`--delay` 速率防护 → `try generate_one ... except BatchItemError` 记入失败 → 继续；最后写 `run/assets/batch-report-<UTC时间戳>.json` + stdout 汇总。
- `_call_gpt / _call_gemini`：429 退避重试 1 次（最小新增，仅 `time.sleep`）。

## 失败/成功报告（`run/assets/batch-report-<ts>.json`）
```json
{ "run_id": "...", "started": "...", "ended": "...", "delay": 3, "total": 10,
  "succeeded": ["ui-knife", ...], "skipped": [...],
  "failed": [{ "name":"crate-supply", "stage":"gate", "error_type":"count_mismatch",
               "error":"切格帧数 2 与状态数 3 不匹配…" }],
  "success_rate": 0.7, "by_stage": {"gate":2,"api":1}, "by_error_type": {"count_mismatch":2,"429":1} }
```
stdout 打印人类可读总结；失败模式直接对应可操盘的调优动作（`gate.count_mismatch` → 模型没画准网格，考虑改 prompt 的 grid 指令或退单帧；`api.429` → 加大 `--delay`；`gate.content_too_low` → 描述太稀疏）。

## seed 登记清单（10 项，覆盖 + 对齐任务六）
混 7 单帧（压 ui 图标=image Task 6 武器/状态/装备）+ 3 多帧（压切格多状态=image 失败易发的部件），覆盖 7/8 类型，两语境都到：
1. `ui-combat-knife` weapon-melee ui single — "rusty combat knife"
2. `ui-crossbow` weapon-ranged ui single — "tactical crossbow"
3. `ui-handgun` weapon-firearm ui single — "police-issue handgun"
4. `ui-poison-dart` item-consumable ui single — "venom-tipped dart (poison status)"
5. `ui-frost-shard` item-consumable ui single — "frost-shard flask (freeze status)"
6. `crate-supply` environment map [closed,open,broken] — "wooden supply crate"
7. `keycard-reader` device map [idle,active] — "keycard reader panel"
8. `wooden-door` environment map [closed,open] — "sturdy wooden door"
9. `ui-brass-key` item-tool ui single — "old brass door key"（已知可出，作 sanity 基线）
10. `ui-flashlight` item-equipment ui single — "tactical flashlight"

多帧组件刻意保留，因为切格/帧数匹配是失败主发点（现有 run/assets 9 例里 3 成 6 败，多 crate 迭代反复踩闸门）——不跑多帧就看不到这类失败模式。

## 风格规范核验（跑通后）
逐个成功条目开 `contact.png` + `frames/*.png` 按 `05_组件生成风格规范.md` 自检：正面俯视视图（无前/侧/顶/斜投影/isometric）、语义色（按类型）、硬边像素 64×64、上左光、`#FF00FF` 纯品红底；把违规项记入报告 human-readable 段并给提示词调整建议。

## 验证门禁
1. 离线：`python tools/sprite-component.py --registry run/assets/batch-registry.json --dry-run`（解析/prompt/校验，无 API 无写盘）。
2. 离线：对现有 `run/assets/test-key/raw.png`、`crate-nc-v5/raw.png` 跑循环再处理，确认失败分类与续跑逻辑正确（无 API）。
3. 实跑（先确认 `tools/.env` 已配 `SPRITE_GPT_KEY` 或 `SPRITE_GEMINI_KEY`，不回显密钥值）：`python tools/sprite-component.py --registry run/assets/batch-registry.json --delay 4`，目标 ≥7/10 成功 + 失败可识别可修正；按失败模式迭代提示词/脚本。
4. 回归：`npx tsc --noEmit` / `npx vitest run`(相关) / `npm run lint` / `npm run verify:docs` 确认对 `src/`、文档无回归（本任务不动 `src/`，预期 0 影响）。

## 交付物
1. `run/assets/batch-registry.json` — seed 10 条登记清单（也是格式的实例）。
2. `sprite-component.py` — 批量模式扩展（非破坏式、含速率防护/失败分类/续跑/dry-run）。
3. `run/assets/batch-report-<ts>.json` + 人类可读总结 — 小规模验证报告（成功率 + 失败模式 + 风格规范核验 + 调优建议）。

## 风险/边界
- 付费外部调用：实跑前核实 API key 在位；不在位则停在「可跑就绪 + 说明需配 key」，不擅自发起任何计费请求。
- 不动 `src/` 产品区与 `manifest.json` 现有契约（引擎不消费 manifest，批量只是按现约定多产几份）。不动 `asset-pipeline`/MapData 链路。
