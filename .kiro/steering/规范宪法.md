# 规范宪法（Constitution）

> **用途**：唯一权威规范文件。所有其他文档均引用本文档，不得与之冲突。
> **维护规则**：本文档变更需手动审批；其他文档可由 AI 起草。
> **版本**：v1.0 | 创建于 2026-08-05

## 一、术语铁律

| 术语 | 定义 | 状态 |
|------|------|------|
| **引擎层（Kernel）** | 底层原语集。Entity、Component、Op、Expr、Hook... | ✅ 有效 |
| **基类层（Class）** | 实例库。可组合的语义最小单元（武器类、散射谱型、NPC实例...） | ✅ 有效 |
| **玩法层（Play）** | 组合基类层实例 + 数值约束 + 玩法规则 | ✅ 有效 |
| **实例（Instance）** | 基类层的具体产物 | ✅ 有效 |
| **~~模板~~** | **废用词**，禁止使用 | ❌ 禁用 |
| **~~内容层~~** | **废用词**，改为基类层 | ❌ 禁用 |
| **~~Layer 1/2/3~~** | 除非配合具体架构图使用，禁止单独使用 | ⚠️ 慎用 |

## 二、三层架构定义

```
引擎层（Kernel）
  ├─ Entity、Component、Relation、Op、Expr、Hook...
  ├─ 不知道"武器"、"技能"是什么
  ├─ 只知道：实体、状态、关系、动作、规则
  └─ 铁律：0追加。底层设计完成后可自我迭代，不影响上层
        ↓ 基类层使用引擎层 Op/Query
基类层（Class）
  ├─ 武器实例
  ├─ NPC实例
  ├─ 载具实例
  ├─ 角色实例
  ├─ 状态效果库
  ├─ 物品实例
  ├─ 网关实例
  └─ 铁律：
     ├─ 实例不含玩法数值约束（霰弹枪不写"伤害=3"）
     ├─ 实例不含具体玩法规则（霰弹枪不写"在哪种模式出现"）
     └─ 实例可组合、可继承、可扩展
          ↓ 玩法层组合基类层实例
玩法层（Play）
  ├─ 大逃杀规则
  ├─ 夺旗规则
  ├─ 具体数值配置（霰弹枪伤害=3、近战流派验证...）
  ├─ 玩法包定义
  └─ 铁律：可高频迭代，不影响引擎层和基类层
```

## 三、基类层的判定标准与已知类别

> **核心原则**：基类层不能被穷举，但必须有判定标准。穷举是玩法验证阶段的事，不是宪法的事。

### 3.1 基类的判定标准

一个概念是否属于基类层，用以下三条判断：

| 判据 | 含义 |
|------|------|
| **可枚举** | 在当前玩法范围内，可以被有限列举 |
| **可组合** | 可以与其他基类组合产生实例 |
| **不含玩法语义** | 不知道自己在服务什么具体玩法 |

**反例**：`霰弹枪`不是基类，它是`枪类+散射谱型+枪械伤害`的组合实例。
**正例**：`枪类`、`散射谱型`、`枪械伤害`是基类。

### 3.2 已知类别（示例，非穷举）

以下是目前已识别的基类类别，**不代表完整清单**：

| 类别 | 说明 | 示例 |
|------|------|------|
| 武器类 | 攻击动作的抽象 | 枪类、近战类 |
| 谱型类 | 效果的形状/范围 | 散射谱型、单点谱型 |
| 伤害类 | 伤害计算方式 | 物理伤害、穿透伤害 |
| 状态类 | 标签型/数值型效果 | 中毒、眩晕、加速 |
| 物品类 | 可携带物品的抽象 | 消耗品、工具 |
| 防具类 | 防御能力的抽象 | 护甲、盾牌 |
| 载具类 | 移动+交互能力 | 车辆、飞行器 |
| 容器类 | 持有其他物品的能力 | 背包、箱子 |
| 移动模式 | 移动方式抽象 | 步行、跳跃、飞行 |
| AI行为类 | NPC行为范式 | 守卫、僵尸、载具AI |
| 网关类 | 条件/检定/资源转换 | 商店、宝箱、上锁门 |

### 3.3 已知类别外的处理

**遇到未在清单中的新概念时**：

```
Step 1: 用三条判据判断是否属于基类层
Step 2: 如果是 → 新增基类类别，记录决策原因
Step 3: 如果否 → 归入玩法层
Step 4: 更新"已知类别"列表（仅用于文档追踪，不是宪法修改）
```

**禁止行为**：
- ❌ 在宪法里穷举所有基类
- ❌ 要求人类预先列出完整基类清单
- ❌ 将新基类的发现视为"违反宪法"

## 四、引擎层铁律（补充）

> 以下为引擎层必须满足的不变量，是基类层和玩法层的设计前提

### 4.1 Op 通道铁律
- 唯一写入通道：`OpRegistry.invoke`
- 所有行为必须映射到 Op，不得硬编码
- 武器攻击效果 → 通过现有结构化 Op（`prop.add`/`prop.set`）表达
- Hook 分发引擎（H-001 缺口）必须修复后才能接入真实链路

### 4.2 数值铁律
- 所有玩家可见数值严格限制在 1-5 范围内
- 内部数值（回合编号、实体数量）例外

### 4.3 拓扑铁律
- 微型场景由实体创建，附属于天然场景
- 五并列原则：节点连接数不超过 5

---

## 五、玩法层铁律

### 5.1 数值约束
- 玩法层可以指定霰弹枪伤害=3，但必须基于基类层的谱型定义
- 数值必须落在 1-5 范围内

### 5.2 迭代边界
- 玩法层变更不得回溯修改基类层定义
- 基类层实例可被多个玩法层复用
