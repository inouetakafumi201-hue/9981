# Requirements: 开发板（独立地图编辑器 Web 应用）

## Introduction

开发板是 WakeUp 的**独立地图编辑器 Web 应用**，开发者/创作者用图形化方式编辑地图（MapData），并可导入、另存为（以已加载地图为蓝本）、校验、预览和导出为玩法包。它**不是正式的玩家侧素材库**，也不同步实现正式素材库的玩法侧功能（点击查看详情、库内修改素材、LLM 生成素材）。开发板现在就能动工，不与局外系统/素材库运行时状态捆绑，让局内迭代（可挂素材对局）不必等局外系统全部落地。

开发板与游戏**解耦开发但同仓**：它作为独立 Web 应用内嵌在本仓库中，后面可顺畅接进游戏；它复用既有数据契约（`src/play/map` 的 MapData 契约、`compileMap`、曲线抽样、`validateMapStructure`），而不是重新实现一套。删除开发板，游戏照常运行（守工程纪律：反向依赖红线）。

开发板管理**地图的几何/拓扑**（MapData 的节点、边、布景、双分层坐标），**不直接拥有**「素材库元状态」一族（玩家拥有量、已改动/未改动、素材与玩法包状态、拥有状态角标、UGC 新增标记）。后者是独立于地图几何、独立于渲染的**状态层模块**，由系统维护，供编辑器、素材库 UI、玩法包导出共同消费。开发板通过一个**素材可用性决策钩子**与该状态层解耦。

开发板遵循既定 ID 机制（见 `docs/创作系统/01_创作工具与产权.md` §ID 规范 2026-08-15）：地图稳定命名无随机尾缀；新建的 UGC 对象在**导出玩法包时**才生成一次且复用不变的随机尾缀。开发板只处理地图，不改动力学定义的 ID 生成。

**范围责任划分：**
- **在本范围**：独立 Web 应用壳（Vite + React + TS）；地图导入 / 新建（可选已加载地图为蓝本）/ 导出到文件；图形化编辑 MapData 全套图元与交互（见 `docs/创作系统/01` §九地图编辑器交互契约）；每次改动即时结构校验；编译为 PrefabDef 的可运行性/预览；两态素材视觉呈现（右侧快捷素材栏 / 展开全量矩阵）且可使用入口由「素材可用性钩子」控制；给全部 demo 版本留接口、**当前开发板先给全部权限**。
- **不在本范围**：正式素材库的玩法侧（点击查看详情、库内修改素材、LLM 生成素材 / LLMUGC）；素材库元状态层的实现（作为独立模块立项，开发板只消费其决策钩子）；MapData / 玩法包装载引擎本身（已实现或在其他 spec）；任何渲染无关的状态机内核改动。

## Glossary

- **开发板**：此处立项的独立地图编辑器 Web 应用。
- **MapData**：`src/play/map/types.ts` 定义的完整地图契约（MapNode/MapEdge/MapPlacement/MapBackdrop、双分层坐标、场景三档尺度、连接数上限、无 weight 字段）。（地图稳定命名，无随机尾缀。）
- **PrefabDef**：`compileMap` 的产物；编译时丢弃几何后的可运行定义。
- **蓝本（blueprint）**：新建地图时可选择的「已加载地图」作为起点；复制其内容作为基底。
- **导入 / 导出**：把地图 JSON/玩法包读入开发板工作区、或从工作区写回文件（`asset-pipeline` 样例格式见 `scripts/asset-pipeline`）。
- **快捷素材栏 / 全量矩阵**：`04` §3.4——右侧未展开 7 格快捷素材栏、展开后 70 格矩阵（小型素材库选择器，只拖拽取用）。
- **素材可用性钩子（material-availability hook）**：开发板判定「某素材是否可在当前编辑器使用」的决策端口；**当前实现为全放行（开发者权限）**，真实可用性判定由素材库元状态层提供。玩家 demo 中素材有限（仅不能进自家地图 / 带图匹配，但不禁止其编辑地图）。
- **素材库元状态**：`04` §3.6 一群——已改动/未改动、玩家拥有量、素材与玩法包状态、拥有状态角标、UGC 新增标记。由独立状态层模块维护，开发板只消费其可用性钩子。
- **UGC 新增**：该对象是否玩法层命名集之外的新实体；唯一决定随机尾缀的轴。
- **立即校验 / 保存校验**：`src/play/map/violate.ts` 的 `validateMapStructure`（无 IO、编辑器每次改动即校验）与 `validateMapAgainstClasses`（带 index、保存/发布时）。
- **双分层坐标系**：`01` §九——场景框（抽象）与内部坐标（几何）两层。
- **isStableIdentity**：引擎稳定命名判据（非空、无前后空白）。

## 要求

> 每项要求下以「**权威**」列出其依据的设计文档。冲突时以此处序号与文档章节锚点为据。

### 要求 1：独立 Web 应用壳与同仓解耦

**用户故事**：作为开发者，我想以独立 Web 应用的方式运行开发板，以便不依赖游戏运行时、不被局外系统阻塞先行编辑地图。
**权威**：`docs/创作系统/01_创作工具与产权.md` §二 44 行（路径落点 `src/editor/map/`、工作台 `src/editor/bench/`）、`docs/00_架构域与文档分类.md`（编辑器归创作系统）、`docs/工程治理/02_技术栈与开发流程.md`（React+SVG+Tailwind+Electron 选型）；同仓解耦纪律见 `docs/L2_基类层/06_UGC系统.md` §2.3（删除创作工具后已装载玩法包仍须独立运行，玩法层生产代码禁止反向依赖编辑器）。

1. 开发板应作为本仓库内、可独立启动的运行构建（Vite + React + TypeScript），包名与源码目录与既有零渲染内核解耦。
2. 开发板源码应位于独立的 `src/` 子目录（如 `src/devboard/`），不得被 `src/play/**`、`src/scene/**` 等游戏运行时反向依赖。
3. 当开发板代码或源码目录被移除后，既有生成的游戏仍应能独立构建与运行（守工程纪律：不反向依赖编辑器）。
4. 开发板应能导入现有的 `src/play/map` 契约与校验/编译实现作为依赖，且这些 import 是只读消费、不修改契约本身。

### 要求 2：加载 / 新建（可选蓝本）/ 导出

**用户故事**：作为开发者，我想从已加载地图继续编辑，或新建地图（可选以已加载地图为蓝本），并在完成后导出为玩法包文件，以便循环编辑地图形。
**权威**：地图片加载/蓝本/导出载体见 `docs/创作系统/02_地图生产管线.md`（MapData 契约权威叙述）与 `docs/L2_基类层/06_UGC系统.md` §7.7（素材=单独 JSON 单实例化、玩法包=打包集合 zip、地图=唯一装载锚点）；样例生成/校验/编译/可视化见 `scripts/asset-pipeline/` 与 `.agents/skills/asset-pipeline/SKILL.md`（样例蓝本 `卧铺车厢 sample-sleeper.json`）；「已在开发板内部实现地图锚点扩展、Map 校验码、蓝图新建」见 `docs/工程治理/02_素材工作流增量规划.md` 主梁二与既有 `src/play/map/**`。地图稳定命名不裹尾缀见 `docs/创作系统/01_创作工具与产权.md` §ID 规范（2026-08-15）。

1. WHEN 启动开发板，THEN 它应呈现「已加载地图列表」，供选择加载后进入编辑。
2. WHEN 用户从列表选择一张已加载地图，THEN 开发板应把该地图装载进工作区供编辑。
3. WHEN 用户选择「新建地图」，THEN 开发板应提供「以某已加载地图为蓝本」的可选基底；若选蓝本则以蓝本内容复制为起点，否则从头开始（空地图）。
4. WHERE 用户完成编辑，THEN 开发板应提供「导出」动作，把工作区地图以玩法包 / 地图 JSON 文件形式写出到文件（沿用 `asset-pipeline` 样例格式与地图持久化载体）。
5. WHEN 一张地图作为**蓝本**被复制，THEN 新建地图应获得**新的稳定命名（无随机尾缀）**，源图的命名不因派生被破坏（蓝本是复制基底，不是别名）。
6. 开发板提供显式「校验并导出」路径：导出前应运行带索引的保存校验（`validateMapAgainstClasses`），任何错误诊断应阻止导出或明确展示。

### 要求 3：图形化编辑 MapData 全套图元

**用户故事**：作为开发者，我想用图形化方式编辑地图的完整图元集，以便以最小摩擦搭建地图。
**权威**：`docs/创作系统/01_创作工具与产权.md` §九「地图编辑器交互契约」（状态机 `Select/PlaceNode/DrawEdge/Sample/Playtest`、全局输入表、拉边流程、Catmull-Rom 非贝塞尔样条塑形、取样、校验反馈、图元穷举——场景框/连线/视觉遮挡/物理遮挡/高地/洼地/过渡窗口、双分层坐标系、必要 vs 延后清单）；数值/连接约束见 `src/play/map/types.ts`（归一化坐标、场景三档尺度、连接上限大5/中4/小3）与 `src/play/map/violate.ts`（`validateMapStructure` 无 IO、诊断是列表不带 correction、20+ 诊断码）及既有 73+ 测试。

1. 开发板应提供选择、放置节点、拉边、取样、测试运行的状态机（`Select/PlaceNode/DrawEdge/Sample/Playtest`，见 `01` §九）。
2. 开发板应支持编辑以下图元：场景框（节点）、连线（边）、视觉遮挡、物理遮挡、高地、洼地、过渡窗口；每条连线支持拉边流程。
3. 开发板应支持样条线塑形（Catmull-Rom，非贝塞尔），并提供取样与吸附（沿用 `src/play/map/curve.ts` 的折线简化/重采样/吸附 SNAP_TOLERANCE）。
4. 开发板应维护双分层坐标系：抽象场景框层与内部几何坐标层，二者可切换编辑与查看。
5. 开发板应尊重连接数上限（大 5 / 中 4 / 小 3）与归一化坐标 `[0,1]²`，越界与超限应明确提示。
6. WHEN 用户每次改动地图，THEN 开发板应运行无 IO 的结构校验（`validateMapStructure`）并即时展示诊断；诊断是列表（无自动 correction）。

### 要求 4：素材视觉呈现（两态）与可用性钩子

**用户故事**：作为开发者，我想在编辑器右侧看到「快捷素材栏」并可展开到全量矩阵、可灵活切换，且当前先解锁所有已注册素材，以便摆放素材时不阻塞。
**权威（素材与地图是两态呈现）**：`docs/运营系统/04_局外养成的保险箱与素材库交互.md` §3.4（右侧 7 格快捷素材栏 → 展开 70 格全量矩阵、分类筛选+搜索、只拖拽取用、不可编辑/调 LLM、与正式素材库的分界）与 §3.6（「素材库元状态」一族：已改动/未改动、玩家拥有量、状态、角标、UGC 新增，由独立状态层维护，开发板只消费其可用性钩子）；开发者/玩家双权限形态见 `docs/L2_基类层/06_UGC系统.md` §2.4（开发者装载=常驻最终版、玩家=插拔可回滚）与 `docs/运营系统/01_运营与局外养成.md`；MVP 玩家素材有限（仅不能进自家地图/带图匹配，不禁止编辑地图）见 `docs/访谈决策记录.md`。

1. 开发板应提供编辑器右侧快捷素材栏：未展开显示 7 格（最近/高频），展开后进入全量矩阵（70 格），矩阵上方有分类筛选与搜索框；仅用于取用拖拽，不提供编辑/LLM/详情。
2. 快捷素材栏与展开矩阵的「素材可用」判定应通过**素材可用性钩子（material-availability hook）**统一决策，不直接内联判断。
3. WHERE 当前处于开发板（开发者权限）模式，THEN 素材可用性钩子应对所有已注册素材**返回可用**（全放行）、全部已加载内容可见；它同时应保留给 demo 版本的接口形态（后续玩家模式传入受限素材集，MVP 中玩家素材有限，仅不能进自家地图 / 带图匹配）。
4. 素材库元状态（拥有量/改动标记/角标等）不属于开发板实现范围；开发板只消费「某个素材是否可用」这一布尔决策，不承担拥有量/状态角标等局外状态维护。
5. 素材视觉呈现是可开关的抽象预览，**不加载全屏粒子、曲线等动画**；但素材所引用的**图片（image）必须存在与显示**（占位到真实素材表观可切换，后续正式素材版本再接入 sprite-forge 位图渲染）。

### 要求 5：编译 / 可运行预览（Playtest）

**用户故事**：作为开发者，我想在地图编辑后将其编译为可进引擎的 PrefabDef 并做运行态冒烟，以便验证地图契约链路通畅。
**权威**：`docs/创作系统/02_地图生产管线.md`（MapData → PrefabDef 编译、几何在此丢弃、确定性重放）；「Material→PrefabDef→引擎 spawn 断言→地图进引擎」端到端链路由 `.agents/skills/asset-pipeline/SKILL.md` 定义并已跑通（`asset:generate`/`asset:pipeline`/`asset:view`、mermaid 可视化）；编译器现实现于 `src/play/map/compile.ts`，spawn/装载在 `src/core/kernel/schedule/playpack.ts` 与 `src/play/map/anchor.ts`；可视化思路见 `scripts/asset-pipeline/map-to-mermaid.mjs`。

1. 开发板应能把工作区 MapData 调用 `compileMap` 编译为 PrefabDef（纯函数、可确定性重放；几何在该步骤丢弃）。
2. 开发板应提供一个「测试运行 / Playtest」入口，把编译产物喂给既有 spawn 断言 / 引擎装载路径做可运行性冒烟（复用 `asset-pipeline` 的 spawn 断言思路与既有 `src/play/map` 测试工具）。
3. 开发板应能可视化校验结果（如走 `asset:view` 的 mermaid 可视化思路），把地图拓扑画成图以便开发者检查。

### 要求 6：规划 / 架构边界遵守

**用户故事**：作为架构维护者，我想让开发板严格落在创作系统边界内、不触碰渲染无关内核与素材库元状态层的职权，以便保住解耦纪律。
**权威**：三层边界/候选归属见 `docs/L2_基类层/06_UGC系统.md` §2.1-2.4（创作系统只生成候选、编辑器不写注册表、地图永远单独装载）；编辑器 UI 延后清单见 `docs/创作系统/01_创作工具与产权.md` §十一；素材库元状态层作为独立模块见 `docs/运营系统/04_局外养成的保险箱与素材库交互.md` §3.6；ID/尾缀机制见 `docs/创作系统/01_创作工具与产权.md` §ID 规范（2026-08-15）。

1. 开发板不应修改 `src/play/map/**` 契约源码（只 import 消费）；任何契约缺口应以「交接口」记录，不越权改契约。
2. 开发板不应实现正式素材库的玩法侧功能（点击查看详情、库内修改素材、LLM 生成素材 / LLMUGC）；这些列为「加法/后置」，不随开发板首版落地。
3. 开发板不应实现「素材库元状态」层的拥有量/改动标记/角标状态机；它只消费可用性钩子，元状态层作为独立模块立项。
4. 地图 ID / UGC 尾缀机制应遵循 `01` §ID 规范（地图稳定命名不裹尾缀；尾缀仅在 UGC 新建时、导出玩法包时生成一次且复用不变）；开发板不改动力学定义的 ID 生成规则。
5. 所有玩家可见数值应守 1–5 铁律；开发板只编辑地图几何与可放置素材，不引入新的可玩数值语义。

## 明确不做（non-goals）

- 正式素材库的玩法侧（详情 / 库内改素材 / LLM 生成素材）。
- 素材库元状态层实现（拥用量、改动标记、角标状态机）——作为独立模块立项。
- 地图 / 玩法包装载引擎本体（已实现于 `src/core/kernel/schedule/playpack.ts`、`src/l2/registry/`、`src/play/map/anchor.ts`）。
- **全屏粒子 / 曲线动画的运行时表现**（`sprite-forge` 表现动画接入）——后置；但开发板编辑的**图片（image）必须存在并显示**，占位到真实素材表观可切换。
- 任何引擎原语、新 Op、新 Ref 前缀、新 Def kind。
- 服务端 / 网络同步、多人协作、云端持久化。
