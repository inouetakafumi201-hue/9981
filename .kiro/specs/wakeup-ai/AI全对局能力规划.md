## 一、现状核实（实事求是，不含糊）

对上一轮工作结论的复核，落到代码与文档，不凭记忆：

- `DesignCurrencyGateway`（`src/core/kernel/ai/design-currency.ts`）确实接进了 `EvaluationGateway`，且 `scoreDesignCurrency` 已把真实资源池投影（`world.props.pools.*.*.real`）读进来，接 `vitality / heal / range / pool.ap / pool.stamina`。`design-currency-decision.test.ts`、`design-currency-scenarios.test.ts`、`design-currency-resource-pools.test.ts` 证明它在真实内核链路上能选「保全生命」分支、不把 AP/体力压零。
- `SequentialSearchPlanner`（`src/core/kernel/ai/sequential-search.ts`）+ `KernelSearchSessionGateway` + `SchedulePhaseParticipants` + `KernelSimulationAdapter`：多参与者顺序搜索、参与者各用自己 Policy 与认知切片、试探走真实 Action→Intent→Op 链并 restore。`sequential-kernel.test.ts` 证明三参与者在真实内核上各自选择、隐藏实体不泄露、试探零污染、跨相位推进。
- `ScopedCandidatePlanner`（候选唯一来自 `queryActions`）、`FiniteEvaluationGuard`、`BoundedAIDecisionFacade as 唯一入口`、静态架构边界（不暴露 WorldState、无写入旁路）均已落地。

**缺口（诚实列明，这是用户纠正的根源）**：
1. **测试场景全是"单实体自保"**：两个候选分支只改写自己的 `vitality` / `pool.ap` / `pool.stamina`。没有任何"两个活体互打""捡武器""吃治疗""追敌人"的端到端对局。
2. **`attackAction` 是死的**：`src/play/core-mechanics/defs/actions.paid.ts:302` 的 `attackAction` 首条守卫 `PATH_DAMAGE_AMOUNT_REF` 恒为 `null`（T-001 未冻结），因此"攻击"在任何写入前就被拒绝。没有一个 AI 能在测试里真正打出一记伤害。
3. **设计货币没有"攻击对局"维度的分**：`scoreDesignCurrency` 只对自己实体的 `vitality / pool.ap / pool.stamina / heal / range` 计分，**不含对敌方生命的扣分**，也没有"拾取更强武器"的估值。所以它天然只能"避害"，不能"趋利、进攻"。
4. **没有"敌人"概念被喂给 AI**：AI 的候选来自 `queryActions`，但注入的 action 集合里从没有带 `target` 指向另一个活体、且目标会反过来打我方的对局。`visibleTo` 能暴露敌人，但没有任何估值去权衡"杀他→他被淘汰"。
5. **`nextDecisionContext` 确实实现了顺序参与者推断**，但测试只做到"各自按自己 initiative 选"，没有"因为我方攻击分支，导致敌方血降到一→敌方下一回合自保/还手，从而我方敢继续压"这种真预判。

> **一句话定论**：不要把"设计货币"当"AI 会玩了"的证据。设计货币是评估器；攻击动作没被配置、敌人估值没进分数表、多参与者还没跑过攻击对局，这三个缺口不补，它永远只能"趋利避害地保命"，不是 MVP。

## 二、目标与分层模型

"AI 会玩"= 一条完整决策链在一个**真实对局**里,能对**玩家会尝试的绝大多数动作序列**给出不显漏洞、不趋利避害的回应。拆成三层（与 `docs/L2_基类层/07_AI系统.md` 一致）：

1. **玩法层（合法动作真实化）**：AI 能发起的动作集合 = 玩家能发起的动作集合。攻击能真正改目标生命、拾取能真正把物品放进背包、治疗能真正回血、移动能真正到达敌人/物品所在节点。**这是前提，缺它后面全是空中楼阁。**
2. **评估（设计货币 + 目标/敌人权衡）**：分数表不仅要"保自己的命"，还要"压敌人的命""拿更强的武器""备治疗"。"避害"与"趋利"必须同时成立，才叫常识。
3. **搜索（顺序多参与者真预判）**：AI 不只决定"我这个动作"，还要顺着别的参与者的回合预测"我打了这刀之后敌人会怎么应对"，再反过来选这个动作是否值得。

阶段划分以此三层为纵轴,每一阶段收敛到一组可机械判定的用例。

## 三、MVP 常识机制全清单（玩家会尝试什么，AI 就要能独立应对什么）

把"玩家尝试的行为"按类别枚举。每一类都必须是 AI 能在真实对局里**独立发起**的，才算没有显式漏洞。

| # | 机制类别 | 玩家的常见尝试 | AI 必须独立做到 | 当前状态 |
|---|---|---|---|---|
| M1 | 攻击 | 对着敌人按攻击，期望掉血 | `attackAction` 真打出伤害：目标 `vitality` 降低、能降到 0 | ✅ 阶段1 对局靶真打出伤害（test） |
| M2 | 选择攻击目标 | 血多的挑血少的、残血的补刀 | 对每个可见敌方候选，评估"杀他收益/自损代价"，不无差别乱打也不畏战不敢打 | ✅ 阶段2 敌方估值进分数表、满血补刀收敛 |
| M3 | 拾取 | 看到地上武器/治疗拿起来 | `pickupAction` 真把物品移进背包（`item.move` 生效） | ✅ 阶段4 多步宏序真串进背包（槽位+hholds 双查） |
| M4 | 治疗 | 残血时用背包里的治疗品 | 背包里有治疗物时不傻站着，会用代价可接受的方式恢复 | ✅ 阶段4b 残血+背包有治疗 → 优先治疗 |
| M5 | 移动/追敌 | 敌人跑了追上去或躲开 | 把"到敌人身边""到治疗/武器旁""远离危险"都变成有真实代价与收益的分支 | ✅ 移动分支 entity.place 真实生效、宏序含 move |
| M6 | 自保 | 残血撤退、找掩体、举盾、睡下/起床回体力 | 生命/资源低时不鲁莽进攻（已部分成立：死亡锚） | ✅ 设计货币覆盖自保维度（死亡锚/耗尽锚） |
| M7 | 预判敌方 | 猜测敌人下回合会不会打我/逃跑再决定这回合 | `nextDecisionContext` 顺着敌方回合展开：我砍这刀→敌掉血→敌可能还手→我是否值得 | ✅ 阶段3 前瞻展开敌方回合、scoreVector 双参与者 |
| M8 | 背包装配 | 换更强武器、把没用的扔掉 | 评估"装备更强的"比"空手/弱武器"更优 | ✅ 阶段4a 武器 E 费目进分数表、分值随 E 上升 |
| M9 | 终结/长眠 | 敌人零血倒地后补刀(令其长眠) | 对零血倒地目标发起 `eternalSleepAction` | ✅ 阶段4c+5 倒地威胁费目+跨回合终结靶 |
| M10 | 状态与恢复边界 | 过载/倒地/睡下起床的时点判断 | AI 尊重与玩家相同的状态转换（不倒贴外不偷偷绕开） | ⚠️ 对局驱动器(round 承载)已落地；完整状态机靶受 T-001/U-001 接权阻塞，见 7.3 交接 |

> **完备判据（总纲）**：上述 M1~M10 每一行都要有一条端到端对局用例，AI 在真实 `queryActions` + `effects` + Hook 链路上，做出**与理性玩家一致的动作选择**。任何一行没有对应的"AI 真的做到了"用例，就不算阶段性完备。

## 四、四个阶段与各自的完备判据

### 阶段 0（前置，不改产线语义，只为让 AI 有据可依的数值注入点）

**不是实现主干的阶段，是把 M1~M10 缺的"能打的靶子"补上的两个独立产出。**

- 0A. **选择一个最小近战攻击动作/伤害结算**：为 AI 对局用例造一个"攻击能造成确定性伤害"的可注入伤害数值源。这是测试靶（`ai-significant` 标签 + `PATH_DAMAGE_AMOUNT_REF` 在测试装配时被配置），**不抢 T-001 的裁决**：文档上明确标注"这是 AI 开发期测试注入点，T-001 冻结后由玩法层权威数值源替换"，不混入任何基类层默认值。
- 0B. **`readyToPickUp` / 治疗 / 装备物品的测试实例**：造一组最小物品（治疗物、普通武器）与对应动作，使 AI 的拾取/治疗/装备候选能真实改变状态。

**阶段 0 完备判据**：三条独立测试链路的动作效果真实生效（攻击真的减目标血、拾取真的把 item 移进容器、治疗真的回血），且全门禁绿。

### 阶段 1：玩法层合法动作真实化（喂给 AI 的攻击 / 拾取 / 治疗 / 追敌候选）

**目标**：AI 的 `queryActions` 不再只有"自保原语"，而是包含能伤害敌人、能捡到物品、能治疗自己的真实动作；且每个动作都是**真能走的合法反馈**。

- 1.1 攻击：AI 候选里出现对"另一个活体"的 attack，其 effect 走真实的 `play.damage` 管道，目标 `vitality` 真实降低。
- 1.2 拾取 / 装备：AI 候选里出现对物品的 pickup / equip，`item.move` 真实把物品移进 `ownContainer`。
- 1.3 治疗：AI 候选里出现对背包内治疗物的 use，目标 `vitality` 真实恢复。
- 1.4 移动 / 追敌：AI 候选里出现对节点/敌人的 move/attack 距离判定，`entity.place` 真实改变位置。

**完备判据**：造一个 2 活体对局（我方 AI + 一个可伤敌方），给它一组含攻击/拾取/治疗/移动的合法候选，端到端断言：AI 选择攻击分支后，敌方 `vitality` 下降；选择拾取分支后，物品从地面移进背包；选择治疗分支后，自己 `vitality` 回升。**这是"AI 能攻击、能捡、能治"的第一次真实现**，previous 的 4 个自保用例全部升级为真实对局。

### 阶段 2：敌方可见性 + 攻击 / 自保对称评估（设计货币接上对敌生命的权衡）

**目标**：`scoreDesignCurrency` 不再只顾自己，而要同时权衡"我方生命/资源（保命）"与"敌方生命（进攻）"，两者都是常识的一部分。

- 2.1 对敌估值：在分数表加一个"敌方目标生命"维度——目标越残血，攻击它的直接收益越高（补刀/淘汰收益），同时对"我方被反击的风险"给出对称惩罚。
- 2.2 攻击/自保并发（关键反常识漏洞）：
  - 我方满血、敌方残血 → 选补刀（趋利）。
  - 我方残血、敌方满血 → 选自保/撤退/治疗（避害）。
  - 我方残血、敌方更残 → 理性的"对换"判断，不无差别送死、也不因怕死错过能赢的换血。
- 2.3 敌我对称：设计货币对"敌方生命低于阈值"给正分（杀/t他），对"我方生命低于阈值"给负分（保命）；两者同分表，互不覆盖。

**完备判据**：攻击对局里,给定四象限（强对弱/弱对强/同残/同强）状态，断言 AI 稳定选择：残血敌方→补刀；残血自己→自保；剩下两象限给出与"理性对换"一致的固定取向（用测试锁定，防回归）。

### 阶段 3：顺序多参与者真预判（search 真把敌方回合展开）

**目标**：不是"我选一个动作",而是"我选一个动作 → 敌方回合他会如何应对 → 结论再回来决定我这刀砍不砍"。

- 3.1 攻击-还手回路：两个 AI 活体轮流行动。我方候选"攻击他"进入仿真分支→敌方回合基于血降后的认知切片选"自保还是还手"→`nextDecisionContext` 把敌方回合展开→终端状态把本方+敌方都计入 ScoreVector→回来决定这刀值不值。
- 3.2 非全知预判：预判时每个参与者只能看到自己可见/已知的认知切片，不能透 view 敌方隐藏信息（已由 read-adapter 保证,需在攻击对局里显式断言：预判分支不含敌方隐藏事实）。
- 3.3 真趋利（预判不倒退）：如果"攻击"分支预判后敌方血更低、且不反过来立刻打死我→攻击被选中（不再是"永远保守"）。

**完备判据**：2 活体攻击对局,`nextDecisionContext` 真实把敌方回合推进，终端 `ScoreVector` 同时含我方与敌方,断言"该打的时候敢打、该撤的时候会撤"落在稳定动作上，且预判分支零隐藏信息泄露。

### 阶段 4：物品 / 背包价值（M3/M4/M8 的估值闭环）

**目标**：AI 会"自主拾取更强武器、备好治疗物"，而不是等测试用例替它把治疗摆进背包。

- 4.1 物品价值进入分数表：为物品/背包投影加估值——空的治疗槽/弱武器槽是"待改善",拾取强武器/治疗物是正分。
- 4.2 背包优先级：有治疗物时不乱用（资源保守原则 `resourceConservation`）,没治疗又不安全时优先去捡。
- 4.3 与 M1~M3 联动：拾取强武器后攻击的分值随武器等级上升，形成"拾取→更强→进攻"链。

**完备判据**：给 AI 一个"附近有强武器、远处有敌人"的对局，断言 AI 为"先拿武器再进攻"的宏序列（move→pickup→attack）选择优于空手直接冲；并在"背包已有治疗且残血"时优先治疗而非继续进攻。

## 五、执行纪律与红线

- **三命令门禁**：每个阶段完成都跑 `npx tsc --noEmit`、`npx vitest run`（相关范围）、`npm run lint`；文档更新跑 `npm run verify:docs`。
- **不做 MVP 缩水**：任何阶段不得用"给一个 action 硬编码优值""打补丁让测试通过"代替真实估值/真实动作链路。宁可少、但真。
- **不跨 Spec 改交付物**：`src/play/core-mechanics` 攻击动作被 T-001 挡死是真实短板，但阶段 0 用"开发期测试注入点"搭桥，**不修改** `actions.paid.ts` 的守卫逻辑,也不为它伪造 T-001 的裁决；T-001 冻结后由上层接权。需要跨包改 deliverable 处,登记为交接项。
- **不把 AI 测试注入点到被误读为玩法层基类默认值**：阶段 0 的伤害/物品实例全部落在 AI 测试目录,文档标注测试靶性质。
- **`1–5` 铁律**：所有玩家可见数值保持 1–5；AI 内部评分（死亡锚 -10、资源锚 -6 等）是 `Internal_Metric`,不投影给玩家。
- **术语纪律**：沿用 `Template`→禁词（`模板` 违例）,AI 侧不用 `模板` 描述行为类。

## 七、优先级与建议执行顺序(节奏)

1. 先 **阶段 0**（攻击能真打、拾取/治疗能真生效）——这是全部后续的地基,先打通。
2. 再 **阶段 1**（把攻击/拾取/治疗/追敌候选喂进 AI 对局,端到端一次打穿）。
3. **阶段 2**（敌方估值接进分数表,攻击/自保对称）——这是把"避害"翻成"会玩"的最关键一步,也是用户点名"趋利"的落点。
4. **阶段 3**（预判敌方回合）——顺序多参与者真预判。
5. 最后 **阶段 4**（背包/物品价值）层叠在前三者之上,形成"拾强武器→进攻"链。

每个阶段都可独立验收、独立 commit;阶段内做完才可进入下一阶段。总完备度判据回看第 3 节的 M1~M10 清单,每一项都必须有一条"AI 真是这么做的"端到端用例背书,缺一不算 MVP。

### 7.3 M10 完整状态机端到端靶——交接项（结构性阻塞，非本线拖欠）

**目标（M10 完整靶，未完成）**：把 `sleepDown→wakeUp`（睡下→起床只做完工时回体力）、过载自动剔除下一回合（且过载者不能提 intent）、倒地→`standUp` 三种状态转换，串成一条**真实连续、可决策的对局**（每一拍是 `facade.act` 的规范提交，相位由 `driveOnePass` 推进回绕），再让顺序 planner 沿链展开，为 M10 造端到端用例。

**两块权威接权都被结构性门禁用，写权不在 AI 测试层、也不在我本会话的职权内：**

1. **睡下/起床/站起/攻击的守卫在玩法层 `actions.paid.ts`**：`sleepDownAction`/`wakeUpAction`/`standUpAction`/`attackAction` 用 codec 登记 ActionDef，其 `require` 结构（`TAG_SLEEPING`/`TAG_KNOCKED_DOWN`/`TAG_DOWNED_ZERO` 标记前后置 + T-001 伤害源守卫 `PATH_DAMAGE_AMOUNT_REF` 恒 null 在写入前拒绝攻击）。AI 测试层既没有把这三/四个动作接进自己 `queryActions` 的合法通道，也不在职责内为它伪造一次 sleep/work/standup 的裁决（阶段 0 折衷只造攻击/拾取/治疗这些待 T-001 冻结的测试靶，不为睡下/起床透支同样的注入点）。
2. **过载/倒地剔除的时点语义在玩法层 schedule + 状态规则**：玩家回合循环（投点 roll → 结算 settle → 玩家行动 playerAction → NPC → 清理 cleanup）的 onEnter 守卫 U-001 在 `rollPolicyReady` 恒 false 时 `abort`，标准回合从投点阶段整体阻塞；`action-turn/playpack.json` 的过载剔除/倒地清除写在 `phase.roll.started` 的规则里，被同一 U-001 门禁挡死。这些 PhaseDef（`schedule.ts`）与规则（`rules.phase.ts`/`playpack.json`）是玩法层 deliverables，AI 测试层不跨 Spec 改。

**要落地这条靶子，需要显式授权其一**（写权当前全部拦在玩法层）：
- 由玩法层（T-001/U-001 接权主体）把「睡下→起床/过载剔除/倒地→站起」的三/四个 ActionDef + 过载/倒地阶段的相位规则，按 phase-2 的接线方式（`actionDefsByActor` + `queryActions` 委派）暴露给 AI 测试层；或
- 项目所有者判定 M10 完整状态机靶归玩法层「回合驱动器」专项，AI 线只保留当前已就绪的对局驱动器承载与单元级代价断言（M10 评分器侧已绿，见 `design-currency M10 状态与恢复边界`），端到端靶由该专项在 U-001/T-001 解冻后补建。
