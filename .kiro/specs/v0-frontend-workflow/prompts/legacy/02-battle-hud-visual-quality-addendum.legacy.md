# V0.dev 投喂追加 Prompt · batch-2：对局 HUD 质感与反网页感硬门禁

> **使用方式**：把本文件完整追加在 `02-battle-hud.md` 后面，再开始生成或修改 `hud-main`。本文件只补充视觉构图、材质和动效的硬约束，不改动 batch-2 的功能清单、数据形状、档位规则和排除项。
>
> **优先级**：本文件的视觉硬约束高于 V0 的通用网页组件惯例、默认 shadcn 卡片模板和 dashboard 排版习惯。遇到冲突时，保留游戏内 HUD 的空间感，不要退回网页布局。

---

## 0. 先给 V0 的一句话

这是**正在运行的 2D 独立游戏画面上的 HUD**，不是后台、控制台、SaaS 仪表盘、数据可视化页面，也不是一组悬浮网页卡片。先建立一个有空间、有事件、有前后层次的游戏世界，再把 HUD 作为附着在世界上的透明信息层；不要先铺满页面面板再把地图塞进剩余空白。

**核心构图原则**：游戏世界占满全屏 → HUD 是用半透明、局部、不对称的几何体附着在世界上的工具层。不是”地图在中央留白位，HUD 在周围围一圈”。

---

## 1. 不可妥协的视觉判定

生成结果必须让人先看到”正在发生的对局”，再读到 UI 信息。即使把所有文字隐藏，只看轮廓、光层、像素实体和动效，仍然应该像一个游戏场景，而不是网页后台。

### 必须满足

- 中央区域首先是**完整的游戏世界承载层**：即使本批次不实现真实地图，也必须有低饱和、半透明、可辨识的全息投影占位场景、空间深度、实体落点和环境光层。
- HUD 面板是附着层：半透明、局部遮罩、让背景光层和实体轮廓透出；不得把整个画面切成三块不透光的栏目。
- 轮次栏、动作、投点和状态信息必须围绕”当前行动者 / 当前事件 / 当前目标”组织，形成空间锚点，不是平均分布的表格字段。
- 前景像素实体与背景全息光层分层：像素图标、头像、角色和物品是高辨识前景；背景只提供氛围、深度和方向感。
- 用不对称尺寸、局部突出、遮挡、偏移、斜切或断开的边缘建立层级；不要让所有组件拥有相同宽高、相同圆角、相同边框和相同阴影。
- 所有重要状态都要有”静止态 → 变化态 → 结果态”的视觉节奏，变化由 Framer Motion 编排，不以瞬时变色代替演出。

### 直接判定为失败

- 看起来像管理后台、分析面板、表格、卡片墙、设置页或网页游戏充值界面。
- 画面有标准浏览器 chrome、地址栏、标签栏、网页滚动条、登录条、SaaS 侧边导航或工程属性面板。
- 采用”顶部导航 + 左侧栏 + 中央卡片网格 + 右侧详情栏”的 dashboard 骨架。
- 采用大量等大的圆角矩形卡片，内容只是图标、标题、数值和一条细边框。
- 地图/世界区域是空白纯色矩形，HUD 面板反而成为画面的主体。
- 依靠图片素材、渐变背景或霓虹边框掩盖平面布局问题；素材必须成为空间中的实体，不是卡片中央的贴图。
- 所有按钮只靠 hover 变色，所有过渡都是线性淡入淡出，或所有元素同时弹入。
- 使用 9-slice 边框图或缝合式边框素材（`frame-card.png` 等）做面板边界——这是”太独立/生硬”的直接原因，必须用 CSS `clip-path` + 半透明全息材质替代。

## 2. 构图硬规则：世界先于面板

### 2.1 空间层级

按以下层级构图，不要把每层做成独立网页栏：

1. **环境层**：低饱和全息投影、微弱暖/冷光、雾化光斑、稀疏漂浮尘粒。它必须覆盖中央世界区域，而不是一张空白底图。
2. **实体层**：角色、节点、物品、弱点图标和投点舞台。实体必须有位置、落地阴影、遮挡关系或局部高光。
3. **事件层**：当前行动者、投点横条、目标关系线、受击/充能/结算演出。事件层可以越过普通 HUD，但必须有明确的来源和去向。
4. **HUD 层**：轮次栏、动作菜单、资源格和固定入口。只占必要区域，不遮住事件发生处。
5. **仪式层**：投掷爆闪、一次性粒子、纯白/结算等低频覆盖演出。结束后必须退回世界，不留下网页式弹窗。

### 2.2 版式限制

- 不使用 CSS Grid 做均匀的“三栏应用模板”作为主构图。
- 不使用完整宽度顶栏、完整高度侧栏和完整宽度底栏同时封闭画面。
- 不给每个信息组都加标题栏、分割线和外框；标题只在确实需要建立语义时出现。
- 轮次栏是左侧的**纵向空间装置**，不是表格。当前玩家框要有尺寸、材质和投影上的明显突出；已行动者只是降饱和，不出现“已完成”网页标签。
- 动作菜单是从场景底部/右下方长出来的**局部动作托盘**，不做固定宽度的后台列表；付费与零费两套菜单切换时，用同一空间的形态变化表达，不同时铺开两张卡片墙。
- 投点结果从轮次框旁和当前行动者处**向外生长**，骰子是悬空的事件锚点；不把投点做成独立居中的对话框。
- 允许并鼓励留出不规则空白、局部遮挡和层间重叠。空白必须像镜头留出的空间，不像网页组件没有填满。

## 3. 材质和形状硬规则：禁止卡片汤

### 必须使用

- 半透明多层表面：底色、内侧高光、边缘光、局部阴影和轻微噪声/颗粒至少形成两层深度。
- 语义色只用于事件、边缘和局部高光；大面积由暗调灰阶或低饱和全息光承载。
- 轮次框、动作托盘、投点横条使用不完全相同的几何语言：可分别使用斜切、缺口、悬浮条、断边、内嵌槽或局部光带，但必须属于同一个视觉系统。
- 像素图标和头像使用清晰剪影、像素化缩放和落地阴影；图像与 UI 表面之间要有距离，不要把素材贴成卡片背景。
- 可交互态用边缘发光、反光扫过、局部凸起或材质变化；不可交互态用扁平、降饱和、无高光表达。

### 禁止使用

- 默认 shadcn/SaaS 卡片：`rounded-lg + border + shadow + icon + title + description` 的重复组合。
- 所有面板统一圆角、统一 1px 边框、统一内边距、统一背景不透明度。
- 霓虹扫描线、黑底荧光栅格、发光二极管阵列、过度玻璃拟态、金属工程面板。
- 将每个数字包装成 badge、pill、chip，再把 badge 排成网页信息卡。
- 用一个大渐变背景替代空间层、实体层和事件层。

## 4. Framer Motion 使用纪律：把它当作演出编排，不是 hover 装饰

本批次必须实际使用 Framer Motion；不能只安装依赖或用少量 `whileHover` 伪装动效质量。

### 必须落地的动效

- `AnimatePresence`：动作菜单、轮次框、骰子、投点横条、结果状态的进入/退出与状态替换。
- `layout` / `layoutId`：轮次排名重排、当前行动者框的空间迁移、付费/零费菜单在同一舞台内的形态切换。重排要保留空间连续性，不能整块闪现。
- `useSpring` 或 spring transition：资源格填充、当前行动者高亮、滑块推挡、投点条生长。避免所有动画使用同一默认 duration。
- `useAnimate` 或 variants：投点三段式演出、选择充能 → 确认爆发 → 横条结算，按阶段顺序编排。
- `whileHover` / `whileFocus` / `whileTap`：只做局部触感（边缘光、轻微位移、材质反馈），不要把整个 HUD 变成按钮网格。
- `motionValue` / `useTransform`：连续的光带、反光扫过、进度和局部透明度变化；不要用 React state 每帧重建整棵组件树。

### 动效节奏

- 静止态必须稳定，不能让所有面板永久呼吸、闪烁或漂移。
- 低频仪式动作可以有更强的全屏覆盖；普通交互只动相关对象及其邻近层。
- 当前行动者的高亮是材质反光和局部层级变化，不是整框持续放大或霓虹呼吸。
- 动画必须有起点、路径和落点：例如灰白横条伸出 → 强力骰段快速延伸 → 结果从左侧刷色。禁止只做 `opacity: 0 → 1`。
- 不要让所有元素同时 `initial` / `animate`；按环境、实体、事件、HUD 的层级错峰入场。
- `prefers-reduced-motion` 下保留状态、空间锚点和结果顺序，只缩短位移/闪烁，不删除语义。

## 5. 交互语法：玩家是在操作场景，不是在填写表单

- 动作选择优先表现为场景中的局部托盘、悬浮选项或目标附近的上下文关系，不做网页表单。
- 滑块必须是离散推挡器：手柄、刻度、充能残影和档位落点要有材质反馈，不使用浏览器原生 range 外观。
- tooltip 只解释对象，不创建新的大面板；焦点、键盘和 ARIA 仍使用 Radix。
- 物品、头像、骰子和弱点图标优先成为空间锚点；lucide-react 只承担语义图标，不用 lucide 图标堆满每个卡片角落。
- 保留真实世界中的遮挡、投影和层级：一个事件发生时，只有相关对象响应，其他区域保持稳定。

## 6. 技术边界

- 使用现有 React + TypeScript + Tailwind/design-tokens + Framer Motion + Radix + lucide-react 技术栈。
- HUD 继续使用 DOM/CSS 作为 UI 表现层；本追加 Prompt **不引入 Pixi.js、Three.js、Phaser、WebGL 或新的 Canvas engine**。
- 地图/世界占位只需提供视觉承载，不实现地图规则、拓扑、实体移动、ORCA、寻路或真实结算；不要因为“不做地图逻辑”而输出空白底板。
- 所有颜色从项目 tokens 读取；不要为追求“科技感”自由增加紫粉霓虹色、渐变彩虹或新的主色。
- 所有假数据和假交互继续遵守 `02-battle-hud.md` 的 `mock` 与 `placeholder-only` 规则。

## 7. V0 实施顺序（必须按顺序，不要先生成卡片）

1. 先完成全屏游戏世界承载层：背景光层、实体占位、事件舞台和前后层级。
2. 再放置轮次栏、动作托盘、投点舞台和固定状态；每一项都说明它附着的空间锚点。
3. 再实现材质系统：透明度、内高光、边缘光、阴影、断边/斜切和像素缩放。
4. 再用 Framer Motion 编排状态变化、空间重排和投点三段式演出。
5. 最后补 Radix 可访问行为、mock 标记、键盘焦点和 reduced motion。

不得从“先做一个顶栏、三个侧栏、若干卡片”开始。那条路径会自动生成网页。

## 8. 交付前视觉验收（任一失败就继续修改）

- [ ] 关闭所有文字后，画面仍然像一个正在发生的游戏场景，而不是组件拼贴。
- [ ] 中央世界区域不是空白纯色矩形；至少能读出空间、实体、事件舞台和背景光层。
- [ ] 不存在浏览器 chrome、SaaS dashboard、三栏后台、卡片墙、属性面板或网页滚动条。
- [ ] HUD 面板不是全不透明；背景光层和实体在合理位置仍可见。
- [ ] 轮次重排、动作切换、滑块充能、投点横条和结果结算都有空间连续的 Framer Motion 演出。
- [ ] 页面中没有所有元素同时入场、永久呼吸、统一圆角、统一边框或线性淡入淡出堆叠。
- [ ] 至少存在三种明确层次：环境层、实体/事件层、HUD 层；一次性仪式层只在触发时出现。
- [ ] 从灰度截图仍能看出可交互对象、当前行动者和投点事件的层级，不只依靠颜色。
- [ ] `+3极限爆发` 仍不可选，原 Prompt 的功能和排除项未被本追加 Prompt 改写。

**最终判断标准：如果结果更像“一个做得很漂亮的前端页面”，而不是“一个游戏的战斗画面”，则视为未通过，继续改构图、层级和动效，不要通过增加图片、边框或新依赖来掩盖。**

## 9. 落地范本：一组可行的分层构图方案

> 这一节把上面的反网页感判据，翻译成一组**具体、可落地、彼此协同的构图与材质方案**。它不是硬性设计锁定，而是「世界先于面板 + 不对称几何 + 逐层动效」的最小可行范本。若实现里能想出更贴合 `01`/`02` 语义的方案也可以，但必须满足本节的「共享约束断言」，并且保持同一套视觉系统的自洽。

### 9.1 共享约束断言（所有入选方案必须满足）

- 三栏 grid（顶栏 + 左卡片列 + 底卡行）的 dashboard 骨架**不再使用**；全局改为绝对定位的分层叠合。
- 每种信息载体（轮次、回合、动作、投点、资源）用**不同但相关**的几何语言：不共用同一套圆角矩形 + 1px 边框。
- 材质统一走「半透明多层光层 + CSS `clip-path` 轮廓 + 语义色边缘光」，平台表面可以从世界浅浮起，但始终让世界透出。
- 任何组件都不能是「静态卡片 + hover 变色」；状态变化必须有起点、路径、落点。
- **不引入新的渲染引擎**（Pixi / Three / WebGL），不引入新的 9-slice 边框贴图。
- “绝对定位”只针对**战斗 HUD 的视觉层**；必须保留响应式安全区、键盘焦点顺序、Radix ARIA 语义和 `prefers-reduced-motion` 降级，不得用坐标硬编码破坏可访问性或 1280×720 最小分辨率。

### 9.2 世界层（全屏基层，先于任何 HUD）

- 战场底图透传入屏（低饱和全息光层 + `clip-path`/渐变光池），作为空间承载，不是空白纯色矩形。
- 实体令牌 = 固定位置的勋章/圆片（medallion chip），带落地阴影 + 派系色环（`01` 语义色）+ 当前活动者脉冲。
- 可选：一条动画 SVG 目标线连接相关实体，把静态地图变成有方向、有事件的场景。
- 领土（terrain）与遮挡（obstruction）可沿用编辑器已落地的 SVG 几何语言（剪影 + 边缘光），与实体令牌保持同一套像素前景语言；它们是世界层的图元，不是 HUD 卡片。

### 9.3 轮次栏 = 左侧悬浮「脊柱」（spine）

- 不要做成等高等宽的一摞边框卡片；做成一条**悬浮的纵向脊柱**，盾形/六边形勋章挂在发光的导管上。
- 当前行动者勋章明显放大 + 偏移 + 名字旗帜 + 底座辉光；其余成员扁平、降饱和、只留一个小刻度弧（`D-035` 不显著的降饱和，不加"已结束"横幅）。
- 点击勋章用 Framer Motion `layout`/`layoutId` 做平滑提升/重排，保持空间连续；玩家自己的勋章仍比他人大且带反光（`01` 轮次栏核心规则）。
- 生命 5 格红 + 清醒 5 格蓝沿勋章/旗帜分布，用 `useSpring` / `useTransform` 表达填格与耗尽，不用细长连续条。

### 9.4 投点档位 = 悬在脊柱上的小型「仪表组」（instrument cluster）

- 把强力骰挡位齿轮 + 逆转/AP 菱形**合并**成一个小型斜切仪表组，斜挂在轮次栏脊柱旁，就近配合投点舞台（`01` §就地播放 D-036）。
- 滑块是离散推挡器（0/1/2，`+3` 仍不可选）：手柄、刻度、充能残影、档位落点都有材质反馈，不用浏览器原生 range 外观。
- 仪表组与轮次栏共用「导管/光层」语言，但用斜切几何区别于纯卡片。

### 9.5 回合指示器 = 顶部居中悬浮的「锯齿徽章」（notched insignia）

- 不再做通栏细条；缩成一个顶部居中、带锯齿边/刻痕的半透明徽章，显示回合/阶段/当前方。
- 轮到自己时徽章高亮 + 橙色 `⚡ 你的回合！剩余 AP`（`01` 回合指示器语义），NPC 阶段用其语义色提示。

### 9.6 动作行 = 底部居中的「非对称贝形托盘」（scalloped tray）

- 付费/零费动作从场景底部长出，用**贝形/波浪形**托盘承载，不是右下角一张固定宽度的后台列表。
- 托盘内动作卡用**斜切**（chamfered）而非圆角矩形；有成本卡 hover/tap 时上浮 + 边缘发光，AP 不足时下凹落平、扁平无高光（`01` 视觉定律）。
- 付费与零费两套菜单在**同一托盘空间**内做形态切换（`AnimatePresence` + `layout`），不同时铺开两张卡片墙；`2 AP` 中间过程动作仍不成灰。

### 9.7 动效分镜（Framer Motion 真编排，不只是 hover）

- 错峰入场：世界层稳定 → 实体令牌 → 事件层 → 脊柱/仪表/托盘 HUD → 固定组件，按层级分步进入。
- 活动态过渡用 spring 驱动（勋章提升、反光扫过、HUD 局部材质变化）。
- 投点三段式仪式：充能（滑块/档位光晕）→ 爆闪确认 → 横条分步揭示（`AnimatePresence` 顺序进入 + 结果从左侧刷色），三段按序编排。
- `prefers-reduced-motion`：保留状态、空间锚点、结果顺序，只缩短位移/闪烁、降低粒子。

### 9.8 材质与边界（本范本的关键）

- **完全放弃 9-slice 边框贴图**（`frame-card.png` / `frame-card-gold.png` 等）——它是"太独立/生硬"的直接来源。
- 面板边界用 CSS `clip-path`（斜切角、锯齿、贝形）+ 半透明多层光层：底色、内侧高光、边缘光、局部阴影、轻微噪声，至少两层深度。
- 颜色只从 tokens 取；大面积由暗调灰阶/低饱和全息光承载，语义色只做事件、边缘和局部高光。
