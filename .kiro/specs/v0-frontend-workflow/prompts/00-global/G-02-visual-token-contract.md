# G-02 视觉令牌契约

## 1 页面定位

统一所有批次的视觉语言、空间层级、材质和可见性。它是可直接投喂给视觉/前端生成 AI 的令牌摘要，不要求 AI 阅读源文档。

## 2 权威来源（只写 attachmentId / provenance）

- `presentation-art-direction` / `docs/表现系统/00_创作指导.md`：颜色是语义，动效是结果重演。
- `presentation-ui-authority` / `docs/表现系统/01_图形化与UI.md`：HUD、交互高光、可访问和层级。
- `presentation-elements-baseline` / `docs/表现系统/04_画面要素文档.md`：1080p、离散资源格和 HUD 分区。
- `decision-d083` / `docs/访谈决策记录.md`：像素前景 + 全息投影背景。

## 3 当前决策

- 基准 1920×1080，最小 1280×720；安全区响应式缩放。
- 当前视觉基线：高辨识像素前景 + 暖/冷全息投影背景 + 半透明 UI 层。旧“像素+简笔画”不是当前口令。
- 视角表述使用 `top-down plan view`；不使用等距、侧视或斜投影作为地图/实体视角。
- 允许和鼓励使用登记素材、纹理、光效、立绘和参考图。素材必须成为空间/界面的一部分，不只是卡片贴图。
- 页面不能退化为 SaaS dashboard、卡片墙或统一圆角矩形网格。

## 4 状态机

每个可交互元素：`base` → `hover/focus` → `active` → `return`；不可用元素进入 `disabled`。仪式层：`hidden` → `playing` → `result` → `hidden`。

## 5 组件树

环境层 → 实体与表现层 → 事件层 → HUD/面板层 → 仪式/错误覆盖层。不要把每层强制做成独立网页栏。

## 6 只读数据

颜色、图标语义、标签、状态和数字来自页面 fixture 或投影；视觉层不得根据颜色自行推断规则。

## 7 动作意图

视觉动作不执行规则，只产生 UI intent。素材加载失败产生 `asset.fallback` 呈现，不删除组件位。

## 8 本地 UI 状态

允许局部高亮、焦点、展开、排序、动画阶段、面板透明度和 reduced-motion profile；不允许本地推断状态。

## 9 视觉令牌

| 语义 | 颜色用途 |
|---|---|
| red | 生命减损、伤害、失败、危险 |
| blue | 清醒、体力、科技、信息 |
| yellow | 感官、警戒、需要注意 |
| orange | AP、进行中、行动 |
| green | 安全、正面、免费、完成 |
| purple | 约束、远程、条件、反制 |
| coral | 近战、格斗 |
| cyan | 社交、UGC、创作来源 |
| gray | 冷却、延迟、不可用 |
| gray-white | 受状态限制但仍可交互 |
| white/cream | 梦境边界、过载、纯白显形 |
| gold/silver | 少量品级、成就、收藏高光 |

材质：半透明多层光层、局部高光、边缘光、阴影、轻微噪声；大面积使用低饱和灰阶/全息光。

## 10 动效绑定

可交互：边缘发光、局部凸起、反光扫过、短 spring。页面切换：余辉、轮廓显影、列表重排。仪式：纯白显形、黑幕收束仅作为内容显影，不替代入梦/返回传送。

## 11 输入无障碍

不能只靠颜色表达状态；必须同时有图标、文字、材质或形状。焦点环不能被视觉裁剪，文字放大不应截断关键控制。

## 12 加载错误超时

资源缺失使用语义占位（图标/轮廓/文字），背景保留结构；不要让空白或 broken image 成为唯一反馈。

## 13 明确不做

不增加新的主色、霓虹彩虹、浏览器 chrome、9-slice 卡片框、统一圆角卡片汤或未经登记的视角。

## 14 依赖交接

组件可接受 `assetRef`、`iconRef`、`portraitRef` 和 `textureRef`，由宿主提供；AI 不负责资产生产管线或后端载入。

## 15 验收条件

关闭文字后仍像游戏界面而非后台；灰度下仍可读层级；素材/纹理/光效可正常替换；所有状态有明确视觉语义；无零素材叙事限制。
