## 一、核心原则

### 像素风 + 程序化动效

- 常规动作优先使用代码驱动的位置、旋转、缩放、透明度、粒子和震动。
- 低频、仪式性动作才使用全屏演出。
- 地图规则状态与动画播放严格分离；动画失败或被跳过不能改变结算结果。
- 表现资源缺失时走确定性降级，不拒绝合法规则对象，也不伪造规则事实。
- 动画、音效和震动都由语义描述符驱动，不根据字段名或显示文本猜测动作类型。

## 二、程序化移动

### 2.1 跳跃式移动

移动不是逐帧角色动画，而是沿权威投影给出的路径进行程序化变换：

```typescript
interface ProceduralMoveSpec {
  readonly durationMs: number;
  readonly arcHeightRatio: number;
  readonly rotationDegrees: number;
  readonly landingSquashRatio: number;
  readonly emitLandingDust: boolean;
}

function sampleMove(
  from: Point,
  to: Point,
  progress: number,
  spec: ProceduralMoveSpec,
): TransformSample {
  const eased = easeOutCubic(progress);
  const arc = Math.sin(Math.PI * progress) * spec.arcHeightRatio;

  return {
    position: lerp(from, to, eased),
    offsetY: -arc,
    rotation: Math.sin(Math.PI * progress) * spec.rotationDegrees,
    scaleY: 1 + arc - landingSquash(progress, spec.landingSquashRatio),
  };
}
```

### 2.2 默认参数语义

| 参数 | 默认方向 | 目的 |
|------|----------|------|
| 时长 | 短促、可读 | 明确起点与终点，不拖慢回合 |
| 弧高 | 轻微 | 表达棋子被“提起并落下” |
| 旋转 | 小幅摆动 | 增加手感，不改变朝向语义 |
| 落地压缩 | 瞬时 | 强化到达反馈 |
| 落地灰尘 | 可选 | 地面移动时增强质感 |

技术默认值可由表现 Profile 调整；它们不是玩法数值，也不能被玩法包用于计算移动成本。

### 2.3 路径与时序

- 路径只决定动画轨迹，不参与 AP、距离或命中计算。
- 状态修订令牌变化时，旧动画必须取消或收敛到新权威位置。
- 回放使用记录的语义事件与时间轴，不重新执行规则。
- 快速模式可以缩短或跳过动画，但必须保留最终状态反馈。

## 三、动作表现分级

### 3.1 程序化常规动作

- 节点移动、转身和待机。
- 近战挥击与远程后坐力。
- 上车、下车和换位。
- 受击闪烁、资源块增减和状态图标变化。

### 3.2 原地图内的图标切换

- 拾取、丢弃、装备与收纳。
- 精密交互完成，例如锁图标解开。
- 简单部署与回收。

### 3.3 全屏仪式动作

按 D-026 与 D-032，仅允许四项默认全屏演出：

| 动作 | 触发 | 边界 |
|------|------|------|
| **翻窗** | 成功完成翻窗动作 | 可使用碎玻璃和跨越演出 |
| **跳窗** | 成功完成向下跳窗 | 落地伤害另由规则结果驱动 |
| **令其长眠** | 对合法零血目标完成处决 | 使用统一蓝色仪式语义 |
| **招架触发** | 招架实际拦截近战攻击 | 远程或不可招架伤害使其静默失效，不播放 |

- 全屏演出通常为短时长并允许个人跳过；“令其长眠”等需要完整仪式感的动作可以由 Profile 标记不可跳过。
- 跳过只影响本地播放，不提前或延后权威结算。
- 多个演出同时到达时按显著性与因果顺序排队或合并，不丢失规则结果。

## 四、动画配方库

> 归档中的 A/B/C 变体恢复为“动画配方”，不使用废用术语。配方只绑定表现，不改变动作语义。

### 4.1 近战配方

- **近战 A：挥砍**——短弧线、轻微前冲、目标红色受击反馈。
- **近战 B：突刺**——直线压缩/伸展、命中点短促粒子。
- **近战 C：横扫**——较宽弧线，可用于散射式视觉但不推导实际目标数。

### 4.2 远程配方

- **远程 A：手枪后坐力**——短促后移、枪口火焰、单次音效。
- **远程 B：步枪后坐力**——更明显的持续抖动与连续火焰，但命中次数完全取自规则事件。

### 4.3 门户配方

- **翻窗 A：正面跨越**。
- **翻窗 B：侧面跨越**。
- **跳窗：向下跃迁与落地反馈**。
- 配方读取门户表现锚点；缺少锚点时降级为淡出/淡入，不修改位置结果。

### 4.4 仪式配方

- **令其长眠**：统一蓝色插头/导流演出，默认不允许 UGC 替换核心语义。
- **招架**：仅真实触发时播放擒拿/格挡演出；准备状态对对手无任何提示。

### 映射约束

- 绑定键是稳定语义 ID，不是本地化名称。
- 未知动作使用声明的降级配方，不得拒绝渲染整个状态。

- `ACTION_ANIMATIONS` 的配置所有权属于表现系统，不属于基类层或玩法层。

## 六、状态与姿态动画

### 零血倒地

- 角色旋转躺下，保持短促可读的过渡。
- 蓝色边缘闪烁表示可处决状态。
- 本地玩家可获得轻微屏幕边缘压暗；不得遮挡关键动作与退出操作。

### 普通击倒姿态

- 使用同类躺下变换但无蓝色处决闪烁。
- 若玩法包允许爬行，显示合法移动候选；动画不自行创建爬行动作。

### 爬行

- 可使用少量循环帧或程序化拖拽。
- 视觉速度低于正常移动，但实际时序和成本完全由规则投影决定。
- 拖痕粒子是可选表现，低性能或无障碍 Profile 可关闭。

## 七、粒子系统

### 7.1 最小高价值粒子集

| 粒子 | 用途 | 默认生命周期 |
|------|------|--------------|
| 灰尘 | 移动落地 | 短 |
| 血液飞溅 | 生命伤害 | 短 |
| 枪口火焰 | 远程开火 | 极短 |
| 碎玻璃 | 翻窗/破窗 | 短 |
| 蓝光粒子 | 令其长眠 | 短至中等 |

### 7.2 原则

- 优先程序生成的圆点、线段与简单多边形，减少贴图依赖。
- 粒子数量、颜色和寿命来自表现 Profile，不参与规则计算。
- 屏幕外粒子不更新；同类粒子可批量渲染并复用对象池。
- 关闭粒子不能丢失语义结果，关键结果必须同时有图标、文字或音频反馈。

## 八、音效设计

### 8.1 UI 音效

- 聚焦与确认。
- 菜单切换。
- AP 消耗、动作不可用与结构化拒绝。
- 诊断出现、定位和修正完成。

### 8.2 对局音效

- 脚步声按场景材料或语义类别选择。
- 武器声音由表现描述符决定，不由显示名猜测。
- 环境音包括风、雨、机械和 NPC 声音。
- 声音既可以是玩家反馈，也可能对应规则中的可感知事件；两者必须区分：规则声音事件来自权威投影，纯 UI 声音不进入 NPC 感知。

### 8.3 混音与可访问性

- UI、对局动作、环境、语音和音乐使用独立音量通道。
- 关键音效提供字幕或可视提示。
- 快速重复事件应合并或限频，避免音频轰炸。
- 隐藏动作不能通过预加载、空间音效或辅助字幕提前泄露。

## 九、震动与触觉反馈

| 反馈 | 建议强度 | 示例 |
|------|----------|------|
| 轻 | 极短 | 移动落地、菜单确认 |
| 中 | 短 | 射击、受击 |
| 重 | 较短 | 倒地、爆炸 |

- 震动必须可全局关闭，并支持强度 Profile。
- 设备不支持时静默降级，不显示错误。
- 震动只能响应已确认语义事件，不能在预测阶段提前触发不可逆反馈。
- 时长和波形是表现技术参数，不成为玩法数值。

## 十、资源缺失与降级

降级顺序：

```text
指定配方
  → 同语义类别默认配方
  → 通用程序化反馈
  → 图标/文字状态变化
```

- 任何一级降级都必须保留结果、目标和不可用原因。
- 资源加载失败记录有界诊断，不影响规则状态。
- 缺失仪式资源时不得借用语义错误的其他全屏动画。
- 版本不兼容的资源包拒绝激活该资源包，但保留基础表现 Profile。

## 十一、性能策略

- 同类粒子批量绘制，图集减少纹理切换。
- 远离镜头的实体降低非关键信息的刷新率。
- 屏幕外粒子与装饰动画暂停。
- 动画与粒子实例池化，避免高频分配。
- 低性能 Profile 优先关闭装饰粒子、屏幕震动和非必要过渡，不删除规则反馈。
- 动画预算超限时按显著性降级，不能阻塞权威事件消费。

## 十二、UGC 动画与音效指南

### 12.1 最低提交

创作者只需提供：

1. 静态图标（建议 32×32 或 64×64 像素）。
2. 从已发布动画配方中选择一个绑定。
3. 必要的语义替代文本。

### 12.2 高级定制

可选提交：

- 自定义帧动画，遵守像素网格与帧数配额。
- 自定义音效，使用发布契约允许的格式与大小。
- 粒子颜色和形状参数 JSON。
- 自定义表现 Profile，但不能修改动作语义 ID。

### 12.3 静态验证

Linter 至少检查：

- 图标尺寸、透明边界和资源格式。
- 帧数、时长、文件大小和解码能力。
- 动画配方与动作语义是否兼容。
- 音效版权/来源元数据与安全格式。
- 粒子参数是否在技术预算内。
- 是否提供替代文本和降级配方。
- 是否试图用表现资源携带脚本、网络地址或规则数值。

### 12.4 所有权边界

- UGC 表现包只改变感知方式，不改变命中、伤害、AP、目标或状态。
- 玩法包可以声明需要表达的语义，不直接引用具体资源路径。
- 创作系统负责制作、预览、审核和发布；表现系统负责运行时消费。

## 素材工作流与工具链（D-072 ∕ D-078）

素材工作流管线按总纲收敛三件事——**人机协作、双分层坐标系、地图编辑器为桥梁**（D-072）。表现侧承接其中与**图形化呈现、工具界面**相关的部分，规则/编译侧契约见创作系统与 UGC 层文档，此处只定表现语义，不画线框（待细化）。

### image2：AI 生成底图草案 + 人工挑选定稿（D-072）

- **开发者侧生产工具**：`image2` 用于 AI 生成**底图草案**，由人充当**眼睛与迭代裁决者**——人选定稿、裁定版本。它是开发者/创作者侧的生产管线，**不受"LLM 不生成素材"的玩家运行时约束**（该约束服务玩家运行时，不约束创作侧生产工具）。
- **人机迭代闭环**：AI 与创作者讨论需求、依据既定设计（如预设色板/风格）迭代 `image2` 产出；人在自己负责的判定处出手（选稿、裁定拓扑/隔离），其余由 AI 与校验闭环推进。
- 表现侧约定：底图草案列表以**像素前景 + 全息投影背景**的统一视觉基准呈现（见 `01_图形化与UI.md` 视觉风格定位，2026-08-19 D-083 升级），帮助人在同风格下对比挑选；具体排布待细化。

### LLM 工具双通道的人机呈现（D-078）

LLM 工具分两种行为，**人机入口与产出互不归入对方**，图形化在界面与入口上区分（分别对应**素材编辑入口 / 玩法包创作入口**）：

- **辅助修改素材（快路径，单素材替换）**：选择素材库中某个素材时，点一个选项弹出问答框。问答框**不同于**既有反复采访——AI 只当再询问一轮以补全边界，之后**直接行动**；prompt 规定：若 LLM 认为边界已补齐无歧义、或玩家极大概率只是该需求，则**不询问直接开始**（单查询 → 直接行动）。修改后**直接作用于并替换该素材，不创建任何玩法包**；产出改后的**单个 JSON 素材**（素材 = 单条 def，见 D-075）。图形化呈现为一个精简问答面板，无歧义即不打断、直接落地替换结果。
- **从 0 生成玩法包（打包装载）**：自由度更高，从零直接造一个玩法包，可改数值、建新实例、改旧实例（**引擎层 LLM 根本不知道存在、也改不了**）。产出**可插拔的玩法包（标准 zip）**，走打包装载；图形化承接既有"采访 → 生成玩法包 → 调用编译器 → 展示诊断"流程（见 `01_图形化与UI.md` 创作工具的 UI 切换）。

**两条通道区分点**：素材编辑走**单素材替换快路径**（不造包）；玩法包创作走**完整采访+打包装载**。界面语义沿用既有视觉约定（青色承载 UGC/创作来源，见视觉定律 1），不新增主色，不画线框。

## 十三、验收不变量

1. 禁用全部动画、粒子、音效和震动后，规则仍能完整运行。
2. 快速跳过动画不会改变事件顺序或最终状态。
3. 表现 Profile 切换不要求重载玩法包。
4. 未知动作有确定性降级，并保留语义说明。
5. 隐藏信息不会经动画、声音、字幕、预加载或震动泄露。
6. 表现系统没有规则状态写入通道；交互只提交待校验意图。
