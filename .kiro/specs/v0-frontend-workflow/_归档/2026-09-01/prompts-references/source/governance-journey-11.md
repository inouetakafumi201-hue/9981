## 〇、设计前提：先读这篇再看本文

本文把三条权威主线钉成一张旅程图，**不发明新概念**：

| 权威基线 | 出处 |
|---|---|
| **节点就是局外菜单**：现实地图（出租屋）= 主界面，传统「竞技匹配/其他模式/自建房」按钮矩阵不是默认入口 | `运营系统/01` §二 |
| **床 = 装载入口；锚定导流仪 = 门控**：床在锚定导流仪交互前不可点是铁律 | `运营系统/03` §四 |
| **入梦/返回统一用「纯白显形」**：约 1 秒、可跳过、床全程不消失 | `运营系统/03` §六、`表现系统/01`「驻地演出」 |

**三条铁律贯穿全文，任何人都不得在旅程里打破**：

1. **标题画面 = 启动前置，落地即出租屋实景**（2026-08-19 所有者审查裁决）：启动第一眼是标题画面（开始菜单，标准四入口），`新游戏` 淡入落地出租屋；落地后「节点 = 局外菜单」。匹配完成不加载独立大厅（影子方案）。
2. **床 = 装载入口，研究台 = 素材级工作台、造梦舱 = 地图编辑器、电脑 = 元状态港湾，两两不可混同**（`运营系统/03` §三、`运营系统/07` §一、`创作系统/01` §驻地入口映射）。
3. **所有出入对局的视觉门 = 纯白显形**，不做第二套传送语汇（`叙事设定/00` §十二）。

**玩家画面归属边界**：本文件按「三层 + 正交域」组织——**玩法层（对局内）** 的画面是 `表现系统/01` 的对局 HUD（投点/动作/状态）；**运营系统（对局外）** 的画面是 `运营系统/01/03/04/05` 的驻地/素材库/收藏室/真相板。二者**不是两套 UI 实现**：驻地复用战斗内的 `uiDescriptor` 端口，用 `PresentationProfile.pacingPresentations = 'minimal-ui'` 配置为少 UI 实例（`表现系统/01`「创作工具的表现接入」）。任何单一「交互流」文档（含本文）都**不可自造第二套规则/播放器语义**——尤其证据提交被反复强调是「假游戏循环，**依然是玩法**，不是纯文本播放器」（`运营系统/05` §4.1）。

## 一、启动 → 落地（第一眼）

### 1.1 启动前置：标题画面（2026-08-19 所有者审查裁决）

2026-08-19 所有者审查裁决：偷师前端包含五脏俱全的标题画面（开始菜单）与暂停菜单。标准四入口：`新游戏` / `继续` / `选项` / `退出`；`选项` 展开五脏俱全的设置面板（显示/声音/输入/无障碍/语言/图形）；`新游戏` 淡入落地出租屋。暂停菜单包含 `继续` / `设置` / `重新开始` / `返回标题`。

该裁决**取代「无传统主菜单」旧铁律的启动入口部分**（6.1 同步修订）。两条铁律不变：**床 = 装载入口**（标题的 `新游戏` 落地到出租屋，不直接进对局）、**纯白显形唯一传送**。

### 1.2 落地后的画面 = 出租屋实景（少 UI 模式）

驻地**默认使用少 UI 模式**（`运营系统/01` §3.3 :106-113）：

- **隐藏**：行动轮列表、HP、SP、AP、战斗动作面板。
- **保留**：节点移动、局部交互、必要文本和运营反馈。

**必禁**：少 UI 模式只减少表现、不赋予额外规则权限、不允许 UI 本地推进状态；**任何允许战斗的活动都不得伪装成少 UI 模式**（`运营系统/01` §3.3 :112、§八 :225）。

### 1.3 落地后的地图布局（出租屋正面俯视视图）

承载物布局是**正面俯视视图**（`表现系统/01` §视觉风格定位），不是 Isometric、不是侧视图：

```text
出租屋（现实地图 = 主界面，正面俯视）
  ├─ 床A（蓝）       → 主线 + 竞技入口    （非 UGC，青不背它）
  ├─ 床B（珊瑚）     → 联机副本入口        （MVP 留后续）
  ├─ 床C（青）       → 进入「自己建好的梦」= 体验沙箱（UGC，青）
  ├─ 锚定导流仪      → 选模式 / 状态 / 规则准备 / 匹配（床旁一人高黑色科技机箱）
  ├─ 研究台          → 素材级工作台：词条库 / 提取词条 / 锻造 / 合成仪式 / 塑形备选栏（权威名，原「锻造台」，见运营/07）
  ├─ 造梦舱          → 地图编辑器入口（纯编辑器，不再承担多应用台）
  ├─ 电脑            → 梦核多应用台 · 元状态港湾（套餐订阅 / 活动领取 / 行业评价 / 证据提交 / LLM 造玩法包，见运营/07 §七）
  ├─ 电视            → 公告 / 活动 / 行业评价等被动显示
  ├─ 书架            → 梦境素材库（元素 / 蓝本，创作资源，青；含地图/蓝本只读 tab）
  ├─ 保险箱          → 收藏室（高价值 / 纪念对象，"一眼是高价值物"）
  ├─ 门缝            → 世界气味（辅助叙事，不入口，纸条/传票/水电单）
  └─ 边缘氛围        → 视觉氛围、碎片化叙事载体
```

实体 → 节点职责映射对齐 `运营系统/03` §二 :46-60 与 §三 :64-77：

| 出租屋实体 | 承担的节点职责 | 悬停/可交互语义 | 点击/交互后 |
|---|---|---|---|
| **床A**（蓝） | 主线出口、竞技入口（装载边界） | 锚定导流仪未交互前**不可点**（扁平无高光） | 匹配完成后高光亮起 → 躺下 = 就绪 |
| **床B**（珊瑚） | 联机副本入口 | MVP 不可点（留后续） | — |
| **床C**（青） | 自建梦入口（体验沙箱） | MVP 仅编辑器内自测，**不可入局** | — |
| **锚定导流仪** | 模式选择 + 异步匹配 + 规则/状态准备 | 可点击（彩色 UI 完整） | 打开匹配界面 |
| **研究台** | 素材级工作台（词条库/提取/锻造/合成仪式/塑形栏） | 可点击（青色 UGC 边缘发光） | 进入研究台界面（词条库 / 锻造工作台 / 合成 / 塑形栏） |
| **造梦舱** | 地图编辑器入口（纯编辑器） | 可点击（青色） | 进入地图编辑器（三栏工作台） |
| **电脑** | 梦核多应用台 · 元状态港湾（套餐订阅/活动领取/个人面板/行业评价/证据提交/LLM 造玩法包） | 可点击（青色） | 进入电脑应用台 |
| **电视** | 公告 / 活动 / 行业评价被动显示 | 壁挂/置物柜上的屏幕，**只读不交互** | 玩家主动走到电视前看公告 |
| **书架** | 梦境素材库入口（创作资源，含地图/蓝本只读 tab） | 可点击（青色） | 打开素材库界面 |
| **保险箱** | 收藏室入口（长期高价值/纪念） | 可点击（金色高光） | 打开保险箱界面 |
| **门缝** | 辅助叙事（不承担任何入口） | 纸条出现时悬停可读 | 阅读纸条/传票/水电单 |

**承载物职责两两不可混同**（`运营系统/03` §三、`创作系统/01` §驻地入口映射、`运营系统/04` §五、`运营系统/07` §一）：

- **床 vs 研究台**：床 = 装载入口，研究台 = 素材级工作台。**床不锻造、研究台不装载**。
- **造梦舱 vs 研究台**：造梦舱 = 地图编辑器，研究台 = 素材级工作台。**造梦舱不放素材，研究台不放地图**。
- **电脑 vs 研究台**：电脑 = 元状态管理港湾（账号级状态/应用），研究台 = 创作素材工作台。**素材不进电脑，账号状态不进研究台**。
- **书架 vs 保险箱**：书架 = 梦境素材库（创作资源，可星标检索、可看详情），保险箱 = 收藏室（长期纪念对象，拒堆叠、无丢弃）。**两套不混装**。
- **床C 与床A/B**：A/B 通往他人/官方梦境，C 通往自己的梦境；C 的装载源是自己的素材库/研究台里打造好的素材 + 造梦舱里建好的沙箱。

**少 UI 模式下的信息保留**：节点可移动、局部交互、必要文本（节点名/悬停说明）与运营反馈（如匹配状态、纸条出现）——**不显示任何战斗数值**（HP/SP/AP）。

## 二、局外循环：在出租屋里做什么

### 2.1 局外循环 = 出租屋内的前进/位移导航

**局外循环与对局循环不是两个独立入口，它们都发生在出租屋场景内**（`运营系统/01` §一 :9-17 运营系统定位：决定玩家是否处于对局、下次装载哪份场景/玩法包；`运营系统/03` §七 :160-168 退出对局后落在出租屋）。

玩家在出租屋里自由移动（WASD / 点击移动），在承载物之间导航：

```
[出租屋 - 局外循环]
    ├─ 锚定导流仪交互（选模式/匹配）→ 进入对局流程（见 §三）
    ├─ 研究台 → 素材级工作台（词条库/提取/锻造/合成/塑形栏）→ 回到出租屋
    ├─ 造梦舱 → 地图编辑器（创作地图）→ 回到出租屋
    ├─ 电脑 → 梦核多应用台（套餐/活动/证据提交/玩法包 LLM/元状态总览）→ 回到出租屋
    ├─ 书架 → 梦境素材库（浏览/检索/星标/地图蓝本只读）→ 回到出租屋
    ├─ 保险箱 → 收藏室（回看/纪念/陈列）→ 回到出租屋
    ├─ 门缝 → 阅读纸条（纯叙事）→ 回到出租屋
    └─ （对局结束）→ 结算 → 回到出租屋
```

> **三界面切换（2026-08-19）**：素材库（书架）、地图编辑器（造梦舱）、研究台构成**全屏替换、状态保留**的三界面切换链（编辑器右栏快捷素材栏上方按钮 → 素材库；素材详情小按钮 → 研究台）。详见 `运营/07` §二。

### 2.2 局外承载物交互（对齐权威设计）

| 承载物 | 交互骨架 | 关键约束 | 出处 |
|---|---|---|---|
| **书架（素材库）** | 星标置顶 + 分类/关键字检索 + 素材卡片 + 详情 + 地图/蓝本只读 tab | 书架服务**创作**（检索优先，与编辑器/研究台三界面切换）；「编辑素材」全屏切到研究台（不内嵌编辑） | `运营系统/04` §三、`运营系统/07` §四/§五 |
| **保险箱（收藏室）** | 抽屉式平铺 + 左侧带色类别栏 + 点击右侧详情/大图 + 可有「使用」按钮 | **拒堆叠**（不放材料/垃圾）、丢弃先不做；陈列随主线渐进增加；收藏室不得被实现为仓库/素材库，不得沦为对局配装 | `运营系统/04` §二、`运营系统/01` §4.2 |
| **研究台（素材级工作台）** | 词条库（材料收集库）+ 提取词条 + 锻造工作台（5 槽、底图感、右侧组合预览）+ 合成仪式（3 台子特效）+ 塑形备选栏 + 素材快捷栏（与素材库共享；无词条快捷栏，D-084） | 床是装载入口，研究台是素材级工作台，不可混同；研究台**不**做地图编辑、不做玩法包生成；锻造素材仅来自拥有库 | `运营系统/07` §六、`创作系统/01` §三 |
| **造梦舱（地图编辑器）** | 三栏工作台 + 涂鸦式交互（场景框/连线/遮挡框/高地洼地/过渡窗口） | 编辑器几何标注产出 `MapData`；**改图闭环必要 = 载入/选中/放置/拉边/挂实例/撤销重做/校验/存档读档**；右栏快捷素材栏上方 = 切素材库按钮 | `表现系统/01`「地图编辑器」、`创作系统/01` §九、`运营系统/07` §二 |
| **电脑（梦核多应用台）** | 套餐订阅 / 活动领取 / 个人面板 / 行业评价 / 证据提交（VR 取证室）/ LLM 从零造玩法包 / 元状态总览 | 模块化应用可拓展；**查看/管理为主，不陈列不收藏**；领取/订阅动作必须到电脑（电视只被动显示） | `运营系统/05` §4.6/§4.7、`运营系统/07` §七 |
| **门缝** | 纸条/传票/水电单出现 + 阅读 | 纯叙事、**不承担任何入口**；主线间歇不可连来 | `运营系统/04` §三·五 |

**真相板 / 证据提交（VR 取证室）**：素材库之上的**叙事组织视图** + 证据提交玩法（`运营系统/05` §三/§四/§4.7）：
- 真相板 = 按叙事线索分类的证据墙，显示进度和空缺；承接落点待细化（`运营系统/05` §三 :83）。
- 证据提交 = **电脑**内的 VR 取证室应用：独立图层（`height = null` 三界之外独立层），虚空白底 + 正面斜投影取证室 + 桌面 3–5 槽位 + 警官对话（复用叙事对话框系统）（`运营系统/05` §4.2.1/§4.7）。
- **可提交素材 = 仅拥有库**；不消耗、可反复试探；「隐藏真相」每组合首触发（`运营系统/05` §4.7.3）。
- 证据提交是**主线的平行暗线**，不是前置条件，不强制（`运营系统/05` §4.4）。

### 2.3 局外循环的核心原则（权威约束）

1. **反仓库/反无限变强**：局外养成不做塔科夫式逐件带入带出、不做自由配装（`运营系统/01` §4.1）。
2. **低心智经营**：同屏主要经营选项应收敛；货币余额可超 5（内部记录），但不得用多币种制造虚假深度；归并入口优先于加新菜单/新条（`运营系统/01` §4.3）。
3. **颜色语义不可因界面切换改义**：运营系统与对局共用全局颜色语义，商店/收藏室/匹配状态/主线节点都按「玩家看到颜色先猜什么」选主色（`运营系统/01` §六、`表现系统/01` §视觉定律 1）。
4. **不可点击不能只靠灰色表达**：可点击冷却用高光/凸起/材质感；不可点击扁平无高光（`表现系统/01` §视觉定律 2，`运营系统/01` §六）。
5. **收藏室/素材库/仓库职责严格分离**（`运营系统/01` §4.2/§10.2、`运营系统/04` §五）。

## 三、进入对局流程（匹配 + 装载 + 入梦）

### 3.1 床 + 锚定导流仪双实体流线（对齐 `运营系统/03` §四）

```
[玩家走到锚定导流仪]
    ↓
[点击锚定导流仪]
    ├─ 选择模式（MVP：仅竞技；联机副本/自建房灰显【扁平无高光】，留后续）
    ├─ 展示规则 / 状态 / 规则准备（彩色 UI 完整）
    └─ 发起匹配（异步，见 §2.2——匹配期间可继续在租屋移动，不得锁进等待界面）
    ↓
[匹配完成]
    ├─ 对应床由灰变可交互（床高光亮起，边缘发光）
    └─ 玩家走到床边，躺下 = 「就绪」（睡眠姿态就是就绪动作，无 UI 或极简）
    ↓
[全屏世界介绍 + 玩法包说明]（可跳过）
    ↓
[纯白显形传送演出]（约 1 秒，多帧曲线不僵硬，可跳过；床全程不消失）
    ↓
[进入对局装载边界]
```

**门控铁律**（`运营系统/03` §四 :94-117）：**锚定导流仪未交互完成前，床不可交互**（呈灰色、不可点）。防止玩家误以为能直接躺床乱开。

**锚定导流仪负责「匹配/状态/规则准备」**（信息密度高，彩色 UI 完整）；**床负责「躺下即就绪」**（进入侧，无 UI 或极简，睡眠姿态就是就绪动作）。

### 3.2 影子大厅（匹配成功后的就绪交互留在原场景，`运营系统/03` §五）

- **方案 A：影子站桩（已采纳）**：匹配完成后**不加载独立大厅场景**，其他已就绪的玩家以「半透明影子」形式在租屋可见——
  - 真实物理影子在场（半透明白色轮廓，悬停显示名字，站桩等待，不能交互）。
  - 就绪状态由**权威侧推进**（快照/中继），本地不伪造状态。
  - 匹配期间可继续活动（异步原则，`运营系统/01` §2.2）。
- **否决统一大厅**：统一大厅需要重载到集体场景，破坏异步原则，不采用。
- **MVP 可退化**：就绪后直接进装载边界，无条件强制影子的全量同步（`运营系统/03` §八）。

### 3.3 装载与入梦（`运营系统/03` §六 + `表现系统/01`「驻地演出」）

**入梦（实 → 梦）** 子流程：

```
1. 床从平地被翻起/浮现（床是固定实体，全程不消失）
2. 人 + 床整体纯白（约 1 秒，高冲击过载感）
3. 复原色彩（颜色滚动/曲线，多帧不僵硬）
4. 人物从床跳下 → 进入梦境
```

**返回（梦 → 实）** 子流程：

```
1. 床在（床是固定实体，全程不消失）
2. 人物纯白显形（约 1 秒）
3. 纯白被推向床（颜色滚动/曲线）
4. 人物在床上复原色彩 → 起床演出
```

**铁律**（`运营系统/03` §六 :133-156）：
- 床是固定实体，**不销毁**；演出只移动人形与改变色彩。
- 约 1 秒纯白，**高冲击**（过载闪光感），不做成常态底色。
- **曲线 / 多帧，不僵硬**，不做单帧跳变。
- **可跳过**，且不影响规则装载。
- 纯白 > 其他白：显形白是短暂的高冲击白，不是常态底色（`表现系统/01`「驻地演出」:1086）。
- 睡眠姿态只在床侧呈现，且**只在锚定导流仪已就绪、床变可交互后**触发就绪演出，不提前播放（`表现系统/01`「驻地演出」:1089）。

## 四、对局内循环（战斗核心）

### 4.1 对局 HUD（对齐 `表现系统/01` + `表现系统/09` §三·五）

进入对局后，玩家看到**完整对局 HUD**。**布局/交互/动效的一切权威细节见 `表现系统/01`**（轮次栏 D-036、动作菜单 D-042、投点滑块、状态栏、物品栏、回合指示器）。本文只钉「在对局里走一圈」的顺序，不重复表现细节：

```
[对局开始画面]
    ├─ 地图名称 / 玩法包说明（可跳过）
    └─ 淡入到对局

[对局 HUD 布局]
    ├─ 顶部：回合指示器（回合/阶段/当前行动方；轮到时「你的回合！」）
    ├─ 左侧常驻：轮次栏（D-036，头像+名字+HP 红 5 格+SP 蓝 5 格；当前行动方反光高亮；已行动者降饱和）
    ├─ 中央：地图（正面俯视视图绘制 + 实体 + 动效）
    ├─ 右下：动作菜单（D-042，付费面板 + 零费切换钮；AP 耗尽只留零费 + 3s 倒计时）
    ├─ 投点阶段：两个推挡滑块（强力骰+逆转，MVP 3 档 0/1/2，+3极限爆发预留，本地播放 + 横条生长 + 结算行）
    ├─ 左上：退出 + 设置入口（`运营系统/03` §七）
    └─ 物品栏：2 手 + 2 格（出生空手进场，D-041）
```

**对局内核心循环（回合制战斗）**——一个完整回合的流程（对齐 `L3/01` 行动轮）：

```
[回合开始：投点阶段]
    ├─ 所有玩家推滑块（强力骰+逆转，消耗清醒值/SP）
    ├─ 同时投点（骰子悬空 + 横条三段式生长）
    └─ 结算排名（轮次栏重排，layout 动画）
    ↓
[玩家行动阶段]
    ├─ 轮到玩家 A:
    ├─ 轮次栏高亮（反光感）
    ├─ 回合指示器「你的回合！」
    ├─ 动作菜单展开（付费面板）
    ├─ 选择动作（移动/攻击/技能/物品）
    ├─ 选择目标（如需要）
    ├─ 动作结算（规则引擎计算 + 动画播放）
    ├─ AP 扣除（轮次栏 AP 数字 -1）
    └─ 已行动标记（降饱和，不加叉）
    ↓
    （轮到玩家 B，重复上述流程）
    ↓
[NPC 行动阶段]
    ├─ 「NPC 行动阶段」提示
    └─ NPC 自动行动（快速结算，不等玩家确认）
    ↓
[清理阶段]
    ├─ 过载/倒地/站起等状态处理
    ↓
[回合结束 → 下一回合]
```

**对局内数据铁律**（`表现系统/01` §动画与规则结算的解耦 + §响应式不变量）：
- **表现层只提交意图**；任何设备都不能本地预先扣除 AP 或推进状态。
- **动画 = 规则结果的视觉重演**：`after:*` 事件投递时规则已完成；动画失败/跳过 → 静默跳过、直接显示规则结果。
- **结算不等待动画，但轮权交接必须等所有动画结束**（唯一硬同步点；单人模式无此限制）。
- 招架是真隐藏（无任何标识，D-032）；瞄准是低显著性公开（悬停点线，无感叹号，D-033）。

### 4.2 一人模式（同局动态升降，`运营系统/01` §3）

- **一人模式 ≠ 少 UI 模式**，不得共用一个开关（`运营系统/01` §三）。
- 当同一对局只有玩家本人且无 AI/其他玩家 → 进入一人模式：轮次栏不移动、不竞争，只突出玩家状态栏；玩家以 1 AP 推进 1 回合；连续 x 秒无操作 → 请求权威运行时自然流逝 1 回合（经权威动作通道，不本地强推）。
- 任一 AI/玩家进入有效范围 → 战斗轮升起恢复标准节奏；升降**不重载场景、不重建轮次栏、不重置玩法包状态**。

### 4.3 对局结束 → 结算 → 返回驻地

```
[对局结束条件满足]   （最后站立者获胜 / 时间到 / 特殊条件——MVP 规则由玩法包定义）
    ↓
[结算画面]
    ├─ 胜负展示
    ├─ 回合数 / 击杀数
    ├─ 奖励：记忆碎片/点数（能力货币）、美元（生存货币）、素材（梦境碎片）
    └─ 「继续」
    ↓
[纯白显形返回演出]    （梦 → 实，见 §3.3）
    ↓
[返回驻地]           （落在出租屋原位置/床旁；`运营系统/03` §七）
```

**中途退出**（`运营系统/03` §七）：
- 左上角提供**退出 + 设置入口**。
- 退出 = 请求离开当前对局（经权威动作通道），不是本地强退。
- 返回后落在出租屋原位置/床旁，不强制重复入梦流程。

## 六、关键 UX 决策与衔接点（对齐权威）

### 6.1 为什么启动有标题画面（开始菜单）？

**2026-08-19 所有者审查裁决**：偷师前端包含五脏俱全的标准开始菜单（`新游戏` / `继续` / `选项` / `退出`）。本文件旧版「无传统主菜单：启动即出租屋实景」的表述，其启动入口部分已被该裁决取代——玩家第一眼是标题画面，`新游戏` 淡入落地出租屋（保留「节点就是局外菜单」的局外骨架：落地后仍是出租屋实景，`床 = 装载入口` 不变）。

**推论**：退出与设置入口不是「回主菜单」，而是：
- 对局内：左上角退出+设置（返回出租屋）（`运营系统/03` §七）；暂停菜单可 `返回标题`。
- 出租屋内：直接退出游戏；或回标题画面（`返回标题`）。

### 6.2 为什么床 + 锚定导流仪是两个实体？

**权威**：床 = 装载入口，锚定导流仪 = 门控（`运营系统/03` §四）。锚定导流仪负责信息密度高的一方（模式/规则/匹配状态），床负责进入侧（就绪，无/极简 UI）。**门控铁律**：锚定导流仪未交互前床不可点；匹配完成后床由灰变可交互。

### 6.3 为什么驻地用少 UI 模式？

**权威**：`运营系统/01` §3.3——驻地默认少 UI，隐藏行动轮/HP/SP/AP/战斗动作面板，只保留节点移动、局部交互、必要文本和运营反馈。**少 UI ≠ 一人模式 ≠ 终点**：少 UI 不影响规则权限，任何允许战斗的活动不得伪装成少 UI。

### 6.4 为什么入梦/返回都用纯白显形？

**权威**：`运营系统/03` §六 + `表现系统/01`「驻地演出」——纯白显形是唯一出入传送语言（不做第二套传送语汇），约 1 秒、多帧曲线、可跳过、床全程不消失。

### 6.5 对局结束后为什么返回驻地，而非「主菜单」？

**权威**：运营系统是对局外的会话调度与长期推进域（`运营系统/01` §一）；对局结束 → 结算 → 返回出租屋原位置（`运营系统/03` §七）。继续下一局前，玩家在出租屋里可以：使用奖励（美元/记忆碎片/素材）、整理素材库/收藏室、创作、再匹配——这就是完整闭环。

## 七、界面切换动效规范（向 V0.dev 投喂的「全流程」动效基线）

所有界面切换必须**有明确的过渡动画**，不得瞬间跳变；动效一律 Framer Motion，时长 < 1.5s，可跳过：

| 切换类型 | 动效方案 | 时长 | 库 |
|---|---|---|---|
| 启动落地 → 出租屋 | 淡入（首启可加短演出「起床」，可跳过） | 1-1.5s | Framer Motion |
| 出租屋 → 对局（入梦） | **纯白显形**（床演出，实→梦子流程） | 约 1s | Framer Motion |
| 对局 → 出租屋（返回） | **纯白显形**（床演出，梦→实子流程） | 约 1s | Framer Motion |
| 出租屋 → 素材库（书架） | 全屏淡入 | 0.3s | Framer Motion |
| 出租屋 → 编辑器（造梦舱） | 全屏淡入 + 侧栏滑入 | 0.5s | Framer Motion |
| 素材库 → 编辑器 | 页面级切换（编辑器独立切换屏幕） | 0.3s | Framer Motion |
| 暂停/设置 | 半透明遮罩 + 菜单滑入 | 0.2s | Framer Motion |

**统一原则（对齐 `表现系统/09` §〇 + `表现系统/00` §二）**：
- 所有动效用 Framer Motion（不用 CSS transition，除 hover 微状态）。
- 时长 < 1.5s（不让玩家等太久）。
- 随时可跳过（Esc / 点击跳过）。
- **纯白显形 = 入梦/返回的专属演出，是唯一传送语言，不做第二套传送语汇**（`叙事设定/00` §十二）。
- **确定性降级**：动画失败/跳过 → 静默跳过、直接显示规则结果；永不拒绝合法规则对象、永不伪造规则事实（`表现系统/00` §二 原则一）。
- 全屏动画仅限仪式性四项（翻窗/跳窗/令其长眠/招架触发），受「认知判据」约束（`表现系统/00` §二 原则三）。

## 八、MVP 范围与「明确不做」（对齐 `运营系统/03` §八 + `运营系统/05` §八）

## 十一、总结

**本文件回答三个根本问题**：

1. **启动后第一眼看到什么？** → 标题画面（开始菜单，标准四入口；2026-08-19 所有者审查裁决），`新游戏` 淡入落地出租屋实景（少 UI 模式，节点 = 局外菜单）。
2. **怎么进入对局外循环？** → 在出租屋里移动节点：书架（素材库）/造梦舱（地图编辑器）/研究台（素材级工作台）/电脑（梦核多应用台）/保险箱（收藏室）/门缝（纸条），都回落到出租屋。
3. **怎么进入对局内循环？** → 锚定导流仪（选模式+匹配）→ 影子大厅 → 床就绪 → 纯白显形 → 对局战斗 → 结算 → 纯白显形 → 回出租屋。

**完整旅程**：标题画面 → 落地出租屋（局外循环）→ 匹配 → 入梦 → 对局（局内循环）→ 返回 → 出租屋 → 循环。

**三条铁律**（任何人不得打破）：
1. 标题画面 = 启动前置，落地即出租屋实景；匹配完成不建独立大厅（影子方案）。
2. 床 = 装载入口；研究台 = 素材级工作台；造梦舱 = 地图编辑器；电脑 = 元状态港湾；四者职责严格分离。
3. 出入对局统一用纯白显形做门，不做第二套传送语汇。
