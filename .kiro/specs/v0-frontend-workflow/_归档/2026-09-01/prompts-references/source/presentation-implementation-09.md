## 〇、读法

08 §2.4 的用法是"AI 在表现层写任何东西前先查这张表；表里没写的效果先登记再实现"。三大子系统的设计文档给出了**参数**，本表给出这些参数对应的**库与数据形状**。逐行对号：拿到一个设计参数 → 查本表 → 落到库。表里没写的新效果 → 按 08 纪律先登记再实现，不即兴造轮子。

**总原则（承接 08 六条硬纪律）**：动效一律 Framer Motion；粒子一律 tsparticles；图标一律 lucide-react；可访问行为一律 Radix；音效一律 Howler；**禁止手写 CSS 过渡做线性淡入淡出做 UI 动效**（CSS 过渡只允许 hover/focus 微状态）。

## 一、镜头子系统（`02_镜头动态设计.md`）→ 库落点

镜头是一个**运行时状态机 + 纯函数变换**，不需要任何动效库——它就是 `zustand` store 只管状态、一个**渲染循环驱动的变换函数**把状态投影到 CSS `transform`。关键是把设计里的 lerp / 缩放 / 缓动用**声明式代码**表达，不要用 Framer Motion 的 `animate` 驱动镜头（镜头是连续高频跟随，不是一次入/出场）。

| 设计参数（02 出处） | 需要的实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| 四种模式状态机（对局焦点/观战自由/编辑器诊断/关键演出锁定，§一） | 模式枚举 + 切换规则（Tab/WASD/演出锁） | `zustand` | `cameraStore`：`mode`, `followTarget`, `zoom`, `offset`, `overrides`；切换前后用声明式状态迁移，不瞬时跳帧 |
| 平滑追随 `lerp(pos, target, 0.15)`（§2.1） | 每帧位置插值 | 渲染循环（`requestAnimationFrame`）+ **不要**用 DOM 动效库 | 一个 `useRaf` hook 每帧读取 `cameraStore.follow()` 返回的 lerp 结果，经 `transform: translate3d(...)` 写到一个顶层容器（GPU 合成） |
| 边缘软推（进边缘 20% 时 lerp 系数 0.15→0.35，§2.1） | 阈值分支的插值系数切换 | 同一渲染循环里的纯函数 | `followEasing(distanceToEdge)` 返回平滑变化的系数（可再用一个 lerp 让它不突兀切变） |
| 自动缩放 `clamp(100% - d*5%, 60%, 100%)` 单/双/多目标（§2.2） | 视距→缩放档位（40%/60%/100%）切换 | 渲染循环 + 缩放用 CSS `scale` | 缩放变化用轻缓动（easeOut 0.5s）包一层，**不用 Framer Motion 的 spring**（镜头缩放是跟随不是跳变，spring 会多余回弹） |
| 焦点切换过渡（同场景 1s ease-in-out / 跨场景 0.3s ease-out / 选项淡入淡出，§2.3） | 过渡时长与缓动 | Framer Motion 的 `animate` 包一次位移 | 只在**轮权交接**这一离散事件上用 `animate`：`animate(cameraRoot, { x, scale }, { duration: 1, ease: 'easeInOut' })`；跨场景用 `duration: 0.3, ease: 'easeOut'` + 一个 0.1s 的黑屏 `AnimatePresence` 遮罩 |
| 观战自由 WASD / 拖拽移动（§3.2） | 输入→偏移量累积 | React 键盘/鼠标事件 + `zustand` | `useEffect` 挂 `keydown`/`pointermove`，写 `cameraStore.offset`；Shift 提速（×2） |
| 关键演出预设机位（Close-up 150% / Two-shot 120% / Env 100% / Top-down 40%，§4.2） | 固定机位数据 + 锁输入 | `zustand` + 一个可跳过的全屏演出时间轴 | 机位 = `cameraStore.preset(position, zoom)`；跳过用 `CeremonialTimeline`（`03` §三），锁输入 = 演出期间吞掉输入事件 |
| 屏幕抖动 轻±2/中±5/强±10 像素（§6.2） | 3 档振幅/频率/衰减 + 可关闭 | 渲染循环里的叠加噪声（**不**用 tsparticles） | 一个 `useScreenShake` hook：`trauma` 值衰减（ease-out），每帧采样 `(sin(t*freq)*amp)` 加到 transform 的 X/Y；`prefers-reduced-motion` 或设置 0% 时直接跳过 |
| 镜头边界软约束 + 橙色偏离蒙版（§7） | 边界限位 + 蒙版透明度 | 纯函数 + `zustand` | 边界 `clamp` 镜头坐标；偏离>2 屏宽时 `overrides.drifting = true`，画一个 `motion.div` 橙色渐变蒙版，透明度按偏离度（最浓 30%） |
| 图层高亮（聚焦对象所在层 100% 不透明，§8.2） | 透明度覆盖 | 交给图层子系统（见本文件 §三） | 镜头不写图层状态，只把"当前焦点 height"喂给图层的透明度缓存 |
| 视锥剔除 / LOD（§9.2/9.3） | 只渲染视野内、按缩放省细节 | React 渲染级（`useMemo` 可见集合） | 缩放<50% 时从可见集合剔除粒子与曲线细节，只留图标；>100% 时编辑器加网格线（原生 SVG） |
| Z 轴移动（编辑器 Q/E，§5.1） | 编辑器专用 Z 偏移 | `zustand` + 显示 | `cameraStore.z`, 左上角 `Z: +2.5` 文本；对局内禁用 |

> **镜头纪律**：镜头是高频连续跟随，**绝不用 Framer Motion 的 `whileInView`/`variants` 驱动它**——那是入/出场的一次性动画，不是跟随。过渡只在轮权交接这种离散事件用 `animate`，平时是一条渲染循环的纯函数插值链。

## 二、声音子系统（`03_声音动态设计.md`）→ 库落点

声音子系统已有相当具体的参数（四层混音、距离衰减公式、音高随机、连播上限）。它的实现载体就是 08 已定的 **`howler`**，外加一套**"语义事件 → 播放"**的解耦层（承接 `02` §8 声音语义描述符 + 规则事件不进入 NPC 感知）。

| 设计参数（03 出处） | 需要的实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| 四层混音（关键反馈 100%/战斗 70%/环境 40%/UI 50%，§2.1） | 音量分层 + 各层连播上限 | `howler` | 每个 `Howl` 的分层 `volume` 乘数写死；用一个 `audioBus` 单例如：`key_feedback` 层最多 3 个实例，超限 kill 最旧 |
| 跨层总音量压缩（>100% 时按比例降其他层，§2.2） | 总输出限幅 | `Howler.volume()` 全局 | 每帧累加各层实时音量，>1 时给非关键层乘 `1/total`；用一个 `AudioMixer` 纯函数算每层最终乘数 |
| 距离衰减 `base × (1 - d/R)²`（§4.2） | 3D 音量 + 左右声道 | `howler` 的 `stereo`/`pos` + 一个纯函数 | 规则事件带 `source.pos`, 表现层算 `pan = (source.x - camera.x) / screenWidth`，`vol = attenuate(d)`，`howl.stereo(pan); howl.volume(vol)` |
| 音高随机 ±5%（§3.3 脚步声/受击） | 播放前随机 `rate` | `howler` | `howl.rate(1 + (Math.random()-0.5)*0.1)`；枪声/爆炸不随机（识别特征） |
| 环境音动态（平静/警戒/激烈/濒死，§5.2） | 按游戏状态切环境层音量与音轨 | `howler` + `zustand` | `audioStore.gameState`；两个 `Howl` BGM 交叉淡入（旧 `fade(0)` + 新 `fade(vol)`），环境层体积按状态表 |
| 视听音效提示（无障碍，§9.2） | 音源方向屏幕箭头 + 振动 | 原生 DOM/SVG（箭头）+ Web Audio（振动）或手柄 API | 箭头用 lucide 图标 + 位置跟随音源投影；开"减少突发音效"时 `Howl.volume` 压限 |
| 音效文件加载/卸载（§8.3） | 预加载对局音效、卸载非当前 | `howler` 的 `Howl.load`/`unload` | 对局开始 preload 一/二/四层 + 当前地图环境音；结束时 `Howl.unload` 只留 UI 层 |
| 字幕/语音（§7.3） | 底部居中字幕 + 名字色 | 原生 React + `zustand` + `howler` | 走 06 对话框模块的字幕槽（见 `06` §七.3），字数→时长表；玩家=青/NPC=灰白 |
| 换弹三段音效 + 曲线同步（§3.2 例外） | 分三段播放与曲线动画对齐 | `howler` 返回 id 可 `stop` | `03` 的 M 组换弹曲线是物品局部旋转（枪口下倾抖两下），音效 0.5+0.5+0.5 三段各在曲线阶段起点触发，用 `howl.seek()`/`id` 精确对齐 |

> **声音纪律**：声音由**规则事件触发**（`after:*` 事件），不等动画；表现层只 `Audio.play(soundId)` 不写任何规则状态（`02` §8.3、`03` §十）。所有音效（包括无害的 UI 音）都区分"规则可感知事件"vs"纯 UI 音"，后者不进 NPC 感知。

## 三、图层子系统（`04_图层动态设计.md`）→ 库落点

图层是最"数据驱动"的子系统——它本质是**每个实体挂一个 height 值，表现层用透明度函数换算 CSS opacity**。核心是一个纯函数 + 一个派生渲染，不需要任何动效库的"动画"（透明度切换走 CSS transition / Framer Motion 的 `animate` 过渡）。

| 设计参数（04 出处） | 需要的实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| height 模型 + 透明度函数 `opacity = clamp(0, 1 - |Δh|×0.1)`（§1.2） | 实体→图层→高度 的派生表 | 纯 TS 函数（可单测） | 一个 `layerOpacity(entityHeight, focusHeight)` 纯函数，被所有实体渲染读；`Δh≤9` 交互高亮时返回 `1`（覆盖函数，见 §2.4） |
| 三界之外独立层 `height = null` 恒不透明（§1.2/§2.1） | 标记为 UI/特效/对话框的实体不做透明度处理 | 一个 `layerTag` 元标记 | `height === null` 的对象跳过透明度函数，恒 `opacity: 1`（但可被自身动效单独控制） |
| 焦点图层判定（对局焦点跟随行动主体 / 观战点角色 / 编辑器选中，§2.2） | 当前 focus height | `zustand` | `layerStore.activeHeight`；轮权交接/位移/点角色时更新，配透明度 0.5s 过渡 |
| 透明度过渡 0.5s ease-in-out（§2.2 焦点切换） | 图层批量的透明度平滑过渡 | CSS `transition: opacity .5s ease-in-out` 在实体内 | 不是每帧重算——切焦点时各实体 `opacity` 走一次 CSS 过渡；`prefers-reduced-motion` 时改为即时 |
| 跨层交互高亮 `Δh≤9` 优先于透明度（§2.4） | 规则层 `canInteract` + Δh 判定 → 覆盖 opacity | 纯函数 + 复用 `01` 边缘发光 | `canInteract(target) && |Δh|≤9` → `opacity: 1` + 边缘发光（tokens 色）；>9 → 不渲染 |
| 跨层动画四类：坠落/位移/楼梯/传送（§4） | 高度连续变化的动画 | Framer Motion `animate` + 曲线配方（`03`） | 坠落=下坠位移曲线 + 各层透明度实时重算（每帧 `layerOpacity(height)`）；楼梯=P1 跳跃 + S3 阶梯缩放；电梯=匀速 `animate` + 人物姿态不动 |
| 编辑器"当前图层特权"（当前+以下可见，以上隐藏，§3.1） | 编辑器视图的图层过滤 | 纯函数 + `zustand` | `editorStore.currentLayerId`；渲染层不再产出高于当前层的对象，低于的半透明（`04` §3.4） |
| 贴纸锁定 + 移动图层（剪切/粘贴或右键菜单，§3.3） | 图层归属的编辑操作 | Radix `dropdown-menu` | 右键菜单"移动到图层..."；锁定 = 拖拽不使用图层命中，改走菜单 |
| 透明度预计算缓存（§7.2 `OPACITY_TABLE`） | Δh 0-10 查找表 | 常量数组 | 直接用 `04` §7.2 的 `OPACITY_TABLE`，避免逐实体重复算 `min/max` |
| 渲染剔除（Δh≥10 不渲染，§7.1） | 可见集合过滤 | React `useMemo` | 渲染循环里只产出 `|Δh|≤9` 或 `height===null` 的对象 + 当前层；性能预算内 |
| 图层切换提示（中央"2F" 1s 淡出 + 上升/下降音，§9.2） | 过渡演出 | Framer Motion `AnimatePresence` + `howler` | 切层时中央 `AnimatePresence` 显示层名，`translateY+scale` 入场、淡出 1s；上升音阶如何尔（见本文件 §二声音） |

> **图层纪律**：图层是**纯视觉派生**，`layerOpacity` 只读投影、永不反写规则（寻路/射线检测是 3D 几何，见 `04` §五）。写新特效时颜色一律走 tokens 语义色，不新增主色。

## 三·五、对局 HUD 组件拆解（核心：轮次栏 / 动作菜单 / 投点滑块 / 状态栏 / 物品栏）

> 08 §2.4.1 已把对局 HUD 的**效果层**钉了库（轮次栏 `layout` 重排、数值条 `useSpring`、玩家框反光 `boxShadow`）。本节补的是 08 没落的**组件怎么拆**：一个 UI 组件由哪些子状态、哪些 zustand store、哪些 Framer Motion 变量、哪些 Radix 原语构成。**规则事实永远来自玩法层只读投影，表现层只消费、不本地扣 AP / 推进状态**（01 §响应式不变量 5）。颜色一律走 tokens 语义色（01 §1 五条视觉定律），图标一律 lucide，动效一律 Framer Motion，可访问行为一律 Radix。

### A. 轮次栏（D-036，最核心组件）

**组件拆解**：轮次栏 = 一个 `TurnOrderBar` 组件，内含 `TurnFrame` 列表。它同时是状态栏、排名榜、动效舞台——但**动效不改规则**，所有排序/高亮都读只读投影重新派生，绝不本地改排名。

| 子状态 / 行为 | 需要的实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| 轮次框列表（玩家头像+名字+排名） | 按键行动轮排名排列 + 每次变化立即重排带 `layout` 动画 | Framer Motion `layout`（08 已钉）+ `zustand` | `turnStore` 存只读投影的排名数组；`motion.div` 列表项加 `layout`，排序变化自动过渡 |
| 当前行动方高亮 = **反光感**（glossy）不是描边 | 材质高光：从顶到下的渐变光带 + 轻微 scale | CSS（tokens 光亮色）+ Framer Motion `animate={{scale:1.02}}`（08 已钉） | 高亮用 `background: linear-gradient(...)` + `boxShadow inset` 做反光条；`whileLayout` 时并行动画，不动用粒子 |
| 玩家自己的框 > 他人约一骰宽 + 条更粗 | 尺寸差异化（骰宽≈图标宽度，用 tokens 间距常量） | Tailwind + tokens | 自己框 `width: base + diceWidth`，数值条 `height` 略增；颜色规则与他人一致（不换语义色） |
| 生命 5 格红 / 清醒 5 格蓝（离散分段） | 每格一个独立方块，变化走 `useSpring` 宽度 | Framer Motion `useSpring`/`useTransform`（08 已钉） | 受击红格"闪烁→消失"，恢复灰格"填彩"（01 §柱状图动画）；清醒格降透明度耗尽 |
| 已行动者变灰降饱和（D-035，**不显著**） | 整框降饱和，**不加大叉/不加"已结束"横幅** | CSS `filter: saturate(.4)` + `opacity` | 只是 `desaturate` 一层，保持可读但不抢眼；轮值状态用 tokens `cooldown` 灰 |
| 投点骰子悬空（只在投点时出现，右侧） | 条件渲染一个悬空骰子图标 + 序号块（1-5） | lucide `Dice` + 原生 div | 只在"统一投点/行动投点"时于当前行动者框右侧 `AnimatePresence` 出现；平时 `display:none`，**不以 DOM 恒在**（低心智，不在时就是不在） |
| 投射条比较面板（右侧一排横条） | 横条从各自序号右侧伸出 + 上移避让面板 | Framer Motion `animate` 宽度 | 横条默认灰白，`AnimatePresence` 批量进出；面板伸出时整体上移一个 `reserveSpace` 高度，避免盖右下动作面板（01 §骰子横条面板适配） |

**轮次栏数据纪律**：`turnStore` 必须是**只读投影的镜像**，来源是玩法层权威行动轮。排序变化（逆转/处决/弱点/招架）都来自 `after:*` 事件或投影变更，表现层不推断"谁行动过了"。

### B. 动作菜单（两套独立 + 上下文菜单 + 倒计时）

| 子状态 / 行为 | 需要的实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| 付费动作面板（1 AP，铁律 0 与 1 AP 分离） | 有费用菜单 + 切换零费按钮 | Radix 单选项列表（`radiogroup`/`dropdown-menu`）+ Tailwind 卡片 | 每张动作卡 = 图标 + 文字 + 底部菱形数字；不足 AP 用扁平灰、无高光（`tokens` `cooldown` + 高光仅 on-hover） |
| 附赠动作面板（0 AP，依附） | 切换按钮触发、与付费菜单互斥显示 | zustand（`menuTab: 'paid'|'free'`）+ Radix | 两面板**不同时渲染**；0 AP 卡顶部标 `green` 免费语义 |

## 六、各落点的素材需求清单（哪些真需要素材管线、哪些纯代码）

响应 08 §1.2"极少素材"原则，本表明确：**凡是能代码画出的动态一律代码，素材管线只在"静态精密细节"补位**：

| 落点 | 代码动态 | 是否需要素材管线（sprite-forge / asset-pipeline） |
|---|---|---|
| 镜头 lerp / 缩放 / 抖动 | 全部代码 | ❌ 纯代码 |
| 声音混音 / 衰减 / 音效 | `howler` 播放，音效文件来自外包/AI 生成 | ⚠️ 只需音效文件（`03` §11 音效清单），非像素素材 |
| 图层透明度 / 高亮 / 跨层动画 | 全部代码 | ❌ 纯代码 |
| 对话框 / RPG 模块 / 驻地导航 | 全部代码 + tokens | ❌ 纯代码（对话框立绘可能用角色贴图，见下） |
| 出租屋承载物（床/锚定导流仪/研究台/造梦舱/电脑/电视/书/保险箱/桌） | hover 高光 + 隐藏态 | ✅ **需要静态组件帧**（`sprite-component.py`，map 语境正面俯视视图，`05` 规范） |
| VR 取证室（白虚空 + 桌 + 警官 + 槽位） | 槽位/虚线/发光代码；桌/警官/VR | ✅ **桌、警官需要静态帧**（警官 = 角色管线，桌 = 组件管线） |
| 玩家/NPC/怪物（对局实体） | ORCA 位移 + 姿态曲线 | ✅ 角色管线（`sprite-forge` 母版系统） |
| 底图（梦境场景） | 全息投影光层背景渲染（D-083：背景非简笔画贴图，优先代码光层——渐变/发光/透明度；确需美术质感的底图仍经底图管线产出后按光层处理） | ✅ 底图管线（asset-pipeline / Nano Banana，`02_地图生产管线`） |

> **分界铁律**：素材只在"**零渲染继承不到**的静态精密细节"补位（`00` §二·六）：可交互/有生命的用代码动态 + tokens 语义色；静态承载物与角色用素材管线产出；**任何可以靠曲线/透明度/颜色语义表达的都优先代码**，不因"想省事"就请素材。

## 七、落地顺序建议（三命令门禁可验证的里程碑）

不一次铺完，按"先让玩法可读 → 再提质感 → 补氛围"的次序（承接 `03` §Ⅻ + `00` §二·五）：

1. **镜头最小集**：对局焦点跟随（lerp + 缩放）+ 关键演出机位 + 屏幕抖动可关——保证"镜头聚焦该看谁"（`02` §一/§二/§四）。
2. **声音最小集**：四层混音 + 关键反馈音效 + 距离衰减——保证"换弹=音效+曲线"的省力杠杆先落地（`03` §二/§三/§四）。
3. **图层最小集**：透明度函数 + 焦点判定 + `Δh≤9` 高亮——保证"叠层分离 + 跨层可交互"（`04` 核心）。
4. **UI 最小集**：对话框（P5 动态）+ 通知 + 轮次栏（08 已钉）——保证叙事与对局反馈可读。
5. **驻地与局外**：出租屋承载物高亮 + 纯白显形 + 保险箱/书架/证据提交层——整个局外体验串起来。

**每个里程碑都以 `08` 的 2.4 映射表 + 本文件的对应小节为唯一落点**，做完过三命令门禁，新效果未登记不实现。

## 九、ORCA 寻路与移动动画 → 库落点（核心缺口补全）

> **性质**：本节补全 `01_图形化与UI.md` §前端动态图形化所有设计的**技术栈映射与数据契约**。ORCA 三重寻路算法、表现层碰撞箱、传染式恢复对峙、点对点寻路、双段寻路的完整设计在 `01` 已定，本节只定**用什么库实现、数据形状是什么、事件契约怎么接**。
> **边界**：本节完全是**表现层边界**。它不读取玩法层微型场景，不对玩法层归属做判断，只消费 `after:*` 类事件和自己的碰撞箱 / 对峙群状态。
> **依赖**：`01_图形化与UI.md` §前端动态图形化（ORCA 算法设计）、`02_镜头动态设计.md`（镜头跟随）、`08_技术栈与代码生成画面.md`（库纪律）

### 九·一、双段寻路的技术分解

`01` §双段寻路把寻路解耦为两段，本节定每段的实现载体：

| 段 | 时机 | 内容 | 实现载体 | AI 落点 |
|---|---|---|---|---|
| **段1 · 可通行判定** | 对局启动时预运算 | 场景框组 + 物理遮挡 + 地形 + 全体碰撞箱快照 → 可通行域；判定"这个移动命令可不可通" | Web Worker + 纯 TS 函数 | 启动时调一次 `precomputeTraversableDomain(mapData)`，缓存到 `zustand` 的 `spatialStore.traversableDomain`；移动命令灰显判定 = 查缓存 `canTraverse(from, to, moverRadius, collisionBoxes, roomFactor)` 纯函数 |
| **段2 · 实时挤压寻路** | 实时（每次移动） | 在可通行域内，活体间实时挤压避让 / 移动；动态碰撞箱参与阻塞判断 | ORCA 算法（见 §九·二） + 渲染循环 | 每次 `after:entity.place` 事件触发一次 ORCA 寻路 + 移动动画；动画走 Framer Motion `animate` |

**为什么段1 用 Web Worker**：可通行域预运算是 CPU 密集计算（遍历地图节点 + 物理遮挡 + 静态碰撞箱），主线程会卡顿；Web Worker 异步算完再回传结果，启动时不阻塞 UI。

**失败闸门**：
- 段1 失败（`canTraverse` 返回 `false`）→ 动作菜单里该移动目标**变灰 + 提示"因阻塞无法执行"**，不提交意图。**动态碰撞箱参与段1**（不假设它们避让，堵死即失败）——这是 `01` §ORCA 寻路失败机制的动态平衡：人群堵住路径 → 无法进入 → 不更挤。
- **膨胀系数**：碰撞箱按 `moverRadius + box.radius × roomFactor` 膨胀，系数默认 <1（待调试）。不完全膨胀——多数稀疏情形仍可穿（贴合"同场景可穿"常识），只有拥挤到"过分"才判不可通；如果出现贴脸穿模就调高系数、稀疏堵死就调低。
- 段2 失败（ORCA 寻路在可通行域内仍找不到路径）→ 动画中断 + 提示"路径被活体阻挡"，**不回滚规则**（规则已结算，只是表现层失败，见 `01` §ORCA 寻路的失败机制）。

### 九·二、ORCA 避障算法的库选择

`01` §ORCA 定了"统一避让原语（传染式连锁）+ 不用纯斥力"的设计。实现有三条路：

| 方案 | 优点 | 缺点 | 判定 |
|---|---|---|---|
| **A. 引入 `rvo2-js`** | 工业实现、稳定、性能好 | 需适配到 Web 环境；API 偏底层 | ✅ **优先方案** |
| **B. 自实现简化 ORCA** | 完全可控、可按游戏需求裁剪 | 开发量大、容易有边界 bug | ⚠️ 备选（若 A 接入成本过高） |
| **C. 纯斥力（弹簧力）** | 简单 | 违反 `01` 设计（"不用纯斥力"）、可能振荡 | ❌ **不采用** |

**最终选择**：**优先尝试 `rvo2-js`（RVO2 的 JavaScript 移植），若接入成本过高再退到自实现简化 ORCA。** 纯斥力方案不符合设计约束，不考虑。

**`rvo2-js` 接入要点**：
- 每个可动活体对应一个 `Agent`，设置半径 = 碰撞箱半径、最大速度、邻居距离。
- 每帧调 `simulator.doStep(timeStep)`，读取各 `Agent` 的新速度 → 更新位置。
- 传染式连锁：挤到可动碰撞箱时，把它也加入 `simulator.agents`。

**自实现简化 ORCA 的最小集**（若方案 B）：
- 每帧为每个活体计算"可行速度锥"（避开其他活体碰撞箱的速度范围）。
- 从可行速度中选最接近目标速度的一个。
- 迭代若干帧直到收敛或超时。

### 九·三、碰撞箱的数据契约

`01` §碰撞箱定了"任何实体都有碰撞箱，半径圆，圆心 = 贴图最下方几何中心，半径 = 组件宽度一半的 80%"。数据形状：

```typescript
/** 碰撞箱（圆形） */
interface CollisionBox {
  /** 圆心位置（世界坐标，像素） */
  readonly center: Vec2;
  
  /** 半径（像素） */
  readonly radius: number;
  
  /** 可动性分类 */
  readonly mobility: 'movable-entity' | 'movable-actor' | 'immovable-entity' | 'immovable-actor';
  
  /** 关联的实体 ID */
  readonly entityId: Id;
}

interface Vec2 {
  readonly x: number;
  readonly y: number;
}
```

**可动性判定表**（承接 `01` §碰撞箱分类）：

| 分类 | 参与 ORCA? | 被扰动? | 朝向逻辑? | 典型实例 |
|---|---|---|---|---|
| `movable-actor` | ✅ | ✅ | ✅ | 玩家、NPC、怪物 |
| `movable-entity` | ✅ | ✅ | ❌ | 有人驾驶的车 |
| `immovable-actor` | ❌ | ❌ | ❌ | 睡眠中的玩家（不被连锁扰动） |
| `immovable-entity` | ❌ | ❌ | — | 无人驾驶的车、柜子 |

**碰撞箱注册时机**：
- 活体 spawn 时自动注册碰撞箱（读 sprite 尺寸 → 计算半径 = `width / 2 * 0.8`）。
- 车辆的可动性**动态变化**：有人上车 → `movable-entity`；最后一人下车 → `immovable-entity`。

**存储**：`zustand` 的 `spatialStore.collisionBoxes: Map<Id, CollisionBox>`。

### 九·四、点对点寻路（A* 或 Dijkstra）

段1 预运算的可通行域是栅格或图结构，段2 在可通行域内做点对点寻路：

| 算法 | 适用场景 | 库选择 | AI 落点 |
|---|---|---|---|
| **A\*** | 有明确目标点（最常见） | `pathfinding` (npm) 或自实现 | 优先 `pathfinding` |
| **Dijkstra** | 无明确目标、求"从 A 到所有点的最短路" | 自实现 | 只在需要时才写 |
| **Navmesh** | 复杂多边形障碍物 | `navmesh` (npm) | ⚠️ 后置（地图复杂度不足时不装） |

**当前判定**：**用 `pathfinding` 库的 A\* 实现，输入 = 可通行域栅格，输出 = 路径点数组。** Navmesh 是后置方案，只有地图复杂到栅格 A\* 性能不够时才引入。

**寻路输入输出**：
```typescript
/** 点对点寻路 */
function findPath(
  traversableDomain: Grid,  // 段1 预运算的可通行域
  from: Vec2,
  to: Vec2,
  collisionBoxes: CollisionBox[]  // 动态活体碰撞箱
): Vec2[] | null;  // 路径点数组，失败返回 null
```

**与 ORCA 的配合**：A\* 给出粗略路径（避开静态障碍），ORCA 在路径上平滑避开动态活体。

### 九·五、恢复对峙算法的实现

`01` §恢复对峙定了"向心移位的迭代松弛"算法。实现为纯 TS 函数：

```typescript
/** 恢复对峙：给定群体(对峙群/微场景点)内所有活体，求目标位分配 */
function resolveStandoff(params: {
  /** 群体中心（世界坐标） */
  readonly center: Vec2;
  
  /** 该群体内所有活体的当前位置 + 碰撞箱 */
  readonly actors: ReadonlyArray<{ id: Id; pos: Vec2; box: CollisionBox }>;
  
  /** 可通行域 */
  readonly traversableDomain: Grid;
  
  /** 全体碰撞箱（跨群体，用于可站性判定） */
  readonly allCollisionBoxes: CollisionBox[];
}): Map<Id, Vec2>;  // 每个活体的目标位
```

**算法步骤**（照抄 `01` §恢复对峙）：
1. 可站性判定：原位就"不与任何碰撞箱重叠、且在可通行域内" → 目标位 = 原位，一步不走。
2. 向心移位：以中心为锚，沿"当前位置 → 中心"方向试探前行，找最近的合法可站位。
3. 被卡兜底：向多个方向微位移找最近合法可站位；真无解才判定失败回滚。

> 可站性判定向**全体碰撞箱并集**判定（跨群体），不局限于某个群体——表现层没有玩法层"微型场景"概念，靠全体并集天然跨群达成 `01` §恢复对峙"跨微型场景的碰撞箱"效果。

**调用时机**：
- 任何 `after:entity.place` / `after:attack` / `after:item.pickup` 等**扰动事件** → 触发该群体一次恢复对峙。
- 传染式连锁：恢复对峙过程中若挤到其他可动碰撞箱 → 触发它所在群体的恢复对峙。

**性能约束**：单次恢复对峙应在 16ms 内完成（不阻塞渲染帧）；若超时，标记为"收敛失败"并回滚到上一个稳定态。

### 九·六、泛光圈动态的视觉实现

`01` §泛光圈定了"泛光圈半径随实体数变化、不可重叠"。泛光圈是**表现层对峙群（微场景点）**的视觉表达，与玩法层微型场景无直接引用关系。视觉实现：

| 需求 | 实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| 泛光圈是对峙群（微场景点）的视觉表达 | 每个对峙群渲染一个半透明圆形光圈 | 原生 SVG `<circle>` + CSS `radial-gradient` | `<circle cx={cluster.center.x} cy={cluster.center.y} r={radius} fill="url(#glow)" />`；半径 = `baseRadius + entityCount * radiusPerEntity` |
| 半径随实体数变化 | 实时重算半径 | `zustand` 派生 + CSS 过渡 | `spatialStore` 派生 `clusterRadii: Map<Id, number>`；变化走 `transition: r 0.3s ease-out` |
| 不可重叠约束 | 重叠时触发传染式 ORCA | 纯函数判定 + ORCA | 每帧检测泛光圈重叠：`detectOverlap(circles) → overlappingPairs`；若有重叠 → 触发两对峙群的传染式 ORCA |
| 可落脚/可交互语义 | 玩家悬停时高亮 | CSS `hover:brightness(1.2)` + tokens | 光圈颜色走 tokens（中性灰白），可交互时边缘发光（tokens 高光） |

**泛光圈参数**（待调试）：
```typescript
const GLOW_BASE_RADIUS = 32;  // 像素
const GLOW_RADIUS_PER_ENTITY = 8;  // 每个实体增加 8px

function calcGlowRadius(entityCount: number): number {
  return GLOW_BASE_RADIUS + entityCount * GLOW_RADIUS_PER_ENTITY;
}
```

**重叠检测**：
```typescript
function detectOverlap(circles: Array<{ center: Vec2; radius: number }>): Array<[number, number]> {
  const pairs: Array<[number, number]> = [];
  for (let i = 0; i < circles.length; i++) {
    for (let j = i + 1; j < circles.length; j++) {
      const dist = distance(circles[i].center, circles[j].center);
      if (dist < circles[i].radius + circles[j].radius) {
        pairs.push([i, j]);
      }
    }
  }
  return pairs;
}
```

### 九·七、移动动画的实现

`01` §三动画攻击模型定了"快步跳移动 + 攻击受击 + 恢复对峙"，移动动画是其中的 ①。

| 动画类型 | 曲线配方 | 实现 | 指定工具 | AI 落点 |
|---|---|---|---|---|
| **正常移动** | 跳跃式位移（高度 ↑ 再 ↓） | `translateY` 曲线 + `translateX` 线性 | Framer Motion `animate` | `animate(sprite, { x: [from.x, to.x], y: [from.y, from.y - 20, to.y] }, { duration: 0.3, ease: [0.4, 0, 0.2, 1] })` |
| **重物移动** | 低矮跳跃（高度 ↑ 幅度小） | 同上，`y` 峰值降低 | 同上 | `y: [from.y, from.y - 8, to.y]` |
| **迟缓移动** | 拖曳感（慢启动、慢停止） | 缓动函数调整 | 同上 | `ease: [0.65, 0, 0.35, 1]`（slower ease） |
| **快步跳移动**（攻击前冲） | 更高的跳跃 + 快速 | 同上，峰值增高、时长缩短 | 同上 | `y: [from.y, from.y - 40, to.y], duration: 0.2` |

**ORCA 平滑避让的视觉**：
- A\* 给出粗略路径点 `[p0, p1, p2, ..., pN]`。
- 每两个路径点间，ORCA 实时调整实际位置（避开动态活体）。
- 视觉上是"沿路径点移动，但遇到活体时平滑绕开"。

**实现**：
```typescript
async function playMoveAnimation(
  sprite: HTMLElement,
  pathPoints: Vec2[],
  collisionBoxes: CollisionBox[]
): Promise<void> {
  for (let i = 0; i < pathPoints.length - 1; i++) {
    const from = pathPoints[i];
    const to = pathPoints[i + 1];
    
    // ORCA 实时调整
    const smoothPath = await orcaSmooth(from, to, collisionBoxes);
    
    // 用 Framer Motion 播放跳跃曲线
    await animate(sprite, {
      x: smoothPath.map(p => p.x),
      y: smoothPath.map(p => p.y - jumpHeight(p)),
    }, {
      duration: 0.3,
      ease: [0.4, 0, 0.2, 1],
    });
  }
}
```

### 九·八、朝向视觉的实现

`01` §朝向定了"单一左右朝向，纯画面因素"。实现：

| 需求 | 实现 | 指定工具 | AI 落点 |
|---|---|---|---|
| 左右翻面 | CSS `scaleX(-1)` | 原生 CSS + Framer Motion | `animate(sprite, { scaleX: direction === 'left' ? -1 : 1 }, { duration: 0.1 })` |
| 攻击后目标转向攻击者 | 计算攻击者在目标左侧还是右侧 | 纯 TS 函数 | `const dir = attacker.x < target.x ? 'left' : 'right'; setFacing(target.id, dir)` |
| 新玩家进入时随机几人转向 | 随机选 1-3 人转向新玩家 | `Math.random()` + 同上 | `const turnCount = Math.floor(Math.random() * 3) + 1; randomSample(actors, turnCount).forEach(...)` |
| 恢复对峙不改朝向 | 恢复对峙只改位置，不调 `facing` | — | 位移动画不触碰 `facingStore` |

**朝向状态存储**：`zustand` 的 `facingStore: Map<Id, 'left' | 'right'>`。

### 九·九、不可动实体静默重划分归属的实现

`01` §不可动实体静默归位定了"行动轮结束时，归属脱节的不可动实体 → 最近同天然场景微型场景点"。这里的变化是归属刷新，不是可见位移动画。

| 层 | 职责 | 实现 | AI 落点 |
|---|---|---|---|

### 九·十、事件契约：规则层 → 表现层

所有移动/攻击/恢复对峙的触发都由**规则层事件驱动**，表现层只消费事件、不推断规则。

| 规则事件 | 表现层响应 | 数据负载 |
|---|---|---|
| `after:entity.place` | 播放移动动画 + 触发恢复对峙 | `{ entityId, from, to, pathPoints }` |
| `after:attack` | 播放三动画攻击（快步跳 + 攻击受击 + 恢复对峙） | `{ actorId, targetId, hitResult }` |
| `after:item.pickup` | 拾取动画 + 触发恢复对峙 | `{ actorId, itemId }` |
| `after:turn-end` | 触发不可动实体静默迁移信号（静默、无动画，见 §九·九） | `{ actorId }` |
| `after:vehicle.board` | 上车动画 + 车辆可动性切换 | `{ actorId, vehicleId }` |
| `after:vehicle.leave` | 下车动画 + 车辆可动性切换 | `{ actorId, vehicleId }` |

**事件监听**：
```typescript
// src/ui/presentation/choreography/move-choreographer.ts

  eventBus.on('after:entity.place', async (event) => {
    const { entityId, from, to, pathPoints } = event.payload;

    await resolveStandoffForScene(findCluster(entityId));
  });
```

### 九·十一、性能约束与降级策略

| 性能指标 | 目标 | 降级策略 |
|---|---|---|
| ORCA 每帧计算时间 | < 5ms | 超时 → 退化为直线位移（不避让） |
| 恢复对峙收敛时间 | < 16ms | 超时 → 回滚到上一稳定态 |
| A\* 寻路时间 | < 10ms | 超时 → 返回"路径被阻挡" |
| 同屏活体数 | < 20 | 超过 → 渲染剔除远处活体 |
| 同屏泛光圈数 | < 15 | 超过 → 只渲染可交互的圈 |

**性能监控**：
```typescript
const performanceStore = {
  orcaFrameTime: 0,  // ms
  standoffResolveTime: 0,  // ms
  pathfindingTime: 0,  // ms
};

// 每帧采样
if (performanceStore.orcaFrameTime > 5) {
  console.warn('ORCA 超时，降级为直线位移');
  useLinearMovement();
}
```

### 九·十二、开发里程碑（分阶段实现）

不一次铺完，按"先让移动能看到 → 再加避让 → 补恢复对峙"的次序：

**里程碑 1：最小移动动画（无 ORCA）**
- ✅ `after:entity.place` 事件监听
- ✅ 直线位移动画（Framer Motion）
- ✅ 跳跃曲线配方（正常 / 重物 / 迟缓）
- ✅ 朝向翻面
- ❌ 暂无 ORCA 避让、无恢复对峙

**里程碑 2：碰撞箱 + A\* 寻路**
- ✅ 碰撞箱注册（spawn 时自动）
- ✅ 可通行域预运算（Web Worker）
- ✅ A\* 点对点寻路（`pathfinding` 库）
- ✅ 段1 可通行判定（动作灰显）
- ❌ 暂无 ORCA 实时避让

**里程碑 3：ORCA 避让 + 恢复对峙**
- ✅ 引入 `rvo2-js` 或自实现简化 ORCA
- ✅ 移动动画接入 ORCA 平滑避让
- ✅ 恢复对峙算法（向心移位）
- ✅ 传染式连锁（挤到可动碰撞箱 → 触发恢复对峙）
- ✅ 三动画攻击模型

**里程碑 4：泛光圈 + 不可动实体承接桥**
- ✅ 泛光圈视觉（SVG 圆形 + 半径动态）

- ✅ 不可动实体静默迁移信号（行动轮结束）
- ✅ 车辆可动性动态切换

**里程碑 5：性能优化 + 降级策略**
- ✅ 性能监控（ORCA / 恢复对峙 / A\* 耗时）
- ✅ 超时降级（ORCA 超时 → 直线位移）
