## 〇、一句话定位

**对话框是表现层可配置模块，任何实例都可以触发，UGC 友好且高质量流畅。**

叙事对话框是 RPG 游戏中的核心 UI：角色对话、选择分支、剧情演出、社交交互。它必须：
- **单一且模块化**（玩法层 ↔ 前端的清晰接口）
- **UGC 友好**（任何实例都能方便调用，降级检索机制保证总能显示）
- **高质量流畅**（P5 风格的动态对话框 + 强烈的偏移变换 + 选项动效）

## 一、核心设计原则

### 1.1 玩法层 ↔ 表现层交接面

**对话框是表现层的可配置模块，由玩法层数据触发**：
- 官方/宿主 TS 运行时调用：`showDialog({ speaker: entityId, text: "...", options?: [...], ... })`
- 前端负责：呈现对话框 + 动画 + 交互 + 播放选项音效
- UGC 玩法包用 JSON 声明"何时触发哪段对话"（见 §5.4），装载走统一 `PlaypackLoader.load` / `PlaypackActivator.activate` 管道（D-073）
- **不是硬编码 UI**，是可编程模块

**UGC 对象直觉**：
- 对话框可以在**任何实例**上被触发（角色、NPC、物品、场景框、甚至抽象实体）
- 不需要"这个角色有没有对话框能力"的前置判断——任何实例都可以说话

### 1.2 降级检索机制（图像来源）

**对话框左侧图像的降级检索顺序**（保证总能显示）：
```
1. 模块指定的 image（dialogConfig.imageRef）
   - 玩法层可以显式指定空 image（imageRef: null） → 效果同第 4 步，不使用左侧图像
   ↓ 没有
2. 该实例的第一个立绘（entity.portraits[0]）
   ↓ 没有
3. 该实例的第一个贴图（entity.sprites[0] or entity.icon）
   ↓ 没有
4. 不使用对话框左侧图像（仅有对话框 + 名字栏，无立绘）
```

**图像缩放策略**（不裁切，保持完整）：
- **立绘可以占据屏幕左侧任意大小**（只要不占满全屏）
- **缩放规则**：图像中心靠左，上下左右不许超过屏幕边界
- **算法**：
  ```
  1. 计算屏幕安全区：
     - 左边距：屏幕宽度 × 5%
     - 上下边距：屏幕高度 × 5%
     - 右边距：保留对话框空间（屏幕宽度 × 40%）
  2. 如果图像宽/高超过安全区 → 等比缩小至刚好不超过
  3. 图像左对齐（left = 屏幕宽度 × 5%）
  4. 图像垂直居中（top = (屏幕高度 - 图像高度) / 2）
  ```
- **不裁切**：无论原图尺寸（64×64 或 512×1024），都完整显示
- **为什么这样**：立绘是视觉焦点，保持完整性比固定尺寸更重要

**P5 风格的美学**（立绘被遮挡是正常的）：
- 立绘的一部分**被对话框遮挡**是正常的（符合 P5 风格，见女神异闻录 5）
- 对话框浮在立绘之上（`z-index: 立绘 100, 对话框 200`）
- 这种遮挡关系增强视觉层次感，不是 bug

### 1.3 名字的可变性

**名字栏使用实例的 `displayName`**（不是 `id`）：
- `displayName` 在底层是可变的（规则层可以运行时改名）
- 对话框的名字栏自动跟随 `displayName` 的当前值
- 例子：
  - 初始：`displayName = "？？？"`（未知角色）
  - 剧情后：`displayName = "侦探 · 艾琳"`（身份揭晓）
  - 对话框自动显示当前的 `displayName`，不需要手动更新

## 二、P5 风格的动态对话框

### 2.1 布局结构（Persona 5 风格）

**屏幕布局**：
```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  [左侧立绘区]          [对话框主体区]                       │
│   320×480px           (右侧 2/3 屏幕)                     │
│                                                          │
│  ┌────────┐         ┌──────────────────────────────┐    │
│  │        │         │  [名字栏]  艾琳 · 侦探         │    │
│  │ 立绘   │         ├──────────────────────────────┤    │
│  │ 图像   │         │                              │    │
│  │        │         │  "这个案子不简单。"           │    │
│  │        │         │  "我们需要更多线索。"          │    │
│  │        │         │                              │    │
│  └────────┘         └──────────────────────────────┘    │
│                                                          │
│                      [选项区]                             │
│                      ① 继续调查                           │
│                      ② 返回驻地                           │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**组件分解**：
1. **左侧立绘区**（320×480px，屏幕左下角）
2. **对话框主体区**（右侧 2/3 屏幕，屏幕下半部）
   - **名字栏**（顶部，黑底 + 白字 + 红色斜条装饰）
   - **文本区**（中部，半透明黑底 + 白字）
3. **选项区**（对话框下方，悬浮按钮）

### 2.2 对话框主体的动效

> **设计原则**：P5 的核心是"强烈的偏移变换"——对话框不是简单淡入，而是带**斜切 + 滑入 + 弹性**的组合动效

**出现动画**（0.6 秒）：
```
1. 立绘从左侧滑入（translateX: -100% → 0%，ease-out-back）
2. 对话框主体从右下角斜切滑入：
   - translateX: 50% → 0%
   - skewX: -5deg → 0deg（斜切变换，P5 招牌）
   - opacity: 0 → 1
3. 名字栏红色斜条从左扫过（wipe effect，0.2 秒延迟）
4. 文本逐字打字机效果（可选，见 §2.3）
```

**消失动画**（0.4 秒）：
```
1. 对话框主体向右上角斜切滑出：
   - translateX: 0% → 50%
   - skewX: 0deg → 5deg
   - opacity: 1 → 0
2. 立绘向左侧滑出（translateX: 0% → -100%，同步）
```

**切换说话人动画**（0.5 秒）：
- 立绘淡出 + 向左平移 50px → 新立绘淡入 + 从左平移 50px
- 名字栏红色斜条重新扫过（刷新视觉焦点）
- 文本区淡出 → 新文本淡入

### 2.3 文本显示选项

**打字机效果**（默认开启，可配置关闭）：
- 文本逐字显示（20 字符/秒，可配置）
- 配合**打字音效**（轻微的"哒哒哒"声，见声音子系统）
- 玩家点击 → 跳过打字机，直接显示全部文本

**定时 vs 不定时**：
- **定时对话框**（`dialogConfig.autoAdvance = true, duration = 3000`）：
  - 文本显示完成后，**自动倒计时 3 秒**（右下角显示倒计时进度条）
  - 倒计时结束 → 自动进入下一句对话
  - 玩家可以点击跳过倒计时
- **不定时对话框**（`dialogConfig.autoAdvance = false`）：
  - 文本显示完成后，**等待玩家点击**（右下角显示"点击继续"提示）
  - 玩家点击 → 进入下一句对话

**跳过机制**：
- **不定时对话框可以被整段跳过**（按住 `Ctrl` 或 `Space`）
- **定时对话框不能被跳过**（用于关键剧情演出，保证玩家看到）
- 跳过时，对话框淡出（0.2 秒），不播放完整消失动画

## 三、选项系统（分支选择）

### 3.1 选项的视觉呈现

**选项布局**：
- 选项显示在对话框下方（悬浮按钮，不是内嵌在对话框中）
- 每个选项是一个**独立的按钮**（黑底 + 白字 + 红色左边框）
- 最多显示 **4 个选项**（超过 4 个需要分页或滚动）

**选项按钮样式**（P5 风格）：
```
┌──────────────────────────────────┐
│ ▐ ① 继续调查                      │ ← 红色左边框（4px）
└──────────────────────────────────┘
  ↑ 黑底 + 白字 + 序号
```

**选项按钮的交互动效**：
- **悬停**：
  - 按钮整体向右平移 10px（强调"选中"）
  - 红色左边框加粗（4px → 8px）
  - 背景色微亮（从纯黑 → 深灰）
- **点击**：
  - 按钮闪烁（白色高光，0.1 秒）
  - 按钮向右滑出 + 淡出（0.3 秒）
  - 其他选项同时淡出
  - 对话框主体淡出（0.4 秒）

### 3.2 选项的排列顺序

**垂直排列**（从上到下）：
- 选项 ① 在最上方
- 选项 ② 在下方
- 选项 ③、④ 依次排列

**为什么垂直排列**：
- 符合阅读习惯（从上到下）
- P5 风格的选项通常是垂直的
- 垂直排列更容易扩展（如果有 5+ 个选项，可以滚动）

### 3.3 选项的快捷键

**数字键快速选择**：
- 按 `1` → 选择选项 ①
- 按 `2` → 选择选项 ②
- 按 `3` → 选择选项 ③
- 按 `4` → 选择选项 ④

**方向键 + Enter**：
- `↑/↓` 键切换高亮选项
- `Enter` 确认当前高亮选项

**复用动作菜单选择框**：
- 正常情况下，UI 的选择框（动作菜单的选择框）**不会被改变**
- **只有在对话框的选项模块被调用时**，才临时改变选择框样式为对话框选项样式
- 选择结束后，恢复原样式

## 四、语音与音效

### 4.1 语音播放（可选）

**对话框可以伴随语音**（`dialogConfig.voiceClip`）：
- 对话框出现时，**自动播放语音**（如果提供了语音文件）
- 语音播放期间，打字机效果**同步**语音进度（尽量让文字显示与语音节奏匹配）
- 玩家跳过对话框 → 语音立即停止

**语音文件来源**：
- 玩法层提供语音文件路径（`dialogConfig.voiceClip = "voice/chapter1/scene3/line5.ogg"`）
- 如果没有提供语音，对话框正常显示（纯文本）

### 4.2 音效（必备）

**对话框必备音效**（见声音子系统）：
1. **对话框出现音效**（"咻"的一声，0.2 秒）
2. **打字机音效**（"哒哒哒"，轻微的机械声，20 字符/秒）
3. **选项悬停音效**（"叮"的一声，轻微）
4. **选项点击音效**（"咔"的一声，确认感）
5. **对话框消失音效**（"嗖"的一声，0.2 秒）

**音效的音量**：
- 对话框音效的音量应该**低于背景音乐**（约 60% 音量）
- 语音的音量应该**高于对话框音效**（约 80% 音量）

## 五、运行时接口与 UGC 表达

### 5.0 表达手段与装载管道

- 对话框模块是**表现层**运行时能力：`showDialog` 一类函数是**官方/宿主代码**（TypeScript）直接调用的 helper 形状。
- **UGC 玩法包用 JSON 表达同一件事**——在玩法包数据里声明「事件/规则 → 触发一段对话」，不写任何 TS。
- **官方也可以写 TS 对象字面量**（如 `CoreMechanicsPlaypack`）构造同一份 `PlaypackDef` 数据。这只是**表达手段分离，不是装载权限分离**：两者最终都进入 `PlaypackLoader.load` / `PlaypackActivator.activate` 统一管道，装载后注册表里的 Def 快照地位完全一样，后装同 key 覆盖先装（D-073，见 `docs/L2_基类层/06_UGC系统.md` §7.9）。
- 下面 5.1-5.3 用 TS helper 展示调用形状；JSON 表达示例见 5.4。

### 5.1 最小调用示例

**单句对话**（最简单）：
```typescript
// 表现层运行时（官方/宿主代码）调用
await showDialog({
  speaker: 'e:npc_detective_001',  // 说话人实体 ID
  text: '这个案子不简单。',
});
```

**前端自动处理**：
- 检索 `e:npc_detective_001` 的立绘/贴图（降级检索）
- 显示该实体的 `displayName`（例如："艾琳 · 侦探"）
- 显示对话框（P5 风格动画）
- 等待玩家点击
- 关闭对话框

### 5.2 完整配置示例（带即刻结算的选项）

**选项的即刻结算模式**（符合 UGC 心智）：
```typescript
await showDialog({
  speaker: 'e:npc_detective_001',
  text: '你愿意帮我调查这个案子吗？',
  
  // 可选：指定图像（覆盖降级检索）
  imageRef: 'portrait:detective_serious',
  
  // 可选：语音文件
  voiceClip: 'voice/chapter1/scene3/line5.ogg',
  
  // 可选：选项（即刻结算，回调包在模块里）
  options: [
    { 
      label: '① 我愿意帮忙',
      onSelect: () => {
        // 玩家接受任务的逻辑直接写在这里
        givePlayerQuest('investigate_case_001');
        addReputation('detective_guild', 10);
      }
    },
    { 
      label: '② 我没兴趣',
      onSelect: () => {
        // 玩家拒绝任务的逻辑
        addReputation('detective_guild', -5);
        endConversation();
      }
    },
    { 
      label: '③ 告诉我更多细节',
      onSelect: () => {
        // 继续对话树的另一分支
        showNextDialog('detective_details_branch');
      }
    },
  ],
  
  // 可选：定时（秒）
  autoAdvance: false,  // 不自动推进，等待玩家选择
  
  // 可选：打字机效果
  typewriterSpeed: 20,  // 20 字符/秒（默认）
});

// 注意：不再返回选项 ID，所有逻辑在 onSelect 中即刻执行
// 想做复杂的状态追踪，UGC 用户可以自己存值：
// let playerChoice = null;
// options: [{ label: '...', onSelect: () => { playerChoice = 'accept'; } }]
```

### 5.3 连续对话示例

**多句对话（对话树）**：
```typescript
// 玩法层可以串联多个对话
await showDialog({
  speaker: 'e:npc_detective_001',
  text: '这个案子不简单。',
});

await showDialog({
  speaker: 'e:npc_detective_001',
  text: '我们需要更多线索。',
});

await showDialog({
  speaker: 'e:player_001',  // 玩家角色
  text: '我知道该怎么做。',
});
```

**前端自动处理**：
- 第一句对话出现 → 玩家点击 → 第一句对话消失
- 第二句对话出现（同一说话人，立绘不变）→ 玩家点击 → 第二句对话消失
- 第三句对话出现（切换说话人，立绘切换到玩家角色）→ 玩家点击 → 对话结束

### 5.4 UGC 的 JSON 表达

**UGC 玩法包把"何时触发哪段对话"声明为数据**。例如一条规则：当玩家进入某个节点时，触发 NPC 说一句话。整段对话可以作为一个 def 放进玩法包的 `defs` 数组，由表现层投影消费：

```json
{
  "id": "dialog:detective-intro",
  "kind": "action",
  "play": {
    "dialog": {
      "speaker": "e:npc_detective_001",
      "text": "这个案子不简单。",
      "imageRef": null,
      "voiceClip": null,
      "autoAdvance": false,
      "typewriterSpeed": 20
    }
  }
}
```

选项分支同样是数据（即刻结算语义保留——选择**由规则/流程直接推进**，不返回"选择编号"给创作者存）：

```json
{
  "id": "dialog:investigate-choice",
  "kind": "action",
  "play": {
    "dialog": {
      "speaker": "e:npc_detective_001",
      "text": "你愿意帮我调查这个案子吗？",
      "options": [
        {
          "label": "① 我愿意帮忙",
          "onSelect": [
            { "op": "prop.set", "args": { "path": "quest:001.state", "value": "accepted" } }
          ]
        },
        {
          "label": "② 我没兴趣",
          "onSelect": [
            { "op": "prop.set", "args": { "path": "quest:001.state", "value": "declined" } }
          ]
        }
      ]
    }
  }
}
```

> 约定：**上面的 `op` 效果、`props`、事件声明都属于引擎层/玩法层既有数据契约**，具体字段名以装载验证为准；这里只演示"对话模块的数据形状"。官方 TS 对象字面量与这份 JSON 装载后完全等价（D-073 单调重定义）。

## 六、降级检索的具体实现

### 6.1 图像检索流程

**Step 1：检查模块指定的 image**
```typescript
if (dialogConfig.imageRef) {
  const image = loadImage(dialogConfig.imageRef);
  if (image.exists) return image;
}
```

**Step 2：检查该实例的立绘库**
```typescript
const entity = getEntity(dialogConfig.speaker);
if (entity.portraits && entity.portraits.length > 0) {
  return entity.portraits[0];  // 第一个立绘
}
```

**Step 3：检查该实例的贴图/图标**
```typescript
if (entity.sprites && entity.sprites.length > 0) {
  return entity.sprites[0];  // 第一个贴图
}
if (entity.icon) {
  return entity.icon;  // 图标
}
```

**Step 4：返回默认占位符**
```typescript
return createPlaceholder({
  backgroundColor: '#000',  // 纯黑背景
  text: entity.displayName[0],  // 名字首字母
  textColor: '#FFF',
});
```

### 6.2 图像缩放与裁剪

**等比缩放 + 居中裁剪**（CSS `object-fit: cover`）：
```typescript
function fitImage(image, targetWidth = 320, targetHeight = 480) {
  const aspectRatio = image.width / image.height;
  const targetAspectRatio = targetWidth / targetHeight;
  
  if (aspectRatio > targetAspectRatio) {
    // 图像太宽 → 高度填满，宽度裁剪
    return {
      width: targetHeight * aspectRatio,
      height: targetHeight,
      crop: 'horizontal',
    };
  } else {
    // 图像太高 → 宽度填满，高度裁剪
    return {
      width: targetWidth,
      height: targetWidth / aspectRatio,
      crop: 'vertical',
    };
  }
}
```

**视觉遮挡空间固定**：
- 无论原图是 64×64 还是 512×1024，左侧立绘区永远占据 **320×480px**
- 这保证了对话框布局的稳定性（不会因为图像尺寸变化而布局混乱）

## 七、与其他子系统的衔接

### 7.1 与图层系统的交互

**对话框是三界之外独立层**（`height = null`）：
- 对话框始终 100% 不透明，不受图层透明度函数影响
- 对话框显示时，**不暂停游戏**（除非玩法层明确要求暂停）
- 对话框可以与其他 UI 共存（例如：对话框 + 轮次栏 + 动作菜单）

### 7.2 与镜头系统的交互

**对话框出现时，镜头行为**：
- **默认**：镜头不移动，保持当前位置
- **可选**：镜头聚焦到说话人（`dialogConfig.focusSpeaker = true`）
  - 镜头平滑移动到说话人位置（见镜头子系统）
  - 对话框关闭后，镜头恢复原位（或保持在说话人位置）

### 7.3 与声音系统的交互

**对话框音效的优先级**：
- 对话框出现/消失音效：**高优先级**（不被其他音效打断）
- 打字机音效：**中优先级**（可以被语音覆盖）
- 语音：**最高优先级**（播放语音时，降低背景音乐音量 20%）

### 7.4 与动画系统的交互

**对话框动画使用 `03` 曲线配方**：
- 对话框出现：`P1-近距移动` + `M8-透明度渐变` + 自定义 `skewX`
- 对话框消失：`P1-近距移动` + `M8-透明度渐变`
- 立绘切换：`P1-近距移动` + `M8-透明度渐变`

## 八、实现要点与性能优化

### 8.1 实现要点

**模块化设计**：
- 对话框是独立的 UI 组件（`DialogBox.tsx`）
- 不依赖特定的游戏状态（通过 props 传入所有数据）
- 可以被任何玩法层数据触发（UGC JSON 声明 → 表现层投影消费）

**动画性能**：
- 使用 CSS `transform`（GPU 加速）而不是 `left/top`（CPU 渲染）
- 使用 `will-change: transform, opacity` 提示浏览器优化

**图像缓存**：
- 立绘/贴图在首次加载后缓存（避免重复加载）
- 降级检索结果缓存（同一实体不需要每次重新检索）

### 8.2 性能优化

**懒加载立绘**：
- 立绘只在对话框出现时加载（不是游戏启动时全部加载）
- 使用低分辨率占位符（10×10px）+ 渐进加载

**文本渲染优化**：
- 使用 Canvas 或 WebGL 渲染文本（避免 DOM 操作的性能开销）
- 打字机效果使用 `requestAnimationFrame` 而不是 `setInterval`

## 九、扩展性与未来增强

### 9.1 MVP 范围（Steam demo 可展示）

**MVP 必须有**：
- 单句对话（文本 + 立绘 + 名字栏）
- P5 风格的出现/消失动画
- 打字机效果
- 不定时对话框（等待玩家点击）
- 降级检索机制（立绘 → 贴图 → 占位符）

**MVP 可以没有**（后续增强）：
- 语音播放
- 定时对话框
- 选项系统（分支选择）
- 镜头聚焦到说话人

### 9.2 未来增强方向

**增强 A：表情变化**：
- 立绘可以根据对话内容切换表情（例如：`imageRef: 'portrait:detective_serious'` → `portrait:detective_smile'`）
- 表情切换动画（淡入淡出，0.3 秒）

**增强 B：多人对话（已解决 UGC 友好性）**：
- **问题**：对话模块绑定在角色实例上，多角色对话是否需要复杂的广播机制？
- **解答**：不需要广播。多角色对话通过**顺序调用多次 `showDialog`** 实现，每次调用绑定不同的 `speaker`：
  ```typescript
  // A 说话
  await showDialog({ speaker: 'e:npc_a', text: '你好。' });
  // B 回应
  await showDialog({ speaker: 'e:npc_b', text: '你好啊。' });
  // A 继续
  await showDialog({ speaker: 'e:npc_a', text: '今天天气不错。' });
  ```
- **UGC 友好性**：每次调用都是独立的、简单的 1 行代码，无需特殊的"多人对话容器"或"广播协议"。前端自动处理立绘切换（见 §5.3 连续对话示例）。
- **未来增强方向**（非 MVP）：
  - 同屏多立绘（左侧 2-3 个立绘，当前说话人高亮 100% 不透明，其他 50% 透明）
  - 对话链式辅助函数（`DialogChain` 类，封装顺序调用，减少重复代码）：
    ```typescript
    const chain = new DialogChain();
    chain.add('e:npc_a', '你好。');
    chain.add('e:npc_b', '你好啊。');
    await chain.play();
    ```

**增强 C：对话框主题**：
- 不同角色/场景可以有不同的对话框主题（颜色、装饰、字体）
- 例如：梦境对话框（蓝色主题）vs 现实对话框（黑色主题）

**增强 D：对话历史**：
- 按 `H` 键打开对话历史（显示最近 20 条对话）
- 玩家可以回溯查看之前的对话

## 十、自主创作测试报告

> **自我检查**：这份设计是否足够完整、是否有遗漏？

### 10.1 已覆盖的设计点

✅ **P5 风格的动态对话框**（斜切 + 滑入 + 弹性）  
✅ **UGC 对象直觉**（任何实例都可以触发对话框）  
✅ **降级检索机制**（立绘 → 贴图 → 占位符）  
✅ **图像尺寸归一化**（320×480px 固定视觉遮挡空间）  
✅ **名字的可变性**（使用 `displayName`，不是 `id`）  
✅ **选项系统**（分支选择 + 强烈的偏移变换）  
✅ **语音与音效**（可选语音 + 必备音效）  
✅ **定时 vs 不定时**（自动推进 vs 等待点击）  
✅ **跳过机制**（不定时可跳过，定时不可跳过）  
✅ **UGC 友好接口**（最小调用 + 完整配置 + 连续对话 + JSON 表达）  
✅ **与其他子系统的衔接**（图层/镜头/声音/动画）

### 10.2 可能的遗漏或待验收点

**❓ 对话框的 Z 轴层级**：
- 对话框应该在**所有其他 UI 之上**（包括轮次栏、动作菜单）？
- 还是对话框可以与其他 UI 共存（例如：对话框 + 轮次栏同时显示）？
- **我的判断**：对话框应该在最上层（`z-index: 1000`），遮盖其他 UI（但不遮盖设置菜单/暂停菜单）

**❓ 对话框出现时，游戏是否暂停**：
- 对话框出现时，**游戏时间是否暂停**（其他角色不行动）？
- 还是对话框只是"遮盖视线"，游戏仍在后台运行？
- **我的判断**：默认**不暂停**，但玩法层可以选择暂停（`dialogConfig.pauseGame = true`）

**❓ 对话框与战斗的交互**：
- 对话框可以在**战斗中**出现吗（例如：敌人说话）？
- 如果可以，对话框出现时，**AP 计时是否暂停**？
- **我的判断**：可以在战斗中出现，但玩法层需要明确控制暂停逻辑

**❓ 对话框的多语言支持**：
- 对话框的文本是否需要多语言支持（英文/中文/日文）？
- 如果需要，字体如何选择（不同语言的字体不同）？
- **我的判断**：暂不考虑多语言（MVP 只做中文），字体使用统一的像素字体（见画风基调）

**❓ 对话框的文本长度限制**：
- 单句对话最多多少字？
- 如果文本超长（例如 200 字），如何处理（分页？滚动？）？
- **我的判断**：单句对话最多 **100 字**，超过 100 字需要玩法层拆成多句对话

## 十一、总结

叙事对话框系统是**表现层可配置模块、玩法层可触发**，任何实例都可以触发，UGC 友好且高质量流畅。核心设计：
1. **P5 风格**：斜切 + 滑入 + 弹性 + 红色斜条装饰
2. **降级检索**：立绘 → 贴图 → 占位符（保证总能显示）
3. **图像归一化**：320×480px 固定视觉遮挡空间（无论原图尺寸）
4. **名字可变**：使用 `displayName`（运行时可改名）
5. **选项系统**：垂直排列 + 强烈的偏移变换 + 快捷键 + 即刻结算
6. **语音与音效**：可选语音 + 必备音效（打字机/悬停/点击）
7. **定时 vs 不定时**：自动推进 vs 等待点击 + 跳过机制
8. **运行时接口**：官方 TS 直接调用 helper；UGC 用 JSON 声明同一条数据，装载走统一 `PlaypackLoader.load` / `PlaypackActivator.activate` 管道（D-073）

这份设计遵循了 `00_创作指导.md` 的五条动态图形化原则，使用了 `01` 的视觉风格定位和边缘发光交互语法，动画配方来自 `03`。待项目所有者验收。
