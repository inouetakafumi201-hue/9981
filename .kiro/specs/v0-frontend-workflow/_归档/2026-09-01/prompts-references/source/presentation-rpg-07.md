## 一、核心设计原则

### 1.1 RPG 叙事系统的职责边界

RPG 叙事系统 ≠ 战斗 UI。它负责：

| 职责域 | 包含内容 |
|--------|----------|
| **叙事推进** | 对话、剧情演出、过场、旁白、环境叙事 |
| **任务引导** | 任务日志、目标追踪、导航标记、提示箭头 |
| **社交系统** | 社交链接（Social Links）、好感度、关系网、NPC 档案 |
| **世界导航** | 地图、快速旅行、区域名显示、位置标记 |
| **玩家成长** | 技能树、统计数据、成就、收藏图鉴 |
| **日程管理** | 日历、时间流逝、限时事件、日程规划 |
| **信息整合** | 教程、帮助文档、术语表、回顾系统 |

**不包含**：战斗 HUD（轮次栏、血条、AP 显示）、动作菜单、装备界面——这些属于对局内操作 UI，已由 `01_图形化与UI.md` 覆盖。

### 1.2 对标 Persona 5 的核心特征

| P5 特征 | WakeUp 对应设计 |
|---------|----------------|
| **动态出入场动画** | 所有 UI 元素用 P5 风格的斜切滑入 + 弹性 + 红色条纹装饰 |
| **强烈的视觉个性** | 遵循 `00_创作指导.md` 画风基调 + `01` 五条视觉定律 |
| **信息分层清晰** | 主信息 + 次要信息 + 装饰层三层分离 |
| **无缝融入世界** | UI 不是「浮在游戏上的框」，而是世界的一部分 |
| **快捷键优先** | 所有操作都有快捷键，减少鼠标点击 |
| **渐进披露** | 新手只看核心，老手可深入每个系统 |

### 1.3 WakeUp 的独特约束

| 约束 | 影响 |
|------|------|
| **梦境 + 现实双层** | UI 必须在梦境（对局内）和现实（驻地）两侧都能用，但风格统一 |
| **UGC 友好** | 所有叙事模块都能被玩法包数据（JSON）触发，运行时 helper 简单 |
| **代码生成画面（AI 原生）** | 用前端框架 + 代码特效（CSS/JS 动画）生成视觉，零或极少美术素材依赖——AI 能直接写代码产出画面，不依赖美术资产 |
| **像素前景 + 全息投影背景风格** | 仅需的少量素材必须是像素艺术或代码光层（D-083），不是照片级写实 |
| **模块化按需加载** | 不同游戏模式按需启用模块（竞技模式≠主线模式≠沙盒模式），避免功能污染 |

## 二、模块清单与优先级

### 2.1 完整模块清单（对标 P5 + RPG 标准）

**设计理念**：提供足够多的"框"（挂载点），但不强制使用。每个模块都是独立的工具，玩法包按需启用。

| 模块 | 职责 | MVP | 适用模式示例 |
|------|------|-----|-------------|
| **对话框系统** | 角色对话、旁白、选项分支 | ✅ | 主线剧情、竞技赛前/赛后演出、沙盒 NPC 交互 |
| **任务日志（Quest Log）** | 主线/支线任务、任务描述、目标列表、完成状态 | ✅ | 主线剧情、沙盒模式（竞技模式不需要） |
| **目标追踪器（Objective Tracker）** | 屏幕角落的当前目标提示 | ✅ | 主线剧情、沙盒模式（竞技模式不需要） |
| **教程系统（Tutorial）** | 新机制引导、关键词解释、首次提示 | ✅ | 所有模式（首次游玩时） |
| **通知系统（Notifications）** | 任务更新、道具获得、成就解锁 | ✅ | 所有模式（竞技=击杀提示，主线=任务完成） |
| **区域名显示（Location Title）** | 首次进入区域时的大标题演出 | ✅ | 所有模式（竞技=赛前演出，主线=新区域） |
| **导航标记（Nav Markers）** | 地图上的任务标记、NPC 标记、可交互物标记 | ⏸️ | 主线剧情、沙盒模式（竞技模式不需要） |
| **日历系统（Calendar）** | 日期显示、时间流逝、限时事件提醒 | ⏸️ | 主线剧情模式（竞技/沙盒不需要） |
| **社交链接（Social Links）** | NPC 好感度、关系网、社交事件 | ⏸️ | 主线剧情模式 |
| **NPC 档案（NPC Database）** | NPC 信息、对话历史、关系图谱 | ⏸️ | 主线剧情模式 |
| **地图系统（Map）** | 世界地图、区域地图、快速旅行 | ⏸️ | 主线剧情、沙盒模式 |
| **技能树（Skill Tree）** | 能力解锁、技能升级、成长路线 | ⏸️ | 主线剧情模式 |
| **统计数据（Stats）** | 游玩时间、击杀数、完成率 | ⏸️ | 所有模式 |
| **收藏图鉴（Codex）** | 敌人图鉴、道具图鉴、地点图鉴 | ⏸️ | 主线剧情、沙盒模式 |
| **回顾系统（Recap）** | 剧情回顾、关键事件时间线 | ⏸️ | 主线剧情模式 |
| **环境叙事（Ambient）** | 场景文字提示、环境音效触发的叙事 | ⏸️ | 主线剧情、沙盒模式 |

**优先级说明**：
- ✅ MVP：Steam demo 必须有，否则 RPG 体验不完整
- ⏸️ 后置：可在 MVP 后迭代加入

### 2.2 不同游戏模式的模块启用示例

**核心原则**：避免功能污染，按模式特点按需加载。

| 模式 | 启用的模块 | 不启用的模块 | 理由 |
|------|-----------|-------------|------|
| **竞技模式** | 对话框（赛前/赛后演出）、通知（击杀提示）、教程（首次提示）、区域名显示（赛前演出） | 任务日志、目标追踪、导航标记、日历、社交链接、NPC 档案、地图、技能树、图鉴、回顾、环境叙事 | 竞技专注对抗，不需要叙事推进/任务系统 |
| **主线剧情模式** | 全部 15 个模块 | — | 完整 RPG 体验 |
| **沙盒模式** | 对话框、任务日志、导航标记、教程、通知、区域名显示、地图、图鉴、环境叙事 | 日历、社交链接、NPC 档案、技能树、回顾 | 自由探索，不需要时间压力/社交养成 |
| **教学模式** | 对话框、教程、通知、区域名显示 | 其他所有模块 | 专注引导，避免信息过载 |

**配置示例**（玩法包数据，UGC 用 JSON 表示）：
```json
{
  "modules": {
    "dialog": true,
    "questLog": false,
    "objectiveTracker": false,
    "navMarkers": false,
    "tutorial": true,
    "notifications": true,
    "locationTitle": true,
    "calendar": false,
    "socialLinks": false,
    "npcDatabase": false,
    "map": false,
    "skillTree": false,
    "stats": false,
    "codex": false,
    "recap": false,
    "ambient": false
  }
}
```

> 这里展示的是 UGC 的表达形态。官方内部如果用 TS 对象字面量 authoring，同一份数据装载后仍会进入同一个 `PlaypackDef` 管道。

## 三、MVP 必备模块设计

### 3.1 任务日志（Quest Log）

#### 3.1.1 核心功能

**打开方式**：
- 快捷键：`J`（Journal）
- 或从暂停菜单进入「任务」选项

**信息架构**：
```
任务日志
├─ 主线任务（Main Quests）
│  ├─ [进行中] 调查梦境入侵事件
│  │  ├─ 目标 1：✅ 与艾琳对话
│  │  ├─ 目标 2：⏳ 前往废弃医院
│  │  └─ 目标 3：❌ 找到幸存者
│  └─ [已完成] 入梦教学
│
├─ 支线任务（Side Quests）
│  ├─ [进行中] 寻找失踪的猫
│  └─ [失败] 及时送达包裹（已超时）
│
└─ 日常任务（Daily Quests）
   └─ [可接取] 清理地下室的僵尸
```

**视觉设计**（P5 风格）：
- 左侧：任务列表（斜切卡片 + 滑入动画）
- 右侧：任务详情（任务描述 + 目标列表 + 奖励预览）
- 任务卡片颜色：主线=红色、支线=青色、日常=绿色
- 选中任务时，卡片向右偏移 + 红色条纹装饰

**运行时接口**：
```typescript
// 添加任务
addQuest({
  id: 'quest_001',
  title: '调查梦境入侵事件',
  description: '艾琳委托你调查最近频发的梦境入侵事件。',
  type: 'main', // 'main' | 'side' | 'daily'
  objectives: [
    { id: 'obj_001', text: '与艾琳对话', completed: true },
    { id: 'obj_002', text: '前往废弃医院', completed: false },
  ],
  rewards: {
    佣金: 500,
    记忆碎片: 10,
  },
});

// 更新目标状态
updateObjective('quest_001', 'obj_002', true); // 完成目标 2

// 完成任务
completeQuest('quest_001');

// 失败任务
failQuest('quest_001', reason: '超时');
```

#### 3.1.2 特殊设计点

**任务追踪（Track）**：
- 任务卡片右上角有「📌 追踪」按钮
- 追踪后，该任务的当前目标显示在屏幕右上角（见 3.2 目标追踪器）

**任务分类与筛选**：
- 顶部 Tab：全部 | 主线 | 支线 | 日常
- 状态筛选：进行中 | 已完成 | 失败

**任务奖励预览**：
- 右侧显示任务奖励（佣金、记忆碎片、道具）
- 使用 `01` 的颜色语义（佣金=青色、记忆碎片=蓝色）

### 3.2 目标追踪器（Objective Tracker）

#### 3.2.1 核心功能

**位置**：屏幕右上角（不遮挡轮次栏和动作菜单）

**显示内容**：
```
[主线] 调查梦境入侵事件
  ⏳ 前往废弃医院 (500m ↗)
  ❌ 找到幸存者

[支线] 寻找失踪的猫
  ⏳ 在公园附近搜索 (3/5)
```

**视觉设计**：
- 半透明黑色背景 + 白色文字
- 任务类型用颜色标记（主线=红色、支线=青色）
- 当前目标用 `⏳` 标记，未开始用 `❌`，已完成用 `✅`
- 如果目标有距离/数量，显示在括号内

**交互**：
- 点击目标 → 在地图上标记该目标位置（见 3.3 导航标记）
- 可折叠/展开（点击任务标题）
- 可通过快捷键 `T`（Track）快速切换追踪的任务

#### 3.2.2 特殊设计点

**距离与方向指示**：
- 如果目标有明确位置，显示距离（米）+ 方向（↗ ↙ → ←）
- 距离 < 50m 时，方向箭头闪烁（提示即将到达）

**进度条**：
- 收集类目标显示进度（3/5）
- 可选：用细条形进度条可视化（60% 填充）

**动态更新动画**：
- 目标完成时：✅ + 绿色闪光 + 滑出动画
- 新目标出现时：从右侧滑入 + 橙色高亮 1 秒

### 3.3 导航标记（Nav Markers）

#### 3.3.1 核心功能

**地图上的标记类型**：

| 标记类型 | 图标 | 颜色 | 含义 |
|---------|------|------|------|
| **主线任务** | ⚠️ | 红色 | 主线目标位置 |
| **支线任务** | ❓ | 青色 | 支线目标位置 |
| **可接取任务** | ❗ | 黄色 | NPC 有新任务可接 |
| **可交互 NPC** | 💬 | 青色 | 可对话的 NPC |
| **商店** | 🛒 | 绿色 | 商店入口 |
| **快速旅行点** | 🚩 | 白色 | 已解锁的传送点 |
| **未探索区域** | ？ | 灰色 | 尚未到达的区域 |
| **玩家位置** | 🔵 | 蓝色 | 玩家当前位置 |
| **队友位置** | 🟢 | 绿色 | 队友当前位置（联机） |

**标记的可见性**：
- **地图模式**：所有标记都可见
- **游戏内 HUD**：只显示追踪的任务标记 + 可交互 NPC（距离 < 100m）
- **距离过滤**：距离 > 500m 的标记在 HUD 上不显示（避免屏幕混乱）

**3D 世界中的标记**：
- 标记悬浮在目标上方（Y 轴偏移 +2m）
- 标记大小随距离缩放（近大远小，但有最小/最大限制）
- 标记被建筑遮挡时，半透明显示在遮挡物前（X 光效果）

**运行时接口**：
```typescript
// 添加地图标记
addMarker({
  id: 'marker_hospital',
  type: 'main_quest',
  position: { x: 100, y: 0, z: 200 },
  label: '废弃医院',
  icon: '⚠️',
  color: 'red',
});

// 移除标记
removeMarker('marker_hospital');

// 高亮标记（闪烁 3 秒）
highlightMarker('marker_hospital', duration: 3000);
```

#### 3.3.2 特殊设计点

**追踪路径线**：
- 追踪任务时，可选显示从玩家到目标的**路径线**（半透明白色虚线）
- 路径线沿地形贴合，不穿墙
- 可通过设置关闭（有些玩家觉得路径线破坏探索感）

**标记聚合**：
- 同一位置多个标记时，显示**数字徽章**（例如：❗×3）
- 点击徽章展开所有标记列表

**距离显示**：
- 追踪的任务标记旁边显示距离（例如：⚠️ 500m）
- 距离 < 10m 时不再显示数字，改为「到达」提示

### 3.4 教程系统（Tutorial）

#### 3.4.1 核心功能

**触发时机**：
- **首次遇到新机制**时自动触发（例如：首次进入战斗、首次使用技能）
- **上下文提示**：玩家靠近可交互物时显示提示（例如：「按 E 打开门」）
- **主动查询**：按 `F1` 打开帮助菜单，查看所有教程

**教程类型**：

| 类型 | 触发方式 | 示例 |
|------|---------|------|
| **弹窗教程** | 首次遇到新机制时自动弹出 | 「战斗入门：如何使用 AP」 |
| **悬浮提示** | 鼠标悬停在 UI 元素上 | 「AP：行动点，用于执行动作」 |
| **上下文提示** | 玩家靠近可交互物 | 「按 E 拾取道具」 |
| **引导箭头** | 指向玩家应该去的地方 | 箭头指向出口 |
| **高亮边缘** | 高亮关键 UI 元素 | 动作菜单发光 |

**教程弹窗设计**（P5 风格）：
```
┌─────────────────────────────────────┐
│  ⚡ 新机制：行动点（AP）              │ ← 红色条纹 + 斜切边缘
├─────────────────────────────────────┤
│                                     │
│  行动点（AP）是你在战斗中执行       │
│  动作的资源。每回合开始时，你       │
│  会根据投点结果获得 AP。            │
│                                     │
│  [示意图：AP 条 + 动作成本]         │
│                                     │
│  ✅ AP 越多，能做的动作越多         │
│  ✅ 不同动作消耗不同的 AP           │
│                                     │
│  [  明白了  ]  [ 查看更多 ]         │ ← 按钮
└─────────────────────────────────────┘
```

**运行时接口**：
```typescript
// 显示教程弹窗
showTutorial({
  id: 'tutorial_ap',
  title: '新机制：行动点（AP）',
  content: '行动点（AP）是你在战斗中执行动作的资源……',
  image: 'tutorial/ap_diagram.png', // 可选示意图
  buttons: [
    { label: '明白了', onSelect: () => closeTutorial() },
    { label: '查看更多', onSelect: () => openHelp('ap') },
  ],
});

// 显示上下文提示
showContextHint({
  text: '按 E 拾取道具',
  key: 'E',
  position: { x: 100, y: 50 }, // 世界坐标
  duration: 3000, // 3 秒后自动消失
});

// 高亮 UI 元素
highlightUI({
  element: 'action_menu',
  color: 'yellow',
  pulse: true, // 脉冲闪烁
  duration: 5000,
});
```

#### 3.4.2 特殊设计点

**教程进度追踪**：
- 记录玩家已看过的教程（避免重复弹窗）
- 可在设置中重置教程进度（重新观看所有教程）

**渐进披露**：
- 新手第一次玩时，只显示最核心的教程（战斗、移动、拾取）
- 高级机制（如状态、连击）延后到玩家实际用到时才教

**跳过选项**：
- 教程弹窗有「不再显示此教程」选项
- 老玩家可以在设置中关闭所有教程

**教程重放**：
- 帮助菜单（F1）列出所有教程，玩家可以随时重看

### 3.5 通知系统（Notifications）

#### 3.5.1 核心功能

**位置**：屏幕右下角（不遮挡目标追踪器）

**通知类型**：

| 类型 | 图标 | 颜色 | 示例 |
|------|------|------|------|
| **任务更新** | ✅ | 绿色 | 「任务完成：寻找失踪的猫」 |
| **任务失败** | ❌ | 红色 | 「任务失败：及时送达包裹」 |
| **道具获得** | 🎁 | 黄色 | 「获得：急救包 ×3」 |
| **技能解锁** | ⚡ | 橙色 | 「解锁技能：潜行攻击」 |
| **成就解锁** | 🏆 | 金色 | 「成就达成：首次击杀」 |
| **货币变化** | 💰 | 青色 | 「佣金 +500」 |
| **社交事件** | 💬 | 青色 | 「艾琳的好感度提升」 |
| **系统消息** | ℹ️ | 白色 | 「游戏已保存」 |

**通知显示方式**：
- 从右侧滑入（0.3 秒）
- 停留 3 秒
- 淡出并向右滑出（0.3 秒）
- 多个通知排队显示（不叠加）

**通知堆叠**：
- 同类通知可堆叠（例如：「获得：急救包 ×3 → 获得：急救包 ×5」）
- 堆叠时刷新停留时间（重新计时 3 秒）

**运行时接口**：
```typescript
// 显示通知
notify({
  type: 'quest_complete',
  icon: '✅',
  title: '任务完成',
  message: '寻找失踪的猫',
  color: 'green',
  duration: 3000, // 可选，默认 3000ms
});

// 堆叠通知
notifyItem({
  item: '急救包',
  count: 3,
  stackable: true, // 同类通知合并
});

// 系统通知（简化接口）
notifySystem('游戏已保存');
```

#### 3.5.2 特殊设计点

**通知历史**：
- 按 `N`（Notifications）打开通知历史面板
- 显示最近 50 条通知（可滚动）
- 通知按时间分组（今天、昨天、更早）

**通知音效**：
- 每种通知类型有独特音效（见 `02_镜头与声音.md`）
- 成就解锁有特殊音效（更响亮、更华丽）

**通知优先级**：
- 高优先级通知（任务失败、死亡）立即打断当前通知
- 低优先级通知（货币变化）排队等待

### 3.6 区域名显示（Location Title）

#### 3.6.1 核心功能

**触发时机**：

## 五、UI 动效统一规范

所有 RPG 叙事/引导模块的动效必须遵循 P5 风格：

| 动效类型 | 实现方式 | 参数 |
|---------|---------|------|
| **入场动画** | 斜切滑入（从左/右） + 弹性缓动 | duration: 0.3s, easing: elastic |
| **出场动画** | 斜切滑出 + 透明度渐变 | duration: 0.3s, easing: ease-out |
| **选中动画** | 向右偏移 + 红色条纹装饰 | offset: 10px, stripe: animated |
| **悬停动画** | 轻微放大 + 边缘发光 | scale: 1.05, glow: white |
| **完成动画** | 绿色闪光 + 滑出 | color: green, duration: 0.5s |
| **失败动画** | 红色闪光 + 震动 | color: red, shake: 3px |

所有动效使用 CSS `transform`（GPU 加速），不使用 `left/top`。

## 七、运行时接口与 UGC 友好性设计

所有模块都提供简单的运行时接口。这里的示例写成函数式只是为了展示 helper 的调用形状；如果是 UGC 玩法包落盘，表达必须是 JSON，官方内部若用 TS 对象字面量 authoring，也只是为了构造同一份数据，最后仍会进入统一的 `PlaypackLoader.load` / `PlaypackActivator.activate` 管道。

### 7.1 最小调用示例（1 行代码）

```typescript
// 任务
addQuest({ id: 'q1', title: '调查医院', type: 'main' });

// 通知
notify({ type: 'quest_complete', message: '任务完成' });

// 标记
addMarker({ id: 'm1', type: 'main_quest', position: {x:0,y:0,z:0} });

// 教程
showTutorial({ id: 't1', title: '战斗入门', content: '……' });
```

### 7.2 完整配置示例（10 行代码）

```typescript
addQuest({

  title: '调查梦境入侵事件',

```

### 7.3 模块化设计

每个模块都是独立的：
- 任务系统不依赖地图系统
- 通知系统不依赖对话框系统
- 玩法包可以只使用部分模块（例如：只用对话框 + 任务日志，不用日历）
