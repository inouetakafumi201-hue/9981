# V0.dev 投喂 Prompt · batch-3：入局流程（标题画面 + 出租屋 + 过渡屏）

## 1. Project Positioning

本项目是一个「偷师前端」UI 壳层：用一套声明式 React 界面，把整个游戏的 UI 表面全部做出来（标题画面、对局 HUD、驻地、叙事对话框、过渡屏、系统通知、控制面板、次面板），供开发期演示、抽取与后续接线。**本壳层只表达视觉与交互手感，不实现任何玩法规则。**

本批次交付入局流程链：标题画面（`menu-title`）→ 出租屋主界面（`residence-main`）→ 进出过渡屏（`transition-dream` / `transition-battle-intro` / `transition-result`）。这条「标题 → 驻地 → 入梦 → 对局开始 → 结算 → 返回驻地」的 UI 旅程在壳层内闭环演示。

## 2. Scope List

**In scope（本批次）：**
- `menu-title`：标题画面（开始菜单）。标准四入口：`新游戏` / `继续` / `选项` / `退出`。`选项` 展开五脏俱全的设置面板（显示/声音/输入/无障碍/语言/图形，全部 mock 可调）。`退出` 有确认态。
- `residence-main`：出租屋主界面（现实地图 = 主界面外观），实体入口：床A（蓝，主线+竞技）、床B（珊瑚，联机副本）、床C（青，自建梦）、锚定导流仪、研究台、造梦舱、电脑、电视、书架、保险箱、门缝、边缘氛围、左上角退出入口。
- `transition-dream`：纯白显形（入梦/返回，enter-dream / return-home 两变体，可跳过）。
- `transition-battle-intro`：对局开始（世界介绍 + 玩法包说明，可跳过）。
- `transition-result`：对局结算（结算展示 → 返回驻地）。

**Out of scope（本批次及全项目）：**
- 研究台/造梦舱/电脑/书架/保险箱的**内部界面**——本批次只做「入口占位」（可点击、显示入口占位提示，不展开内部）。
- 地图节点、空间拓扑、ORCA、寻路、路径成本、玩法规则。
- `editor` / `research-bench` / `material-library` / `computer` 内部界面。

## 3. Reference Materials

- 标题画面：无既有基线草图（open item）。布局以本 Prompt 第 6 节文字描述为准；如后续产出草图（草图级即可），作为 layout 基线替换。
- 出租屋与过渡屏：无既有基线草图，以本 Prompt 第 6 节文字描述为准（登记 open item）。

## 4. Technical Constraints

- 技术栈：React + TypeScript；动效 Framer Motion；图标 lucide-react；可访问 Radix；状态 Zustand；音效 Howler（留音频槽）。
- 基准 1920×1080，最小 1280×720。
- 语义色 token：红/蓝/黄/橙/绿/紫/珊瑚/青/灰/灰白/纯白/金/银（同全局语义，见 batch-1 第 4 节）。
- 视觉：标题画面 = 低饱和全息投影光层背景 + 前景标题字与菜单项，克制暗调、半透明 UI、边缘发光表达可交互；出租屋为同一视觉语言的实景；床A 蓝语义、床B 珊瑚、床C 青；锚定导流仪为一人高黑色科技机箱；纯白显形 = 高冲击但克制的白色过渡，不是常态底色。
- 门控呈现：锚定导流仪未交互完成前，床呈灰色不可点（视觉门控，不做真实规则）。

### 4.1 反网页感硬门禁（不可妥协）

- 这是独立游戏的标题、出租屋和过渡演出，不是网页首页、后台导航、SaaS 仪表盘或应用启动器。不得生成浏览器 chrome、地址栏、登录条、现代侧边导航、卡片墙或网页滚动条。
- `menu-title` 必须像游戏世界中的标题场景：标题与入口悬浮在全息光层和空间氛围上，菜单项是有层级的交互对象，不是居中的四张等宽按钮卡片。
- `residence-main` 必须先呈现出租屋的空间、承载物、光影和遮挡，再叠加少量入口提示。床、书架、研究台、电脑等是场景实体，不是导航图标网格；不得用“三栏面板 + 中央空白内容区”替代房间。
- `transition-*` 必须是连续的全屏仪式演出，不是 loading 页面、进度条页面或弹窗。纯白显形要有前后关系、遮挡、光线推进和复原落点，不能用单帧白屏或线性淡入糊过去。
- 面板和提示只在需要时出现，使用半透明全息浮层，让场景继续可见。不要给所有入口加相同圆角、相同边框和相同阴影。
- 先搭建环境层、实体层、交互层和过渡层，再放置文字与控件。若隐藏所有文字后仍像网页布局，视为失败。
- 所有入场、出场、门控和传送演出使用 Framer Motion 的 `AnimatePresence`、`layout`、spring 或声明式序列；不要用 CSS 线性淡入淡出代替空间演出。

### 4.2 交付前视觉验收

- [ ] 标题画面不是四按钮菜单页；出租屋不是导航 dashboard；过渡屏不是 loading screen。
- [ ] 背景空间和实体在 UI 之下仍然可见，且有明确的层次、遮挡和光源。
- [ ] 三个页面没有统一卡片模板、均匀三栏骨架、网页 chrome 或工程属性面板。
- [ ] 新游戏、床门控、入梦、返回和结算都能看出起点、路径和落点，而不是瞬间换页。

## 6. Interaction Rules

### 6.1 标题画面（menu-title）

- 状态：`初始` / `选项展开` / `退出确认`。
- 入口与行为（全部 placeholder-only）：
  - `new-game`（新游戏）：淡入落地出租屋（`residence-main`），首启可加短演出「起床」（可跳过）。**保留产品铁律：床 = 装载入口、纯白显形唯一传送**——新游戏不直接进对局。
  - `continue`（继续）：占位（mock 存档），进入 `residence-main`。
  - `options`（选项）：展开设置面板（五脏俱全，见 6.5）。
  - `quit`（退出）：进入退出确认态（确认 = 占位；取消 = 回初始态）。
- 菜单项五态：hover 边缘发光亮起 + 轻微右移/凸起；focus Radix 焦点环；active 高光加深；disabled 置灰（如无存档时 continue 置灰——mock 展示）；return 回基线。
- 键盘：↑/↓ 切换菜单项，Enter/Space 确认，Esc 关闭选项/取消退出。

### 6.2 出租屋主界面

- 状态：`默认漫游` / `锚定导流仪交互中` / `匹配中(异步)` / `匹配完成(床亮起)` / `床前就绪`。
- 实体交互：
  - 床A/B/C：可悬停显示床名与语义色；锚定导流仪交互前床灰不可点；交互完成后对应床高光亮起（视觉状态，不接真实匹配）。
  - 锚定导流仪：交互态呈现模式选择（MVP 仅「竞技」）+ 规则/状态/规则准备摘要（彩色 UI）+ 发起匹配按钮（占位）。
  - 研究台/造梦舱/电脑/书架/保险箱：点击 = 弹出「入口占位」浮层（显示该入口名称 + 一句职责说明），不展开内部。
  - 电视：被动显示公告横幅（可展开/关闭，属 notice 家族，本批次只放入口触发位）。
  - 门缝：纸条/传单静态呈现（辅助叙事，无功能入口）。
- 左上角退出 + 设置入口（与 HUD 一致）。

### 6.3 纯白显形（transition-dream）

- `enter-dream`（实→梦）：床浮现 → 人+床整体纯白（约 1 秒）→ 复原色彩 → 人物跳下进入梦境。
- `return-home`（梦→实）：人物纯白显形（约 1 秒）→ 纯白推向床 → 人物复原色彩 → 起床演出。
- 纯白显形可跳过（跳过不影响任何规则）。
- 曲线/多帧，不做单帧跳变；床是固定实体，全程不消失。

### 6.4 对局开始 / 结算

- `transition-battle-intro`：地图名称 / 玩法包说明（可跳过）→ 淡入到对局。
- `transition-result`：结算展示（结果行/奖励行，mock）→ 「返回驻地」按钮 → 回到 `residence-main`。

### 6.5 设置面板（五脏俱全，本批次经 `options` 与左上入口共用）

- 选项卡齐全（全部 mock 可调）：显示（分辨率/全屏/UI 缩放）、声音（主音量/音乐/音效/语音）、输入（键位/手柄）、无障碍（reduced motion/字幕/高对比）、语言、图形（品质）。
- 每个可调项都有五态与即时视觉反馈（滑块/开关/下拉）；关闭后焦点归还触发位置。

### 6.6 通用规则

- 五态：hover / focus / active / disabled / return 全部实现。
- placeholder-only：所有交互只改变呈现。
- mock 标注：假存档、假匹配状态、假结算数据一律标 `mock`。

## 7. Explicit Exclusions

- ❌ 不实现研究台/造梦舱/电脑/书架/保险箱内部界面（只入口占位）。
- ❌ 不做地图节点/拓扑/ORCA/寻路/路径成本。
- ❌ 不接真实存档/匹配/结算，不写规则状态。
- ❌ 不做编辑器/素材库/研究台/电脑内部界面。
- ❌ 不引入第 4 节之外的新依赖。
