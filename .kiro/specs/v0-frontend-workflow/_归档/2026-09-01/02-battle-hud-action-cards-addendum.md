# V0.dev 投喂追加 Prompt · 行动卡交互（对局动作选择 UX）

> **使用方式**：完整追加在 `02-battle-hud.md` 后面，在 `hud-main` 的动作选择启用此交互模型。本文件只管**动作选择的渲染交互层**，只替换"动作面板/价格面板"的呈现手握手感，不触碰任何规则投影与意图提交契约。
>
> **一句话目标**：把「从一列/一排 CSS 方框里点按钮挑动作」改成「手里拈着一叠行动卡、悬停看详情、点一下卡就生效」的卡牌式直接操作。鼠标悬停即详情，单击即生效，丝滑、低心智、不并排、不切页、不推滑块。

---

## 0. 先给 V0 的一句话

玩家的对局决策 = 「我能做什么、花多少 AP、对谁生效」。正确的体验是用一只手指拈着行动卡：**悬停一张卡就看清楚它**，觉得可以就**点一下把卡打出去**。不要做成一行行并排的 CSS 方框、不要用滑块堆叠挑选、不要用选项卡一页页切。那是最费劲的挑法，且天然是网页感。

---

## 1. 为什么"并排方框 + 滑块/选项卡"对动作选择是错的

1. **吃掉决策区**：动作选择要读的是「代价 + 目标 + 是否可用」，并排方框把它压成等大图标行，详情只能藏进 hover 或二级弹窗，玩家被迫横向扫视——违反低心智（`01`：显著降低视线切换成本）。
2. **稀释语义色**：每个框被套同样的发光/边框，可交互与不可交互在尺寸上"一样大"，只能靠灰色区分；但 `01` 视觉定律明令"不可点击不能再只靠灰色表达"，并排框恰恰把灰色当主要手段。
3. **打断就地播放**：投点、结算、因果链必须在轮次栏旁就地闭环；并排卡片墙是把动作选择做成独立桌面组件，与 D-036 就地播放相悖。
4. **付费/零费二分被做成选项卡**：两者是契约硬性分离（`paidActions`/`attachedActions`），切换允许（D-042）但应在**同一空间做形态变化**，不是两个同级标签页——那违背"0/1 AP 分离是为防误点"的本意。

---

## 2. 形态：底部居中的扇形行动卡手牌

- **付费动作** = 底部居中、以当前行动者/当前目标为锚的**扇形手牌**。卡与卡之间允许遮挡、偏移、斜切、重叠、层级差（不是等大矩形排），落点是 `02-addendum` 的贝形托盘演化的**手牌舞台**。
- **零费动作** = 手牌侧沿的一条**窄带/悬浮徽章簇**，与付费手牌**空间分离**，绝不混排在同一区域正排（守 `01` "0/1 AP 分离"铁律）。
- 手牌沿用像素前景 + 全息投影语言的材质：半透明多层光层、边缘光、断边/斜切、语义色高光；不用 9-slice 边框图、不用统一圆角矩形。

### 2.1 过多选项的整合（不突破 ≤5 分级导航）

- 底层逻辑遵循既有 `option-set.ts` 的**分级导航**：`cost-category（付费/零费）→ interaction-intent（4 意图 + 未声明档）→ leaf（动作页）`，任一瞬间同时可选项恒 **≤5**（含"上一页/下一页/上一级"导航控件）。这套逻辑层是既有契约，**保持不动**，只改它的渲染呈现。
- 手牌呈现把这些"分档"翻译成**卡牌堆叠 + 翻牌**：后卡叠在前卡下方露出一条边缘光带，悬停/拨动翻出下一张，近似翻牌；导航项（上一级/上一页/下一页）渲染成手牌边缘的小锚点/翻页角标，不占用整张卡槽。
- 用动作自带的四个交互意图做**次级分组/角标**：移动=traversal、攻击=hostile-interaction、撬锁/精密=precise-interaction、令其长眠/处决=executable-target。不发明新枚举。
- 上下文动作（点击目标弹出的局部菜单）与手牌并行不冲突：目标始终是空间锚点，手牌作为可选动作的载体。

---

## 3. 交互铁律：悬停即详情、单击即生效

### 3.1 悬停即详情（不进弹窗）

- 悬停任意行动卡 → 该卡**局部放大 + 卡面详情展开**，在当前画面内展示：图标、语义色边缘光、成本菱形（橙◆=AP / 蓝💧=SP）、目标意图、可用/不可用原因。
- 详情只展示**投影里已有的显式语义字段**——不得凭图标/颜色推断伤害、成本之外的自算规则，不本地算 AP/命中/目标范围。这是"表现层不本地推断"的边界。
- 触控等价：长按/聚焦展开，复用输入等价表（`01` §输入等价）。

### 3.2 单击生效（目标两级跳转）

- **无目标动作**（意图缺省 / self / none）：单击卡片 → 卡**飞出**（飞向当前行动者/当前目标）→ 就地进入演出。不弹确认框。
- **有目标动作**：单击卡片 → 卡**吸附到光标**进入目标选择态→ 在当前投影可见的实体/节点上叠加**边缘发光候选高亮**（按意图映射颜色：近战=珊瑚、远程=紫、免费=绿等）→ 玩家再点目标实体即执行；点空白取消。
- 全程只是选择界面态：目标标识只能来自投影，点击后只构造意图提交，**绝不本地结算**。

---

## 4. 动效与手感（Framer Motion）

- 手牌入场：扇形展开用 `AnimatePresence` + spring，卡与卡错峰滑入，不是同时平铺。
- 悬停：卡片用 spring 局部放大 + 上浮 + 边缘光增强，卡面详情就地在卡上展开（`layoutId` 过渡，不弹新浮窗）。
- 飞出/吸附：有目标动作单击后卡片 `layoutId` 吸附到目标区，同一张"卡"跨空间迁移，不是新开一个元素。
- 目标候选高亮：边缘发光按意图脉冲；
- `prefers-reduced-motion`：保留目标顺序、可读性与结果落地，只缩短位移/闪烁。

---

## 5. 视觉判定（与 `02-addendum` 共用断言）

- 我不希望动作选择里出现静止的并排卡片墙、滑块堆叠、选项卡切页、hover 弹窗式详情或按钮式纵列。
- 每张行动卡都不共用同一套圆角矩形 + 1px 边框；不同几何、不同斜切/断边、不同层级。
- 交互态 = 边缘发光 + 高光 + 材质 + 卡可飞；扁平降饱和无高光 = 不可用。灰白高光带材质 = 可用但受限；不可用必须扁平无高光，不只用灰色。
- 悬停详情在画面内就地展示，不弹遮挡地图的新浮窗，不触发网页式 tooltip 弹层。
- 单击生效流畅，目标两级跳转无需确认框，点空白即取消。

---

## 6. 技术边界与约束对齐

- 渲染交给 React + Tailwind/design-tokens + Framer Motion + Radix + lucide-react；**不引入 Pixi/Three/WebGL/new Canvas engine**。
- 绝对/扇形定位只作用于视觉层；保留响应式安全区、键盘焦点顺序、Radix ARIA、1280×720 最小分辨率、`prefers-reduced-motion`。
- **不改 L2 契约、不本地推断规则、不发明新枚举**：只用 `ActionDescriptor` / `TargetDescriptor` / `PresentationDescriptor` 里的显式字段，沿用 `option-set.ts` 的 ≤5 分级导航与既有分档键。**本文件只改 V0 壳层动作选择的渲染呈现**：底层 `buildMenuFaces` / `buildOptionSet` / `intent-factory` 保持零改动。
- 遵守 `mock` 与 `placeholder-only` 规则；不引入新的主色，颜色全走 tokens 语义色；目标/详情只展示投影显式字段，不本地推断。

## 7. 交付前验收清单（针对动作选择）

- [ ] 动作选择底部为扇形手牌，付费与零费空间分离，无并排卡片墙、无滑块堆叠、无选项卡切页。
- [ ] 悬停任一行动卡即在卡上就地展开详情（图标/成本菱形/目标/可用原因），不弹遮挡地图的新浮窗。
- [ ] 无目标动作单击即飞出执行；有目标动作单击进入目标选择，再点目标实体生效，点空白取消。
- [ ] 可用/不可用完全通过边缘发光 + 材质 + 扁平无高光表达，不只靠灰；灰白=可交互但受限，扁平无高光=不可点。
- [ ] 目标候选高亮按意图映射颜色（近战珊瑚/远程紫/免费绿），有图标或材质等价通道，不只靠颜色。
- [ ] 手牌/卡面/距离详情、骰子横条面板不与骰子横条/动作区重叠。
- [ ] `prefers-reduced-motion` 下目标顺序、可读性、结果落地仍完整。
- [ ] `npx tsc --noEmit` 0 error、`npm run lint` 0 error、相关测试全绿、无 console/资产错误。

## 8. 一句话总结

把动作面板从「一排按钮让玩家点」改成「一叠行动卡让玩家拈」。玩家悬停看清楚，点一下就打出去，目标随点击走。这才是符合直觉的动作选择；也是消除"网页方框感"的关键。
