# Requirements Document: WakeUp Content Templates (Layer 2)

## Introduction

本文档为《起床》（WakeUp）项目的**内容层（Layer 2）**制定工程需求。内容层是介于底层内核（Layer 1）与用户生成内容（Layer 3）之间的中间层，提供可组合的内容模板库——包括武器模板、NPC模板、载具模板、角色模板、状态效果库、物品模板六大类。所有模板均以 JSON 格式定义，由底层内核的 Op/Query 原语驱动，确保三层架构铁板一块。

**设计原则**：

1. **数值≤5 铁律**：所有玩家可见数值（伤害、生命、AP消耗、状态持续回合等）必须落在 1-5 范围内
2. **内核对齐**：所有模板动作必须映射到内核 Op，所有感知/查询必须映射到内核 Query
3. **无硬编码语义**：模板本身不包含游戏逻辑，只声明数据；逻辑由内核解释器执行
4. **UGC友好**：Layer 1 的换皮/组装创作（Layer 3 第一层）通过修改模板参数实现

## Glossary

- **模板（Template）**：可实例化的内容定义，包含数值参数、标签、动作列表
- **实例（Instance）**：模板在游戏运行时生成的具体实体
- **武器谱型（Weapon Paradigm）**：2×4 范式 = 重量级（轻/中/重/异）× 距离级（近/远）
- **枪械谱型（Gun Caliber）**：Pistol/Rifle/Shotgun/Sniper/SMG/Machine Gun 六型
- **NPC守卫范式（Guard Paradigm）**：五状态 FSM（sleeping→patrolling→listening→chasing→attacking）
- **状态效果（Status Effect）**：临时影响实体能力的标签化状态
- **EvaluationService**：通用估值服务，AI 决策调用的标签打分系统

## Requirements

### 要求 1：武器模板分类体系

**用户故事**：作为内容设计师，我需要一套完整的武器分类体系，使所有武器都能用统一的数据结构描述。

#### 验收标准

1. 系统应定义 2×4 武器谱型矩阵（重量级：轻/中/重/异 × 距离级：近/远），共 8 个基础类别
2. 每类武器模板应包含：名称、描述、体积、标签列表、动作列表、基础伤害范围（1-5）
3. 系统应定义枪械的六种谱型（Pistol/Rifle/Shotgun/Sniper/SMG/Machine Gun），每型包含独立的距离DC表
4. 枪械谱型模板应区分"默认两步流程（瞄准→发射）"与"特例一步流程（枪械简化）"
5. 非枪械远程武器（弓、弩、飞刀）默认使用两步流程模板，除非另有特殊说明
6. 武器模板的动作定义必须映射到内核 Op（`Attack`、`UseItem`、`Move` 等）

### 要求 2：NPC 模板库

**用户故事**：作为内容设计师，我需要一套 NPC 模板库，使不同类型的 NPC（守卫、僵尸、平民等）能够快速配置生成。

#### 验收标准

1. 系统应定义 NPC 模板，包含：类型名称、生命值（1-5）、感知阈值、行为范式、初始装备列表
2. 守卫范式应实现五状态 FSM（sleeping→patrolling→listening→chasing→attacking），包含各状态转换条件
3. NPC 行为必须通过内核事件系统触发，不得硬编码 AI 逻辑
4. NPC 生命值必须落在 1-5 范围内，超出范围应被静态验证拒绝
5. NPC 模板应支持通过参数覆盖快速生成变体（如调整感知阈值改变警觉程度）
6. AI 决策必须通过 EvaluationService 调用，不得直接访问模板内部数据

### 要求 3：载具模板库

**用户故事**：作为内容设计师，我需要一套载具模板库，使车辆等载具能够作为可交互实体在游戏中使用。

#### 验收标准

1. 系统应定义载具模板���包含：类型名称、体积、座位数（主驾/副驾等独立索引）、生命值/耐久度（1-5）、动作列表
2. 载具模板应区分实体属性（生命值、耐久度）与空间属性（内部微型场景、外部交互点）
3. 载具内部应作为微型场景处理，占用者之间可以近战
4. 载具交互（上车/下车/撞击/爆胎）必须映射到内核拓扑原语，不得硬编码
5. 载具位置优先于索引：行动方站在载具旁边即可对车内任意乘员发起交互
6. 载具模板应支持破碎效果（如分别破坏不同车门），但日常交互不区分具体门索引

### 要求 4：角色模板库

**用户故事**：作为内容设计师，我需要一套角色模板库，使玩家角色和 NPC 角色能够共享基础属性结构。

#### 验收标准

1. 系统应定义角色模板，包含：名称、体积、初始生命值（=5）、初始体力（=5）、初始背包容量、初始装备列表
2. 角色模板应与 NPC 模板共享基础属性结构，但角色模板专用于玩家生成内容
3. 角色死亡后应生成死亡背包实体，继承原背包部分物品
4. 角色模板的体积分类应与物品体积分类（小/中/大）保持一致
5. 角色模板不得定义任何硬编码行为，所有能力通过装备和状态实现

### 要求 5：状态效果库

**用户故事**：作为内容设计师，我需要一套标准化的状态效果库，使所有状态都能用统一的方式定义和应用。

#### 验收标准

1. 系统应定义状态效果模板，包含：状态名称、效果类型、持续回合数（1-5）、叠加规则、打断条件
2. 状态效果应区分为数值型（修改数值）与标签型（触发条件）两类
3. 同名状态不叠加，取最长持续时间
4. 特定状态克制（如火焰解除冰冻）和状态放大（如 `[重装]` + `[加速]` 效果叠加）应明确定义
5. `[淋湿]` 状态已从 MVP 中移除，相关叠加规则不再存在
6. 掩体机制（D-017 待重新设计）应在状态效果库中预留位置，但具体规则待专题讨论后填充
7. 状态效果必须通过内核事件系统触发，不得硬编码状态逻辑

### 要求 6：物品模板库

**用户故事**：作为内容设计师，我需要一套物品模板库，使消耗品、工具、装备等都能用统一的数据结构描述。

#### 验收标准

1. 系统应定义物品模板，包含：名称、体积（小/中/大）、标签列表、动作列表、赋予状态列表
2. 物品体积应与角色背包槽位系统对齐，确保可堆叠性可计算
3. 物品动作必须映射到内核 Op，不得硬编码
4. 物品赋予的状态应在保存时进行引用完整性验证（状态必须存在于状态效果库）
5. 物品模板应支持模板继承，允许基于已有模板覆盖特定字段生成变体
6. 消耗品使用后应从背包移除，非消耗品保留

### 要求 7：枪械伤害数值表

**用户故事**：作为内容设计师，我需要枪械的完整伤害数值表，使命中判定后能正确结算伤害。

#### 验收标准

1. 系统应为六种枪械谱型（Pistol/Rifle/Shotgun/Sniper/SMG/Machine Gun）分别定义基础伤害值（1-5）
2. 伤害数值必须落在 1-5 范围内
3. 距离DC表（D-018 确认存在但数值待专题讨论）应与伤害数值分开定义
4. 命中判定（查DC表）与伤害结算（查伤害表）是两个独立步骤

### 要求 8：模板与内核 API 的映射规范

**用户故事**：作为系统实现者，我需要明确的模板→内核映射规范，确保 Layer 2 完全对齐 Layer 1。

#### 验收标准

1. 每个武器动作应声明对应的内核 Op 类型（`Attack`、`UseItem`、`Move` 等）
2. 每个 NPC 行为应声明对应的内核事件触发条件（`OnPlayerEnter`、`OnNoise`、`OnDamage` 等）
3. 每个状态效果应声明对应的内核事件处理逻辑
4. 模板数据不得包含任何游戏逻辑语义���只声明可被内核解释的数据
5. 静态验证应检查模板中引用的 Op/Query/事件是否在内核中已定义

### 要求 9：网关机制的模板定义

**用户故事**：作为内容设计师，我需要通过模板定义三种网关（资源转换/检定/条件），使上锁的门、商店、合成台等玩法可配置。

#### 验收标准

1. 系统应定义资源转换网关模板，包含：消耗资源类型/数量、产出效果、是否消耗AP
2. 系统应定义检定网关模板，包含：检定类型（敏捷/力量等）、难度阈值（1-5）、失败效果
3. 系统应定义条件网关模板，包含：前置条件（持有物品/状态/阵营关系）、通过效果
4. 三种网关的共同结构（门槛/呈现/AP成本/效果）应在模板中统一表达
5. 网关模板的数值（难度阈值、资源数量等）必须落在 1-5 范围内

### 要求 10：世界观呈现的模板位置

**用户故事**：作为内容设计师，我需要在模板中预留世界观呈现位置，但不需要实现完整的叙事系统。

#### 验收标准

1. 物品模板应包含描述字段，用于简短呈现"零和睡眠协议"世界观的轻量叙事
2. 场景模板应包含环境文本字段，用于呈现场景氛围
3. 世界观呈现不应涉及对话树、剧情章节等重系统
4. 模板中的描述字段不影响游戏机制，仅作为叙事填充

### 要求 11：模板参数化与 UGC 第一层创作

**用户故事**：作为轻度玩家，我需要通过修改模板参数（换皮）快速创作内容，而不需要理解底层实现。

#### 验收标准

1. 所有模板参数应具有人类可读的名称和默认值
2. 模板应支持通过覆盖特定参数生成变体，无需修改基础结构
3. LLM 辅助创作入口应能接收自然语言描述并映射到模板参数填充
4. 第一层创作（换皮/组装）的输出应直接保存为模板实例，无需额外转换

### 要求 12：模板静态验证

**用户故事**：作为系统，我需要在模板加载时就检测出不合法的定义，而不是等到运行时才发现。

#### 验收标准

1. 所有数值型参数应进行 1-5 范围检查
2. 所有引用型参数（状态ID、Op名称、事件类型）应进行存在性检查
3. 循环引用（模板A引用B，B引用A）应被检测并拒绝
4. 模板验证失败应给出明确错误信息，指出具体字段和问题
5. 验证器应区分错误等级（致命/警告），警告不阻止加载
