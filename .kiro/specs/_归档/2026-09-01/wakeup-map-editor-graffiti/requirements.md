# Requirements: 地图编辑器涂鸦式交互第二版（图元穷举 + 交互契约全量）

## Introduction

本 spec 是开发板地图编辑器的**交互层重写第二版**。它逐字句对齐权威文稿 `docs/创作系统/01_创作工具与产权.md` **第八节「工作台交互契约」**、**第九节「地图编辑器交互契约」**（状态机 / Select 态裸输入 / 全局输入 / 拉边流程 / 样条塑形 / 取样 / 校验反馈 / 视觉语言零新增 / 必要 vs 延后）与 **第八节「图元穷举」**（场景框 / 连线 / 视觉遮挡 / 物理遮挡 / 高地 / 洼地 / 过渡窗口 + 涂鸦式交互 + 场景框聚合 + 空洞全填 + 粘连判定）。

第一版实现了「界面的形」，本版拨正为「交互与语义的实」——把第一版遗漏或做错的**每一项设计行为**——涂鸦式交互、场景框聚合与空洞全填、样条折点调整/删除、框选、取样、过渡窗口独立拖拽、遮挡框旋转、撤销/重做、拉边空白红闪、校验摄像机飞跃与红脉冲、视觉语言零新增——补全，做到可直接交付 demo。

**范围**：只重写开发板编辑器交互层，全部落在 `src/devboard/`。**不碰 `src/play/map/**` 契约源码**（校验 / 编译 / curve 只 import 消费）。几何图元的存储字段（视觉遮挡 / 物理遮挡 / 高地洼地 / 过渡窗口）已存在于 `MapEdge` / `ObstructionSpec` / `TransitionWindowPoints`，开发板只消费。

## Glossary

- **涂鸦式交互**：`01` §九图元穷举——所有矩形 / 线用同一种涂鸦式交互，拒绝 PS 式 4 点拖拽框。四角无控制点，阴影提起的感觉；同类型重叠 = 合并（边界消失）；滚轮旋转 10°/格；点击选中、Delete 删除；框的形状只在造的时候定，之后整体拖动。
- **场景框（Scene Box）**：`01` §八——原「节点框」。灰白，多重叠加 / 旋转 / 融合；同类型重叠合并为一块、边界消失。多个场景框聚合成一个场景。「最大距离矩形中心」= 高光点（连线拖出锚点）。
- **高光点（Highlight Point）**：`01` §八——创建多个场景框构成一个场景后，取「最大距离矩形中心」创建一个高光点，可用它拖出直线；单点高光点可设场景属性（大/中/小档位）。
- **空洞全填**：`01` §八——仅对场景框生效。场景框形成内部封闭空洞时，视觉上像油漆桶般被填充、逻辑上该区域是场景的一部分、不可在其中放置其他场景节点；储存仍是多个矩形拼成，不用虚假矩形填补。
- **粘连判定**：`01` §八——若一次场景框拖拽/创建把两个已创建的节点（场景）连接了起来，此次操作被拒绝（拖了没效果），并给淡出提示。
- **样条塑形**：`01` §九——拉线后的塑形是**平滑样条线（Catmull-Rom，穿过全部样本点）**，非贝塞尔。三态合一最小动作集：[A]拉伸建线 / [B]折点调整 / [C]拉弯塑形 / [D]折点删除。隐藏样条点不可见、不可选中、不可二次编辑。
- **折点（Knot）**：`path` 数组里的点。首尾吸附节点中心；中间为折点。
- **隐藏样条点**：拉弯（[C]）时追加进线段内的点。不可见、不可选、不可二次编辑；只能整体清空重拉（双击拉直）。
- **框选（Box Select）**：`01` §九 Select 态——左键拖空白给框选。只有这个，没有替代（平移有空格与中键两条路）。
- **过渡窗口（Transition Window）**：`01` §八图元——素材库组件，不吸附到节点、独立拖到任意位置；一旦经过一条线即成为该线过渡窗口。落在 `MapEdge.transitionWindow.control`。
- **遮挡框**：视觉遮挡黄 / 物理遮挡红 / 高地深绿 / 洼地浅绿。阴影框选中、Delete 删除、滚轮 10°/格旋转。颜色即图元身份。
- **视觉语言零新增**：`01` §九——编辑器状态直接映射霓虹边交互语法，不发明新颜色。白=悬停可选、黄=已选中、红=校验错误、蓝=拖拽合法落点。

## 要求

> 每项要求下以「**权威**」列出依据的设计文档。冲突时以此处序号与文档章节锚点为据。

### 要求 1：状态机与全局输入

**用户故事**：作为创作者，我想用统一的状态机（Select/PlaceNode/DrawEdge/Sample/Playtest）和一套全局输入（平移/缩放/撤销/重做/面板/楼层/模式切换）在编辑器里行动，以便不迷路、低心智地完成地图编辑。
**权威**：`01` §九「状态机」「全局输入」「Select 态裸输入」；技术实现 SVG viewBox 见 `工程治理/02`（主画面渲染 SVG）。

1. 编辑器应以 `Select / PlaceNode / DrawEdge / Sample / Playtest` 五种模式组织创造性动作；只要三种（造节点、拉边、取样）有模式，其余是 Select 与 Playtest（Esc 永远回得来回）。
2. WHERE 编辑器处于任何模式，THEN Esc 应回到 Select 并清除当前进行中的草稿（描线、塑形、拖拽、框选）；WHERE 已在 Select，THEN Esc 应清空选择。
3. WHERE 用户按下 `N / E / I / P`，THEN 编辑器应切换到对应模式（节点 / 边 / 取样 / 试玩）。
4. WHERE 用户按下 `1 / 2 / 3`，THEN 编辑器应在楼层间切换（地面层为 1）。
5. WHEN 用户按住空格并拖拽，或按住鼠标中键拖拽，THEN 编辑器应平移画布（走 SVG viewBox，不走浏览器滚动）。
6. WHEN 用户滚动滚轮，THEN 编辑器应以光标为中心缩放画布。
7. WHEN 用户按下 `Ctrl+Z`，THEN 编辑器应撤销最近一次修改。
8. WHEN 用户按下 `Ctrl+Shift+Z`（或 `Ctrl+Y`），THEN 编辑器应重做最近一次撤销。
9. WHEN 用户按下 `Delete`（或 Backspace，焦点不在输入控件时），THEN 编辑器应删除当前选中图元。
10. WHEN 用户按下 `Ctrl+S`，THEN 编辑器应触发保存（结构校验即时反馈）。
11. WHEN 用户按下 `Tab`，THEN 编辑器应开合当前面板。
12. 编辑器应维护栈式撤销/重做历史（每次破坏性修改入栈一个可撤销单元；`Ctrl+Z` 退栈、`Ctrl+Shift+Z` 前进）。

### 要求 2：Select 态裸输入与框选

**用户故事**：作为创作者，我想在 Select 态用一套无歧义的裸输入（单击选中、拖空白框选、双击空白不创建、右键菜单），以便符合编辑器直觉、避免误创建。
**权威**：`01` §九「Select 态裸输入」。

1. WHEN 用户在 Select 态左键单击空白区域，THEN 编辑器应清空当前选择。
2. WHEN 用户在 Select 态左键单击节点 / 边 / 道具，THEN 编辑器应选中该图元。
3. WHEN 用户在 Select 态左键拖拽空白区域，THEN 编辑器应进入框选（矩形选区，选中落在框内的图元）；平移另有空格与中键两路，不占用左键拖空白。
4. WHEN 用户在 Select 态左键拖拽节点 / 道具，THEN 编辑器应移动该图元（曲线端点随节点中心吸附）。
5. WHEN 用户在 Select 态左键拖拽边，THEN 编辑器应按样条塑形 [C] 拉弯该边（见要求 4）。
6. IF 用户在 Select 态双击空白区域，THEN 编辑器应**不**创建任何图元（误创建是编辑器第一号烦人事；造节点按 N 或走右键菜单）。
7. WHEN 用户在 Select 态双击已拉弯的边，THEN 编辑器应按样条塑形 [C] 拉直该边（清空该线段内全部隐藏样条点）。
8. WHEN 用户在 Select 态右键点击任意位置，THEN 编辑器应弹出对应上下文菜单（空白 = 画布菜单；节点 / 边 / 道具 = 元素菜单）。
9. WHEN 用户悬停在可交互图元上，THEN 该图元应显示白色描边（悬停可选；视觉语言零新增，白 = 可交互）。

### 要求 3：拉边流程（描线 + 吸附 + 红闪）

**用户故事**：作为创作者，我想按下 E 后从场景框高光点拖出描线，经折点简化、端点吸附、空白丢弃回退，以便画出贴合想法的行动线。
**权威**：`01` §九「拉边流程」第 1–8 步、「拉边后的塑形」[A] 拉伸建线；`src/play/map/curve.ts`（simplifyPath RDP、findSnapTarget、SNAP_TOLERANCE）。

1. WHEN 用户按下 `E` 进入 DrawEdge 模式，THEN 编辑器应保持该模式可连续画多条边，直到按 Esc 退出。
2. WHERE 用户悬停在节点（场景框）上，THEN 该节点应显示蓝色（合法起点）。
3. WHEN 用户在节点上按下左键，THEN 编辑器应开始描线草稿（记录起点节点、捕获指针），并实时采集拖动中的采样点、预览折线。
4. WHEN 用户拖动描线进入另一节点吸附半径，THEN 该节点应亮蓝（合法终点）。
5. WHEN 用户在节点上松手，THEN 编辑器应把采样点经 RDP 简化（`simplifyPath`）压成少量折点、端点**精确吸附节点中心**，然后建立带 `path` 的边。
6. WHEN 用户在空白处松手，THEN 编辑器应丢弃整条描线、不建立任何边，并**红色一闪**（第 7 步是设计过的行为：未设计的默认要么建出悬空边，要么静默失败）。
7. **只有松手点吸附，中间采样点永不吸附**：描线绘制过程中，采样点不得对任何节点作吸附判定（否则曲线绕过节点旁时会被抢走）。
8. 端点吸附是正确性要求而非可选：浮点近似必须由编辑器保证「边端点存在」，否则校验器判出 `MAP_EDGE_ENDPOINT_MISSING` 类错误。
9. [A] 拉伸建线：WHEN 用户在边**末端**按下并拖拽，THEN 编辑器应橡皮筋式拉出新折线，松手后在 `path` 末尾追加新折点。

### 要求 4：样条塑形（Catmull-Rom 非贝塞尔；折点调整 + 删除 + 拉弯/拉直）

**用户故事**：作为创作者，我想对显式连线用三态合一的最小动作集塑形（拉伸建线 / 折点调整 / 拉弯塑形 / 折点删除），全程不需控制柄状态机，以便「指哪打哪、所见即所得、不爽就重来」。
**权威**：`01` §九「拉线后的塑形：平滑样条线（不是贝塞尔）」[A][B][C][D] 与逐条关键语义；`curve.ts`（insertControlPoint / simplifyPath）；`docs/创作系统/01` §八连线「从场景高光点拖到目标场景边缘点」。

1. 编辑器的边路由应渲染为**平滑样条线（Catmull-Rom）**，曲线**绝对穿过每个样本点**；术语只叫「样条线」，不得称「贝塞尔」。边路径 `path: readonly Vec2[]` 直接喂给运行期运动核（`jumpMotion` 消费），引擎侧零改动。
2. [B] 折点调整：WHEN 用户按住中间折点拖动，THEN 编辑器应移动该折点坐标，左右连线跟随（Catmull-Rom 重采样）。
3. [C] 拉弯塑形：WHEN 用户按住任意线段主体往外拖，THEN 编辑器应在鼠标落点**追加一个隐藏样条点**进该线段（松手定型）。
4. [C] 拉弯即追加（Fire-and-Forget）：用户拖多少次就在该线段塞多少隐藏样条点、无上限；S 型就是在一段上拖两次。隐藏点**不可见、不可选中、不可二次编辑**；想改只能整体清空重拉。
5. [C] 双击拉直：WHEN 用户双击已拉弯的线段，THEN 编辑器应清空该线段内全部隐藏样条点，瞬间绷直回直线。这是唯一的重塑入口。
6. [D] 折点删除：WHEN 用户选中折点并按 Delete，THEN 编辑器应移除该折点，前/后折点直接连成直线（删除即拍直——防止「幽灵曲线」两段不同曲率强行拼接成大乱线）。
7. [D] 吸附删除：WHEN 用户拖某折点距左右任一邻折点小于融合阈值（不暴露给创作者，约 10px），THEN 目标折点应高亮提示「松手即融合删除」；WHEN 松手，THEN 该折点消失、左右重连成直线。
8. 单击线段只触发高亮（表现层反馈「当前操作焦点在这条线」），**不选中任何控制点、不弹菜单**；编辑态期间线段恒为高亮，但它只是镀层，不与任何逻辑纠缠。
9. RDP 简化**只在拉边阶段做一次**（要求 3.5）；之后的样条点是创作者主动追加的，**不再简化**。直线段 `path` 为空数组时按线性插值渲染，非空即切换 Catmull-Rom 逐段穿过样本点。
10. 连线的存储与语义：连线用半透明白色 + 阴影渲染，从场景高光点拖到目标场景边缘点；样条线的数据只落在 `path` 这一个数组上。

### 要求 5：图元穷举与涂鸦式交互

**用户故事**：作为创作者，我想用尽量少的框/线/点覆盖全部逻辑，用统一的涂鸦式交互（阴影选中 / 无角控制点 / 滚轮旋转 10° / 同类型重叠合并）操作它们，以便低心智、不迷路。
**权威**：`01` §八「图元穷举」「涂鸦式交互」「场景框聚合 = 场景」「空洞全填」「粘连判定」。

1. 编辑器应支持以下七种图元，颜色严格映射视觉语义（不允许发明新色）：
   - **场景框**：灰白（`01` §八），多重叠加 / 旋转 / 融合，同类型重叠合并为一块、边界消失。
   - **连线（样条线）**：半透明白色 + 阴影。
   - **视觉遮挡框**：黄（半透明）。
   - **物理遮挡框**：红（半透明、醒目 + 不可通行）。
   - **高地框**：深绿。
   - **洼地框**：浅绿。
   - **过渡窗口**：素材库组件。
2. 所有矩形 / 线用同一种涂鸦式交互：四角没有控制点，而是「阴影提起」的感觉；点击选中、Delete 删除；鼠标拖拽**不能拖边框变形状**（框的形状只在造的时候定，之后整体拖动 / 旋转）。
3. 同类型框重叠 = 合并：多拖几个矩形，同类型重叠不报错、效果一致；重叠后合并为一个图形、边界消失；选中时选中整个阴影、整体删除或整体旋转。
4. 滚轮旋转：一次小滚 = 10°（对选中框施加旋转）。
5. 线同理：一条线也是整体图元，阴影选中、整体删除 / 旋转，不逐控制点拖变形；线自带一条可整体拉弯 / 拍直的平滑样条（塑形走要求 4）。
6. 场景框的多个框聚合为一个场景（连在一起的多个框视为一个场景）；可以旋转后再拖新框融合。
7. 空洞全填（仅对场景框生效，其他方框图元不参与填充判定）：若场景框形成内部封闭空洞，视觉上应像油漆桶一般被填充（像没有空洞）、逻辑上该区域是场景的一部分、**不可在其中放置其他场景节点**；储存仍是多个矩形拼成，**不用虚假矩形填补空洞**。
8. 粘连判定：WHEN 一次场景框拖拽 / 创建把两个已创建的节点（场景）连接了起来，THEN 此次操作应被拒绝（拖了没效果），并给淡出提示；违反场景框原则的操作同样被拒绝并给出违反原则的提示。
9. 高光点：创建一个或多个场景框构成一个场景后，取「最大距离矩形中心」创建一个高光点——可用它拖出直线；单点高光点可设置该场景属性（大 / 中 / 小档位）。

### 要求 6：过渡窗口独立拖拽

**用户故事**：作为创作者，我想把过渡窗口当作不吸附到节点的独立组件，拖到任意位置、一旦经过某条线就成为该线的过渡窗口，以便精确放置过渡场景。
**权威**：`01` §八图元——过渡窗口「不吸附到节点，独立拖到任意位置；一旦经过一条线即成为该线过渡窗口」；`MapEdge.transitionWindow` / `TransitionWindowPoints.control`。

1. 过渡窗口应渲染为非节点悬浮组件（贴图可不同、效果可不同）。
2. 过渡窗口**不吸附到任何节点**，WHEN 用户拖动它，THEN 它应独立移动到任意位置。
3. WHEN 被拖动的过渡窗口经过（覆盖 / 接触）一条线，THEN 它应成为该线的过渡窗口：`control` 落在 `MapEdge.transitionWindow.control`，作为该样条线过渡点（切分场景，不自我创造）。
4. 过渡窗口应支持选中、拖动、Delete 删除；其颜色走「素材库组件」语义，不发明新色。

### 要求 7：遮挡框 / 高地 / 洼地（旋转 + 落字段）

**用户故事**：作为创作者，我想用阴影选中、Delete、滚轮 10°/格旋转的方式编辑视觉 / 物理遮挡框与高地 / 洼地框，并把它们落进 MapEdge 的严格字段，以便 AI 读编码而非看图猜。
**权威**：`01` §八图元（视觉遮挡黄 / 物理遮挡红 / 高地深绿 / 洼地浅绿 + 阴影选中 + 滚轮旋转 10°）；`MapEdge.visualObstruction` / `physicalObstruction` / `semanticAnchor`；`ObstructionSpec`.

1. 视觉遮挡框应渲染为黄色半透明框；物理遮挡框应渲染为红色半透明框（醒目 + 不可通行），颜色即图元身份。
2. 高地框应渲染为深绿、洼地框浅绿；高地 / 洼地只做表现层阶梯式缩放微调，**没有任何落差逻辑**（`01` §八明确：无断层、无跳窗高差，与楼层无关）。保留逻辑锚点供玩法包未来挂功能。
3. 视觉遮挡的储存应落 `MapEdge.visualObstruction`（`ObstructionSpec`，shape 'box'，bounds 归一化）；物理遮挡落 `MapEdge.physicalObstruction`；高地 / 洼地落 `MapEdge.semanticAnchor`（'high' / 'low'）。
4. WHEN 用户对选中的遮挡 / 高地 / 洼地框滚动滚轮，THEN 该框应旋转 10°/格。
5. 遮挡框选中时整体阴影提起、Delete 整体删除；无法通过拖动角控制点改变框形状（涂鸦式交互要求 5.2）。

### 要求 8：取样

**用户故事**：作为创作者，我想用 `Alt+点击` 或 `I` 指着地图上已存在的东西说「再来一个这样的」，以便零注册表、零打标、零搜索地复制已有图元。
**权威**：`01` §九「取样」。

1. WHEN 用户按下 `I` 或按住 Alt 并点击，THEN 编辑器应进入取样动作（I 进入模式、松开即退；Alt+点击 取样后即退）。
2. WHERE 用户对着已配置好的场景框 / 放置取样，THEN 样本槽应指向该实例引用，点其他节点即套用。
3. 取样不应依赖注册表、打标或搜索（`01` §九：对「已有基础划分与拓扑的地图」是最优匹配）。

### 要求 9：校验反馈（摄像机飞跃 + 红脉冲）

**用户故事**：作为创作者，我想点击底栏诊断让摄像机飞到出问题的元素并红色脉冲，并明确「错误阻止发布、不阻止保存」，以便明确知道哪里坏了、怎么改。
**权威**：`01` §九「校验反馈」；`01` §九「错误不阻止保存，只阻止发布」；`docs/表现系统/01`「地图编辑器的诊断呈现」。

1. 编辑器底栏应显示问题计数（错误 / 警告分色），按 `severity` 分组（error / warning / info）。
2. WHEN 用户点击一条诊断，THEN 编辑器应让摄像机飞到出问题的元素（根据 `subject` 定位节点 / 连接 / 放置），并对该元素施加**红色脉冲**（error）或黄色边缘闪烁（warning）。
3. 编辑器应展示 `correction`（面向创作者的改法）作为右侧悬浮提示。
4. error 级诊断应阻止发布（导出），但**从不阻止保存**（半成品地图必须能存盘）。
5. 每次改动地图应即时运行无 IO 结构校验 `validateMapStructure` 并展示诊断（诊断是列表、稳定排序、无自动 correction）。

### 要求 10：视觉语言零新增与设计令牌

**用户故事**：作为架构维护者，我想让编辑器状态直接映射霓虹边交互语法、不发明新颜色，以便创作者在编辑器学的颜色含义进游戏直接通用。
**权威**：`01` §九「视觉语言零新增」；`工程治理/02` 第四章「design-tokens 唯一美学真相源」禁止裸色值。

1. 编辑器状态的颜色映射应固定为：**白 = 悬停可选（可交互）、黄 = 已选中、红 = 校验错误、蓝 = 拖拽合法落点**。
2. 编辑器所有颜色应取自 `src/design/tokens.ts`（美学真相源）注入的语义色变量，代码中禁止出现 tokens 之外的裸色值。
3. `tokens.ts` 不应因编辑器新增而增长（复用既有的 damage / alert / stamina / social 等语义色）。

### 要求 11：撤销 / 重做（必要，不可延后）

**用户故事**：作为创作者，我想对一切破坏性交互做撤销 / 重做，以便每个删除、移动、拉弯、拉直都可安全回退，无需弹确认框。
**权威**：`01` §九「必要 vs 延后」——撤销 / 重做在必要列且不可延后，它是让所有破坏性交互变安全的前提。

1. 编辑器应提供撤销（`Ctrl+Z`）与重做（`Ctrl+Shift+Z` / `Ctrl+Y`）的全部界面与快捷键入口。
2. 每次破坏性修改（建 / 删 / 移动 / 拉弯 / 拉直 / 加遮挡 / 旋转 / 拖过渡窗口 / 放置 / 撤销红闪丢弃等）入栈一个可撤销单元；撤销与重做应保持"栈式、最近优先"的语义。
3. 撤销 / 重做不应改变已发布的结构校验结论（撤销后重新即时校验，诊断随当前状态刷新）。

### 要求 12：双分层坐标系

**用户故事**：作为架构维护者，我想让编辑器在「人性化涂鸦层（人怎么画）」与「逻辑层严格声明（AI 怎么读）」之间翻译，储存只存逻辑层语义，以便人分层编码的视觉操作被 AI 读编码而非看图猜。
**权威**：`01` §八「图元穷举」开场白（双分层坐标）、`01` §九「地图编辑器作为人机协作桥梁」（D-072）、`docs/创作系统/02_地图生产管线`（几何与拓扑分离）。

1. 编辑交互应在「人性化涂鸦」（拖框、划线、放窗口、定锚点）与「逻辑层严格声明」（`MapData` 的字段）之间翻译。
2. 储存只应有逻辑层语义：编辑器的拖框 / 划线 / 放窗口在落盘时必须翻译为 `MapData` 严格字段；人层只在视觉上镀层，不做逻辑承载。
3. 编辑器维持双分层坐标：抽象场景框层与内部几何坐标层，二者可切换编辑与查看（沿用 `01` §九「双分层坐标」）。

## 明确不做（non-goals）

- **`src/play/map/**` 契约源码的修改**（校验 / 编译 / curve / types 只 import 消费；任何契约缺口以交接口记录，不越权改）。
- 正式素材库的玩法侧功能（详情 / 库内改素材 / LLM 生成素材）。
- 素材库元状态层（拥有量 / 改动标记 / 角标状态机）。
- 全屏粒子 / 曲线等运行时表现动画（开发板渲染走 SVG，图片须存在并显示）。
- **多选批量改**（`01` §九「必要 vs 延后」——好用，非必要）。
- **全局注册表搜索**（`01` §九——采样 + 类型约束已覆盖）。
- **跨地图复制粘贴**（`01` §九——需 ID 重映射 + 产权检查）。
- **网格吸附**（`01` §九——post-MVP 拓扑）。
- **对齐辅助线**（`01` §九——纯效率）。
- 服务端 / 网络同步 / 多人协作 / 云端持久化。
- 任何引擎原语 / 新 Op / 新 Ref 前缀 / 新 Def kind。
