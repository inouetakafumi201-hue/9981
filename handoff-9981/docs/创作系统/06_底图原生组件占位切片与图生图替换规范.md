# 底图原生组件占位切片与图生图替换规范 (Crop-to-Sprite)

> **版本**：v1.0  
> **定位**：全项目解决“手绘/矢量底图上不规则原生组件（斜门、转角设施、异形通道）如何无割裂实现像素动态交互”的唯一权威流程规范。

---

## 一、核心设计哲学与洞察

### 1.1 坚持「场景作为纯底图」第一原则
- **禁止打碎底图**：底图（Backdrop）始终作为一张完整无瑕、统一绘制的背景画作，严禁在运行时对底图进行复杂的 SVG 矢量拆解、动态布尔运算或实时路径抠图。
- **退缩与专一法则**：只有**像素组件（Pixel Sprites）**承担动态交互、状态流转与动画表现。

### 1.2 破除「角度与透视适配」死锁
- **痛点**：底图上的原生组件形态各异——例如 37°/45° 倾斜的木板封门、弧形地铁闸机、异形书架、转角配电箱。如果强行用标准正方体像素贴片拼接，会产生严重的角度错位与透视割裂；如果让画师或 AI 从零为每一个角度画全套状态图，管线将彻底失控。
- **顿悟与解法（底图母图化）**：
  底图中的原生组件本身就是最完美的透视与角度参考。**通过地图编辑器框选占位框并自动切片，以切片为母图进行「图生图（Img2Img）」**，直接继承 1:1 的几何包围盒、斜率与光影，生成精准贴合的像素组件，并在运行时覆写回填。

## 二、标准四步闭环工序

```text
┌────────────────────────────────────────────────────────────────────────┐
│             底图原生组件「切片 - 图生图 - 覆写」标准工序 (Crop-to-Sprite)     │
├────────────────────────────────────────────────────────────────────────┤
│ 步骤 1: 策划轻量标定与编辑器导出                                        │
│   • 策划在底图上拉出【过渡场景框】或【素材占位框】，命名如 door_subway_45 │
│   • 编辑器一键导出: MapData.json + 整张底图 + crops/door_subway_45.png │
├────────────────────────────────────────────────────────────────────────┤
│ 步骤 2: AI 自主玩法设计 (Gameplay & State Planning)                   │
│   • AI 结合占位框命名、地图全局语义，设计玩法机制 (AP/技能检定/钥匙)     │
│   • 规划状态序列帧: [closed, breached, open]                           │
├────────────────────────────────────────────────────────────────────────┤
│ 步骤 3: 链式图生图与确定性后处理 (Chained Img2Img & Post-process)      │
│   • Frame 0: 以 crops/door_subway_45.png 为母图生成 1:1 像素基准帧     │
│   • Frame 1..N: 以 Frame 0 为母图，顺序派生破坏/开启状态序列帧          │
│   • 本地确定性后处理 (纯化、网格像素化、QC、生成 manifest.v2)           │
├────────────────────────────────────────────────────────────────────────┤
│ 步骤 4: 回填绑定与运行时无缝过门 (Binding & Runtime Replacement)        │
│   • AI 将生成素材 ID 绑定回 MapData 占位框，完成替换                    │
│   • 运行时在底图原坐标 1:1 叠加该组件；过门时播放开门帧并在瞬间瞬移角色 │
└────────────────────────────────────────────────────────────────────────┘
```

## 三、逐步骤详细实施规范

### 3.1 步骤一：地图编辑器中的占位框创作与切片导出

1. **占位框类型**：
   - **过渡场景框（Placeholder Transition Box）**：用于门、闸机、楼梯、管道口等具有拓扑连通意义的通道物件。
   - **素材占位框（Placeholder Asset Box）**：用于配电箱、电视机、固定书架、售货机等纯交互设施。
2. **操作方式**：
   - 策划使用矩形选区工具，直接在底图上框住目标原生组件。
   - 为该框命名有意义的语义 ID（如 `door_slanted_wood_01`、`tv_wall_mount_02`）。
   - 正常进行连线（Edge）和图逻辑初步创作。
3. **编辑器导出包结构**：
   ```text
   export_map_package/
   ├── map_data.preliminary.json   # 包含 placeholderBoxes 定义的地图元数据
   ├── backdrop.png                # 完整底图
   └── crops/                      # 自动根据每个占位框裁切的 PNG 图片
       ├── door_slanted_wood_01.png
       └── tv_wall_mount_02.png
   ```

### 3.2 步骤二：AI 玩法设计与机制定义

当 AI 接手 `export_map_package` 时，处于全权玩法设计阶段：
1. **语义解析**：根据占位框名称（如 `door_slanted_wood_01`）、所在房间节点（如 `room_library`）推导功能定位。
2. **规则制定**：
   - 决定交互类型（如：过渡场景 / 搜刮容器 / 可破坏障碍 / 电力开关）。
   - 确定资源消耗与检定规则（如：需要撬棍、消耗 2 AP、力量检定 DC 12）。
3. **状态序列规划**：
   - 确定该组件必须包含的状态列表（如 `states: ["closed", "cracked", "breached"]`）。

### 3.3 步骤三：链式图生图（Img2Img Chaining）与后处理

1. **第一张像素贴图（Frame 0 - 基准帧）**：
   - **输入母图**：`crops/<placeholder_id>.png`。
   - **生成目标**：生成与原切片 100% 几何重合、同角度、同光影的硬边像素艺术图。
   - **Prompt 侧重**：强调保持母图轮廓与角度（`exact perspective, contour and orientation from reference`），品红 `#FF00FF` 背景。
2. **后续状态序列帧（Frame 1..N）**：
   - **输入母图**：使用 **Frame 0**（或前一状态帧）作为图生图参考。
   - **生成目标**：在保持 Frame 0 锚点、外框边界与主要残留结构不变的前提下，表现形态改变（如门板裂开、门扇旋转 90 度打开、屏幕碎裂点亮）。
3. **后处理执行**：
   - 统一走本地 `asset:v0 finalize` 处理：品红纯化、去杂色、Alpha 二值化、色彩量化。
   - 产出符合 `manifest.v2.json` 契约的标准资产包。

### 3.4 步骤四：回填替换与运行时表现

1. **MapData 回填**：
   - AI 将占位框定义转为正式的 `PrefabDef` / `TransitionDef`，写入 `spriteRef: "asset_manifest_id"`。
   - 占位状态解除，地图包转为合法的 `MapData.json`。
2. **运行时渲染与无缝过门**：
   - **常态（静态叠加）**：引擎在底图的 `[bounds.x, bounds.y]` 处 1:1 渲染 Frame 0。由于 Frame 0 与底图切片完全重合，玩家肉眼察觉不到任何接缝。
   - **交互过门（动态流转）**：
     1. 玩家下达过门指令（扣除 AP/道具）。
     2. 组件播放 `closed → opening → open` 序列帧（2~3 帧微动效）。
     3. 在门完全开通的帧瞬间，角色执行微位移/瞬移至目标房间节点。
     4. 门保持 `open` 帧（遮盖掉底图原画的闭合门板）。
     5. 全程视觉连贯，无穿墙感、无透视撕裂。

## 四、核心价值与防呆规则

1. **无需改动底层渲染器**：不需要为斜门开发复杂的 SVG 遮罩变换或 3D 投影渲染器。
2. **AI 设计心智闭环**：AI 在设计玩法机制的同时，自动完成了特定角度素材的定制化生成，使关卡具备极高的手工定制质感。
3. **零空帧与零错位防线**：
   - 必须严格保证切片图片坐标尺寸与 MapData bounds 整数对齐（Snap to Int）。
   - 图生图后处理必须使用最近邻等比缩放至 bounds 指定的像素分辨率，严禁改变原始长宽比。
