# 底图原生组件占位切片与图生图管线深化设计与改造方案

## 1. 核心定位与设计目标

本项目场景统一使用手绘/矢量全景底图（Backdrop）。对于场景内天然存在的门、闸机、挂墙变电箱、落地设施等原生组件，若强行在底图上手画矢量多态或直接贴通用像素块，会导致严重的透视失真与接缝割裂。

本方案确立**「底图局部母图化（Crop-to-Sprite）闭环」**：
1. **人工标定**：策划在地图编辑器中对需要交互的原生组件框选【占位框】（Bounding Box）。
2. **切片导出**：编辑器一键导出 `MapData.json`、完整底图及对应切片包 `crops/*.png`。
3. **AI 图生图**：AI 接手后自主设计玩法语义与多态，以切片为母图生成 1:1 像素基准图（Frame 0）及后续状态帧（Frame 1..N）。
4. **管线后处理**：经由确定性后处理生成 `manifest.v2.json`。
5. **回填覆写**：AI 将生成的素材 ID 回填至地图占位框并替换，在游戏运行时 1:1 精确覆盖并在过门瞬间瞬移角色，彻底杜绝割裂。

## 3. 面向执行的分步技术设计

### 3.1 地图契约层扩展 (`src/play/map/types.ts`)

在 `MapData` / `CanonicalMapData` 中增加 `placeholderBoxes` 字段：

```typescript
export interface MapPlaceholderBox {
  readonly id: string;             // 语义标识符，如 door_subway_45、breaker_box_01
  readonly type: 'transition' | 'asset'; // 过渡场景框（门/通道）或独立组件框
  readonly bounds: {
    readonly x: number;            // 归一化坐标 [0, 1]
    readonly y: number;
    readonly width: number;
    readonly height: number;
  };
  readonly connectedEdgeId?: string; // 若为 transition，关联的地图边 id
  readonly hostNodeId?: string;      // 若为 asset，绑定的节点 id
  readonly sourceCrop?: string;      // 导出的切片相对路径，如 crops/door_subway_45.png
  readonly spriteRef?: string;       // AI 图生图完成后的替换素材 id（如 d:item/door_subway_45）
}
```

### 3.2 校验器与编译器行为 (`validate.ts` & `compile.ts`)

- **校验器 (`validateMapStructure`)**：
  - 检查 `placeholderBoxes` 坐标是否全在 `[0, 1]` 内，宽高严格大于 0。
  - `id` 唯一且符合命名规范。
  - `transition` 类型的 `connectedEdgeId` 必须存在于 `edges` 中。
  - 诊断分级：未绑定 `spriteRef` 时为 `warning`（允许草稿期保存与导出），不阻塞编译。
- **编译器 (`compileMap`)**：
  - 编译时将已绑定 `spriteRef` 的占位框挂载为 `PrefabDef.entities`，或者透传给运行时地图渲染器作为静态覆盖图层。

### 3.3 素材生成管线扩充 (`asset-pipeline-v2.py`)

在 `prepare` 命令中增加 `--reference-crop` 参数：

```bash
python .agents/skills/sprite-forge/tools/asset-pipeline-v2.py prepare \
  --lane component \
  --id door-subway-45 \
  --type environment \
  --desc "angled subway security gate in wall" \
  --states closed,cracked,open \
  --reference-crop run/sample-map/crops/door_subway_45.png \
  --out run/v0-assets/door-subway-45
```

- **Prompt 构造增强**：
  - 检测到 `reference-crop` 时，提示词自动注入母图约束：`"Derive strictly from the supplied reference crop. Frame 0 must match the exact 1:1 angle, bounding box aspect ratio, slope and lighting of the source crop. Subsequent frames derive sequentially for states: closed, cracked, open."`
  - `job.v2.json` 记录 `references: [cropPath]`。

### 3.4 地图编辑器导出工作流（Node/Canvas 脚本层）

当策划在编辑器点击「校验并导出」：
1. **Canvas 截取**：读取底图 Image 资源，根据每个 `placeholderBox` 的 `(x * pixelWidth, y * pixelHeight, width * pixelWidth, height * pixelHeight)` 进行 `ctx.drawImage` 局部像素拷贝。
2. **输出打包**：
   ```text
   output_dir/
   ├── MapData.json
   ├── backdrop.png
   └── crops/
       ├── door_subway_45.png
       └── breaker_box_01.png
   ```

### 3.5 运行时无缝覆写与角色瞬移逻辑

1. **静态渲染**：
   - 地图加载时，若占位框已有 `spriteRef`，以该占位框的 `bounds` 为绘制目标，将 `Frame 0` 1:1 绘制在底图对应位置上方。
2. **过渡触发（过门）**：
   - 角色点击门交互点（消耗对应 AP）。
   - 占位组件触发状态切换动画（播放 `Frame 0 -> Frame 1 -> Frame 2` 开门/破损序列）。
   - 动画播放至开门关键帧（约 0.15s），引擎触发瞬移指令将角色定位至目标节点。
   - 视觉上底图的实心门被开启状态的像素帧完全遮盖，角色顺畅穿过，毫无穿模割裂。
