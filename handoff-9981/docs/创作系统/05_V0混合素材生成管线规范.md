# V0 混合素材生成管线规范 v2

> 本文是可见素材生产的唯一流程事实源。地图数据契约仍由 `asset-pipeline` 管理。

## 分类与泳道边界

静态组件严格只有 8 类：`weapon-melee`、`weapon-ranged`、`weapon-firearm`、`item-consumable`、`item-tool`、`item-equipment`、`device`、`environment`。机器事实源为 `.agents/skills/sprite-forge/catalogs/component-types.v2.json`，文档与代码不得复制另一套枚举。

生产泳道分工：
1. `component`：上述八类静态组件（由本管线生成）。包含标准自由摆件与由「底图占位框切片」派生的定制原生组件（详见 `06_底图原生组件占位切片与图生图替换规范.md`）。
2. `character`：AI/NPC 角色。**不重新生成**，直接从现有精灵图成品库（`run/精灵图管线/1-成品/` 或 NPC 目录）按文件夹名挑选复用；角色 16 帧管线的后处理逻辑高度学习并复用于组件后处理（组件无需 4×4 切割）。
3. `symbol`：词条与抽象 UI 符号。使用全项目唯一的 304 个 game-icons SVG 语义库，禁止 V0 重绘。
4. **地图底图明确不纳入本轮生成管线**。

## 视角规范（分流铁律）

- **物品类序列帧**（`item-consumable` / `item-tool` / `item-equipment`）：采用 **`front view`**（眼平直接正交正视图，强调物品清晰剪影与细节，无俯仰角度、无三维倾斜深度、无侧立面、无透视消失点）。
- **其余静态组件**（武器类、`device`、`environment`）：暴力锁定为 **`front-top axonometric view`**（正面高位斜测轴：顶部与前部可见，侧部与后部隐藏）。
- 禁止把纯顶视平面、侧视、三面等距立方体、透视消失点作为现行规则。

## 像素后处理三步闭环

后处理严格继承角色管线经验，分为确定性三步：
1. **背景纯化**：将接近品红的边缘与背景像素归一为纯 `#FF00FF`。
2. **去杂色与 Alpha 二值化**：消除边缘毛边杂色，半透明过渡二值化，杜绝 AI 伪像素毛刺。
3. **像素量化与网格对齐**：量化色彩区间，并按最近邻对齐到目标像素网格，保留硬边高对比度。

## 批量生成硬前置门禁

在进行任何批次素材生成之前，必须满足以下硬前置流程：
1. **玩法层与机制规划完全冻结**：确定该批次素材对应的所有玩法交互、规则、状态与数值逻辑。
2. **无头基于属性测试与海量用例验证通过**：通过自动化测试、无头模拟与属性断言，证明底层逻辑完全稳固，无任何规则漏洞。
3. **批量生成与挂载链路**：稳固后方可按批次生成 raw 图，经本地确定性后处理、人工抽验确认后，完成资产挂载。

## V0 接缝

V0 GenerateImage 是 Agent 工具，不存在仓库内可调用的 V0 HTTP provider。标准闭环是：

1. `prepare` 生成 `job.v2.json`，其中含完整 prompt、参考图、raw 目标路径和后处理参数。
2. Agent 读取 job，用 V0 GenerateImage 将 PNG 写到 `rawTarget`。
3. `finalize` 校验 PNG、纯化品红、检测并切格、像素化、执行 QC、计算 SHA-256，再写 `manifest.v2.json`。
4. `registry` 只聚合 schema 合法、`qc.status=passed` 且 `status=ready` 的 manifest。

任何缺图、损坏 PNG、状态数不符、空帧、路径逃逸或 checksum 异常都必须失败。失败保留 raw 和诊断，不进入 registry；重跑默认幂等，覆盖必须显式 `--force`。

## 契约与状态

- Job：`.agents/skills/sprite-forge/schemas/job.v2.schema.json`
- Manifest：`.agents/skills/sprite-forge/schemas/manifest.v2.schema.json`
- Job 状态：`awaiting-generation → raw-ready → complete|failed`
- 成品状态：自动 QC 后为 `pending-human-review`；人工视觉确认后才能改为 `ready` 并进入 ship registry。
- provenance 必须记录 job、V0 GenerateImage 和生成时间；manifest 中每个成品文件必须有 SHA-256。

## symbol 规则

先查询 `.agents/skills/sprite-forge/icon-semantics/icon-index.json`；符号语义由 catalog 决定，品级颜色只由 `token-icon-beautify.ts` 决定。找不到接近语义时先由项目所有者批准入表，禁止临时造名或引用 `src/px-game-icons`。

## Ship 条件

Schema、自动 QC、checksum、语义库审计、文档门禁全部通过只是技术合格。真实生成资产仍须人工检查轮廓、视角、状态可读性与版权来源，确认后才可进入产品目录。
