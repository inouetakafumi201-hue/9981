## 一、起点：全绿的 28 万次随机运行没有发现任何缺陷

重建前的报告写着"18/18 测试通过，0 失败……未发现需要修复的实现缺陷"。
这个结论是真的——那 18 项确实全绿。问题在于它们**看不见**下面这些事。

第一类是**恒真断言**。原套件的招牌用例：

```ts
// Property: replay确定性回放
const a = replay(seed, ops);
const b = replay(seed, ops);
expect(a).toEqual(b);
```

对任何确定性、无副作用的函数恒真。它不检验回放是否正确，只检验是否可重复——
而"完全不回放、直接返回 seed"同样可重复。

第二类更隐蔽：**生成器把缺陷排除在样本空间之外**。同一文件的"快照隔离"属性
生成的 Op 全是 `{...s}` 纯拷贝：

```ts
const op = { id, apply: (s) => ({ ...s, props: { ...s.props, k: v } }) };
```

纯 Op 永远不会原地写 seed，于是"replay 会不会改坏调用方的 seed"这件事
**在这个样本空间里根本不可能发生**。断言写了，但它不可能失败。
这就是 BUG L12#9 藏身之处：`replay` 直接以 `seed` 起步而不克隆，
遇到一个原地写的 Op 就会改掉调用方的状态，且第二次调用结果不同——
回放的全部意义（同一 seed + 同一日志 ⇒ 同一状态）静默失效。
补一个 `impureAddProp` Op 之后，这个缺陷第 1 步就暴露。

**结论：断言的形状比断言的数量重要，生成器的覆盖比 numRuns 重要。**
28 万次运行乘以一个到不了缺陷的生成器，仍然是 0。

## 二、重建的四件套

沿用 L4/L7 已验证的方法，全部**增量添加**，不改动既有文件：

| 文件 | 项数 | 作用 |
|------|------|------|
| `test/l12-property.test.ts` | 18 | **原有文件，未改动**，仍全绿 |
| `test/l12-shadow.test.ts` | 18 | 影子模型：独立算术判据 + DFS 穷举路径 + effect 执行痕迹 |
| `test/l12-invariant-checker.test.ts` | 37 | 损坏注入：证明四个 `checkInvariants` 不是空壳 |
| `test/l12-regression.test.ts` | 20 | 钉住 BUG L12#1 ~ #9 |
| `test/l12-mutation-gap.test.ts` | 27 | 钉住随机搜索**结构上到不了**的点 |

配套的可观测面（`src/persistence.ts` 增量添加，不改变既有语义）：

- `checkWorldState(s, where)` —— 返回违规**列表**而非抛错。抛错只能报告第一条，
  注入多重损坏时无法区分"检查器查到一条就跑了"与"检查器只认得一条"。
- `SnapshotStore` / `Journal` / `CheckpointStore` / `PhaseBoundaryLog` 各自的
  `checkInvariants(): string[]`。
- `VERSION_PATTERN` / `isWellFormedVersion` —— 由持久化层统一提供，
  `migration.ts` 顶部转出。两处各写一份正则会静默漂移出互相矛盾的结论。

几条关键的方法论决定：

- **影子模型必须用不同算法。** 产品的 `findMigrationChain` 用 BFS 求最短链；
  判据用 DFS 穷举所有简单路径再取长度下界。若判据也用 BFS，
  "链最短"就退化成"产品等于产品"。
- **判据必须能看见执行痕迹。** `findMigrationChain` 是私有函数，
  且多条链常常抵达同一最终状态。给每个 `MigrationEffect` 挂一个 sink，
  "走了哪条链""跳过了哪一跳"才成为可观测事件。
- **ID 池刻意极小且互相重叠。** 版本池只有四个值，且 from/to/current 共用同一池。
  两池不相交时菱形与等长多路径永不出现，链选择相关的分支永远得不到表决机会。

## 三、发现的产品缺陷：9 个

每一个都由实际运行确认，不是读代码推断出来的。

| 编号 | 缺陷 | 后果 |
|------|------|------|
| L12#1 | `takeSnapshot` 未深拷贝 | 快照与活状态共享 `props`，"快照"随后续修改而变 |
| L12#2 | `CheckpointStore.checkpoint` 未克隆入参 | 存入后改活状态，检查点被一起改掉 |
| L12#3 | `CheckpointStore.restore` 未克隆出参 | 调用方改返回值，回写进检查点 |
| L12#4 | `PhaseBoundaryLog.markBoundary`/`rewind` 未克隆 | 相位边界历史可被事后篡改 |
| L12#5 | 同版本装载返回入参引用 | 调用方改返回状态 = 改存档 |
| L12#6 | bestEffort 跳过时不留诊断 | 静默返回 `ok:true`，调用方不知装载了残缺存档 |
| L12#7 | 畸形版本号被静默折成 `0.0.0` | `compareVersions("abc","0.0.0") === 0`，存档乱码被当成"最古老的合法版本"而触发迁移 |
| L12#8 | 链跑完未达目标版本仍报 `ok:true` | 虚假成功：状态被标记为新版本却缺少变换 |
| L12#9 | `replay` 不克隆 seed | 不纯 Op 下改坏调用方状态，且两次调用结果不同 |

关于 L12#7 的设计决定值得记录：修法**不是**让 `compareVersions` 抛错。
比较器抛错会破坏它自己的全序契约（调用方无法再安全地用它排序）。
正确的位置是在比较**之前**做一次独立的前置校验，
畸形版本号返回专属诊断码 `E_MIG_BAD_VERSION`。
`compareVersions("abc","0.0.0") === 0` 这个事实被保留了下来——
它正是前置校验必须存在的理由，故在回归测试里被钉住而非被"修掉"。

## 四、变异测试：全绿之后才是真正的开始

四件套全绿之后，注入 91 个变异体，逐个跑全套测试。第一轮结果：

```
计分变异体：85  杀死：77  存活：10  变异得分：88.51%
```

存活的 10 个不是噪声，是**测试盲区的证据**。三类：

**(a) 真等价** —— M27（`Number.isFinite` 不做隐式转换，`typeof` 前置判断冗余）、
M34（`trim(0)` 落入 `slice(len - 0)` = `slice(len)` = `[]`）、
M35（`len >= max` 时 `slice(0)` 是整份副本）。标注 `expectEquivalent`，
但标注不算证明，见第五节。

**(b) 观测面缺口** —— M36（`clear()` 不重置发号器）、M44（`list()` 交出内部数组）。
两者共同的形状：**只读不改的断言看不见它们**。
空数组这件事，"重置了 seq"与"没重置 seq"都满足，差异只在下一次 `append` 发什么号；
交出内部数组与交出副本，读起来一模一样，差异只在调用方改了返回值之后。

**(c) 自指判据** —— M88/M89/M90（三对诊断码互相撞车）。这一条最值得记，见第六节。

补上 27 项针对性用例后：

```
变异体总数：91
无效（find 未唯一命中）：0
计分变异体：85  杀死：85  存活：0
预期等价（存活为正确）：6
变异得分：100.00%
```

## 五、等价变异体：存活也要给出证据

标注 `expectEquivalent` 等于宣称"这个改动不可观测"。宣称不是证明。
差分模糊器 `mutation/equivalence.ts` 对每个目标跑 3,000 步，
把 ok / 诊断码序列 / 状态各字段 / effect 执行序列 / 自检违规全部拼成一行文本比对。

### 差分模糊器自己必须先过自检

"跑了 3,000 步没有反例"有两种成因：真等价，或**模糊器根本没走到变异点**。
二者在输出上完全一样。所以第一阶段先注入 17 个**已知不等价**的哨兵，
全部被抓到才说明这个模糊器有分辨力。哨兵必须取自与目标**同一段代码**——
"抓到了别处"不能证明"这里看得见"。

自检确实抓出了四个模糊器盲区（详见第六节），修好后：

```
自检通过：17/17 全部被发现。
结论：6/6 个目标在 3000 步内无可观测差异。
```

被证等价的六个：M27、M34、M35、M59（段数取 min 而非 max）、
M60（`parseInt` 去掉 `|| 0` 兜底）、M81（命中判定移到 `visited` 之后）。

## 六、本轮新增的四种空转形态

前几层已经记录过四种：`fc.uuid()` 永不碰撞、恒真断言、身份不唯一、ID 池不相交。
本轮又撞见四种，都是**靠运行发现的，不是靠读代码想出来的**。

### 6.1 自指判据（self-referential oracle）

M88/M89/M90 把三对诊断码改成同一个值，测试全绿。原因不是漏了断言，
而是断言的**判据来自被测对象自己**：

```ts
import { MIG_CODES } from '../src/migration.js';
expect(codes).toEqual([MIG_CODES.SKIPPED, MIG_CODES.FAILED]);
```

改常量时产品的输出和测试的期望**一起**变，差异恒不可见。
这与恒真断言同属一类：断言存在，但它不可能失败。

破法两条，缺一不可：
1. 字面量钉死取值——判据必须来自代码之外；
2. 断言两两互不相同——每种失败模式必须能被区分，
   否则测试只能说"失败了"，说不出"为何失败"，删掉任一前置守卫都测不出来。

### 6.2 去牙变异体（neutered mutant）

M83 本意是"删掉环保护"。我第一版写成把 `visited` 换成 `if (path.length > 8) continue;`——
**长度上限自己就恢复了终止性**，于是变异体与原实现行为等价，它的存活证明不了任何盲区。

判据：**替换物不得偶然重建被删掉的安全性质。**
改成彻底删除环保护后，环图上队列无界增长，超时即击杀——
"跑不完"与"跑出错"对契约而言同样是违约。

### 6.3 顺序依赖的模块态造成假"不等价"

差分模糊器第一次跑，6 个目标全部报"第 1 步就不等价"，
差异字段是 `global=snap:18` 对 `snap:1`：`takeSnapshot` 用的是**模块级**发号器，
它跨步累积。基线模块在哨兵阶段已经吃掉 17 个号，变异体模块是新导入的、从 1 起。

判定不是来自变异，而是来自观测顺序。**假"不等价"与假"等价"同样是错结论。**
修法是每步先 `resetSnapshotCounter()`：差分比较必须两侧同起点。

修好这一条之后，此前被这个噪声掩盖的四个真盲区才浮出水面
（M64、M79、M80 因为"装载成功"这条主路径几乎不可达而漏检；
M25 因为 `props` 永远是对象而漏检）。
**噪声不只是噪声，它会掩盖信号。**

### 6.4 区分性断言本身也要被验证

M82 是"BFS 换成 DFS"。我为它写了三条确定性菱形用例，全绿。
但把 M82 手动打上去再跑——**三条全过**。

方向搞反了：栈弹出的是**最后入队**的边，入队顺序即声明顺序。
要让 DFS 走上长路，直达边必须**先**声明；我写成了"长路先声明",
那种拓扑下 DFS 恰好也弹到直达边，两者答案相同。三条用例都是恒真断言。

真正杀死 M82 的是影子模型的随机图属性，在第 135 次随机才命中——
一个概率事件，随时可能在 200 runs 的变异跑里漏掉。

**结论：区分性断言必须用"已知会违约的实现"验过一遍。
"断言通过"只说明它没失败，不说明它能失败。**
修正后，三条用例中的三条在 M82 下失败（第四条按设计钉的是反方向）。
