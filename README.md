## 🎯 项目概述

《起床》是一个基于极简离散系统的策略游戏引擎，核心特点：

- **数值≤5约束**：所有玩家可见数值严格限制在1-5
- **五并列原则**：任何选择不超过5个选项
- **自然语言UGC**：通过LLM将创意转化为游戏规则
- **完全信息对称**：无隐藏属性，纯策略博弈

## 📁 架构与文档

项目采用**严格三层规则链 + 五个正交架构域**的设计：

### 三层规则运行链

```
引擎层（Kernel） → 基类层（Class） → 玩法层（Play） → 已装载对局
```

- **引擎层**：无游戏语义的原语（Entity、Op、Query、Hook、随机流）
- **基类层**：可枚举、可组合的基类与实例（武器类、谱型、状态、网关...）
- **玩法层**：可复用的玩法定义集合（ActionDef、RuleDef、ScheduleDef、PhaseDef、OutcomeDef、PolicyDef、DecisionDef 等）；地图数据和地图表现资产属于独立内容类型，由玩法文件或地图玩法文件引用。

### 五个正交架构域

不是规则链的后继层，但与三层协作：

- **表现系统**：UI、动画、音效、无障碍（读取语义投影，提交意图）
- **创作系统**：编辑器、工作台、地图生产、发布（生成候选，经统一校验）
- **运营系统**：会话装载、匹配、长期推进（并列装载玩法层/玩法文件、地图包、表现 Profile 与叙事包；“玩法包”仅作为内容集合或传输泛称）
- **工程治理**：路线图、技术栈、测试策略（约束开发过程）
- **叙事设定**：世界观、角色、地点（通过稳定ID被玩法包引用）

## 💡 核心创新

### 1. 数值≤5约束
防止数值膨胀，逼迫创作者用机制组合而非堆数字来实现创意

```
❌ 错误："造成999伤害的核弹"
✅ 正确："造成3伤害 + 辐射状态(每回合1伤害，持续5回合) + 影响相邻节点"
```

### 2. 五并列原则
严格限制每个节点的连接数和选项数量，保持可推演性

```
微型场景：最多3个连接
中型场景：最多4个连接
大型场景：最多5个连接
```

### 3. 自然语言UGC
通过LLM降低创作门槛到零

```
玩家："我想做一个香蕉皮，踩到会摔倒"
  ↓
LLM理解并追问边界
  ↓
生成JSON规则
  ↓
自动验证和测试
  ↓
注入游戏，AI自动适配
```

## 🎮 游戏特色

- ✨ **完全信息对称**：无隐藏数值，无手牌，无迷雾
- ✨ **回合制策略**：像下棋一样推演和计算
- ✨ **零费动作智能**：不产生搜索分支的0 AP操作
- ✨ **通用AI**：自动适配所有UGC内容
- ✨ **极简美术**：2D扁平风格，UGC友好

## 🛠️ 技术栈

- **前端**：TypeScript + React + Canvas 2D
- **后端**：Node.js + WebSocket + PostgreSQL
- **AI/LLM**：OpenAI API / Claude API
- **部署**：云服务 + CDN
