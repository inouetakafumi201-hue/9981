## 📚 架构概览

### 三层规则运行链

```
引擎层（Kernel）
  ├─ Entity、Component、Relation、Op、Expr、Hook、随机流
  ├─ 不知道"武器"、"技能"是什么
  ├─ 只知道：实体、状态、关系、动作、规则
  └─ 铁律：底层设计完成后可自我迭代，不影响上层
        ↓ 基类层使用引擎层 Op/Query
基类层（Class）
  ├─ 武器类、谱型类、伤害类、状态类、物品类、防具类、载具类...
  ├─ NPC 行为类、网关类、移动模式...
  └─ 铁律：实例不含玩法数值，不含具体玩法规则
        ↓ 玩法层组合基类层实例
玩法层（Play）
  ├─ 大逃杀规则、夺旗规则
  ├─ 具体数值配置（霰弹枪伤害=3、近战流派验证...）
  ├─ 玩法包定义
  └─ 铁律：可高频迭代，不影响引擎层和基类层
```

详见 [`00_架构域与文档分类.md`](./00_架构域与文档分类.md)

### 五个正交域

不是规则链的第四层，而是消费三层端口或向三层提交候选数据：

| 域 | 职责 | 与三层的关系 |
|---|---|---|
| **表现系统** | UI、动画、音效、无障碍 | 读取语义投影，提交待校验意图 |
| **创作系统** | 编辑器、地图生产、发布 | 生成候选，经三层统一校验 |
| **运营系统** | 会话装载、匹配、长期推进 | 并列装载玩法包+表现+叙事 |
| **工程治理** | 路线图、技术栈、测试 | 约束开发过程，不进运行时 |
| **叙事设定** | 世界观、角色、地点 | 通过稳定ID被玩法包引用 |

## 🎯 快速理解

### 3句话概括项目
1. 将童年的"起床游戏"数字化为离散策略引擎
2. 用极简约束（数值≤5、五并列）保证深度和稳定性
3. 通过LLM降低UGC门槛，让任何人都能创作内容

### 核心创新点
- ✨ **数值≤5约束**：防止膨胀，逼迫维度拆解
- ✨ **五并列原则**：控制复杂度，保持可推演
- ✨ **自然语言UGC**：零编程门槛创作
- ✨ **通用AI适配**：自动理解所有UGC内容
- ✨ **完全信息对称**：无隐藏属性，纯策略博弈

### 目标用户
1. **策略游戏爱好者**：欣赏深度博弈
2. **UGC创作者**：想表达创意但不会编程
3. **桌游玩家**：喜欢回合制和战术规划
4. **怀旧玩家**：想重温童年游戏

## 📊 关键数据速查

### 数值约束
| 项目 | 范围 | 说明 |
|------|------|------|
| 生命值 | 1-5 | 标准5点 |
| 伤害 | 1-5 | 武器伤害 |
| AP成本 | 1-5 | 动作消耗 |
| 持续回合 | 1-5 | 状态持续 |
| 节点连接 | 1-5 | 拓扑限制 |

### 概率分布（3人局）
| 获得AP | 概率 | 说明 |
|--------|------|------|
| 3 AP | ~14% | 大胜（罕见爆发） |
| 2 AP | ~28% | 小胜/并列 |
| 1 AP | ~32% | 紧跟（最常见） |
| 0 AP | ~26% | 掉队（体力退回） |

### 槽位系统
- 左手 + 右手（可持单手或双手武器）
- 左口袋 + 右口袋（仅小型物品）
- 背包槽1 + 背包槽2（任意体积）
- **总计6槽**，符合五并列认知

### 场景类型
| 类型 | 最大连接 | 特点 |
|------|----------|------|
| 大场景 | 5 | 可出生，重装+1AP |
| 中场景 | 4 | 标准战场 |
| 微场景 | 3 | 直接交互，无缓冲 |
| 过渡 | 2 | 不可停留，纯连接 |

## 🔖 重要提醒

**设计原则三不变**：
1. ❌ 不能有超过5的玩家可见数值
2. ❌ 不能违反五并列原则
3. ❌ 不能增加不必要的状态

**开发原则三优先**：
1. ✅ 稳定性优先于功能丰富
2. ✅ 可扩展性优先于快速实现
3. ✅ 用户体验优先于技术炫技

**UGC原则三保证**：
1. ✅ 保证创作安全（永远不崩溃）
2. ✅ 保证创作简单（自然语言）
3. ✅ 保证创作有效（AI自动适配）
