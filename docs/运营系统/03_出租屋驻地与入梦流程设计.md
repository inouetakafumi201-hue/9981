## 一、定位与边界

本文档把讨论中定案的**现实侧驻地**落地为设计：玩家在现实地图（起点定为**出租屋**）里行动，床、匹配机、研究台、电脑、书架等实体承担入口职责。它把 `运营系统/01` §二「节点就是局外菜单」的抽象节点，落到一张可移动的出租屋实景里。

边界：

- 只定**驻地的物理流线与流程契约**（床怎么用、入梦怎么进、随时怎么退）。
- **不重复创作工具内部**：编辑器的实现守 `创作系统/01`；素材库/熟悉度守 `创作系统/02`。
- **不画线框**：租屋的美术、排布、动画帧由 `表现系统/01` 后续专题承担，本文只标「待细化」。
- **不复制世界观正文**：只说「这是入梦者的现实锚点」，引用 `role:dream-agent`；不重述梦境网络设定。

延续 `运营系统/01` §二的关键前提：

> 「公司」「庇护所」「出租屋」只是可能随单机进程变化的**叙事外观**，不是本框架冻结的唯一驻地名称。节点职责保持稳定，叙事承载物可以替换。

出租屋是本作的**次生形态/首发驻地**，职责与 01 §二节点表一一对应，不新增第二种菜单系统。

## 二、现实地图 = 主界面

玩家在一个可移动的出租屋拓扑中行动，各实体承担「运营节点」职责：

```text
出租屋（现实地图 = 主界面）
  ├─ 床A（蓝）   → 主线 + 竞技入口   （非 UGC，青不背它）
  ├─ 床B（珊瑚） → 联机副本入口
  ├─ 床C（青）   → 进入「自己建好的梦」= 体验沙箱（UGC，青）
  ├─ 匹配机     → 选模式 / 状态 / 规则准备 / 匹配
  ├─ 研究台     → 编辑节点（= 工作台的呈现名，见创作/01）
  ├─ 电脑       → 地图编辑器入口
  ├─ 书架       → 梦境素材库（元素 / 蓝本，创作资源，青）
  ├─ 保险箱     → 收藏室（高价值 / 纪念对象，"一眼是高价值物"）
  ├─ 门缝       → 世界气味（辅助叙事，不入口，纸条/传票/水电单，见运营/04）
  └─ 边缘氛围   → 视觉氛围、碎片化叙事载体
```

实体 → 节点职责映射（对齐 `运营系统/01` §二）：

| 出租屋实体 | 承担的 01 节点职责 |
|---|---|
| 床A / 床B / 床C | 主线出口、联机任务入口、自建梦入口（三者都是装载边界） |
| 匹配机 | 模式选择 + 异步匹配 + 规则/状态准备 |
| 研究台 | 工作台与创作入口（编辑） |
| 电脑 | 地图编辑器入口 |
| 书架 | 梦境素材库入口（创作资源：元素/蓝本，青，见运营/04） |
| 保险箱 | 收藏室入口（长期高价值/纪念对象，见运营/04） |
| 门缝 | 辅助叙事（不承担 01 节点职责；见运营/04） |

书架（素材库）与保险箱（收藏室）是**两处独立承载物**：书架承载创作资源（守创作/02），保险箱承载长期纪念对象（运营/01 §4.2「收藏室」在此呈现为保险箱）——「保险箱」一眼即高价值物，也更好绘制。门缝是**纯叙事接触面**，不承担入梦或功能入口（见运营/04）。

「床边匹配机」配套使用：床负责「躺下即装载」，匹配机负责「模式 + 匹配 + 规则准备」，两者是不同的职责实体（见 §四）。

## 三、床 = 装载入口；研究台 = 编辑节点（不可混同）

**核心澄清：床与研究台是两种完全不同的承载物。**

| | 床 | 研究台 |
|---|---|---|
| 作用 | **装载入口**（进入某个对局/梦境） | **编辑节点**（构建/修改） |
| 本质 | 睡眠数据入本文件的装载边界 | 工作台（`src/editor/bench/`）的现实侧呈现名 |
| 产出 | 加载场景信息 + 玩法包 → 进入对局 | 产出实例/玩法包，供后续睡 C 使用 |
| 交互 | 躺下即就绪 → 传送入梦 | 打开编辑界面 |

- 床是「装载用的」：把玩家送进某一段梦境。
- 研究台是「编辑用的」：玩家在此建造、修改梦境内容。

### 三床分工

| 床 | 主色 | 进入什么 | 语义 |
|---|---|---|---|
| **床A** | 蓝 | 主线 + 竞技入口 | 非 UGC（蓝色语义=清醒/体力/主线侧，不背创作） |
| **床B** | 珊瑚 | 联机副本入口 | 珊瑚=近战/对抗/联机对抗 |
| **床C** | 青 | **自己建好的梦** = 体验沙箱 | 青=UGC/创作来源，进入自建沙箱，并可选是否开放自己的梦境 |

**床C 的两种出口**：进入自己建好的梦境后，玩家既可以**单人体验/自测**，也可以**选择开放自己的梦境**给其他玩家（成为梦主，叙事见 `role:dream-builder`）。是否开放在人局前给出一个开关，不设强制。

> 床C 与床A/B 不同：A/B 通往他人/官方梦境，C 通往自己的梦境。三者都经过装载边界，但 C 的装载源是「收集在自己素材库/研究台里建好的沙箱」，A/B 是运营玩法包。

## 四、床 + 匹配机双实体流线

匹配负责规整、床负责就绪，二者组合成一次入梦。**门控铁律**：匹配机未交互完成前，床不可交互（呈灰色、不可点）。

### 流程

```text
玩家走到匹配机
  ├─ 选择模式（MVP：仅竞技）
  ├─ 匹配机展示规则 / 状态 / 规则准备（彩色 UI，完整）
  └─ 发起匹配（异步，见 01 §2.2，可继续在租屋移动）

匹配完成
  ├─ 对应床由灰变可交互（床高光亮起）
  └─ 玩家走到床边，躺下 = 「就绪」

全屏世界介绍 + 玩法包说明（可跳过）
  └─ 传送演出（纯白显形，见 §六）→ 进入对局装载边界
```

要点：

- **匹配机负责「匹配 / 状态 / 规则准备」**，是信息密度高的一方，彩色 UI 完整。
- **床负责「躺下即就绪」**，是进入侧，无 UI 或极简（睡眠姿态就是就绪动作）。
- **床在匹配机交互前不可点**：是铁律，防止玩家误以为能直接躺床乱开。
- **MVP 仅竞技、无房主**：只有竞技匹配，不做房主开房既做编辑又拉人的耦合；房主/游主权级待后续。

## 五、影子大厅（不重载场景）

采用**影子方案（方案 A）**：匹配完成后**不加载一个独立大厅场景**，而是由服务器中继状态，玩家仍在自己的出租屋/原场景内「站桩」等待与看到彼此。

- **真实物理影子在场**：其他已就绪的玩家以「影子」形式在租屋可见。
- **站桩规则**：匹配结果与准备状态由权威侧推进（快照 / 中继），本地不伪造状态。
- **否决统一大厅**：统一大厅需要重载到一个集体场景，会破坏 `运营系统/01` §2.2 的异步原则（匹配期间不被锁住、可继续活动），故不采用。

影子大厅延续 01 §2.2「异步匹配期间可继续活动」，只把「匹配成功后」的就绪交互也留在原场景，不额外建大厅。

## 六、传送演出（状态机）

入梦 / 返回统一用「纯白显形」做门。表现细节（帧、曲线、多帧不僵硬）在 `表现系统/01` 的「驻地演出」节，这里只定状态机与人称约定；表现契约与其对齐。

```text
梦 → 实（返回）
  1. 床在（床是固定实体，全程不消失）
  2. 人物纯白显形（约 1 秒）
  3. 纯白被推向床（颜色滚动/曲线）
  4. 人物在床复原色彩 → 起床演出

实 → 梦（进入）
  1. 床从平地被翻起/浮现
  2. 人 + 床整体纯白
  3. 复原色彩
  4. 人物从床跳下 → 进入梦境
```

铁律：

- **床是固定实体，不消失**——演出不销毁床，只移动人形与改变色彩。
- **约 1 秒纯白显形**：短暂、高冲击（过载闪光感），不做成常态底色。
- **曲线 / 多帧，不僵硬**：显形与显影走多帧曲线，不做单帧跳变。
- **可跳过**：往返演出允许跳过，且不影响规则装载（沿用首次体验可跳过原则）。

## 七、中途退出

玩家在对局中想退出，**不必回床找出口**：

- **左上角**提供退出 + 设置入口。
- 退出 = 请求离开当前对局（经权威动作通道），不是本地强退。
- 返回后落在出租屋原位置/床旁，不强制重复入梦流程。

这避免了「困在梦境里必须回到床才能走」的挫败，与 `运营系统/01` §8 的退出边界衔接。

## 八、MVP 范围与明确不做

MVP（Steam demo 可展示）对驻地的边界：

| 项 | 状态 |
|---|---|
| 三床分工 | 只开**竞技**（床A）；床B 联机副本、床C 自建沙箱**留后续** |
| 匹配机 | 只做竞技匹配；房主/游主权级不做 |
| 研究台 / 电脑 / 书架 / 保险箱 | 在位（编辑器入口、素材库入口与收藏入口），但 MVP 先以端口占位 |
| 自建梦境 | **仅在编辑器内装饰/自测，不可入局**（不可被别人睡进来） |
| 收藏室（保险箱）/ 素材库（书架） | 只在书架/保险箱预览，不完全实现陈列 |
| 影子大厅 | MVP 可退化为「就绪后进装载边界」，无条件强制影子的全量同步 |

本轮明确不做（非否决，是后期专题）：

- 完整房主开房 + 权限体系。
- 三床全开的完整循环。
- 出租屋随剧情变化的多形态（第四章公寓变化），只保留静态首发形态。
- 联机匹配算法、房间协议与队伍权限（属后续联机专题）。

这些不靠临时默认值伪装成已定案。

## 九、与创作工具 / 表现系统的衔接

- **研究台 / 电脑 / 书架 / 保险箱**在运营侧只定为「出租屋的可交互承载物」；其内部实现守 `创作系统/01`（工作台/编辑器）与 `创作系统/02`（素材库/熟悉度/蓝本）、`运营系统/01` §4.2（收藏室/保险箱）。书架=素材库、保险箱=收藏室，两处独立承载。
- **匹配机 / 床的就绪闭环**守本文件；动画、颜色、睡眠姿态的表现映射在 `表现系统/01`。
- **叙事来源**：出租屋是入梦者的现实锚点（`role:dream-agent`），全部入口的叙事底色统一是「入梦」，不做第二套传送语汇。

---

## 十、总结

驻地把「节点 = 局外菜单」落到一张可移动的现实地图：**床是装载入口（A/B/C 分工）、研究台是编辑节点、匹配机管就绪、影子大厅不重载、纯白显形接线往返、左上角随时退出**。床与台职责清晰分离，MVP 只做竞技 + 床C沙箱端口，完整循环留待后续专题。
