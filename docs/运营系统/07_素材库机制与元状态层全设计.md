## 一、定位与边界

### 1.1 为什么需要本文件

既有文档把素材系统拆在多个正交域里：素材/词条/蓝本结构在创作系统（01/02）、素材库交互在运营/04、记忆消耗链在运营/06、证据提交在运营/05。它们各自自洽，但**没有一个文档回答「三个界面怎么连、共享什么数据、承载物怎么命名」**——这恰恰是前端落地前必须焊死的部分。

本文件不重复既有结构契约，只在它们之上定三件事：

1. **承载物与界面的权威命名映射**（研究台/电脑/造梦舱/书架/保险箱各自是什么）。
2. **共享元状态层（MetaState）**：一个独立数据模块，三界面 + 电脑共同消费。
3. **三个界面的完整人机交互**（素材库 / 研究台 / 电脑），以及三界面间的切换契约。

- **研究台 ≠ 素材库**：素材库是「看/找/取」的入口，研究台是「改/锻/合」的工作台。素材库详情页可以看一个素材挂着的词条，但「你拥有哪些词条、怎么用词条」只在研究台。

- **造梦舱 ≠ 电脑**：造梦舱只做地图编辑；套餐/活动/行业评价等应用全部在电脑。

## 二、三界面关系与切换契约

### 2.1 三界面 = 同一创作心智的三段

素材库（取）、地图编辑器（摆/建）、研究台（改/锻）在 UGC 高强度创作时会被**连续交替使用**。它们的共同点是都消费同一个「素材库元状态层」，所以物理上做**全屏替换、状态各自保留**：

```text
地图编辑器（造梦舱）
   │  右栏快捷素材栏上方：小按钮 → 切到素材库
   ▼
素材库（书架）
   │  素材详情界面小按钮 → 切到研究台
   ▼
研究台（原锻造台）
```

- **每次切换 = 全屏替换**：不移动位置、不做多窗口并排。切走时该界面的编辑态（画布内容、选中的素材、未提交的合成）**完整保留**，切回原样恢复。
- **切换按钮是小按钮、常驻在固定位置**：编辑器 → 素材库的按钮在**右栏快捷素材栏上方**；素材库 → 研究台的按钮在**素材详情界面上**（小按钮）。
- **不反向依赖**：编辑器不因素材库/研究台改动而变；三界面只通过元状态层交互（§四），不直接读对方内部状态。

### 2.2 切换语义（状态保留边界）

| 界面 | 切走时保留什么 | 切回时 |
|---|---|---|
| 地图编辑器 | 当前地图工作区（MapData）、当前图层、选中元素、撤销栈 | 原样恢复，可直接继续编辑 |
| 素材库 | 当前筛选/搜索条件、星标排序、浏览位置 | 恢复筛选状态 |
| 研究台 | 当前锻造台上的素材与槽位、素材快捷栏、合成队列 | 原样恢复（合成中的队列在后台继续） |

> **2026-08-19 裁决**：研究台**无词条快捷栏**（原「词条快捷栏」撤销）；右栏为**素材快捷栏**（与素材库/编辑器共享同一份，见 §10.1），词条从词条库直接拖入锻造槽位。§3.2 / §6.2 / §6.4 / §八 / §10.2 同步注记，权威实现见 `.kiro/specs/wakeup-material-library/`。
### 2.3 高频切换的走查（典型 UGC 创作流）

```
1. 玩家在编辑器建图，需要「储物柜」→ 右栏快捷素材栏直接拖（7 格内或展开全库）
2. 想要一个「火焰散射霰弹枪」→ 点快捷素材栏上方按钮 → 切到素材库
3. 素材库没有合适的 → 详情页看现有素材挂的词条 → 点小按钮 → 切到研究台
4. 研究台：词条库看收集 → 提取/合成 → 锻造出目标素材 → 回素材库（或直接经快捷栏回编辑器）
5. 编辑器放上新素材 → 继续建图
```

全程不离开出租屋的「创作语境」，只有全屏切换，没有折返驻地的空转。

## 三、共享元状态层（MetaState）

### 3.1 定位：独立数据模块，不是任何界面的私有状态

「素材库元状态」是**关于素材/词条/蓝本/合成/塑形的"拥有与使用状态"**，独立于地图几何、独立于渲染、独立于对局规则。它由一个**独立状态层模块**维护，供三界面与电脑共同消费。

> 与 devboard spec（要求 6）对齐：devboard 只消费本层的「素材可用性钩子」（`isAvailable(materialId)`），不实现拥有量/角标/改动标记等判定逻辑——那些是本层的职权。

### 3.2 素材属性与分类维度（权威）

素材库前端此前使用单一 `category` 表达装置、照明、陈设、交互、线索和遮挡；该字段只能作为视觉筛选占位，不能承担运行期语义。现行素材模型将以下维度分开：

1. **简介**：素材在列表、地图或运营入口中显示的一句话直接概括。简介采用正式、百科式、运营商叙事口吻，概括素材的表面形态或直接功用。
2. **描述**：素材进入详情页后显示的深入描摹、世界观讲述和可公开线索。描述可以为空；特殊素材可声明证据提交可触发的线索引用，但描述本身不执行规则。
3. **图标（可选）**：缩略列表、快捷栏和非场景界面使用的 icon 引用。图标缺失时由素材库显示语义 fallback。
4. **贴图（必填）**：所有素材必须有可追踪的视觉资产引用。可出现在场上的实体使用严格正面俯视图；物品使用统一正视图。贴图不是规则事实，也不能由贴图推断实体类别。
5. **品级**：玩家可见品级为 `1 | 2 | 3 | 4 | 5`，由权威来源或动作结果提供。
6. **词条分类**：词条只属于 `属性 | 技能 | 状态 | 防御 | 机动` 五类；词条是不可直接放置的语义内容。
7. **运行时实体分类**：素材可引用实体语义，但不复制玩法 profile。实体分类为 `item | weapon | vehicle | npc | character | interactive | environment`；具体 profile 通过稳定 `runtimeEntityRef` 引用。
8. **角色表现与控制分离**：角色表现素材只描述外观和资产引用，不代表角色已经是运行时实体；运行时实体由 `runtimeProfileRef` 装配，控制器由独立配置引用。
9. **控制身份分类**：`player` 表示真实玩家控制；`ai-player` 表示使用玩家角色规则属性、占用玩家席位、参与玩家行动轮的 AI 控制器；`npc` 表示剧情或环境实体，由 NPC 行为控制器在 NPC 阶段行动。AI 本身不是素材，也不是实体实例；AI 是附着于运行时实体的控制配置。
10. **展示分类**：素材库可以提供用于检索的 `displayCategory`，包括 `装置 | 照明 | 陈设 | 交互 | 线索 | 遮挡 | 物品 | 武器 | 载具 | 生物 | 角色 | 机制 | 氛围 | 蓝本`。展示分类不替代运行时实体分类或控制身份。

权威最小引用形状：

```typescript
interface MaterialIdentity {
  id: string;
  name: string;
  introduction: string;
  description?: string;
  iconAssetRef?: AssetRef;
  textureAssetRef: AssetRef;
  quality: 1 | 2 | 3 | 4 | 5;
  displayCategory: DisplayCategory;
  runtimeEntityRef?: { kind: RuntimeEntityKind; id: string };
  actorBinding?: {
    kind: 'player' | 'ai-player' | 'npc' | 'unbound';
    controllerRef?: string;
  };
}

interface AssetRef {
  manifestId: string;
  entryId?: string;
  checksum?: { algorithm: 'sha256'; value: string };
  view: 'world-top-down' | 'item-front' | 'icon' | 'portrait' | 'sprite-sheet';
}
```

`runtimeEntityRef`、`actorBinding`、`displayCategory` 和词条引用必须分别校验。`actorBinding.kind = 'unbound'` 只用于肖像、对话、回顾或背景演出，不装配运行时控制器。AI 玩家不是 NPC；AI 玩家只表达控制器/匹配占位语义，完整角色属性仍由其对应玩法实体和 profile 提供。实体可以可交互或不可交互，是否可交互由权威动作查询决定。

#### 分类细分与互斥规则

**词条分类**细分为五组，每组只表达一种语义职责：

- **属性**：改变实体的稳定性质或数值倾向，例如伤害属性、感知属性、传输属性。
- **技能**：提供可被合法动作查询发现的主动或被动能力，例如快拔、散射、架枪。
- **状态**：表达持续、条件或阶段性状态，例如中毒、过载、屏息、倒地。
- **防御**：表达承受、规避、格挡或抗性语义，例如护盾、掩体适应、减伤标签。
- **机动**：表达位置变化、移动方式或行动窗口语义，例如突进、翻越、短距位移。

词条必须且只能属于其中一组；“伤害”或“移动”这样的词不能直接作为类别，必须落到已登记的词条定义和玩法动作中。

**实体分类**细分为七组：

- **物品 `item`**：可被持有、消耗、装备、放置或作为容器内容管理的运行时对象。
- **武器 `weapon`**：具有攻击动作或攻击能力引用的物品实体；武器同时可以拥有 `item` 的持有语义，但运行时引用指向武器 profile。
- **载具 `vehicle`**：承载角色、改变移动或提供载具交互的运行时对象。
- **NPC `npc`**：由 NPC 行为控制器驱动、具有独立角色属性和 NPC 行动配置的运行时角色实体。
- **角色 `character`**：具有角色身份、外观和角色属性引用的运行时角色实体；角色可以由真实玩家、AI 玩家或其他控制器控制。
- **交互实体 `interactive`**：可被玩家或角色通过合法动作查询交互，但不必具有角色属性的地图实体。
- **环境实体 `environment`**：放置在地图中、主要提供空间或视觉语义、当前没有可用交互动作的实体。

`weapon` 是运行时实体语义，不是展示分类的同义词；`npc` 和 `character` 可以同时存在于一个实体引用上，但 `npc` 表示运行时角色职责，`character` 表示角色身份/表现职责，二者不能据此推导控制器。

**角色表现分类**细分为：

- **玩家角色表现**：用于真实玩家操控的角色视觉。
- **AI 玩家角色表现**：用于匹配补位或占位的角色视觉；其控制器是 `ai-player`，不是 NPC。
- **NPC 角色表现**：用于剧情、环境或梦主防卫的角色视觉；其控制器是 `npc`。
- **无控制角色表现**：只用于肖像、回顾、对话或背景演出，不装配运行时控制器。

角色表现分类只决定视觉检索和挂载，不决定行动轮、AI 算法或规则属性。行动轮和控制器必须由运行时实体装配确认。

### 3.3 数据模型（TypeScript 形状，落点 `src/meta-state/`）

```typescript
type DisplayCategory =
  | '装置' | '照明' | '陈设' | '交互' | '线索' | '遮挡'
  | '物品' | '武器' | '载具' | '生物' | '角色' | '机制' | '氛围' | '蓝本';
type RuntimeEntityKind = 'item' | 'weapon' | 'vehicle' | 'npc' | 'character' | 'interactive' | 'environment';
interface AssetRef {
  manifestId: string;
  entryId?: string;
  checksum?: { algorithm: 'sha256'; value: string };
  view: 'world-top-down' | 'item-front' | 'icon' | 'portrait' | 'sprite-sheet';
}
interface MaterialIdentity {
  id: string;
  name: string;
  introduction: string;
  description?: string;
  iconAssetRef?: AssetRef;
  textureAssetRef: AssetRef;
  quality: 1 | 2 | 3 | 4 | 5;
  displayCategory: DisplayCategory;
  runtimeEntityRef?: { kind: RuntimeEntityKind; id: string };
  actorBinding?: {
    kind: 'player' | 'ai-player' | 'npc' | 'unbound';
    controllerRef?: string;
  };
}

interface MetaState {
  // ── 素材（元素/可放置实例）──
  materials: Record<MaterialId, MaterialMeta>;
  // ── 词条（5 大类 × 白名单 22 + 提取增量）──
  tokens: Record<TokenId, TokenMeta>;
  // ── 蓝本（熟悉度 = 创作资格）──
  blueprints: Record<MapId, BlueprintMeta>;
  // ── 快捷栏（编辑器 + 研究台共享同一份）──
  quickBar: QuickBar;
  // ── 塑形备选栏（研究台锻造界面最下方）──
  moldingBar: MoldingBar;
  // ── 合成队列（研究台）──
  synthesisQueue: SynthesisJob[];
}

interface MaterialMeta {
  owned: boolean;                       // 是否拥有（拥有库 = owned:true）
  source: 'standard' | 'synthesized';   // 标准件（副本/主线领取）| 合成物（合成台产出）
  quality: 1 | 2 | 3 | 4 | 5;           // 品级（合成物按品级公式，标准件按来源）
  starred: boolean;                     // 星标（素材库排序置顶）
  modified: boolean;                    // 改动标记（是否被研究台改过）
  isUgcNew: boolean;                    // UGC 新增标记（玩法层命名集之外的派生）
  equippedTokens: (TokenId | null)[];   // 挂载词条（5 槽，对应五大类）
  weakness: TokenId | null;             // 与生俱来的弱点裂缝（合成物）
  limitedFree: boolean;                 // 限免（地图自带，临时免费）
}

interface TokenMeta {
  owned: boolean;                       // 是否拥有该词条
  category: '属性' | '技能' | '状态' | '防御' | '机动';
  quality: 1 | 2 | 3 | 4 | 5;           // 品质（提取时 LLM 评级）
  starred: boolean;
  collectedAt: number | null;           // 收集时间（材料收集库的"我攒到了"感）
}

interface BlueprintMeta {
  familiarity: number;                  // 0-100，累计记录（不受 1-5 铁律约束）
```

### 3.3 展示投影与权威身份的迁移边界

素材库、研究台和地图编辑器可以拥有本地 UI 状态，但不得复制以下权威事实：`owned`、`source`、`quality`、`starred`、`modified`、`isUgcNew`、`equippedTokens`、`weakness`、`limitedFree`、词条拥有状态、合成结果和蓝本解锁状态。

前端旧模型中的以下字段只能作为兼容 fixture 或展示投影，不得进入 MetaState 权威写入：

- `tile`、`glow`、旧 `desc`：迁移到 `AssetRef`、`introduction`、`description`。
- 嵌套 `TokenMeta`：迁移为 `TokenId` 引用，名称/品质/描述从 token projection 解析。
- `source: 'ugc' | 'craft'`：不得继续作为权威来源枚举；来源、UGC 新增角标和合成/派生身份必须分字段表达。
- 前端确定性生成的品质、拥有状态、词条 bit mask、蓝本、合成任务：只能位于 demo fixture，不能伪装成元状态投影。
- `MaterialCategory` 的旧六类：只能作为旧 UI 筛选兼容映射；新的 `displayCategory` 不得替代 `runtimeEntityRef`。

`src/meta-state/` 是未来唯一的素材元状态权威落点。素材库、研究台、地图编辑器和电脑 UI 通过 projection 读取，通过 action port 提交星标、快捷栏、贴图、提取、锻造、合成、塑形和蓝本动作。动作拒绝必须由元状态动作层产生，UI 只显示不可用原因。

### 3.4 角标状态机（元状态的视觉表达）

每个素材/词条卡片上的角标 = 元状态的一个可读投影。全局颜色语义沿用 `表现系统/01`（不发明新色）：

| 角标 | 含义 | 颜色语义 | 出现在哪 |
|---|---|---|---|
| **限免** | 地图自带、临时免费、不拥有 | 绿（免费/安全） | 素材库可见、编辑器展开全库可见 |
| **UGC** | 玩法层命名集之外的新实体（派生/合成） | 青（UGC/创作） | 合成物、派生素材；**快捷栏中灰显不可拖** |
| **合成** | 合成台产出（可能带弱点裂缝） | 金/银（品级高光） | 合成物 |
| **已改动** | 被研究台修改过（区别于原版） | 橙（进行中/消耗） | 素材卡片小点 |
| **星标** | 快捷订阅 | 黄（感官/注意） | 素材/词条卡片 |

**角标状态机规则**：
- 一个素材可同时有多个角标（如「合成 + UGC + 已改动」），主色取玩家最可能猜中的那个，其余做小徽章。
- **限免与拥有互斥**：`limitedFree:true` 时 `owned:false`，永不进入拥有库。
- **UGC 新增标记**：唯一决定随机尾缀的轴（守 `创作/01` §ID 规范），由本层维护。

### 3.4 读写矩阵（谁读谁写）

| 消费者 | 读 | 写 | 方式 |
|---|---|---|---|
| 地图编辑器（devboard） | `isAvailable(materialId)`、快捷栏配置、素材角标 | —（快捷栏配置在素材库/研究台改） | 只读消费可用性钩子 |
| 素材库 | 素材/词条/蓝本全量、星标 | 星标、快捷栏配置（拖入替换 7 格） | 读写 |
| 研究台 | 词条库、拥有素材、合成队列、塑形栏 | 提取词条、合成（投料/产物/失败返还）、锻造修改、塑形栏配置 | 读写 |
| 电脑 | 全量元状态（只读展示） | 套餐/活动/行业评价等账号级状态（独立于素材元状态） | 管理 |

> **写入纪律**：素材的「拥有/品质/角标」由**机制动作**（提取、合成、领取、对局结算）驱动，界面只触发动作、不直接改元状态。界面 UI 不内联判定合法性（守 devboard 要求 4：可用性判定走钩子）。

### 3.5 与 devboard / 研究台 / 素材库的代码边界

```text
src/meta-state/            ← 本层（独立模块，无渲染、无引擎依赖）
  ├─ types.ts              元状态数据模型
  ├─ store.ts              Zustand store（三界面共享）
  ├─ material-availability.ts   isAvailable 钩子（devboard 消费）

src/editor/bench/          ← 研究台界面，读写 meta-state
src/ui/material-library/   ← 素材库界面，读写 meta-state
src/ui/console/            ← 电脑界面，读元状态 + 管账号级状态
```

删除三界面任一，元状态层照常存在（数据不随界面消失）；删除元状态层，三界面退化为纯展示壳（无拥有/角标/可用性逻辑）。

## 四、素材库（书架）

### 4.1 定位

素材库 = **检索优先的创作资源入口**（守 `运营/04` §三）：浏览可放置元素与蓝本、星标置顶、快速检索、与编辑器高频切换。它**不是**仓库（不承载拥有量管理的主界面）、**不是**研究台（不改素材、不调 LLM）。

### 4.2 界面结构

```
素材库（书架）——全屏，顶部 = 界面切换入口
  ├─ 主视图：可放置元素（元素素材）浏览
  │     ├─ 星标置顶（同筛选栏内排首）
  │     ├─ 类别/类型/关键字检索
  │     ├─ 素材卡片：图标 + 名 + 类别 + 角标（限免/UGC/合成/已改动/星标）
  │     └─ 点击 → 素材详情
  ├─ 素材详情
  │     ├─ 大图 + 名称 + 类别 + 品级（1-5 品质色）
  │     ├─ 词条挂载展示（该素材挂着的 5 槽词条——不代表你拥有它们）
  │     ├─ 弱点裂缝（合成物显示）
  │     ├─ 限免素材：显示「限免」+「摆图可用，不进入你的拥有库」
  │     ├─ 星标按钮
  │     └─ 「去研究台锻造」小按钮 → 全屏切研究台并自动装载该素材
  └─ 地图/蓝本 tab（只读，见 §五）
```

### 4.3 词条挂载展示（详情页）

- 素材详情页**展示该素材当前挂着的词条**（5 槽位：属性/技能/状态/防御/机动，空槽显示「无」）。
- 关键语义：**看到 ≠ 拥有**。这里展示的是「这个素材是什么」，不是「你的词条库里有什么」。词条的拥有与收集在研究台词条库（§6.2）。
- 想看某个词条的来源/品质/可贴宿主 → 点该词条徽章 → **切到研究台词条库**定位到它。

### 4.4 与编辑器的衔接

- 素材库右上方（或详情页）提供「回编辑器」入口（与编辑器快捷素材栏上方按钮对应，双向）。
- 编辑器展开的全库（7×10）本质就是素材库的子集视图（§十一），所以素材库与编辑器共用同一份筛选/星标数据。

### 4.5 「编辑素材」入口（前 MVP 调整）

创作/01 前 MVP 曾定「修改单个素材」在素材库内完成（可调用对话框）。**2026-08-18 调整**：编辑素材的权威落点是**研究台**。素材库详情页的「编辑/锻造」按钮 → **全屏切到研究台并自动装载该素材**，不在素材库内嵌第二套编辑组件。理由：研究台是游戏化工作台，素材库保持检索纯净（`运营/04` §3.5 的「就近修改」原则以全屏切换承接，物理上仍是一键直达）。

## 五、地图/蓝本 tab（素材库内的只读总览）

### 5.1 蓝本是什么（术语澄清）

**蓝本 = 熟悉度满解锁的「整张地图的可再创作模板」**（守 `创作/02` §五）：用途是**在地图编辑器中把它选作底子**（派生起点，`derivedFrom` 溯源），不是一张素材卡片。

- 蓝本本质是**地图**，不在书架里作为素材管理。
- 但从世界观看，地图属于素材库的叙事范畴（每张图有熟悉度），所以**在素材库内设一个「地图/蓝本」tab**。

### 5.2 界面（只读）

```
地图/蓝本 tab（只读总览，不在此编辑）
  每行 = 一张地图
    ├─ 地图封面（缩略图）
    ├─ 地图名 + 场景数
    └─ 右侧熟悉度进度条（0-100%，累计记录，不受 1-5 铁律约束）
        满 100% → 解锁蓝本 → 封面亮起 + 「可在编辑器选作蓝本」徽章
        未满 → 进度条 + 「还差 X%」小字
```

- **只读**：这里不管理、不编辑、不删除蓝本。熟悉度的涨跌由对局记录驱动（`创作/02` §三），本 tab 只投影。
- 解锁的蓝本可点开看详情（构成该梦的完整蓝图预览），但**编辑/再创作入口在地图编辑器**（新建地图时「以某已加载地图为蓝本」）。
- 与素材库主视图的区分：主视图 = 可放置元素（积木），本 tab = 地图（整套房子）。两者同在一个书架里，但语义与操作完全不同。

## 六、研究台（原锻造台，权威名）

### 6.1 定位与质感

研究台 = **素材级工作台**，面向**绝大多数玩家**（不只是硬核创作者）。它的质感与地图编辑器**完全不同**：

| | 地图编辑器 | 研究台 |
|---|---|---|
| 气质 | 工具感、工程感（三栏工作台） | **游戏化、仪式感**（材料工作台） |
| 用户 | 创作者/迭代者 | 所有玩家（塑形、合成是主流玩法） |
| 核心动作 | 建图（摆/连/框） | 收集词条、锻造素材、合成、塑形 |
| 关键演出 | 校验诊断、样条塑形 | 提取、合成仪式、塑形演出 |

**质感关键词**：像「改枪工作台 + 材料收集册」——边上是排开的槽位、底下是科技感长条框，合成有仪式演出。它是「把你攒的东西变成你的作品」的地方。

### 6.2 词条库分区（材料收集库）

**词条库 = 玩家的材料收集库**，从素材库移到研究台（2026-08-18 定案）。游戏感来自「我在攒材料」：

```
词条库（研究台内分区）
  ├─ 五大类标签页：属性 / 技能 / 状态 / 防御 / 机动（颜色语义区分）
  ├─ 每类 = 卡牌式网格：
  │     已收集（owned:true）：词条卡亮起 —— 名 + 品质（1-5 品质色）+ 简介（机制话术）+ 收集时间
  │     未收集：灰暗剪影 + 「？”占位（能看到"这格是什么"的轮廓，但拿不到）
  ├─ 每类顶部 = 收集进度（如 5/22「属性」已收集 4 个）
  └─ 词条详情（点击）：来源/可贴宿主/可提取素材/品质
```

- 词条卡可**星标**（词条库内排序/快速取用标记；2026-08-19 起不再指向「词条快捷栏」，该容器已撤销）。
- 词条卡是**拖拽源**：直接拖进锻造槽位（§6.4）——研究台无词条快捷栏（2026-08-19 定案）。
- **「材料收集库」语义**：词条是「从素材里抽出来的材料」，收集本身是玩法（`运营/06` §三），不是仓库。

### 6.3 提取词条（第一环消耗）

```
素材详情（研究台内）→「提取」
  ├─ 玩家选一个拥有素材 → 聚焦某个可提取属性（打词条标签的属性，白名单 22）
  ├─ 确认提取 → 烧掉该素材（不可逆）→ 得词条（纯语义文本 + 品质 1-5）
  ├─ 词条进入词条库（该大类下亮起）
  └─ 提取演出（素材溶解 → 词条浮现，走 `运营/06` §三.4）
```

- 提取入口可以在素材库详情页发起，但**执行界面在研究台**（跳转），保证动作落点唯一。
- 品质生成：素材语义价值（LLM 评级）+ 随机波动（`运营/06` §3.4）。

### 6.4 选择并锻造素材（改枪式工作台）

**核心交互 = 改枪式 5 槽**（`运营/06` §4.1），但按 2026-08-18 定案强化游戏化：

```
锻造工作台
┌───────────────────────────────────────────────┐
│  基体：手枪（当前锻造的素材，来自拥有库）          │
│                                                │
│  槽位（= 五大类，固定 5 个）：                    │
│  [属性槽] ← 默认「烈焰」（底图感：预设有默认词条）  │
│  [技能槽] ← 默认「快拔」                          │
│  [状态槽] ← 空（可选）                           │
│  [防御槽] ← 空                                   │
│  [机动槽] ← 空                                   │
│                                                │
│  已放 / 默认值恢复提示                            │
└───────────────────────────────────────────────┘
```

**锻造规则（2026-08-18 定案）**：

1. **底图感**：槽位**可能预先就有默认词条**（素材自带），像一张底图上印好的字。玩家拖新词条进来是「盖上去」。
2. **只替换、不删除**：没有「清空槽位」操作。拖新词条进已占用槽 = 替换；把词条**拖回词条库/快捷栏** = 默认值自动恢复（像底图弹回来）。
3. **槽位可空**（素材本来就没这个词条时）：空槽可拖入一个词条填充；一旦填充，之后只能替换、不能变回空（除非拖回恢复默认）。
4. **每大类槽位 1 个词条**，不能双重强化（守 `运营/06` §4.1）。
5. **右侧组合预览**（2026-08-19 取代原「右侧数值栏」）：当前挂载词条的**语义清单**——每个词条一行「名称 + 机制话术」，空槽显示「未挂载」。**不设火力/射程/机动强度条**——不模仿普通改枪界面的数值强度（那会削弱对自主设计机制的强调）。原「火力 ▮▮▮▯▯ 射程 ▮▮▯▯▯」数值栏设计**撤销**。
6. **素材快捷栏**（2026-08-19 取代原「词条快捷栏」）：研究台右侧提供与素材库/编辑器**共享同一份**的素材快捷栏（§10.1），用于拖素材到塑形栏/换基体；词条从词条库直接拖入槽位。
7. 锻造结果 = 一个**改动过的素材**（`modified:true` 角标），可保存（覆盖自身）或派生（`derivedFrom` 溯源，守 `创作/01` §四）。

### 6.5 合成仪式（第二环消耗 · 游戏化核心）

**合成 ≠ 抽卡**：合成是「你的改进智慧组合出来的作品，品质是未知数」，不是开箱赌博。合成面向大众的「定制感」（`运营/06` §6.2），仪式感承担「郑重交付」的体验。

**流程**（承接 `运营/06` §4.1，2026-08-18 强化演出）：

```
1. 玩家在锻造工作台确认槽位组合（基体 + 词条，最多 5）
2. 投料：基体 + 词条全部消耗（第二环消耗，不可逆）
3. 点击「合成」→ 全屏跳进「高科技锻造入口」（贴图场景，不是弹窗）
   ├─ 入口 = 一扇发光的锻造门/闸口（梦境科技质感）
   └─ 点击入口组件 → 进入「3 个台子」的合成 UI
4. 合成进行（覆盖 LLM 真实消耗时长 5-15 秒）：
   ├─ 组件悬浮上下摆动
   ├─ 时而突然高速旋转（带运动模糊）
   ├─ 粒子效果缓缓划过（电焊火花/能量流，可多设计几种）
   └─ 3 个台子各司其职（如：左侧材料熔炼 / 中央主锻造 / 右侧铭刻）
5. 完成：高光爆发 + 成品浮现 → 点击成品弹面板 → 下方「收下」按钮
6. 失败/驳回（LLM 判定语义不相容/输出不合法）：
   ├─ 成品变灰（不是爆炸/惩罚感）
   ├─ 点开面板 → 填充解释逻辑（「这个组合差点意思」「材料之间不太合」）
   ├─ 点击「确定」→ 所有素材和词条返还（守 `运营/06` §4.4：降级到品级 1 保底模板，材料已消耗；驳回则返还）
   └─ 失败是「软裁决」不是惩罚（`运营/06` §4.5：乱拼给低品质）
```

**演出纪律**（守 `表现系统/00` 五条原则）：
- 动画是**规则结果的视觉重演**，不改变结算、不提交状态、不泄露 LLM 细节。
- 粒子/全屏只承担仪式感，**关键结果**（品质、成败）必须靠图标/文字/面板承载（`00` §二原则二）。
- 队列机制：1 个进行中 + N 个排队；可「加急」（花记忆碎片插队，`运营/06` §4.6）。

### 6.6 塑形备选栏（研究台锻造界面最下方）

```
锻造界面最下方 = 塑形备选栏（科技感单独长条框）
┌─────────────────────────────────────────────────┐
│ 塑形备选 │ [槽1] [槽2] [槽3] [槽4] [槽5]          │
│         │  解锁   解锁   锁定🔒  锁定🔒  锁定🔒   │
└─────────────────────────────────────────────────┘
```

- **固定 5 格**，放在研究台锻造界面的**最下方**，独立长条框，科技感呈现。
- **解锁状态**：部分格子随主线/套餐解锁（`运营/06` §5.1：槽位 1-3 随主线解锁；套餐可加槽）。未解锁格子显示锁，不可交互。
- **用途**：把要带进对局的素材拖入备选栏。局内「塑形」从备选栏取用（第三环消耗，`运营/06` §五）。
- **拖入替换**：拖新素材到已占用的格子 = 替换，无删除操作（与锻造槽位同哲学）。

## 七、电脑（梦核多应用台 · 元状态港湾）

### 7.1 定位

电脑 = **新承载物**（电脑显示器、机箱、鼠标）。它是「港湾」：**所有元状态的管理都放进来**。它与保险箱不冲突——保险箱放实物（陈列），电脑是**查看/管理**（账本、订阅、应用）。

- **高度模块化**：内部以「应用」为单位组织，未来新增零碎玩法（联系人/黑市/社交）按「加一个应用」处理，不动其他承载物（承接 `运营/05` §4.6 的梦核多应用台设计，承载物从造梦舱迁至电脑）。
- **查看为主，不是收藏**：电脑不陈列、不收藏，只管理与查看状态。

### 7.2 应用清单

| 应用 | 职责 | 出处 |
|---|---|---|
| **套餐订阅** | 梦境电信套餐（基础/标准/专业/佣兵）查看/订阅/取消 | `运营/05` §5.2 |
| **活动奖励领取** | 不以记忆碎片为奖励的活动奖励集中领取 | `运营/05` §4.6 |
| **个人面板** | 个人周报、近期动态、对局统计 | `运营/05` §4.6 |
| **行业评价** | 组织内/体制内的软件感（公司评价、客户评价、同行排名） | `运营/05` §4.6 |
| **证据提交（VR 取证室）** | 素材作为真相物证提交给警官（VR 头显交互） | `运营/05` §四（机制补全见本文件 §八 / `运营/05` §4.6） |
| **LLM 从零造玩法包** | 原「造梦舱 LLM 创作者」迁入：采访式需求澄清 → 生成完整玩法包 | `创作/01` §3.1 |
| **后续应用（可拓展）** | 联系人 / 黑市 / 社交 等 | — |

### 7.3 与电视的边界

电视只做**被动显示**（公告/活动/行业新闻滚动），不接交互；**领取/订阅等动作必须到电脑**（守 `运营/05` §4.6：电视与电脑的边界）。电脑是「主动查看/操作」的地方。

### 7.4 元状态港湾的语义

电脑是元状态层的**管理视图**：
- 素材/词条/蓝本的**拥有状态总览**（只读投影：你有多少素材、多少词条、几张蓝本）。
- 套餐/活动/行业评价等**账号级状态**（独立于素材元状态，但同属「局外元状态」域）。
- 证据提交的**提交记录与档案**（已提交哪些素材、解锁哪些真相板块）。

> **边界**：电脑不做素材编辑、不做合成、不做地图编辑。它管理「状态」，不生产「内容」。

## 九、素材来源与产权边界

### 9.1 三种素材身份

| 身份 | 来源 | owned | 能否进拥有库 | 能否拖入快捷栏 | 能否锻造/合成 | 能否进塑形栏 |
|---|---|---|---|---|---|---|
| **标准件** | 副本/主线领取 | ✅ | ✅ | ✅ | ✅（可当基体） | ✅ |
| **合成物** | 合成台产出 | ✅ | ✅ | ✅（带 UGC 角标灰显限制见 §9.2） | ✅（可再锻造） | ✅ |
| **限免（地图自带）** | 地图内临时免费 | ❌ | ❌ | ❌（交互 + 数据层双拒绝） | ❌ | ❌ |

### 9.2 限免素材的完整逻辑（2026-08-18 定案）

限免素材 = 地图自带的临时免费实例（`创作/01` §六「临时免费」）：

1. **在素材库界面可见**：浏览/检索时能看到（带「限免」绿角标），可以看详情、看挂载词条。
2. **在编辑器展开的全素材库中可见**：能在地图编辑器里取用摆图（快照内联，守 `创作/01` §四）。
3. **不可拖入快捷栏**：
   - **交互层**：拖拽时快捷栏拒绝落点（红闪/拒绝提示）。
   - **数据层**：快捷栏录入动作在元状态层**拒绝写入**（`quickBar.materialSlots` 不接受 `limitedFree:true` 的素材）。
   - **为什么双拒绝**：快捷栏是编辑器 + 研究台**共享同一份数据**；限免素材一旦进入快捷栏，切到研究台时会出现「我能拖一个不拥有的素材去锻造」的产权漏洞。数据层拒绝是从源头保护。
4. **不显示在标准素材库（拥有库）**：拥有库只列 `owned:true`。限免素材在素材库主视图**按「全部/可用」与「我的素材」分栏**——主视图默认显示全部（含限免），「我的素材」栏只显示拥有。

### 9.3 UGC 新增角标与快捷栏灰显

- 带 **UGC 角标**的素材（合成物/派生）在快捷栏中**灰显、不可拖拽**——快捷栏是「取用」场景，UGC 素材需要进入研究台操作（锻造/派生/合成）才有意义；灰显防止「在编辑器里拖一个 UGC 素材直接摆图」绕过它的创作语义。
- 灰显不是禁用的惩罚：悬停显示提示「UGC 素材请到研究台处理」。
- 限免 + UGC 两套规则独立：限免看 `owned`，UGC 看 `isUgcNew`，互不干扰。

## 十、快捷栏共享设计

### 10.1 素材快捷栏（编辑器 + 研究台共享同一份）

- **数据共享**：编辑器和研究台**共享同一份快捷栏数据**（`quickBar.materialSlots` 7 格 + 展开态）。在素材库/研究台里配置的 7 格，切回编辑器立即生效；反之亦然。
- **未展开**：7 格（最近/高频素材，一屏速拖）。
- **展开**：7×10 矩阵（70 格，**一次性展示尺寸上限，实际有滑条可滚动**）+ 顶部类别筛选 + 搜索框。
  - **本质是全库浏览**：展开后看的是「全素材库」的紧凑网格（图标矩阵），不是 70 个固定位。
  - **悬停显示**：只有图标，鼠标悬停才浮出名称/类别/角标详情（低信息密度、快速扫）。
  - **筛选 + 搜索**：类别筛选 + 关键字，与素材库共用同一套筛选语义。
- **取用方式**：拖拽取用（编辑器：拖到画布放素材；研究台：拖到锻造槽位/塑形栏）。
- **配置方式**：在素材库/研究台把需要的素材拖入 7 格替换（`quickBar.materialSlots[i] = materialId`）。
- **保护规则**：限免素材不可拖入（§9.2）、UGC 灰显（§9.3）。

## 十一、证据提交机制（VR 取证室 · 完整机制）

> **文档整理勘误**：证据提交是既有定案机制（`运营/05` §四），但权威文档只写了方向与图形化语言，**机制细节（入口归属、次数、判定、奖励节奏）此前缺失**。2026-08-18 补全机制并同步进 `运营/05`（见该文件 §4.6/§4.7 更新）。本节是全机制设计。

### 11.1 入口归属（2026-08-18 定案）

证据提交的入口从「造梦舱 §4.6 应用清单」**迁移到电脑**（VR 头显交互，作为梦核应用之一）。造梦舱收窄为地图编辑器后，证据提交与套餐/活动/行业评价并列在电脑里。

### 11.2 空间与交互（承接 `运营/05` §4.2.1 图形化语言）

- 出租屋叠一层**独立图层**（`height = null` 三界之外独立层）：虚空白底 + 正面斜投影取证室（玩家角色 + 办公桌 + 警官对坐）。
- 坐下后桌面浮现 **3-5 个槽位**（青色描边，悬停发光）。
- 对话复用叙事对话框系统（警官左侧立绘，对话框右侧，槽位桌面，三面同屏）。

### 11.3 素材范围与提交规则

| 规则 | 内容 |
|---|---|
| 可提交素材 | **仅拥有库素材**（限免素材不可提交——你只是「借来用」，不是「记住的真相物证」） |
| 提交消耗 | **不消耗素材**、不破坏（可反复试探，守 `运营/05` §六.4） |
| 槽位数量 | 3 个基础 + 证据提交相关主线解锁 +1 + 提交次数里程碑 +1，上限 5 |
| 约谈节奏 | 每次对局返回出租屋后可进行一轮提交（多次组合试探）；「隐藏真相」奖励每组合**只触发一次**（首触发判定，防刷） |
| 判定依据 | 素材背后不可见线索标签（`#2024火并`、`#清理组`、`#玩家身世`），玩家只能通过第二层深层信息推测 |

### 11.4 三层反馈与奖励（承接 `运营/05` §4.3，补齐节奏）

| 反馈 | 触发 | 演出 | 奖励 |
|---|---|---|---|
| **常规提交** | 任意组合（无有效链） | 警官「记录在案」 | 500-1,000 美元（按素材品质） |
| **有效证据链** | 同一事件相关素材 ≥2 | 警官「你发现了什么？说说看」→ 触发对话 | 2,000-3,000 美元 + 解锁该事件档案 |
| **隐藏真相** | 特定组合（跨线索暗线） | 警官愣住 → 反应暴露立场 → 特殊剧情 | 5,000 美元 + 稀有素材/违禁情报（首触发） |

### 11.5 与真相板的衔接

- 提交成功的素材/组合 → 在**真相板**对应板块点亮（`运营/05` §三）。
- 真相板是素材库之上的叙事组织视图，本机制只负责「提交动作 → 点亮」的联动，真相板自身 UI 归表现系统。

### 11.6 与主线的衔接（不变）

- 证据提交是**主线的平行暗线**，不是前置条件，不强制（`运营/05` §4.4）。
- 已提交真相在主线关键对话/选择处解锁额外选项（`运营/05` §4.5）。

## 十二、人机交互质感

### 12.1 四界面质感定位

| 界面 | 质感关键词 | 心智 |
|---|---|---|
| 素材库（书架） | 检索、清爽、书架感 | 「找我要的素材」 |
| 地图编辑器（造梦舱） | 工具感、工程感、筑梦工作台 | 「把梦画出来」 |
| 研究台（锻造台） | **游戏化、仪式感、材料工作台** | 「把材料变成我的作品」 |
| 电脑 | 软件感、梦核多应用台 | 「管理我的状态」 |

### 12.2 颜色语义（沿用，不新增）

- 青 = UGC/创作（素材库/编辑器/研究台的创作入口、快捷栏、切换按钮）。
- 绿 = 免费/限免（限免角标）。
- 金/银 = 品级高光（合成物、品质 4-5）。
- 橙 = 进行中/消耗（已改动角标、合成进度、塑形栏状态）。
- 黄 = 感官/注意（星标、警戒类提示）。
- 红 = 错误/致命（合成失败解释的边界色，不做惩罚感）。
- 灰白 = 可交互但受制于状态（UGC 灰显、未解锁塑形格）。

### 12.3 边缘发光交互（沿用视觉定律 2）

- 可拖拽素材/词条 = 悬停边缘发光（青或所属类色）。
- 限免素材拖拽 = 落点拒绝红闪（快捷栏/塑形栏/锻造槽位统一）。
- 未解锁塑形格 = 扁平灰 + 锁图标，不可交互。

### 12.4 低心智约束

- 同屏主操作收敛（守 `L0` 第五条）：研究台一屏只有一个主动作焦点（锻造 或 合成 或 塑形），不堆叠。
- 素材卡片信息密度分层：图标 → 悬停详情 → 点击详情页，逐级展开（快捷栏 = 最浅，素材库详情 = 最深）。

## 十五、总结

本文件把三界面焊成一套：**素材库（书架）= 检索入口 + 蓝本只读总览**，**地图编辑器（造梦舱）= 建图工具**，**研究台（锻造台）= 游戏化材料工作台（词条库 + 提取 + 锻造 + 合成仪式 + 塑形栏）**，三者共享**独立元状态层（MetaState）** 并全屏切换、状态保留；**电脑（新承载物）= 所有元状态的管理港湾**（套餐/活动/证据提交/LLM 造玩法包，模块化可拓展）。词条收集在研究台、蓝本在书架只读、限免素材双拒绝不进快捷栏、UGC 素材快捷栏灰显、证据提交机制补全并迁至电脑。
