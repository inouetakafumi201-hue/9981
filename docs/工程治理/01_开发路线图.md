## 关键决策点

### 决策1：引擎自研 vs 使用现成引擎
```
决定：自研核心引擎，使用现成渲染库

理由：
- 核心机制非常特殊，现成引擎不适合
- 渲染需求简单，2D库足够
- 保持完全控制权
```

### 决策2：付费 vs 免费
```
已确认：买断制+免费Demo+Steam为主发行渠道，不采用免费+内购模式。

- 买断制（一次性付费）：独立游戏标准发行模式，简单、无道德负担
- 免费Demo：降低试玩门槛，契合UGC生态"先让人玩到愿意创作"的需求
- Steam为主要上架渠道

Web端分发渠道（如itch.io或自建网站直销）仍待定，原因是尚未找到稳定的收益生态。

（详见访谈决策记录 D-028）
```

### 决策3：平台优先级
```
决定：PC优先，后续考虑移动端

理由：
- PC最适合策略游戏
- UGC创作需要大屏幕
- 测试和迭代更方便
```

### 决策4：LLM供应商
```
决定：同时支持OpenAI和Anthropic

理由：
- 避免单点依赖
- 价格和性能对比
- 给用户选择权
```

## 三阶段交付里程碑（回填立项基准）

> 在既有「阶段0/1/2」的基础上，按**可交付目标**重新收敛为三个里程碑。每个里程碑之间有明确鸿沟。本规划由世界观/设计对话（2026-08）回填，用于确定「当前进度在第几步、下一步裂口在哪」。

### 里程碑①：自主迭代白盒

> 玩法已经从"能自行迭代"的意义上构建完成，可以从玩法方面开始整体测试运行。仍然不需要用户的视觉调优。

**内容**：
- 将**所有代码基底**全部解决（引擎层 + 基类层 + 玩法层的运行依赖链跑通）。
- 写完**初步玩法层**。
- 具备自主迭代玩法的能力（改玩法数据即重跑，无需人工配套代码）。

**鸿沟（到达这一步要补的）**：把所有代码基底补齐 + 写完初步玩法层。

**验收**：单局玩法能以数据驱动自主迭代、按规则自测跑通。

### 里程碑②：可挂素材对局

> 此时单局的主要小循环已非常接近交付玩法，目标是不断打磨对局系统，到达最终玩法。从这一步开始，进入"真人监督迭代"。

**内容**：
- 必须写出一张地图。
- 接入**全套素材生成管线**。
- 以真人监督的方式迭代打磨对局。

**鸿沟（难点）**：写出一张地图 + 接全套素材生成管线。**这里的主要难题是图形化。**

**验收**：单局接近交付玩法，唯一地图可玩。

### 里程碑③：MVP（Steam demo 可公开展示）

> 将整个游戏包装起来，做成已经可以公开展示、甚至 Steam demo 的状态。局外循环也要初步搭建起来，让整体可玩。

**内容**：
- 整套外部：互联网联机、海量素材、设计落地调优。
- 局外循环初步搭建（熟悉度、梦境素材库、收藏室等见 `docs/创作系统/02_熟悉度与梦境素材库.md` 与 `docs/运营系统/01_运营与局外养成.md` §十）。
- 让游戏整体成为一个可展示、可游玩的成品。

**鸿沟**：**全套外部（联机问题、海量素材、设计落地调优）**。其中局外循环需在「可挂素材对局 → MVP」之间先行设计。

### 三阶段之间的关键鸿沟

| 跨越 | 鸿沟 | 主要难点 |
|---|---|---|
| 自主迭代白盒 → 可挂素材对局 | 解决所有代码基底 + 写完初步玩法层 | 玩法规则与引擎能力基本盘 |
| 可挂素材对局 → MVP | 写出一张地图 + 接全套素材生成管线 | **图形化** |
| （可挂素材对局 → MVP 的设计先导） | 局外循环（熟悉度/素材库/收藏室） | 世界观→运营→创作的落地 |
| MVP 之后 → 上线 | 互联网联机、海量素材、设计落地调优 | 联机与规模 |

### 当前进度判定

- 若「代码跑通但玩法层需人工配套改代码」= 尚未完成里程碑①。
- 若「有玩法、无一张完整地图、无素材管线」= 处于里程碑①向②过渡，**危坡在于图形化**。
- 若「已有可玩地图、单局接近交付」= 进入里程碑②→③，**此刻亟需本规划所落地的局外循环设计**。

> **结论**：从可挂素材对局到 MVP 之间的设计极其迫切，需通过世界观/设计对话先行解决。本文档所落 `docs/创作系统/02_熟悉度与梦境素材库.md`、`docs/运营系统/01_运营与局外养成.md` §十 即为此先导。
