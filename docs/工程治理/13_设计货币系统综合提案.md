# 设计货币系统综合提案（定数版）

> 状态：提案稿
>
> 目的：把已被证明失败的“单件定价 / 全局估值求解”收束为一条可长期使用的设计价值轴，并给出一组可以直接拿来设计、比较、定价和调参的数字。

## 一句话结论

设计货币不应再被当作“能替系统求解一切价值”的货币系统。它应该被降级为一条线性的设计价值轴，再配若干职责分离的账本。

这条轴像国际象棋的子力分值：先冻结，再按它设计。它不负责证明世界的唯一真理，只负责让不同系统能被稳定比较、排序、取舍和守门。

## 本提案的取舍

这版不再讨论“可能纳入什么数据”，而是直接冻结数值。

我选择的原则很简单：

1. 纯正面的资源先定值，风险资源单独看“可控变化”是否成立。
2. 同样是 1-5 档，越靠后越陡，不用线性平铺。
3. 运营货币、创作资格、素材质量、位移、状态、AI 估值全部可比较，但不允许自由换汇。
4. AI 的内部费目保留现有 1-5 结构，不把它抬成玩家经济。
5. 任何不能在玩法验证里改变玩家选择的数值，不进入提案。

## 1. 设计价值轴的基准单位

我把这条轴定义为 `D`，即设计点（Design Point）。

- `1 D` = 1 个标准 AP 动作的价值
- `1 D` 只用于设计比较、调参和估值，不是玩家直接看到的货币
- 设计讨论中出现的所有资源，都必须能投影到 `D`

这个定义的好处是，`D` 可以跨域比较，但不会把不同账本强行做成一套可自由兑换的总货币。

## 2. 我冻结的数值

### 2.1 即时资源：HP / AP / SP

这里我把“纯正面资源”和“风险可控资源”分开。

| 账本 | 冻结数值 | 设计含义 |
|---|---:|---|
| `HP` | `1 HP = 2 D` | 纯正面的生存资本，归零就进入濒死，不应被视为普通缓冲值 |
| `AP` | `1 AP = 1 D` | 纯正面的行动资本，一个标准动作就是一格基准价值 |
| `SP（可控变化）` | `1 SP 的主动增减 = 1.5 D` | 只有“主动让 SP 增加或减少”的变化才计价；被动损失 SP 只是风险，不是价值 |
| `SP(被动增加)` | `1 SP  = 1 D` | 但总体而言，SP是正面的数值，仅在少数情况下意味着高风险，例如对方有意识的战术连加。 |
这组数值的意思是：

- `AP` 是最短周期货币，负责“现在能不能动”。
- `HP` 是纯正面生存货币，负责“能不能活下去”。
- `SP` 不是纯负面，它的价值来自“可控”。只要机制允许玩家主动调高或调低 SP，它就不是噪音，而是有设计价值的杠杆。

> 这也是为什么我不把 SP 当成单纯的危险条。它的价值不在“它危险”，而在“它能被有意识地挪动，并且这个挪动会改变行动窗口”。

### 2.2 位移：位置价值

位移不是新货币，但它必须被数值化，因为它直接改变可选项。

| 位移类型 | 冻结数值 | 设计含义 |
|---|---:|---|
| 基础位移（相邻节点 / 同微型场景重定位） | `1 D` | 最基础的位置重排，是动作价值的直接投影 |
| 跨天然场景位移（大场景穿越） | `2 D` | 位置改变更大，通常伴随更高风险或更高收益 |
| 过渡门槛位移（楼梯 / 窗户 / 重装） | `+1 D` | 进入特定过渡结构时的额外成本 |
| 强制位移 / 抢位 / 推拉 | `2 D` | 因为它改变对方位置控制，所以比普通移动更值钱 |
| 无视阻挡 / 瞬移级位移 | `3 D` | 直接绕过位置约束，属于高阶位势变化 |

这里的含义不是“位移可以自由卖钱”，而是“位移是价值轴上的位置控制”。

### 2.3 状态：行动与控制价值

状态要分成增益、约束、失能三档看。下面的数值按当前文档里的典型持续窗来算。

| 状态类 | 示例 | 冻结数值 | 设计含义 |
|---|---|---:|---|
| 动作增益 | `加速`、`格挡` | `+2 D` | 直接改善动作效率或防御窗口 |
| 位置增益 | `隐蔽` | `+3 D` | 改变被发现概率，直接影响路线与战斗选择 |
| 恢复增益 | `睡眠` | `+2 D` | 通过恢复 HP / SP / 清醒度，换来未来行动能力 |
| 轻约束 | `前往 X`、`撬锁中` | `-1 D ~ -2 D` | 占用行动面，但还没把人完全锁死 |
| 中约束 | `迟缓`、`重装` | `-2 D` | 让常规动作变贵，影响节奏 |
| 重约束 | `冰冻`、`辐射` | `-3 D` | 明显改变行动优先级 |
| 失能 | `倒地（击倒）` | `-4 D` | 严重压缩行动空间，但仍可恢复 |
| 濒死 | `倒地（濒死）` | `-5 D` | 接近系统上限的失败态，代价最高 |

这里的核心不是“状态多不多”，而是“状态能不能改变玩家在当前回合里怎么选”。

### 2.4 容量与槽位

| 账本 | 冻结数值 | 设计含义 |
|---|---:|---|
| `战斗携带槽` | `1 槽 = 2 D` | 槽位会锁死可选项，因此比单次动作更贵 |
| `证据桌面槽` | `1 槽 = 1 D` | 这是提交和展示用的槽位，价值低于战斗携带槽 |
| `快捷素材栏格` | `1 格 = 0.5 D` | 这是纯取用层，不该和正式携带槽等价 |

这里我明确不把所有槽位混成一个池。它们可以比较，但不能互相吞并。

### 2.5 熟悉度与蓝本资格

| 进度段 | 设计值 |
|---|---:|
| 0%–19% | `0 D` |
| 20%–39% | `1 D` |
| 40%–59% | `3 D` |
| 60%–79% | `6 D` |
| 80%–99% | `10 D` |
| 100% | `15 D` |

这不是把熟悉度当成钱，而是把“理解一张梦”的阶段做成一个陡峭的价值梯子。

我选择这个梯子，不选线性 1/2/3/4/5，原因很简单：

- 前两段应该容易进，给玩家起步反馈
- 中段开始明显变贵，避免随便刷一刷就能开蓝本
- 满熟悉必须显著更贵，才能匹配“可再创作资格”这种权力

### 2.6 知识投入与记忆碎片

| 账本 | 冻结数值 | 设计含义 |
|---|---:|---|
| `记忆碎片` | `1 片 = 2 D` | 它是学习和创作的认知成本，不是战斗币 |
| `素材学习` | `1 次学习 ≈ 2 D` 起步 | 普通元素不便宜，但也不该贵到劝退 |
| `高价素材学习` | `1 次学习 ≈ 4 D` 到 `6 D` | 稀有语义应明显更贵 |

这里我没有把记忆碎片定成 1，因为它承担的是“把看到变成学会”的成本，应该比纯动作更贵，但不能贵到变成第二套美元。

### 2.7 运营流动性：美元

我给美元定一个最简单也最稳的换算：

| 金额 | 设计值 |
|---|---:|
| `500 美元` | `0.5 D` |
| `1000 美元` | `1 D` |
| `2000 美元` | `2 D` |
| `3000 美元` | `3 D` |
| `5000 美元` | `5 D` |
| `10000 美元` | `10 D` |

这组数值直接对齐了现有文档里的奖励和套餐档位：

- 常规证据提交 500–1000 美元，属于低档正反馈
- 有效证据链 2000–3000 美元，属于中档奖励
- 隐藏真相 5000 美元，属于高档奖励
- 标准套餐 2000，美金价值 2 D
- 专业套餐 5000，美金价值 5 D
- 佣兵套餐 10000，美金价值 10 D

这让美元有了清晰的阶梯，而不是只写“有紧张消费出口”。

### 2.8 素材质量：品级与强度上限

| 品级 | 设计值 |
|---|---:|
| 1 | `1 D` |
| 2 | `3 D` |
| 3 | `6 D` |
| 4 | `10 D` |
| 5 | `15 D` |

我在这里选的是三角数列：`T(n)=n(n+1)/2`。

原因是：

- 1 级到 2 级应该有明显提升
- 3 级开始才算真正能撑住成品定义
- 4、5 级必须陡涨，否则高品没有稀缺感

这组数值也和现有合成公式的意图一致：基体主导、词条平分、随机只做小幅扰动。

### 2.9 AI 内部设计货币

AI 侧我保留现有的 1-5 费目 ladder，不把它改成另一套玩家经济。

| 费目 | 当前权重 |
|---|---:|
| `range` | `1` |
| `E` | `2` |
| `heal` | `3` |
| `vitality` | `4` |
| `e:enemy.vitality` | `5` |
| `pool.stamina` | `1` |
| `pool.ap` | `2` |

锚点继续保持：

- `deathAnchor = -10`
- `exhaustionAnchor = -6`
- `lethalWindow = 4`

稀缺系数继续保留现状：

- `vitality.scarcity.coefficient = 0.2`
- `E.scarcity.coefficient = 0.4`
- `e:enemy.vitality.scarcity.coefficient = 0.5`

这意味着 AI 的内部估值不需要发明新货币，只需要在现有 1-5 ladder 上做稳定排序。

## 3. 统一比较公式

我建议提案里的统一比较分写成下面这个式子：

```text
D_total =
  HP×2
  + AP×1
  + SP主动增减×1.5
  + 位移值
  + 状态值
  + 槽位值
  + 熟悉度阶段值
  + 记忆碎片×2
  + 美元/1000
  + 品级三角值
  + AI 内部费目值
```

其中：

- `位移值` 见 2.2
- `状态值` 见 2.3，增益取正，约束取负
- `熟悉度阶段值` = `0 / 1 / 3 / 6 / 10 / 15`
- `品级三角值` = `1 / 3 / 6 / 10 / 15`
- `AI 内部费目值` 仍按当前权重表读取

这个公式不是给玩家结算用的，是给设计讨论、调参和跨系统比较用的。

## 4. 局外货币验证

这里我把“尤其是局外货币”单独立成验证规则，因为这类货币最容易变成空转数字。

### 4.1 现在保留的两枚局外货币

| 货币 | 设计值 | 主用途 |
|---|---:|---|
| `记忆碎片` | `1 片 = 2 D` | 学习素材、扩容量、支付 UGC 成本 |
| `美元` | `1000 = 1 D` | 套餐、微经营、证据提交奖励、动态难度消费 |

### 4.2 局外货币的合格条件

一枚局外货币必须同时满足下面四条，才值得留在系统里：

1. **有源头**：能在稳定玩法里重复获得。
2. **有出口**：能稳定花掉，而且花掉以后会改变路线、资格、便利或生存压力。
3. **有决策**：至少有一次“现在花还是之后花”的选择。
4. **有验证**：能在实机里观察到它改变了玩家行为，而不是只改了数字面板。

### 4.3 合格阈值

为了尽量早点定下来，我建议局外货币至少满足这三个阈值：

- **第一次消费选择**必须在单次会话的前 10-15 分钟内出现。
- **第一次明显反馈**必须在单次会话的前 30 分钟内出现。
- **三次连续 playtest** 里，只要这枚货币没有改变路线、资格、便利或风险之一，就视为无效或需要合并。

### 4.4 具体到当前两枚货币

`记忆碎片` 合格，因为它能把“看见”变成“学会”，还能继续向 UGC、扩容、LLM 成本延伸。

`美元` 合格，因为它能把局外生存、套餐、微经营、证据提交和动态难度串成一条实际循环。

如果后面要加新货币，必须先回答：它到底是在补能力循环，还是在补生存循环。如果两者都不是，那就不该出现。

## 5. 明确不做的事

1. 不做 AP、HP、SP、美元、记忆碎片、素材值互相自由兑换的总货币。
2. 不把 AI 内部估值暴露成玩家经济。
3. 不把素材品质写成线性市场价。
4. 不把槽位做成可无限购买的容量条。
5. 不把熟悉度做成付费跳过的经验值。
6. 不把美元设计成万能强化货币。
7. 不把被动损失 SP 当成“有价值的资源变化”。

这些一旦成立，系统就会重新滑回“全局定价求解”，也就是已经失败过的那条路。

## 6. 为什么这版比上一版更像一个真正的方案

上一版只说了“有哪些账本可以纳入”，但没有把最关键的几个数字钉死。

这版做了四件事：

- 给了 HP、AP、SP 的明确价值，并把 SP 的可控性单独拎出来了
- 给了位移和状态的具体数值，不再只停留在概念
- 给了局外货币的验证门槛，避免货币空转
- 给了统一比较公式，能直接拿去做设计和调参

换句话说，这版不是“这个系统里有什么”，而是“这个系统到底按什么数字工作”。

## 7. 结语

我建议把这套系统理解成：

- 一条线性的价值轴
- 六本职责分离的账本
- 一套只用于比较、不用于自由兑换的数字表

真正可行的不是一枚万能硬币，而是一条清晰的价值轴，外加几本职责明确的账本。这样既能保留国际象棋式的冻结标准，也能让 AI、素材、运营、创作和玩法各自沿着自己的节奏工作。
