## 〇、核心认知

V0.dev 的价值定位：**生成高质量前端壳层**（交互手感 + 视觉特效 + 组件结构），我们负责**真实数据接线 + 业务逻辑**。

**关键边界**：
- V0 擅长：UI 组件树、动效编排、视觉质感、交互手感
- V0 不做：真实业务逻辑、后端数据接线、画布渲染（SVG/Canvas 几何计算）、运行时高频计算（镜头 lerp / 图层透明度 / ORCA 寻路）

**接线原则**：
1. **前端结构不改，逻辑全换**：保留 V0 的组件层级、样式、动效，只替换硬编码数据为真实端口
2. **学习并模仿 V0 代码风格**：扩展功能时必须模仿 V0 的写法（布局/命名/状态管理）
3. **迁就前端优先**：遇到前端与后端设计冲突，优先扩展后端能力，而非强改前端

## 二、投喂 → 接线 → 验收三阶段工作流

### 阶段 1：投喂准备（需求 MD + 参考图，必须完整）

#### 1.1 产出需求 MD（按模板）

每个界面必须产出一份 **V0 投喂规范 MD**（模板见 `.kiro/specs/v0-frontend-workflow/v0-spec-template.md`），包含：

- **功能清单**（不可遗漏）：所有可交互元素、触发条件、视觉状态
- **视觉规范**（强制约束）：色彩 tokens、布局尺寸、动效库（Framer Motion / lucide / Radix）
- **组件层级**（预期结构）：组件树、状态管理方式（useState / Zustand）
- **数据接口**（接线清单）：硬编码占位数据 → 真实端口映射表
- **交互逻辑**（伪代码）：所有用户操作的响应流程
- **明确不做**（防止 V0 自由发挥）：哪些功能不要、哪些设计不要

#### 1.2 产出参考图（必须有）

**参考图是投喂的第一要素**，必须包含：

- **整体布局**：1920×1080 完整界面截图
- **关键状态**：正常/悬停/禁用/激活的视觉差异
- **动效说明**：用文字标注哪些元素有入场/出场/过渡动画
- **色彩标注**：关键区域标注 tokens 语义色（红/蓝/橙/青/紫/金/灰白）

**参考图来源**：
- 已有：对局 HUD `run/ui-mockup/v2-refined2/ui_v2_refined2_20260815_183135.png`
- 待产出：驻地导航、素材库、保险箱、叙事对话框、证据提交（按 `docs/表现系统/00_创作指导.md` 的 Image-2 提示词规范产出）

#### 1.3 投喂前检查清单（强制）

- [ ] 需求 MD 已按模板填写完整（9 个章节无空项）
- [ ] 参考图已产出并放在 `run/ui-mockup/[界面名]/`
- [ ] 功能清单已逐项对照设计文档，无遗漏
- [ ] 视觉规范明确（色彩/布局/动效库/风格关键词）
- [ ] 硬编码占位数据的 TypeScript 类型已写清
- [ ] 真实端口映射表已填写（文件路径 + 导出名 + 类型）
- [ ] "明确不做"列表已填写（防止 V0 加多余功能）

### 阶段 2：接线执行（保留结构，替换数据）

#### 2.1 接收 V0 产物

V0 导出的代码放入专用目录：

```
src/devboard/editor-shell/          # 地图编辑器壳层（已在做）
src/ui/battle-hud-shell/             # 对局 HUD 壳层
src/ui/residence-shell/              # 驻地导航壳层
src/ui/material-library-shell/       # 素材库壳层
src/ui/collection-shell/             # 保险箱壳层
src/ui/narrative-shell/              # 叙事对话框壳层
...
```

**命名规则**：`[功能模块]-shell/`，标识这是 V0 生成的壳层，与真实业务逻辑分离。

#### 2.2 接线铁律（7 条，来自记忆 `v0-frontend-shell-wiring-workflow`）

1. **前端结构不改，逻辑全换**
   - 组件名、层级、props 接口、样式类名：**原样保留**
   - 硬编码数据、假状态、占位回调：**全部替换成真实端口和逻辑**

2. **学习并模仿 V0 的代码风格**
   - V0 用 `className="flex items-center gap-2"` 写布局 → 后续新增也这样写
   - V0 用 `motion.div` 做动效 → 后续新增也用 Framer Motion
   - V0 用 `lucide-react` 的图标 → 后续新增也从 lucide 选

3. **文字与术语纠正**
   - V0 可能把"场景"写成"节点"、"遮挡框"写成"障碍物"
   - 识别 UI 文字对应的真实概念，替换成项目权威术语（`docs/L0_规范宪法.md`）
   - 记录所有术语替换，形成映射表：`v0文字 → 项目术语 → 对应端口`

4. **真实端口接线**（关键）
   - **地图数据**：`src/devboard/editor/workspace-state.ts` 的 `loadMap` / `exportMap`
   - **图层**：`src/devboard/layers/layer-shapes.ts` + `layer-rules.ts`
   - **素材可用性**：`src/devboard/ports/material-availability.ts`
   - **对局投影**：`src/play/loading-runtime/ui-host.ts` 的只读投影（轮次栏/动作/状态）
   - **编辑行为**：`src/devboard/app/editor-state.ts` 的操作函数
   - **诊断**：`src/devboard/verify/playtest.ts` 的诊断结果

5. **占位素材替换**
   - V0 可能用假图标、假贴图占位
   - 真实素材来源：图标 → `lucide-react`；角色精灵 → `sprite-forge` skill；地图底图 → `asset-pipeline` skill
   - 暂时没有的保留占位，但在清单里标注"待替换"

6. **状态管理迁移**
   - V0 用 `useState` → 迁移到现有 `editor-state.ts` 或新建 Zustand store
   - V0 用 Zustand → 复用结构，只把数据源换成真实端口
   - 表现层 UI 状态（面板开合、通知队列）可保留 V0 的 Zustand store

7. **不迁就前端的例外**
   - V0 的某个 UI 元素对应的后端功能**根本不存在** → 暂时**禁用**该按钮，记入"缺失设计清单"
   - V0 的某个 UI 元素与后端设计**冲突** → **迁就前端优先**：后端扩展，或前端改（优先前者）

#### 2.3 接线步骤（标准流程）

1. **理解组件树**（1-2 小时）
   - 识别 V0 的组件层级、状态管理方式、props 传递链
   - 标记所有硬编码数据：占位地图、假图层、假素材、假诊断

2. **建立术语映射表**（30 分钟）
   - 列出所有 V0 使用的文字 → 对照设计文档 → 找到项目权威术语
   - 形成映射表：`v0文字 → 项目术语 → 对应端口`

3. **替换硬编码数据**（核心工作，2-5 天）
   - 按端口映射表逐个替换占位数据
   - 每替换一个端口，立即在本地测试该功能是否可用
   - 遇到类型不匹配，优先调整前端适配层，不改后端类型

4. **补充缺失功能**（如果有，1-3 天）
   - V0 可能没实现的功能（如"撤销/重做"按钮存在但无逻辑）
   - 模仿 V0 的代码风格添加逻辑，不重构 V0 的结构

5. **纠正术语与文案**（1 小时）
   - 按术语映射表批量替换 UI 文字
   - 确保所有用户可见文字符合项目术语规范

#### 2.4 接线纪律（4 条边界）

1. **禁止提前魔改 V0**：看到 V0 的代码不符合习惯，也不许"重构"、"优化"；唯一允许的改动是：接线、纠正、扩展
2. **禁止只改一半**：不能"左栏接好了，右栏还是假数据"；接线要么不做，要么全做
3. **禁止跨边界污染**：`*-shell/` 是 V0 壳层，不改其他目录；需要新增接口时在 `ports/` 里加
4. **记录所有妥协**：遇到"前端这样设计但后端不支持"，选择迁就前端还是禁用功能，**必须记录原因**

### 阶段 3：验收与收尾（产出清单）

#### 3.1 门禁验证（强制）

- [ ] `npx tsc --noEmit`：壳层代码类型全通过
- [ ] `npx vitest run src/[模块]`：相关测试全绿
- [ ] `npm run lint`：0 error（warnings 可以有）
- [ ] `npm run verify:docs`：术语一致性通过

#### 3.2 功能自测（逐项检查）

- [ ] 打开对应界面，确认所有交互元素可用
- [ ] 真实数据显示正确（从后端端口读取，非硬编码）
- [ ] 动效符合设计（Framer Motion 入场/出场/过渡）
- [ ] 键盘导航可用（Tab/Enter/Esc）
- [ ] 无障碍支持（屏幕阅读器可读）

#### 3.3 产出四张清单（交接文档）

1. **多余项目清单**：V0 实现了但后端不需要的 UI 元素
   - 示例：`分享到社区` 按钮（暂不支持社区功能）
   - 处置：暂时隐藏或禁用，记入"后续功能"

2. **缺失设计清单**：后端有但 V0 没实现的功能
   - 示例：`图层透明度滑块`（设计文档有，参考图里没画）
   - 处置：补充实现或记入"技术债"

3. **术语映射表**：`v0文字 → 项目术语 → 对应端口/文件`
   - 示例：`障碍物` → `遮挡框` → `src/devboard/layers/layer-shapes.ts#ObstructionShape`

4. **占位素材清单**：哪些图标/贴图/精灵还在用假数据
   - 示例：角色头像用 placeholder.png，需 `sprite-forge` skill 产出真实精灵图

**Batch 3：驻地 + 素材管理（P1，依赖 Batch 1/2 完成）**
- 投喂：驻地导航、素材库、保险箱、锚定导流仪 4 个界面需求 MD + 参考图
- 接线：`src/ui/residence-shell/` 等 + 真实素材库端口

### 并行原则

- **同一批次内的界面可并行投喂 V0**（它们互不依赖）
- **不同批次必须串行**（后批次可能依赖前批次的接线结果）
- **接线工作可与下一批次的投喂准备并行**（流水线作业）

## 四、风险控制与兜底方案

### 风险 1：V0 生成的代码质量不符合预期

**表现**：代码结构混乱、无法复用、类型定义缺失

**兜底方案**：
1. **第一次投喂失败**：优化需求 MD（补充更详细的组件层级、TypeScript 类型）
2. **第二次仍失败**：换一个界面先做，或降级为"只要视觉稿，代码自己写"
3. **多次失败**：评估 V0 是否真的适合该界面，考虑完全自己实现

### 风险 2：V0 的设计与后端能力冲突

**表现**：V0 设计了 7 种场景尺度，但后端只有 3 种

**处置原则**：
1. **优先扩展后端**：如果后端扩展成本低（如枚举类型加值），直接扩展
2. **迁就前端有代价**：如果后端扩展会影响核心架构，再考虑改前端
3. **记录所有妥协**：无论哪种选择，都记入决策日志，标注理由

### 风险 3：接线后发现参考图遗漏关键功能

**表现**：参考图里没画"撤销/重做"按钮，但设计文档要求有

**处置原则**：
1. **补充参考图**：重新产出包含该功能的参考图，再投喂 V0
2. **模仿 V0 风格自己加**：如果功能简单（如一个按钮），学习 V0 风格自己加
3. **记入缺失清单**：标注为"待下一版本补充"

### 风险 4：V0 用了项目禁用的库

**表现**：V0 用了 `react-spring` 做动效，但项目规定必须用 `framer-motion`

**处置原则**：
1. **立即替换**：按接线铁律第 2 条，把 `react-spring` 全部替换为 `framer-motion`
2. **记录教训**：在投喂 MD 里补充"禁用库清单"，下次投喂时明确告知 V0

## 五、成功标准（项目级验收）

### 验收维度

| 维度 | 标准 | 验收方式 |
|---|---|---|
| **视觉一致性** | 所有界面符合 tokens 语义色、lucide 图标、Framer Motion 动效 | 人工审查 + 自动化 lint 规则 |
| **功能完整性** | 所有设计文档要求的功能都可交互 | 逐界面功能清单对照 |
| **数据真实性** | 所有显示数据来自真实端口，无硬编码占位 | 代码审查（搜索 `mock` / `fake` / `placeholder`） |
| **门禁通过** | tsc 0 error / lint 0 error / vitest 全绿 / verify:docs 全绿 | CI 自动检查 |
| **性能可接受** | 界面切换 < 100ms / 动效流畅 60fps / 无卡顿 | 性能测试（Chrome DevTools） |

### 项目级里程碑

### 素材管线对接（见 `docs/表现系统/09_图形化实现落点.md` §六）

| 素材类型 | 来源 | V0 占位 | 接线方式 |
|---|---|---|---|
| 角色精灵 | `sprite-forge` skill | placeholder.png | 替换为 `run/assets/[角色名]/manifest.json` 引用 |
| 静态组件 | `sprite-component.py` | 假图标 | 替换为组件管线产出帧 |

### 状态管理对接（只读投影原则）

所有对局数据**必须从只读投影读取**，表现层不得本地推断或缓存：

```typescript
// ✅ 正确：从只读投影读
const currentPlayer = turnStore.getCurrentPlayer(); // 来自 ui-host.ts 的投影

// ❌ 错误：本地推断
const currentPlayer = players.find(p => p.hasActed === false); // 违反只读投影原则
```
