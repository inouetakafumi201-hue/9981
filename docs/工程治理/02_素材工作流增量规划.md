# V0 原生素材工作流增量规划

> **性质**：后续实现规划；不代表能力已经完成
> **状态**：待执行
> **日期**：2026-09-05
> **事实源**：`docs/访谈决策记录.md` D-086
> **依赖**：`docs/创作系统/02_地图生产管线.md`、`docs/创作系统/03_素材工作流管线实现交接.md`

---

## 一、目标

补齐“资产清单 → V0 平台工具出图 → 稳定登记 → 完整实体/表现资产组装 → 表现层实例化 → 编辑器可选”的生产闭环，使 AI、NPC、物品实体素材能原生在 V0 会话中批量生产并真正进入地图编辑与运行路径。

本规划不生成地图底稿。地图全屏视觉由用户导入人工 SVG，空间关系由用户在编辑器中确定。

---

## 二、边界

### V0 负责非确定性生成

Agent 读取规划书和资产清单，通过 V0 `GenerateImage` 等平台工具逐项出图，并把结果保存到项目内。默认流程不得要求用户配置模型 API Key，也不得让仓库脚本直接请求第三方图像 API。

### 仓库负责确定性处理

后续脚本只承担：

- 清单 Schema 与完成度校验；
- 切格、抠图、缩放、格式转换等确定性后处理；
- 稳定 ID、实体定义、渲染描述和编辑器元数据登记；
- 引用完整性校验；
- 表现层实例化与编辑器可选报告；
- 断点续跑所需的状态清单。

### 素材完成定义

素材不是图片文件，而是包含视觉资源、实体/定义关联、渲染描述、编辑器目录元数据和稳定引用的可挂载整体。只有表现层能实例化、渲染层能消费、编辑器能检索选择，才算完成。

---

## 三、实施主梁

### 主梁 1：资产清单契约

定义一个可版本化、可断点续跑的批量清单，至少覆盖：

- 稳定素材 ID 和显示名；
- 类型：AI、NPC、物品；
- 所需视图、动作、状态与变体；
- 尺寸、透明背景、风格和参考资源约束；
- 目标实体/定义引用；
- 渲染描述与编辑器分类；
- 每项状态：待生成、已生成、待处理、已登记、已实例化、编辑器可选、失败。

验收：重复执行只处理缺失或失败项；清单可准确报告漏项、重复 ID 和不完整状态组。

### 主梁 2：V0 Agent 编排

建立面向 V0 会话的执行规约：

1. 读取清单并按依赖排序；
2. 使用 V0 图像工具逐项生成；
3. 每次生成立即保存项目文件并记录结果；
4. 失败项保留诊断，可单独重试；
5. 不把 blob URL 或外部 URL 写进运行时代码；
6. 输出完成报告，交给确定性脚本继续处理。

验收：不使用模型 API Key；会话中断后可从清单状态继续；不会覆盖人工确认产物。

### 主梁 3：登记与组装

将生成文件组装为运行时和编辑器共同消费的资产：

- 使用稳定 ID，不以临时目录名作为身份；
- 绑定实体/定义和渲染描述；
- 生成编辑器目录、搜索、预览元数据；
- 把开发期来源复制/物化到稳定挂载位置；
- 检查资源、定义、描述和索引之间的双向完整性。

验收：运行时不扫描 `run/`；开发目录改名不影响已挂载内容；所有悬空引用被发布闸门拦截。

### 主梁 4：表现层实例化门

建立批量验收场景或无头检查入口，逐项证明：

- 实体可创建；
- 对应视觉资源可加载；
- 状态/动作变体可选择；
- 生命周期销毁后无残留；
- 错误能定位到稳定素材 ID。

验收：全部清单项均有明确通过/失败结果，不能以“图片存在”代替实例化。

### 主梁 5：编辑器可选门

编辑器资产面板消费统一索引，支持：

- 按 AI/NPC/物品分类；
- 搜索和预览；
- 选择、拖放与放置；
- 只展示满足 `placeable` 和完整性要求的素材；
- 使用稳定引用写入 `MapData.placements`。

验收：创作者无需输入路径；每个合格素材都可被检索、选择和放置；不合格素材带明确诊断且不可发布。

## 四、与地图包六步链的接口

| 地图步骤 | 本规划责任 |
|---|---|
| 1. 规划书 | 接收实体资产需求和状态清单 |
| 2. 玩法/API | 接收稳定规则、实体接口与渲染组件能力 |
| 3. 素材生成 | 完成 V0 出图、登记和资产组装 |
| 4. 人工地图编辑 | 提供新旧素材目录，但不替用户生成 SVG/拓扑 |
| 5. 素材挂载 | 完成实例化门与编辑器可选门 |
| 6. AI 高逻辑绑定 | 提供稳定 ID 供玩法文件与节点绑定 |

通用机制缺口在步骤 2 进入玩法层。地图玩法文件可以调用现有渲染组件并绑定场景生命周期，也可承载地图特有机制；倒计时等可复用机制不得在每张地图重复实现。

---

## 五、现有工具的重新定位

- `asset:generate` / `asset:pipeline` / `asset:view`：开发期 MapData 契约自测，不是地图生产或素材批量生成入口。
- sprite-forge 后处理：可选的确定性精灵处理工具；产物进入项目时仍须通过统一登记与挂载门。
- Nano Banana / 外部 API 适配器：历史可选工具，不是 V0 默认出图入口，不能成为闭环的必需依赖。
- 现有角色导入脚本：可作为登记实验参考，但不代表完整实体、表现层和编辑器闭环已完成。

---

## 六、顺序与完成判定

实施顺序必须是：

1. 资产清单契约；
2. V0 Agent 编排与断点状态；
3. 稳定登记和资产组装；
4. 表现层实例化门；
5. 编辑器统一索引与可选门；
6. 用一套完整 AI/NPC/物品清单做端到端验收。

只有第 6 项通过后，才能把素材批量生成管线标记为“已搭通”。当前状态仍是**部分工具已存在，端到端待实现**。

---

## 七、明确不做

- Agent 生成地图 SVG、PNG 底稿或地图空间构图；
- 仓库脚本直接调用外部图像模型；
- 把模型 API Key 作为 V0 原生运行前提；
- 仅登记图片路径而不绑定实体、渲染与编辑器元数据；
- 让运行时或浏览器扫描开发期 `run/` 目录；
- 把样例 MapData 自测冒充正式地图或素材生产。
