## 一、任务一：动态图形化设计全面补全

**目标**：对动态图形化相关的**所有缺口和可能疏漏的细节**进行全面设计，为偷师前端做准备。

**输入（已有）**：
- `docs/表现系统/10_动态图形化补全设计报告.md`（已扫视全部玩法/空间/AI/物品/UGC/运营/叙事/引擎文档，产出 P0/P1/P2 缺口全景：P0 如终局结算演出、淘汰转观战、货币入账、状态解除反馈、商店/交易/合成网关、Decision 征求输入；P1 如弹药可视化、掉线托管、暗押揭示、指令排队、学习基础反馈、武器耐久）
- `docs/表现系统/01_图形化与UI.md`（视觉定律/边缘发光/武器属性符号/姿态拓扑）
- `docs/表现系统/09_图形化实现落点.md`（镜头/声音/图层/对局HUD/驻地 → 库落点全部映射）
- `docs/表现系统/03_动画灵感索.md`（交叉编目表 + J/K/L 子节）

**要做的内容**：
1. 把 10 号报告里的 P0/P1 缺口从"类别性设计"补到"可投喂"程度——每个效果的**参数规范**（duration / intensity / color 具体数值）。
2. 补**跨系统协同规则**：镜头 + 声音 + 动画怎么配合（例如交权硬同步、after:* 事件驱动纪律）。
3. 明确**MVP 界定**：哪些效果第一批必须实现、哪些可后置，逐条列出。
4. 明确**节奏感原则应用场景**：快速反馈 0.15s / 状态变化 0.3s / 叙事节奏 0.6s 分别用在哪些动画上。
5. 产出 **偷师前端 UI 边界清单**：哪些交 V0 生成、哪些手写、示例图精度要求——不生成分级表，只明确边界。

**边界**：驻地、叙事的界面不在此任务生成的范围内（它们不进偷师前端，直接手写）。

**交付物**：更新的 10 号报告（或配套补全文档）+ 偷师前端 UI 边界清单。

## 二、任务二：素材库机制与元状态层全设计（含人机交互）

**目标**：素材库机制和实现**全部设计全，包括人机交互**。这是在为**编辑器和素材库的前端落地**做准备。因为这两部分**相对独立于前端、且编辑器与素材库会高频切换**，它们将专门分离为一个 **V0.DEV 独立项目**来落地（见"独立项"）。

**机制定性（已定）**：
- 素材可用性**由仓库内容驱动**。记忆是获取素材的重要方式。
- 这些玩法机制在任务二里**都要确定下来**；数据形式等**需求完备之后再定合适的选项**（先确定性，再定形状）。
- 熟悉度与梦境素材库**关系非常密切、互补**（`docs/创作系统/02_熟悉度与梦境素材库.md`）。
- 元状态层设计**在任务二范围内**；但**任务三（编辑器+素材库前端）并不实现它**，因为任务三做的是前端。
- 书架（梦境素材库）= 检索优先，与地图编辑器高频切换（星标置顶、快速回编辑器）；保险箱（收藏室）= 质感收藏（抽屉式平铺、拒绝堆叠、无丢弃）。

**要做的内容**：
1. 素材库元状态层逻辑设计：`material-availability` 钩子的数据结构与判定规则（从"全放行桩"到真实判定）。
2. 素材可用性驱动机制：熟悉度系统 + 记忆获取方式 + 塑形消耗触发条件，与 `04_局外养成的保险箱与素材库交互.md`、`06_素材记忆与消耗系统.md` 对接。
3. 素材库与 `docs/创作系统/02_熟悉度与梦境素材库.md` 的完整对接方案（两者互补关系落到设计）。
4. 元状态层数据模型（TypeScript interface）+ 状态转换规则。
5. 素材库 UI 的数据接口：哪些从后端只读投影读、哪些是前端本地状态。

**边界**：只做设计与机制，**不做前端实现**（前端由独立 V0.DEV 项目承接）。

**交付物**：素材库机制设计文档（含元状态层、人机交互、数据接口）。

## 五、任务四：偷师前端前置设计

**目标**：进行全面的**偷师前端**前置设计（**不包含编辑器和素材库部分**）。包括所有**输出口径、输出批次提示、提示词、工程设计、全部人机交互**等全部搞通，确保符合预期。

**已明确的边界**：
- 偷师前端主要提供**动态图形化和 UI 的整体前端**（可交互的视觉规范、零游戏逻辑）。
- **驻地和叙事根本不需要生成**，不投喂 V0。
- 区分明确，**不需要生成分级表**。
- **参考图只需草图即可**（不需要像素级精度的参考 mockup）。

**要做的内容**：
1. 偷师前端完整结构设计：开始菜单 → 入游戏动画（纯白显形）→ 局外大厅（命令面板 + 纯展示物体）→ UI 场景切换（对局界面 / 锚定导流仪 / 素材库 / 保险箱 / 研究台 / 造梦舱 / 驻地）→ 完整对局 HUD 布局（轮次栏 / 动作菜单 / 投点滑块 / 状态栏，假数据）。
2. 命令面板指令集：动画分类（移动/攻击/受击/状态…）、特效分类（纯白显形/货币入账…）、UI 场景切换——**这是后续接线的提取接口**。
3. 全部人机交互：每个按钮的触发 → 视觉响应。伪交互明确"不计算业务逻辑"（点击地图 → 角色播放移动动画；点击攻击 → 播放攻击动画，不结算伤害）。
4. 输出口径：投喂给 V0.dev 的 Prompt 结构（项目定位 / 结构清单 / 示例素材 / 技术约束 / 命名规范 / 参考风格）。
5. 批次提示：哪些内容分几次投喂，顺序与验收方式。
6. 工程设计：命名规范铁律（加粗标记 = 组件名）、组件目录约定、接线时的术语纠正规则。

**参考**：`docs/工程治理/12_v0.dev前端偷师体系设计.md`（已有方法论）；`docs/工程治理/10_V0前端壳层生产与接线规划.md`（接线铁律 7 条 + 纪律边界 4 条）；`.kiro/specs/v0-frontend-workflow/v0-spec-template.md`（投喂模板）。

**交付物**：偷师前端投喂 Prompt（按模板 9 章节填写完整）+ 草图参考图 + 命名规范与边界说明。

## 六、任务五：素材管线批量生成逻辑落地

**目标**：在生成序列素材的过程中，把素材管线落地实现逻辑（也就是"批量生成素材及其作画贴图"）。

**定性（已定）**：
- 这个批量生成的 skill 是**可以自主定义**的。
- **一个脚本 = 生成它读取的所有增量登记素材**：脚本读一份"待生成素材登记清单"，批量调用出图 API 生成，跑品红纯化 → 切格 → proper-pixel-art 后处理 → 成品质量闸门。
- 批量生成阶段当然会**填入大量登记**（登记清单里有多少就生成多少）。
- **这一次是小规模验证**——因为要做偷师前端，只需要前置那点示例素材。
- 此任务**不是立即开始**，因为需要示例素材先供管线跑（与任务六的素材交互）。

**要做的内容**：
1. 定义"增量登记素材清单"格式（类型 / 描述 / 状态数 / 语境 map|ui）。
2. 扩展现有组件脚本（`.agents/skills/sprite-forge/tools/sprite-component.py`）增加批量模式：循环读清单 → 逐个生成 → 后处理 → 质量闸门。
3. 批量失败策略：失败时记录日志、跳过该素材、继续下一个，最后输出失败清单。
4. API rate limit 防护（请求间隔，避免触发限流）。
5. 小规模验证：登记 10 个左右组件试生成，统计成功率与失败模式，按失败模式调整脚本或提示词，目标至少 7/10 成功、失败可识别可修正。
6. 跑通后确认成品符合 `docs/表现系统/05_组件生成风格规范.md`（正面俯视视图、语义色、硬边像素、品红底）。

**参考**：`docs/表现系统/05_组件生成风格规范.md`（组件管线风格权威）、`PLT-01`（角色管线）、`.agents/skills/sprite-forge/SKILL.md`、`.agents/skills/asset-pipeline/SKILL.md`。

**交付物**：批量生成脚本 + 登记清单格式 + 小规模验证报告（成功率与失败模式）。

## 十、任务九：局外地图（出租屋驻地）——人机协作打磨

**目标**：做局外地图。通过**人机协作打磨**地图生成的管线，争取**复用高效**；完成后进行测试，**绑定已经接线好的前端**。

**人机协作的完整流程（你的原话要点）**：
1. **前置**：在所有的素材都被搭建好、并且保证地图编辑器完美之后再做——这时后端 Agent 来做也不麻烦。
2. 大体过程：**先生成一张地图**，按照地图的视觉内容**将节点拖好**，将**所有的遮挡块、方框等等都解决掉**。
3. 可选：如果乐意，**直接使用编辑器中的素材拖拽**。
4. 如果要批量生成：这一步完成之后，把需求给 AI，**让 AI 通过素材进行 JSON 填充**，还可以加**大量提示词控制玩法平衡**。
5. AI 填充的结果：地图显现上会**重叠或零散在一个固定的场景框中**——**没有审美布局，但是逻辑布局都好了**。
6. 末尾：**再载入一次，整理好**（人工整理审美布局）。

**产出与验收**：
- 产出 `maps/residence/residence-v1.json`（canonical layers 契约）。
- 跑通 `asset-pipeline` 校验 → 编译 → spawn 链路，无校验错误。
- 用 `createLoadedMatch` 装载局外地图，启动 devboard 验证驻地可显示、承载物可交互（床 / 锚定导流仪 / 研究台 / 造梦舱 / 电视 / 书架 / 保险箱 / 门缝悬停高亮与点击响应）、纯白显形传送演出走通。
- 绑定已接线好的偷师前端，局外循环可走通，所有入口可点击。

## 十二、贯穿纪律（每步都守）

1. **三命令门禁**：任何代码/文档改动收尾必跑 `npx tsc --noEmit`、`npx vitest run`（相关范围）、`npm run lint`；完成后补 `npm run verify:docs`。
2. **素材工具链纪律**：任何可见美术素材先查素材管线再动手——静态组件走 `sprite-component.py`（map 语境正面俯视视图，`--context ui` 仅背包/图标），角色/NPC 走 sprite-forge 角色管线，地图数据走 asset-pipeline；风格锁定在脚本内，**不手工造贴图/占位图**。
3. **数值铁律**：所有玩家可见数值严格限制在 1-5；内部数值（回合号、实体数）例外。
4. **语义色**：红色=生命/致命、蓝=清醒/体力、橙=AP/行动、青=社交/UGC、紫=约束/远程、珊瑚=近战、金/银=品级、灰白=可交互受制状态、纯白/奶白=梦境边界/过载。
5. **正面俯视视图**：唯一视角和打法规格，任何出图提示词只用 `top-down plan view`，禁用斜投影/立面/等距类比。
6. **表现不写规则**：表现层只读只读投影、只消费 `after:*` 事件做视觉重演，不本地推断、不本地扣 AP / 推进状态。
7. **人工值守原则**：任务六、任务八（以及任务九/十风格的素材质量）默认人工值守检查，宁缺毋滥。
