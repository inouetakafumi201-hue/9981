# 规范编译器与诊断体系（引擎层 L1）

> **层级**：L1 引擎层。本文档定义规范编译器（Specification_Compiler）的诊断分类、静默防御与原子发布契约。
> **权威关系**：受 `docs/L0_规范宪法.md` 约束；与 `.kiro/specs/wakeup-ugc/requirements.md`、`.kiro/specs/l2-base-layer-spec/requirements.md` 对齐。
> **实现位置**：`src/core/kernel/spec-compiler/`、`src/core/kernel/safety/fatal-boundary.ts`、`src/core/kernel/state/source-record.ts`。

---

## 一、职责边界

规范编译器属于引擎层，只提供机械能力，不做玩法判断：

| 属于本模块 | 不属于本模块 |
|---|---|
| 声明式 JSON 严格解析与禁止执行面拦截 | 具体武器、地图、NPC 的数值与规则 |
| Schema、层级归属、数值归属、引用与组合校验 | 基类层实例的语义设计 |
| 来源优先级裁决与未裁决冲突保留 | 替代人类做权威裁决 |
| 确定性归一化、原子发布、完整回滚 | 编辑器界面、分发、审核 |

编译器不写 `WorldState`，不调用 Op，不注册 Hook。它只产出候选模型与产物，或产出拒绝结果。

## 二、两类停机，绝不混淆

| 分类 | 含义 | 行为 |
|---|---|---|
| **候选拒绝**（`halted: 'candidate'`） | 创作者输入不合法 | 收集全部可独立发现的错误；整批拒绝；活动注册表、依赖图、已提交产物完全不变 |
| **基础设施停机**（`halted: 'infrastructure'`） | 诊断、来源映射、确定性或输出设施本身不可信 | 立即撤销输出租约、隔离暂存区、写入固定形状紧急信封、终止会话 |
| **警告**（`warn`） | 仅非语义提示或显式允许的表现降级 | 不阻止发布，且不得改变任何规则结果 |

> **单调重定义装载语义（D-073）**：玩法包装载从「声明型冲突解决」改为**单调重定义**——后装载的包同 key 覆盖先装载，同 key 即替换或新增，剩 ID 即退役，跨作用域冲突一律拒绝。该语义落在装载器/注册表的**原子 swap 之前**：重定义在候选暂存区完成，只有整批通过验证才 `replaceFrom` 换入活动注册表。任何候选拒绝仍走「候选拒绝」停机路径——活动注册表、依赖图、已提交产物完全不变；不得在运行期直接改写已生效注册表。**唯一写入通道 + 原子验证不可绕过。**

关键纪律：**普通创作错误永远不能升级为基础设施停机**。实现中曾出现相反缺陷（闭合校验把候选 error 排除在”拒绝证据”之外，导致每个 JSON 语法错误都被报成系统故障），已由 `closure.ts` 的 `isBlocking` / `declaresHalt` 双谓词修正，并有回归测试锁定。

## 三、来源位置契约

`SourceRecord` 与 `SourceSpan`（`state/diagnostic.ts`，工具在 `state/source-record.ts`）：

- `line`、`column` 从 1 开始，面向创作者；`column` 按 Unicode 码点计。
- `offset` 是 0 基 UTF-8 字节偏移。
- `sourceSliceHash` 是该跨度原始字节的 SHA-256。
- `contentHash` 是整份来源文本的 SHA-256。

每次跨阶段都强制校验：偏移量在界内且不逆序、行列能由不可变原文重算回同一偏移、切片散列匹配、偏移不落在多字节码点内部。任一项失败即基础设施停机（`SOURCE_MAPPING_FAILED`），不允许带着可能指错位置的诊断继续。

---

## 四、错误码归属

全部错误码进入既有封闭注册表（`state/error-codes.ts`），禁止自由字符串。新增成员分布在 `E_LOAD_*`、`E_REF_*`、`E_MIG_*`、`E_QUOTA_*`。

`INFRASTRUCTURE_FATAL_CODES` 是显式闭合集合，而不是按 `E_LOAD` 前缀猜测。原因：`E_LOAD_*` 同时承载普通装载错误与基础设施故障，用前缀判定会把创作者的字段拼写错误当成进程级故障。

覆盖类别（每个都有创作者大白话与修复动作，并由测试锁定“每个已注册错误码都有提示文案”）：

- 诊断与来源完整性：`SOURCE_RECORD_MISSING`、`SOURCE_SPAN_CORRUPT`、`SOURCE_MAP_LOST`、`DIAGNOSTIC_FAILURE`、`E_QUOTA_DIAGNOSTICS`
- 输入与禁止执行面：`INPUT_TRUNCATED`、`JSON_SYNTAX`、`DUPLICATE_MEMBER`、`PROHIBITED_CONSTRUCT`、各 `E_QUOTA_*`
- Schema 与身份：`SCHEMA_VERSION`、`UNKNOWN_FIELD`、`REQUIRED_FIELD`、`FIELD_TYPE`、`DEF_KIND`、`IDENTIFIER_INVALID`、`DUPLICATE_ID`、`OVERRIDE_INVALID`
- 层级、术语、数值、语义：`LAYER_OWNERSHIP`、`TERM_NONCANONICAL`、`NUMERIC_OWNERSHIP`、`GAMEPLAY_VALUE_RANGE`、`CROSS_FIELD_CONSTRAINT`、`DEPRECATED_MECHANIC`、`SEMANTIC_FIELD_DAMAGED`
- 引用与组合：`E_REF_MISSING/AMBIGUOUS/KIND/ABSTRACT/PROVIDER_CONTRACT/CYCLE`、`INHERITANCE_CYCLE`、`COMPOSITION_CONFLICT`、`ORDER_UNDECLARED`
- 来源优先级：`SOURCE_DISPLACED`、`EQUAL_PRECEDENCE_CONFLICT`、`DECISION_ID_REUSED`、`UNRESOLVED_NORMATIVE`、`SOURCE_STATUS_PROMOTION`、`NORMATIVE_WITHOUT_PROVENANCE`
- 归一化与迁移：`CANONICAL_AMBIGUOUS`、`CANONICAL_NONDETERMINISTIC`、`ROUNDTRIP_MISMATCH`、`E_MIG_NEWER_SAVE/NO_PATH/AMBIGUOUS_PATH/CYCLE/FAILED`
- 提交与输出：`BASELINE_STALE`、`COMMIT_RECHECK_FAILED`、`PARTIAL_ACTIVATION`、`OUTPUT_WRITE_FAILED`、`CACHE_ROLLBACK_FAILED`、`PRESENTATION_FALLBACK`

## 五、数值归属

数值必须唯一分类，否则拒绝（`NUMERIC_OWNERSHIP`）：

| 分类 | 约束 |
|---|---|
| 玩法数值 | 必须属于玩法层，且为有限值且落在 1–5（L0 铁律） |
| 内部度量 / 结构边界 / 宪法常量 / 技术配额 | 按自身 Schema 校验，**不套用 1–5** |

因此版本号、字节数、槽位数、配额都不会被错误地压进 1–5。基类层写入具体玩法数值一律拒绝，且不会被搬到其他字段或生成默认值。

## 六、Fatal Error Boundary

`safety/fatal-boundary.ts` 在会话开始、读取任何不可信输入之前，就把 13 个阶段 × 5 个紧急码的 65 个 `FatalEnvelope` 全部预分配并冻结。

失败路径只做两件事：查表取出已存在的信封、执行一次有界写入。它不分配复杂对象、不格式化消息、不依赖普通诊断序列化器。理由：如果 `Diagnostic` 的构建本身正在失败，再去构建第二个普通诊断可能递归崩溃。

紧急日志写入失败也不影响停机：`writeFixed` 抛错被吞掉，但 `CompilationHaltedError` 必然抛出。

`DiagnosticSink` 相应加固：

- `overflowPolicy: 'halt'`（规范编译路径）容量耗尽即基础设施停机，不截断、不丢弃。
- `overflowPolicy: 'evict'`（默认，运行时有界日志）只淘汰 info/warn，**永不丢弃 error/fatal**。
- 去重键包含错误码、来源标识、起止偏移、定义标识、JSON 路径与消息键，避免不同位置的同类问题被折叠成一条。
- fatal 通知回调即使正常返回，也必须抛出 `DiagnosticHaltError`；停机后任何 `emit` 都继续抛错。

## 七、输出租约与原子发布

`OutputLease` 是一次性写入能力：

1. 所有写入只能进入本次编译私有的暂存区。
2. 任何候选拒绝或基础设施停机都把租约置为 `revoked`；被撤销的租约不能写入、验证或发布。
3. 发布前逐项比对暂存字节的长度与散列。
4. 发布是原子的：要么完整成为新 generation 与已提交清单，要么保持上一份清单不变。
5. 运行时只读取已提交清单，不扫描暂存目录。
6. 暂存区无法确认清理时移入隔离区并报 `CACHE_ROLLBACK_FAILED`；隔离数据永不参与缓存命中。

`InMemoryArtifactStore` 提供 `injectFailure` 与 `publishLeaksPartialState`，用于对 `createStaging`、`writeStaging`、`syncStaging`、`publish`、`discardStaging`、`quarantine` 逐点注入故障，并用 `verifyNoPartialGeneration()` 断言不存在半成品。

## 八、编译状态机

```text
intake → parse → schema →（必要时 migration）→ semantic/precedence/reference/composition
      → canonicalization（确定性 + 往返验证）
      → commit-recheck（提交锁内：基线比对 + 全量复核）
      → staging-write → publish → committed
```

- 迁移在隔离候选值上执行，不修改原文档与活动注册表；迁移成功本身不授予发布资格，迁移结果必须重新走完整流水线。
- 提交锁内重新计算基线；基线变化即 `BASELINE_STALE`，要求完整重验，而不是只重验改动部分。
- 提交前复核失败即 `COMMIT_RECHECK_FAILED`，撤销整批候选。

### 语义产物与来源溯源分离

规范产物拆成两份，原子发布：

- `model.canonical.json`：语义身份，**不含来源跨度**。
- `model.provenance.json`：完整来源记录。

原因：只有排版或键序不同的等价候选必须产出字节一致的规范输出。早期实现把跨度写进语义产物，导致等价候选散列不同；这是实现过程中发现并修正的真实缺陷。语义身份散列只覆盖前者。

## 十、已知未完成项

1. **宿主真实文件系统实现**：当前只提供 `InMemoryArtifactStore`。真实 `fsync` + 同卷原子重命名的宿主适配器尚未实现。
2. **跨进程隔离**：设计要求编译工作进程与运行时进程分离，当前实现是同进程内的会话隔离（租约、隔离工作区、原子发布均已具备，进程边界未落地）。
3. **集成契约注册表**：`IntegrationContract` 结构与拒绝路径已就位，但核心机制、空间物品、AI 三个提供方契约尚未汇合，依赖它们的候选按契约缺失拒绝。
4. **术语检查范围**：目前检查 `layerName`/`term`/`terminology` 三个声明字段，尚未对自由文本描述做全文术语扫描。
5. **组合合并规则**：冲突检测已实现（无授权合并规则即拒绝），但 `mergeRules` 的具体合并算子尚未实现，仅作为“已声明授权”标记。
