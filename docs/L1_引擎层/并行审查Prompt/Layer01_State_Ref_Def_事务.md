## 目标
按照**哲学宪法**原则，对内核Spec第1层进行原则性彻查，不是代码审查。

## 宪法铁律（必须逐条核对）

### 一、术语铁律
检查以下术语是否使用正确：
- ✅ 使用：引擎层（Kernel）、Entity、Component、Op、Expr、Hook、Instance
- ❌ 禁用：模板、内容层、Layer 1/2/3（除非配合架构图）

### 二、三层架构边界
第1层属于**引擎层**，必须满足：
- 只知道：实体、状态、关系、动作、规则
- **不知道**：武器、技能、HP、AP等具体玩法语义
- 禁止在第1层出现 `hp`、`ap`、`armor`、`shop` 等玩法词汇

### 三、完备性判据（检查任何新增原语）
一个能力要进引擎层，必须同时满足：
| 判据 | 含义 |
|------|------|
| **不可绕过** | 缺了它，创作者只能改引擎代码 |
| **三处复用** | 至少3个互不相关的表层机制会用到它 |
| **不含语义** | 它不知道自己在服务什么玩法 |

## 第1层审查清单

### 1.1 Ref前缀体系
```
e:Entity, i:Item, n:Node, l:Link, c:Container, s:Slot, 
a:Attachment, g:Agent, d:Def, w:World
```
- [ ] 前缀集合是否封闭？（机械校验可行性）
- [ ] w:0 是否被正确定义和引用？
- [ ] 新增前缀是否有宪法依据？

### 1.2 值域约束
- [ ] Value类型定义是否符合三条完备性判据？
- [ ] NaN/Infinity 拒绝写入是否有设计依据？
- [ ] props自由区与结构区的边界是否清晰？

### 1.3 Entity/Item/Attachment运行时结构
- [ ] `node`与`slot`互斥不变量是否有明确说明？
- [ ] Attachment.target泛化到Node/Link/World是否有三处复用例？
- [ ] `grantedBy`是否解决了一个原本需要写代码的问题？

### 1.4 Agent归位
- [ ] Agent的`controls`、`knowledgeScope`、`omniscient`是否消灭了至少3类专用代码？
- [ ] GM作为普通Agent是否有完整的逻辑支撑？
- [ ] 控制权转移是否真的是纯数据操作？

### 1.5 Def继承体系
- [ ] 多重混入是否会导致语义冲突？
- [ ] 继承展开是纯加载期还是涉及运行时？
- [ ] `abstract`标记是否有被滥用的风险？

### 1.6 Tag系统
- [ ] Tag是否完全取代了硬编码分类？
- [ ] 是否存在Tag无法表达的分类需求？（如果有，说明需要新增原语）

### 1.7 事务模型
- [ ] 事务边界的定义是否与Decision/Intent解耦？
- [ ] rollback机制是否有完整的不变量保证？

## 决策记录检查

对于第1层的每一项设计决策，验证：
1. **为什么不能绕过？**
2. **有哪些复用场景？**
3. **它包含玩法语义吗？**

如果任何一个问题答案不明确，标记为**风险项**。

## 思维实验清单（用例多样性）

请针对第1层设计以下思维实验：

### 边界情况
1. 一个Entity同时在node和slot中会怎样？（应该被不变量禁止）
2. 如果不提供Ref前缀，世界状态会如何崩溃？
3. 在没有Agent概念的情况下，如何实现"中途换人"？

### 反模式检测
1. 在第1层中，哪些结构可能被用来作弊/破坏游戏？（外挂风险）
2. 是否有任何字段允许存储"可执行代码"？
3. props自由区是否可能被滥用导致不可恢复的状态？

### 扩展性边界
1. 如果需要添加"第15种Ref前缀"，需要改多少处？
2. Tag系统能否支持带参数的标签（如"武器.枪.霰弹.双管"）？
3. Def继承能否支持钻石继承？
