## 目标
按照**哲学宪法**原则，对内核Spec第6章（Flow执行流）进行原则性彻查。

## 宪法铁律

### 核心约束
- Flow是**步骤执行器**，不是解释器
- step预算是防止无限循环的机械约束
- Flow与Hook是正交机制（Flow调用Action，Action可能触发Hook）

### 完备性判据
Flow能力必须满足：
| 判据 | 含义 |
|------|------|
| 不可绕过 | 没有它，AI搜索无法运行 |
| 三处复用 | AI搜索、回放、多方决策都需要 |
| 不含语义 | 不知道在跑什么玩法 |

## 第5层审查清单

### 6.1 FlowExecutor

#### 执行模型
- [ ] Flow是否按agent顺序串行执行？
- [ ] "同时决策"如何建模？（等效顺序？并行采样？）
- [ ] step预算如何分配？（固定？按agent？按phase？）

#### 预算管理
- [ ] step超限后的行为是什么？（abort？warning？继续？）
- [ ] 不同phase的step消耗是否不同？
- [ ] prefab.spawn是否计入step预算？

### 6.2 AI搜索支持

#### 影子流机制
- [ ] 搜索时是否创建影子random流？
- [ ] 影子流是否与主流完全隔离？
- [ ] 搜索回退时是否正确恢复状态快照？

#### 评估函数
- [ ] 评估函数如何调用？（在Flow内？外部？）
- [ ] 评估函数是否能访问完整状态？

### 6.3 Flow与Hook的关系

- [ ] Flow执行Action是否会触发Hook？
- [ ] Hook的执行是否计入step预算？
- [ ] Hook中的副作用是否在Flow层面可见？

### 6.4 多方决策同步

- [ ] "所有玩家同时决策"如何实现？
- [ ] 决策超时如何处理？
- [ ] 决策冲突如何解决？

## 决策记录检查

| 决策 | 理由 | 风险 |
|------|------|------|
| step预算机制 | 防止无限循环/超时 | 低 |
| 影子流隔离 | AI搜索需要可回退 | 中 |
| 串行执行 | 确定性优先 | 低 |

## 思维实验清单

### 边界情况
1. step预算耗尽时正在执行的Action是否完整？
2. 两个agent互相等待决策会死锁吗？
3. 影子流搜索期间主状态被修改会怎样？

### 反模式检测
1. 能否通过构造极长Action序列耗尽step预算攻击服务器？
2. 影子流是否可能被用来"预览"对手决策？
3. 能否通过Hook修改step预算绕过限制？

### 扩展性测试
1. 能否支持"回合制"和"实时制"两种Flow模式？
2. step预算能否由玩法包动态调整？
3. 能否支持"异步Flow"（玩家不在线时继续AI）？
