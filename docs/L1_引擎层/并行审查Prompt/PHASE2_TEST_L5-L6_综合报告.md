## 三、TEST_L6 Decision决策树

### 3.1 结果统计（修复后）

| 分类 | 原PASS | 原UNDEF | 修复后 |
|------|--------|---------|--------|
| A: 基本决策流转 | 2 | 8 | **10 PASS** |
| B: 超时与默认答案 | 4 | 2 | **6 PASS** |
| C: 决策effect与解析 | 3 | 1 | **4 PASS** |
| D: 嵌套与并发 | 4 | 0 | **4 PASS** |
| E: 边界情况 | 3 | 3 | **6 PASS** |
| **总计** | **16** | **14** | **30 PASS（100%）** |

### 3.2 核心发现与修复

原14条UNDEF根因：**测试用例基于与Spec §7.5不同的设计维度**。

| 维度 | 测试假设 | 原Spec | 修复方案 |
|------|---------|--------|---------|
| 选项约束 | minCount/maxCount | quorum | 新增 `selection.mode + minCount/maxCount`，与quorum正交并存 |
| 超时机制 | ttl（相对） | deadline（绝对） | `timeout.type: 'deadline'\|'ttl'` 二者皆支持 |
| 默认答案 | 数组 | 单值 | `defaultAnswer: string \| string[]` |
| 答案存储 | 数组 | Record | `answers: Record<actorId, string\|string[]>` |
| 撤销/修改 | 需要 | 无 | 新增 `decision.retract` + `answer(replace)` |
| askee失效 | 未定义 | 未定义 | `onAskeeInvalid: 'waive'\|'replace'\|'abort'` |

### 3.3 合并入Spec的变更清单

| 位置 | 变更 |
|------|------|
| §7.5 Decision/DecisionDef/DecisionOption接口 | 扩展selection/merge/timeout/onAskeeInvalid/retractable字段 |
| §7.5 字段语义表 | 补齐全部新字段语义 + retract语义 + onAskeeInvalid降级策略 |
| §7.5 校验表 | 创建期（E_DEC_*）+ 答题期（E_DEC_*）分层校验 |
| §4.6 不变量 | 新增决策有终/答案合法/完成充分 三条 |
| §13.4 错误码 | E_DEC_*运行期错误码体系 |
| §13.7 加载期校验 | DecisionDef静态校验（E_LOAD_*） |
| Ops签名 | open/answer/retract/resolve/void/queryActions |

### 3.4 命名统一（关键一致性修复）

修复过程中发现两套并存命名，已统一到Spec正文权威命名：

| 早期命名（已废弃） | 最终命名（权威） |
|-------------------|-----------------|
| E_DEC_COUNT_UNDERFLOW | E_DEC_COUNT_BELOW_MIN |
| E_DEC_COUNT_OVERFLOW | E_DEC_COUNT_EXCEEDS_MAX |
| E_DEC_DUPLICATE | E_DEC_DUPLICATE_CHOICE |
| count: {min,max} | selection.minCount/maxCount |

**加载期 vs 运行期分层**：`E_LOAD_*`（DecisionDef静态校验）与 `E_DEC_*`（运行期防御兜底）命名域不同、互补而非重复。已在§13.7加注说明。

| 指标 | TEST_L5 | TEST_L6 |
|------|---------|---------|
| 用例数 | 47 | 30 |
| 第一轮 PASS | 30 (64%) | 4 (13%)（另一口径 16） |
| **第二轮终值** | **47 (100%)** | **30 (100%)** |
| UNDEF性质 | 语义待定义 | 结构性缺失 |
| Spec变更 | **§3.1.2 ~ §3.1.6 五个新小节**（原记"无，待P0补充"已过期） | §7.5 七处合并完成 |
| 完备性影响 | 边界语义已明确 | 核心机制已完备 |

**洞察（当时）**：Decision作为核心机制，缺口必须立即修复以保证完备性；Expr的边界语义（溢出、精度）属于可暂缓的次要缺口，不阻塞核心完备性。这符合宪法"保证基层完备性"的优先级判断。

**后续结果**：两类缺口最终都在同一天内彻底修复。因此"可归档的次要缺口"这个定位只反映当时的
排期优先级，**不构成"L5 缺口至今未补"的依据**。
