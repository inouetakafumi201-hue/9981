## 执行方式

### 方式1：手动并行分发（推荐 — 真正的并行）

开 10 个独立会话，每个会话粘贴一个 Prompt 文件的全部内容，前面加一句：

```
请执行以下任务：

[粘贴 Prompt_LX_*.md 的全部内容]
```

### 方式2：使用 Agent 工具后台并行

```typescript
const tasks = [
  ['L1L2层属性测试', 'Prompt_L1L2_Entity组件原语.md'],
  ['L3层属性测试',   'TEST_L3_Ops事务守恒性.md'],
  ['L4层属性测试',   'TEST_L4_Hook五阶段竞争.md'],
  ['L5层属性测试',   'TEST_L5_Expr表达式求值.md'],
  ['L6层属性测试',   'TEST_L6_Decision决策树.md'],
  ['L7层属性测试',   'Prompt_L7_微场景拓扑.md'],
  ['L8层属性测试',   'Prompt_L8_Relation关系附属.md'],
  ['L9层属性测试',   'Prompt_L9_Phase相位流程.md'],
  ['L10层属性测试',  'Prompt_L10_Intent意图系统.md'],
  ['L11层属性测试',  'Prompt_L11_诊断体系.md'],
];

for (const [desc, file] of tasks) {
  Agent({
    description: desc,
    prompt: `请执行以下任务：\n\n${readFile(file)}`,
    run_in_background: true
  });
}
```

**每个 Agent 独立工作目录**，互不干扰（含后续追加的 L12/L13，共 12 个）：
```
kernel-l1l2-test/  kernel-l3-test/  kernel-l4-test/  kernel-l5-test/  kernel-l6-test/
kernel-l7-test/    kernel-l8-test/  kernel-l9-test/  kernel-l10-test/ kernel-l11-test/
kernel-l12-test/   kernel-l13-test/
```

> 「独立工作目录、互不干扰」是并行的前提，同时也是跨层一致性无法被这批测试覆盖的原因
> —— 见上文 T-03。

## 每个 Agent 的强制执行流程

```
Step 1  搭建环境      npm init + npm install fast-check typescript @types/node tsx vitest
Step 2  写实现        完整可运行的TS，禁止 TODO / 占位符 / 伪代码
Step 3  写不变量检查器 checkInvariants() 返回违规数组
Step 4  写属性测试    fast-check，主测试 numRuns: 100000
Step 5  跑测试        npx vitest run
Step 6  记录失败      保存最小复现序列 + 违反的不变量ID
Step 7  修Bug         改实现，重跑，直到 100% 通过
Step 8  出报告        LX_TEST_REPORT.md
```

**关键契约**：
> **Op 失败是合法的，不变量违反是不合法的。**
>
> 随机操作序列中任何一步都可以被拒绝（抛错/返回 `{ok:false}`），这不算测试失败。
> 测试失败的唯一判据是：执行完序列后 `checkInvariants()` 返回了非空数组。
> 这是随机序列测试有意义的前提 —— 世界状态永远不能进入非法态。

## 注意事项

1. **不要跳过测试** — 必须真正 `npx vitest run`，报告里粘贴真实输出。伪造结果等于任务失败。
2. **不要偷工减料** — 禁止 `// TODO`、`// 省略`、占位符、伪代码（CLAUDE.md §3.1）。
3. **不要合并 Agent** — 各任务必须独立运行，不能在一个会话里顺序做完。
4. **不要降低 numRuns** — 主属性测试固定 100,000 次。跑得慢就等，不许改小。
5. **遇到 Spec 未定义** — 标 UNDEF 上报，不要自己发明规则然后当成"通过"。
6. **用代码说话** — 报告里每一条结论都要能追溯到一次真实的测试运行。
