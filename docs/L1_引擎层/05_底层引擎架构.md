# 底层引擎架构设计

> **架构目标**：保证未来 **0 追加** —— 任意玩法细节都能被表达为有限数据结构上的状态、关系、动作、效果与规则组合，而不需要新增第二套结算系统。

---

## 架构哲学

### 核心理念

**层层叠叠的接口外包和模块化**：
- 不只是把武器对象模块化
- 要对整个类别提取范式封装对象
- 把整个伤害判定模块化
- 连整个被动结算都要模块化
- **把估值函数（得分计算）纳入底层服务**，AI 模块只消费评分接口

### 设计目标

> 任意玩法细节，都能被表达为有限的**三大底层结构**（节点、物品、实体）上的状态、关系、动作、效果与规则组合，而不需要新增第二套结算系统。

---

## 三层架构

### 1. 内核层（Kernel Layer）
**职责**：保证任何合法配置都能确定地执行，不崩溃、不死循环、不产生非法状态

- 三大底层结构的生命周期管理（节点、物品、实体）
- 容器关系维护
- 动作验证与执行
- 状态一致性保证
- **估值函数服务**（为 AI 和规则提供评分）

### 2. 规则范式层（Rule Paradigm Layer）
**职责**：提供库存、伤害、移动、乘载、状态、回合、目标选择等可复用模块

- 通用机制实现（背包、战斗、移动、睡眠/起床）
- 标准流程定义（射击流程、精密交互流程、处决流程）
- 能力组件库（武器谱型、防具、状态效果）

### 3. 玩法包层（Game Mode Layer）
**职责**：定义大逃杀、夺旗、追逐、合作生存等具体规则

- 出生规则
- 胜利条件
- 特定规则集
- 数值约束

## 三大底层数据结构

**这是整个引擎的基石，三者平级且不可混用。**

### 1. 节点（Node）

**定义**：场景空间的离散单位，构成地图拓扑骨架。

```typescript
interface Node {
  id: string;
  type: 'large' | 'medium' | 'small' | 'transition';
  connections: Connection[];  // 最多 5/4/3 条（按类型）
  containedItems: ItemId[];   // 散落物品
  containedEntities: EntityId[]; // 停留的实体
  properties: {
    coverLevel?: number;      // 掩体等级
    hazard?: HazardType;      // 环境危害（火/毒/水/电）
    noiseDamping?: number;    // 声音衰减系数
  };
}

interface Connection {
  target: NodeId;
  portal?: EntityId;  // 门、窗等实体（如果有）
  cost: number;       // 通行 AP 消耗
  condition?: Condition; // 通行条件（如需要钥匙）
}
```

**关键规则**：
- 节点不能移动
- 节点只能通过 `connections` 与其他节点相连
- 散落物品清理：所有活体离开该节点后，`containedItems` 清空

### 2. 物品（Item）

**定义**：可以被放入容器槽位的对象，没有自主行为。

```typescript
interface Item {
  id: string;
  type: ItemType;  // 'weapon' | 'consumable' | 'accessory' | 'material'
  slots: number;   // 占用槽位数（1 或 2）
  properties: Record<string, any>; // 类型特定属性
}

// 武器物品
interface WeaponItem extends Item {
  type: 'weapon';
  properties: {
    profile: BalisticProfile;  // 谱型（手枪/霰弹枪/步枪等）
    damage: number;
    attackShape: 'single' | 'spread' | 'area';
    twoHanded: boolean;  // 使用时需空一只手
    attachments?: {
      scope?: ItemId;
      grip?: ItemId;
      magazine?: ItemId;
      silencer?: ItemId;
    };
  };
}

// 防具物品
interface ArmorItem extends Item {
  type: 'consumable';
  subtype: 'armor';
  properties: {
    tier: 'light' | 'medium' | 'heavy';
    durability: 'intact' | 'worn' | 'broken';
  };
}
```

**关键规则**：
- 物品**不是**实体的子类型
- 物品与实体必须通过**转换**才能实现状态互换（如折叠自行车 ↔ 展开的自行车）
- 物品不能直接与节点/实体交互，必须先进入某个容器

### 3. 实体（Entity）

**定义**：与节点、物品并列的底层结构，能占据空间、创建微型场景、执行动作。

```typescript
interface Entity {
  id: string;
  category: EntityCategory;  // 见下文分类
  location: NodeId;          // 所在节点
  microScene?: MicroScene;   // 创建的微型场景（如果有）
  components: Component[];   // 组件化能力
  lifecycle: 'active' | 'disabled' | 'removed';
}

type EntityCategory = 
  | 'living'      // 活体（玩家、NPC）
  | 'vehicle'     // 载具
  | 'container'   // 容器（柜子、死亡背包）
  | 'portal'      // 门户（门、窗）
  | 'bed'         // 床
  | 'environmental'; // 环境实体（爆炸物、陷阱）

// 活体实体
interface LivingEntity extends Entity {
  category: 'living';
  components: [
    HealthComponent,
    StaminaComponent,
    InventoryComponent,
    APComponent,
    StateComponent
  ];
}

// 载具实体
interface VehicleEntity extends Entity {
  category: 'vehicle';
  components: [
    MovementComponent,
    ContainerComponent,  // 货舱
    MicroSceneComponent  // 车内空间
  ];
}

// 死亡背包实体
interface DeathBackpackEntity extends Entity {
  category: 'container';
  components: [
    ContainerComponent
  ];
  properties: {
    readOnly: true;  // 只出不进
    capacity: 2 | 4 | 6; // 取决于玩家背包拓展状态
  };
}

// 床实体
interface BedEntity extends Entity {
  category: 'bed';
  components: [
    MicroSceneComponent,  // 床上空间
    SpawnPointComponent   // 重生点（如果是固定床）
  ];
  properties: {
    portable?: boolean;  // 是否可折叠/移动
  };
}
```

**关键规则**：
- 只有**活体**（`category: 'living'`）参与：
  - 散落物清理判定（所有活体离开节点 → 物品清空）
  - 世界清理（移除 `lifecycle: 'removed'` 的实体）
  - 自主行动判断
- 实体可以创建**微型场景**（下节）
- 实体不能嵌套容纳另一个实体作为子对象（容器槽位只能放物品）

## 微型场景（Micro Scene）

**定义**：由实体创造的局部接触空间，附属于所在节点。

```typescript
interface MicroScene {
  id: string;
  owner: EntityId;  // 创建者（活体、载具、柜子等）
  parentNode: NodeId; // 所属天然场景
  occupants: EntityId[]; // 当前进入者（活体）
  properties: {
    fire?: boolean;
    water?: boolean;
    oil?: boolean;
    electricity?: boolean;
  };
}
```

**核心机制**：
- **"找到 X" = 进入 X 的微型场景**（花费 1 AP）
- 同一微型场景内的活体**共用一个接敌面**
- 小场景中所有活体天然共处一个微型场景（无需"找到"）
- 大/中场景中，活体默认不在同一微型场景
- 微型场景随父节点销毁（缩圈时）

## 动作系统（Action System）

### 动作定义

**铁律**：一个动作永远消耗 **1 AP**。所谓"2 AP 动作"实际是两个 1 AP 动作 + 中间状态。

```typescript
interface Action {
  id: string;
  name: string;
  initiator: EntityId;      // 声明者
  actor: EntityId;          // 执行者（通常相同）
  source?: EntityId;        // 能力来源（武器/技能）
  targets: EntityId[];      // 目标
  
  // 前置条件
  requirements: Condition[];
  
  // 资源消耗
  costs: {
    ap: 0 | 1;  // 只有这两个值
    stamina?: number;
    items?: ItemId[];
  };
  
  // 效果
  effects: Effect[];
  
  // 失败处理
  onFailure?: Effect[];
  
  // 时序
  timing: 'immediate' | 'deferred';  // 立即 | 延迟（需等待结算）
  
  // 可见性
  disclosure: 'public' | 'hidden' | 'revealed_on_execute';
}
```

### 标准流程（复用单位）

#### 射击流程
```
1. [1 AP] 瞄准 + 射击
   - 前置：持有远程武器，目标在射程内
   - 计算距离 DC（根据谱型 + 距离范式）
   - 投 d6 ≥ DC → 命中
   - 超出 DC 2+ → 伤害提升
   - 效果：造成伤害

无"瞄准"作为独立动作，射击是原子操作。
```

#### 精密交互流程（撬锁示例）
```
1. [1 AP] 开始撬锁
   - 效果：自身获得 [撬锁中] 状态，绑定目标门

2. [1 AP] 完成撬锁（下回合或本回合剩余 AP）
   - 前置：自身有 [撬锁中] 状态
   - 效果：门解锁，移除 [撬锁中] 状态

中断条件：移动、受击、主动取消 → [撬锁中] 状态消失，进度作废
```

#### 令其长眠流程
```
1. [1 AP] 令其长眠
   - 前置：目标零血倒地，自身与目标同微型场景
   - 效果：
     - 目标死亡
     - 自身体力回满
     - 生成死亡背包实体于目标所在节点
```

## 估值函数服务（Evaluation Service）

**归属**：内核层服务，不属于 AI 模块。

**职责**：为 AI 搜索（αβ 剪枝）和规则判定提供统一的评分接口。

```typescript
interface EvaluationService {
  // 活体当前局势评分
  evaluateEntity(entity: LivingEntity, context: GameState): number;
  
  // 动作预期收益评分
  evaluateAction(action: Action, context: GameState): number;
  
  // 位置价值评分
  evaluatePosition(node: NodeId, context: GameState): number;
  
  // 物品价值评分
  evaluateItem(item: Item, holder: EntityId, context: GameState): number;
}

// 评分权重配置（可被玩法包覆盖）
interface EvaluationWeights {
  health: number;
  stamina: number;
  ap: number;
  weaponQuality: number;
  positionSafety: number;
  distanceToTarget: number;
  distanceToCircle: number;
}
```

**设计要点**：
- 评分函数**不包含搜索逻辑**，只返回数值
- AI 模块（αβ 剪枝）调用此服务，不自己实现估值
- 规则模块可调用此服务做决策（如 NPC 优先拾取高价值物品）

## 回合与时序系统

### 回合流程

```typescript
interface TurnSystem {
  phases: [
    'roll',      // 投点阶段：所有玩家同时投骰
    'resolve',   // 结算阶段：分配 AP，判定体力退还
    'action',    // 行动阶段：按 AP 从高到低依次行动
    'npc',       // NPC 阶段：按编号顺序行动
    'cleanup'    // 清理阶段：状态倒计时，触发持续效果
  ];
}
```

### 时序纯洁性原则

**禁止**：
- 回合外选择（不在自己回合的玩家不能做主动抉择）
- 异步等待（所有玩家 AP 耗尽或弃权才进入下一阶段）

**允许**：
- 被动触发（受击时盾牌自动格挡）
- 零费动作（不产生搜索分支）

## 规则范式层：可复用模块

### 1. 伤害结算模块

```typescript
interface DamageModule {
  // 计算最终伤害
  calculateDamage(
    base: number,
    attacker: EntityId,
    defender: EntityId,
    damageType: 'sharp' | 'blunt' | 'poison' | 'fire' | 'bullet',
    context: GameState
  ): number;
  
  // 应用伤害
  applyDamage(target: EntityId, amount: number, source: EntityId): void;
  
  // 检查防具
  checkArmor(defender: EntityId, damage: number): ArmorResult;
}

interface ArmorResult {
  blocked: number;
  penetrated: number;
  armorBroken: boolean;
}

// 防具规则表
const ARMOR_RULES = {
  light: {
    reduction: (dmg: number) => Math.max(dmg - 1, 0),
    breakOn: 1  // 受击一次破损
  },
  medium: {
    reduction: (dmg: number) => Math.max(dmg - 1, 1),
    breakOn: 1
  },
  heavy: {
    reduction: (dmg: number) => {
      if (dmg === 1) return 0;
      if (dmg === 2) return 1;
      if (dmg >= 3) return dmg - 1;
    },
    breakOn: 3  // 承受 3 伤时破损
  }
};
```
