# 引擎层（Kernel）职责边界定义

> **用途**：明确区分引擎层（Kernel）机制与基类层（Class）实例的边界，
> 防止 Agent 误读导致越权设计。
> **创建日期**：2026-08-04
> **术语更新**：2026-08-05（"根基层"→"引擎层"，"内容层"→"基类层"）

---

## 一、边界核心原则

### 1.1 引擎层 = 机制，基类层 = 实例库

| 层级 | 定义 | 例子 |
|---|---|---|
| **引擎层（Kernel）** | 通用游戏机制框架，不含任何具体游戏实例 | Op 注册表、Expr 引擎、Hook 调度、事务机制 |
| **基类层（Class）** | 具体实例定义，但不包含数值约束和玩法规则 | 武器实例、NPC行为实例、地图数据、玩法配置（去数值化） |

### 1.2 引擎层与基类层的铁律

```
✅ 引擎层可以做的：
- 定义通用的 Op 类型（如 entity.create、item.create）
- 定义通用的 Expr 语法（算术、比较、路径访问）
- 定义通用的 Effect 链机制（before/after Hook）
- 定义通用的 InvariantChecker 规则
- 提供原语（Primitives）：attach、detach、enter、exit、stack.split 等

❌ 引擎层禁止做的：
- 预设"一把枪应该如何表现"的语义
- 预设"NPC 应该有哪些状态"的枚举值
- 预设"哪种玩法模式是合法的"
- 为任何具体实体/物品/NPC 指定具体数值
```

## 二、引擎层模块职责清单

### 2.1 已实现的 Kernel 模块

```
src/core/kernel/
├── actions/       # Action 类型定义 + 基本动作原语（移动、攻击等的基础）
├── ai/            # AI 搜索机制（belief-slice、tiering、evaluate-guard）
│                  # ⚠️ 只提供 maxⁿ 搜索 + 认知切片机制，不含具体 NPC 行为
├── attachment/    # Attachment 挂载机制（attach/detach）
├── decision/      # 决策记录（DecidedItem 管理）
├── events/        # 事件系统（Event 生命周期）
├── expr/          # 表达式引擎（Expr 解析与求值）
├── flow/          # 流程控制（FlowInterpreter for DSL）
├── knowledge/     # 知识与感知（visibleTo、knowledgeScope）
├── ops/           # Op 注册表（entity.create、item.create 等）
├── persistence/   # 持久化机制
├── random/        # 随机数（Stamina、强力骰等）
├── safety/        # InvariantChecker、不变量校验
├── schedule/      # 回合调度（PhaseDef、PolicyDef）
├── state/         # 状态管理（WorldState、AgentState）
├── topology/      # 拓扑空间（五并列：Container/Relation/Node/Link/Transition）
├── testing/       # 测试工具（Fuzzer、Snapshot）
└── __tests__/     # 内核测试
```

### 2.2 每个模块的"可以"与"不可以"

#### `ops/` - 操作注册
```
✅ 可以：注册 entity.create、item.create、prop.set 等通用 Op
✅ 可以：定义 Op 的参数 schema 校验逻辑
✅ 可以：实现 Op 的 Effect 链调度
❌ 不可以：预设"武器必须在 ops 里注册"（这是基类层决定）
❌ 不可以：硬编码"载具类实体有特殊 Op"（这是基类层约定）
```

#### `actions/` - 动作原语
```
✅ 可以：定义通用的"进入场景"、"离开场景"、"拾取物品"等动作类型
✅ 可以：定义 AP 消耗规则（一个动作 = 1 AP）
✅ 可以：提供动作的合法性检查接口
❌ 不可以：预设"近战攻击"的具体参数（如伤害值、范围）
❌ 不可以：定义"霰弹枪射击"或"撬锁"等具体动作（基类层/玩法层负责）
```

#### `ai/` - AI 机制
```
✅ 可以：实现 alpha-beta / maxⁿ 搜索算法
✅ 可以：实现 belief-slice 认知切片（过滤 visibleTo）
✅ 可以：实现 tiering 精算/粗略分档机制
✅ 可以：实现 evaluate-guard 守卫校验
✅ 可以：提供 Def.tags 白名单过滤原语
❌ 不可以：预设"僵尸"的 AI 行为树（基类层）
❌ 不可以：预设"守卫"的追逐/巡逻逻辑细节（基类层）
```

#### `topology/` - 空间拓扑
```
✅ 可以：实现五并列拓扑（Container/Relation/Node/Link/Transition）
✅ 可以：实现 spread 预算扩散算法
✅ 可以：定义微型场景（MicroScene）的挂载/脱离机制
✅ 可以：定义过渡场景的阻挡逻辑
❌ 不可以：预设"地图最多 N 个节点"（基类层/地图编辑器决定）
❌ 不可以：预设"大场景有 5 个连接上限"（这是拓扑结构属性，基类层遵守）
```

#### `expr/` - 表达式引擎
```
✅ 可以：实现算术/比较/逻辑表达式
✅ 可以：实现路径访问（entity.props.x、inventory[0]）
✅ 可以：提供内置函数（min、max、count、filter）
❌ 不可以：硬编码"health > 0"是游戏内语义（玩法层决定表达式含义）
❌ 不可以：预设"只有玩家有 AP"（基类层决定）
```

#### `flow/` - 流程解释器
```
✅ 可以：实现 while/for/effect 等 DSL 语法
✅ 可以：强制 maxIter 预算防止死循环
✅ 可以：实现顺序/并行执行模式
❌ 不可以：预设"战斗流程"的步骤序列（玩法包决定）
```

## 三、引擎层对外接口

### 3.1 引擎层向基类层暴露的接口

```
┌─────────────────────────────────────────────────────────┐
│                      玩法层（Play）                       │
│  - 实例定义（武器实例、NPC实例、地图数据）                │
│  - 玩法配置（PolicyDef、ActionDef、带 Def.tags 标记）     │
└───────────────────────┬─────────────────────────────────┘
                        │ 通过这些接口接入
                        ▼
┌─────────────────────────────────────────────────────────┐
│                    引擎层（Kernel）                      │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────┐  │
│  │  Op 注册  │  │ Expr 引擎 │  │ Hook 链  │  │ 事务   │  │
│  └──────────┘  └──────────┘  └──────────┘  └────────┘  │
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌────────┐  │
│  │ AI 搜索  │  │ 拓扑空间 │  │ 感知系统 │  │ 回合调度│  │
│  └──────────┘  └──────────┘  └──────────┘  └────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 基类层必须遵守的引擎层规则

| 规则 | 来源 | 基类层必须 |
|---|---|---|
| 实体必须有 `kind` | `DefRegistry` | 是 |
| `abstract` 实体不可实例化 | `checkInstantiable` | 是 |
| `container.destroy` 触发级联清理 | `cascade-destroy` | 是 |
| Op 签名必须匹配 Def 注册 | `InvariantChecker` | 是 |
| `PolicyDef.mode:'search'` 使用 maxⁿ | `ai/search.ts` | 是 |
| 精算/粗略由 `Def.tags` 决定 | `ai/tiering.ts` | 是 |
| 微型场景占用者数量由拓扑约束 | `topology/*` | 是 |

### 3.3 基类层可自由定义的维度

| 维度 | 引擎层不预设 | 基类层自由决定 |
|---|---|---|
| 实体种类 | ❌ | ✅ 武器、载具、NPC、陷阱... |
| 伤害数值 | ❌ | ✅ 霰弹枪 3 点、拳头 1 点 |
| NPC 行为树 | ❌ | ✅ 巡逻、追逐、攻击序列 |
| 玩法模式 | ❌ | ✅ 竞技场、生存战、解谜 |
| 地图结构 | ❌ | ✅ 节点数、连接方式、场景类型 |
| 感知阈值 | ❌ | ✅ NPC 的 listenThreshold 等 |

## 四、越权警告标记

以下模式出现时，说明有人在引擎层做了基类层的工作：

### 🚨 警告：内核越权模式

```
❌ "kernel 里加一个 WeaponDef"
   → 武器定义是基类层职责，kernel 只提供 entity.create

❌ "在 ai/ 模块里写僵尸追逐逻辑"
   → AI 机制层只提供状态机原语，守卫范式由基类层配置

❌ "给 kernel 加一个 '霰弹枪' 类型"
   → 实体分类由 DefRegistry 的 kind 字段描述，不预设枚举

❌ "kernel 硬编码移动 AP=1"
   → AP 是 ActionDef 的属性，不是内核的全局常量

❌ "在 topology 里预设地图最大尺寸"
   → 拓扑是图结构，尺寸由基类层/地图编辑器控制
```
