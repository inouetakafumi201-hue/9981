# 图形化与 UI 设计

---

## 视觉风格定位

### 像素风 + 简笔画叠加

**核心理念**（已定案）：
- **交互组件**：像素艺术（高饱和度，32×32 或 64×64）
- **地图背景**：简笔画风格（清爽、低饱和度）
- **叠加层分离**：前景像素 + 背景草图，视觉层次清晰

**为什么这套组合？**
1. **UGC 友好**：数字绘图板 + AI 辅助即可创作大批量像素元素
2. **数据轻量**：一张地图 < 1MB
3. **对比鲜明**：高饱和像素元素在低饱和背景上一目了然
4. **工具支持**：游戏内创建工具可用简单像素填充 + 缩放
5. **风格统一**：像素网格天然约束 UGC 内容视觉一致

**不使用 Sprite Canvas 技术**（按你指示）。

## 五条视觉定律

**这是全游戏视觉一致性的基准。**

### 1. 七色语义映射

**严格绑定，不可混用**：

| 颜色 | 语义 | 应用场景 |
|---|---|---|
| **红色** | 生命、伤害、致命风险 | HP 血条、受伤、攻击、伤害数字、毒圈 |
| **蓝色** | 体力 / SP、机会 | 体力条、强力骰滑块、令其长眠（蓝色插头）、可处决闪烁 |
| **黄色** | 注意、感官线索 | 噪音、巡逻、警戒、AP 计数器与成本标签 |
| **橙色** | 进行中的动作、进度 | 撬锁中、精密交互进度、检定标记 |
| **紫色** | 关系约束、特殊动作 | 近战、擒抱、招架演出、对峙类约束 |
| **绿色** | 正面、安全的交互 | 拾取、已开的门、0 AP 免费标记、正面状态 |
| **灰白** | 中性、不可用 | 背景、非活动对象、置灰的不可用选项 |

**一个主色严格对应一类语义**，不得随意添加例外。

> **修订说明**：本节原为"三原色资源映射"（仅红/蓝/黄），已扩充为完整的七色语义体系。红/蓝/黄的原有绑定不变，其余四色将此前散落在各章节的临时用色（绿色 Free、橙色 Chk 等）纳入统一语义。

**与资源色的关系**：红/蓝/黄同时承担"资源"与"语义"双重职责（HP/SP/AP），这三者的资源绑定优先级最高；橙/紫/绿/灰白仅承担语义职责，不映射资源。

### 2. 边缘发光交互语法

**悬停高亮 + 边缘发光，不用传统按钮**：

> **命名规范（D-025）**：本方案的规范名称是**边缘发光交互提示**。不得用第三方游戏名作为技术方案的规范名称（此处曾写作"Among Us 风格"，已按 D-025 与 `wakeup-ui-animation` Spec Requirement 6.3 改为技术描述性命名）。

## 轮次栏（核心组件，D-036）

**轮次栏是图形化实现中最重要的 UI 组件。** 它把行动排名、生命值、体力值三项信息合并到一个常驻组件里，并同时充当投掷/比较动效的舞台。

### 形态与职责

| 项目 | 规范 |
|---|---|
| **位置** | **屏幕左侧常驻**，与持久状态栏一样始终可见，不随回合阶段切换而隐藏 |
| **形态** | 由若干玩家**头像 + 名字**构成的**纵向长方框**列表 |
| **内容** | 每一条同时显示该玩家的**生命值与体力值** → **兼任简易状态栏** |
| **动效舞台** | 投点动画、条形比较等动态效果**就在这几个状态条旁边完成**，不另开独立面板 |
| **排序** | 按行动轮排名，立即生效（每次变化后重新排序） |

### 视觉布局

```
┌──────────────────────┐
│ ① 👤 玩家A            │  ← 排名 + 头像 + 名字
│    ❤️❤️❤️❤️⬜  💧💧⬜⬜⬜ │  ← 血量（红）+ 体力（蓝）
├──────────────────────┤
│ ② 👤 玩家B            │
│    ❤️❤️❤️⬜⬜  💧💧💧💧⬜ │
├──────────────────────┤
│ ③ 👤 玩家C  （已行动） │  ← 变灰/降饱和（D-035）
│    ❤️❤️⬜⬜⬜  💧⬜⬜⬜⬜ │
└──────────────────────┘
        ↑
   动效在此区域右侧就地播放
   （投点、条形比较）
```

### 已行动者的标记（D-035）

- AP 用完的玩家**不从轮次栏移除**，只做**变灰或饱和度下降**处理
- 该效果的唯一语义是"他这回合已经行动过了"
- **不应做得过于显著**——不加大叉、不加"已结束"横幅

### 为什么合并成一个组件

轮次、血量、体力这三项是玩家**每一步决策都要参考**的信息，合并到同一个常驻组件里可以显著降低视线切换成本（低心智性）。

把投点动效放在状态条旁边，则让"**投出的点数 → 得到的 AP → 排名变化**"这条因果链在同一视觉区域内闭环，玩家不需要在弹窗和排名之间来回对照。

#### 零费菜单的触发时机（D-042 已定案）

此前"待定两方案"正式收敛为**两方案合并**：

| 阶段 | 界面状态 |
|---|---|
| **正常情况下** | 显示**有费用的菜单**，但提供一个**切换按钮**可切到**零费菜单**进行选择 |

```
正常情况（还有 AP）：
┌─────────────────────────────────────┐
│ 可用动作 (剩余 AP: 2)   [切换到零费] │  ← 切换按钮
├─────────────────────────────────────┤

┌─────────────────────────────────────┐
│ 零费动作                             │
├─────────────────────────────────────┤
│ [🗑️ 丢弃手枪] 0 AP                  │
│ [💊 使用绷带] 0 AP                   │
├─────────────────────────────────────┤

└─────────────────────────────────────┘
```

### 头顶弱点图标（D-031）

**弱点信息对所有人完全公开**，不需要消耗 AP 侦察。

| 项目 | 规范 |
|---|---|
| **呈现** | 弱点图标**常驻飘在角色头顶** |
| **详情** | 鼠标悬停时显示克制关系补充说明 |
| **渲染层** | 实体层之上（建议 Z-Index 5 附近，与边缘发光同层或略高） |

> **设计理由**：弱点系统的价值在于"有意识地针对"。把弱点做成需要额外获取成本的隐藏信息，会让针对性攻击退化为运气，也违背低心智性——玩家不该为了查一个静态属性反复操作 UI。

### 招架状态：无任何标识（D-032）

**招架是真隐藏信息**——UI 上**不显示任何"待机/准备"标识**。这是与瞄准状态（D-033 红点线）的关键区别。

### 柱状图：资源三色复用

**生命 / 体力 / AP 统一用柱状图表示**（红/蓝/黄，见视觉定律 1 的资源绑定）。生命与体力两条同时显示在**轮次栏**的每一条目内（D-036）：

```
竖向柱状图（像素风格）：

❤️❤️❤️❤️❤️  ← 5 个红色方块（满血）
❤️❤️❤️⬜⬜  ← 3/5（受伤）
❤️⬜⬜⬜⬜  ← 1/5（濒危）

💧💧💧💧💧  ← 5 个蓝色方块（满体力）
💧💧⬜⬜⬜  ← 2/5（消耗中）

⚡⚡⚡⬜⬜  ← 3 AP（本回合）
⚡⬜⬜⬜⬜  ← 1 AP（即将耗尽）
```

**动画**：
- 受伤：红色方块闪烁 → 消失
- 恢复：灰色方块填充为彩色
- 消耗体力：蓝色方块透明度降低 → 消失
- 零挫败退还：消失的蓝色方块瞬间恢复

### 瞄准状态的红点线（D-033）

`[瞄准中]` 状态**可见，但低显著性**。

| 项目 | 规范 |
|---|---|
| **触发方式** | 鼠标**悬停**在某个角色上 |
| **表现** | 若该角色正在瞄准，显示一条**红点线**指向其瞄准目标 |
| **绘制** | 起点 = 瞄准者，终点 = 目标，红色点线/虚线，**仅悬停时出现** |
| **禁止** | **不使用头顶感叹号**等强提示 |

```
悬停玩家 B 时：
   👤B · · · · · · · ▶ 👤C
        ↑ 红点线（B 正在瞄准 C）
```

> **设计理由**：两步流程的远程武器必须让对手有机会反应，否则"反应窗口"名存实亡。但用强提示（感叹号）会让规避变成无脑操作，改为"需要主动看一眼"保留了观察成本，同时不构成信息壁垒。

> **对照**：招架是**真隐藏**（无任何标识，见 D-032），瞄准是**低显著性公开**。两者不可混用同一套表现。

## 技术实现建议

### 渲染层级

```
Z-Index 分层：
  0: 背景图（简笔画）
  1: 节点区域填充
  2: 门户图标
  3: 地面物品
  4: 实体（玩家、NPC、载具）
  5: 悬停高亮 / 边缘发光
  6: UI 面板（半透明遮罩）
  7: 弹出菜单
```

### 动画规范

- **移动**：棋子沿路径滑动（0.3 秒）
- **攻击**：红色射线 + 目标闪烁（0.2 秒）
- **拾取**：物品飞向背包（0.2 秒）
- **受伤**：血条减少 + 红色闪烁（0.3 秒）
- **倒地**：人物旋转躺下（0.4 秒）
- **令其长眠**：蓝色光效 + 体力条瞬间填满（0.5 秒）
- **上车 / 下车**：车辆图标高亮 + 角色淡入淡出（0.2 秒）
- **撬锁完成**（精密交互完成）：锁图标变绿 + 短促闪烁（0.2 秒）
- **蹲下 / 起立**：角色高度变化（0.2 秒）

### 全屏动画清单（D-026 + D-032）

全屏骨骼动画（0.5-1 秒）**仅限四项**低频、仪式感强的动作：

| 动作 | 触发条件 |
|---|---|
| **翻窗** | — |
| **跳窗** | — |
| **令其长眠** | 对零血倒地目标处决 |
| **招架触发** | **仅当被近战攻击时**（D-032 新增） |

**招架的三种结算表现**：

| 情况 | 表现 |
|---|---|
| 被近战攻击 | **全屏动画**（擒拿/招架演出，紫色语义） |
| 被远距离伤害命中 | **静默失效**，无动画、无提示 |
| 受到无法招架的伤害 | **静默失效**，无动画、无提示 |

> **为什么静默**：静默打断保证招架不会因为一次远程流弹，就给对手提供免费的信息反馈（招架是真隐藏信息）。
