## 场景节点分类

### 空间的两套正交坐标

**坐标一：天然空间的三档 + 过渡（构成地图骨架）**

```
大场景 / 中场景 / 小场景  ← 由地图作者划定
过渡场景                  ← 连接用，通常不可长期停留
```

**坐标二：微型场景（附属层）**

```
微型场景  ← 不是天然的，由实体创造，附属于某个天然场景
```

**关键逻辑**：微型场景**没有 owner 字段**——它是按占用者存续的普通 Node，创建/卸载完全由占用者数量的现查结果驱动。唯一记录触发来源的字段是 `props.creator`（写入一次，仅供溯源）。

---

### 1. 大场景（Large Scene）

**特征**：
- 最大连接数：≤5 个
- 可作为出生点
- 空间开阔，容纳多人

**规则**：
- 重武器/负重在此移动 +1 AP
- 两个玩家同时在此，需要花 1 AP "找到"对方才能交互
- 战略缓冲带，适合重整旗鼓、搜刮资源

**示例**：大操场、教学楼整栋、食堂广场

---

### 2. 中场景（Medium Scene）

**特征**：
- 最大连接数：≤4 个
- 不能作为出生点
- 标准战术空间

**规则**：
- 移动消耗正常（1 AP）
- 两个玩家同时在此，需要花 1 AP "找到"对方

**示例**：物理实验室、食堂一楼、教室

---

### 3. 小场景（Small Scene）

**定义**：天然空间的最小一级，遵循大/中/小分类。**不是**"微型场景"。

**特征**：
- 最大连接数：≤3 个
- 天然存在，由地图作者划定
- 选择密度最低，是天然的堵桥点与掩体
- 通常伴随高价值资源

**规则**：
- 移动消耗正常（1 AP）
- 小场景内**所有活体共处小场景自带的共享微型场景**（小场景节点固有属性）
- **空旷地禁入**：小场景内禁止创建个人微型场景，"来到空旷地"按钮复用 = 移动到共享微型场景
- 贴身成本降为 0 AP（因为已在同一微型场景）
- 没有缓冲，进入即意味着白刃战

**示例**：楼梯间、枪店柜台、厕所

> 注意：**车内、柜子里不是小场景**，它们是实体创造的微型场景。

---

### 4. 微型场景（Micro Scene）

> **人机交互边界（2026-08-26）**：微型场景不是玩家需要理解或主动选择的规则对象。玩家跨天然场景时直接点击高亮场景框；玩家在同一天然场景内移动时直接点击实体脚底的泛光圈。个人空旷地不提供独立动作、按钮或高亮目标，由运行期在 `entity.place` 容纳判定中自动创建或复用。

**定义**：**不是天然的，是由实体或过渡场景创造的**局部接触空间。它与大/中/小三档正交，附属于某个天然场景。

**特征**：
- 由某个实体（活体、载具、柜子等）或过渡场景生成
- 依附于所属的天然场景，不能脱离父场景独活
- 是近战与直接交互的**唯一空间前提**

**微型场景的三种创建者**：

| 创建者 | 创建时机 | 微型场景归属 |
|--------|----------|-------------|
| **活体** | 从其他场景进入大/中场景且运行期判定需要容纳时 | 个人私有；运行期自动创建，非玩家动作 |
| **过渡场景** | 门/窗创建 1-2 个（平行双侧，垂直单侧） | 共享（两侧各一） |
| **小场景节点** | 自带一个 | 共享（所有活体） |

> **点状微型场景 / 动态图形化的衔接口（2026-08-14）**：从素材工作流一期讨论起，本项目确认 **微型场景在动态图形化层是「点状」的**——它是围绕"有明确地图位置的实体/场景"展开的局部接触空间，视觉上形成**扎堆而非散乱**的点，反哺玩法逻辑；若没有微型场景与 ORCA，游戏会退化为网格 / JRPG 站点逻辑、"整个大地图爱站哪站哪"，图形化失去支撑。玩家心智无需含微型场景概念：同一天然场景 = 一个场景，不同天然场景因节点相连而可跨，微型场景只是引擎内部切分同一区域内隔离群体的工具，不应强迫玩家内化。
> 动态图形化侧的完整细节（泛光圈 / ORCA 统一避让 / 传染式连锁 / 恢复对峙 / 回合间并发 / 不可动实体静默归位）守 `docs/表现系统/01_图形化与UI.md` 「前端动态图形化」一节；**本节的权威可动性判定**（见下）与其保持一致、互为锚定，不重复成第二套权威。

**核心规则**：

1. **"找到 X"的本质 = 来到 X 这个实体的微型场景**
   - 在大/中场景中，两个活体默认不在同一微型场景，必须花 1 AP "找到"才能近战
   - **载具例外**："找到车"是进入该载具实体的影响范围，而非"进入微型场景"——载具不是微型场景，是独立实体

   **对目标动作的总 AP 成本（D-046）**：

   | 场景类型 | 找到 | 处决 | 总计 |
   |----------|------|------|------|
   | 大/中场景 | 1 AP | 1 AP | **2 AP** |
   | 小/微型场景 | 0 AP（已共享） | 1 AP | **1 AP** |

   > 大场景处决总成本 **2 AP** 判定稳定。这也意味着 3 AP 的回合恰好能完成"找人 + 处决"并剩 1 AP——是行动轮 3 AP 奖励档的重要价值锚点。

2. **贴身关系**
   - 微型场景由每个活体各自私有（大/中场景）
   - 贴身是**成对的对称关系**：A 贴身 B ⟺ B 贴身 A
   - 小场景中贴身成本 0 AP（已在共享微型场景）
   - 脱离贴身：1 AP；或移动到别的天然场景时自动解除

**空旷地（Vacant Ground，仅运行期能力）**：

空旷地不是玩家可选目标，也不是独立动作。运行期只在实体从其他天然场景进入大/中场景、且容纳判定需要时创建或复用个人微型场景；实体离开后不能通过 UI 主动返回该个人空旷地。

| 场景类型 | 空旷地行为 |
|----------|-----------|
| 大/中场景 | 创建个人微型场景，只有你 |
| 小场景 | **禁止创建个人空旷地**，移动到共享微型场景 |

### 过渡场景阻挡机制

- 过渡场景创造的微型场景，`props.creator` 都指向同一个过渡场景（同一 Link）
- 每个微型场景各自的 `parent` 仍指向它所在那一侧的天然场景
- **任意一侧**有活体或具有 `blocking` 属性的实体 → 整个过渡场景不可通行

| 过渡类型 | 微型场景创建 | 阻挡判定 |
|----------|-------------|----------|
| 平行过渡（门、平窗） | 双侧各一个 | 任一侧被占 → 双向阻挡 |
| 垂直过渡（跳窗） | 仅上侧一个 | 上侧被占 → 单向阻挡 |

> **保留确认（D-045）**：封堵规则**保留**。"双方同时试图穿越如何处理"这一追问**不成立**——回合制下**不存在同时**，行动轮决定了谁先执行，先到者占据，后到者面对的就是已封堵状态。因此**不需要引入优先权竞争或掷骰判定**，实现为简单的占用检查即可。为不存在的并发情形设计仲裁规则属于无必要的实体增加。

## 门户系统

### 门户类型与成本

| 门户类型 | AP 成本 | 方向 | 特殊效果 |
|----------|---------|------|----------|
| 走廊 | 1 AP | 双向 | 无 |
| 门（开） | 1 AP | 双向 | 无 |
| 门（关） | 1 AP | 双向 | 需先开门 |
| 门（锁） | 2 AP | 双向 | 撬锁或破锁 |
| 楼梯 | 1 AP | 双向 | 可携带载具 |
| 窗户（跳窗） | 0 AP | 单向（高→低） | 坠落伤害 |
| 窗户（攀爬） | 2 AP | 单向（低→高） | 需攀爬工具 |

### 坠落伤害计算

```
floor_delta = abs(进入楼层 - 离开楼层)

base_damage = floor_delta

if has_tag("heavy"):
    damage += 1  // 重装额外+1

if has_tag("light") or has_skill("parkour"):
    damage -= 1  // 轻装或技能-1

final_damage = max(0, damage)
```

## 缩圈机制

### 规则

不使用几何圆（与离散节点地图冲突）。

1. 确定一个**中心点**（纯随机选取 1 个大/中场景）
2. 使用周边缩圈拟合算法决定收缩顺序
3. **每回合缩去一个天然场景**
4. 其附属微型场景**随父场景一起处理**（柜子、车内不能脱离父场景独活）
5. 收缩结果**提前 1 轮公开**，使玩家可以计算路线

**缩去效果**：不是立即淘汰、不禁止停留，而是**持续伤害** —— 在缩去场景内每回合造成 1 点毒伤。

#### 缩圈伤害的类型与弱点交互（D-049）

| 项目 | 结论 |
|------|------|
| **伤害类型** | **毒素（DMG_07）** |
| **能否触发弱点** | **能** —— 触发活性（WKN_07） |
| **弱点是否使伤害翻倍** | **不会** |

> **关键边界**：弱点触发后**只产出非伤害效果**（装备脱落 / 对方体力 +1 / 对方行动轮 -1），**不改变伤害数值**。伤害翻倍只来自"骰点超出 DC 2 点及以上"，与弱点系统无关。缩圈是无骰点的环境伤害，因此天然不触发翻倍。完整对照见 `L3_玩法层/01_行动轮与体力博弈系统.md` 第 4.4.2 节。
>
> 防具对毒素伤害是否减伤本轮未单独表态，按防具规则**通用适用**处理；若后续需要豁免，须单独决策。

**载具与缩圈**：不适用 —— 载具不是微型场景而是**实体**，缩圈规则只处理天然场景；载具的位置随它自身的 Entity 状态变化。

## 距离范式（基准从 1 开始 — D-051）

**定义**：两个活体之间的场景拓扑连接数量（加权），**编号从 1 起算**。

| 距离 | 含义 |
|------|------|
| **1** | **贴身**，同一微型场景 |
| **2** | 不同微型场景，但同一天然场景 |
| **3、4+** | 按下列公式累加 |

```
跨天然场景 +1（大场景 ×2）
```

**示例**：
- 我在教室（中场景），你在紧邻走廊（中场景）→ 距离 3
- 我在中场景，你在紧邻的大场景 → 距离 2 + 2 = 4

> **基准修订（D-051）**：距离编号已从"0 起算"改为"**1 起算**"，因为"距离 1 = 贴在一起"更符合玩家直觉。这是**纯线性平移**——所有既有 DC 数值与平衡关系完全不变。迁移方法：旧文档中的距离值**全部 +1**（注意"距离 5+"这类开区间上限要同步变为"距离 6+"）。

**适用范围**：枪械距离 DC 判定、感知衰减计算、移动代价估算。

## 掩体的空间侧登记（D-040）

掩体采用**二维正交模型**（完整定义见 `04_物品装备.md` 掩体机制章节）。空间系统负责其中的**场景侧**：

| 维度 | 空间系统的职责 |
|------|----------------|
| **赋予者 = 场景** | 掩体作为**场景固有属性**登记在节点上（如一堵墙天生是掩体） |
| **作用对象 = 场景** | 掩体作用于空间，**进入该空间者均受益** |

另两种象限（赋予者 = 实体、作用对象 = 玩家）由实体侧实现，典型实例是载具半掩体（仅车内乘员受益，见 D-038）。

**小场景与掩体**：小场景"选择密度最低，是天然的堵桥点与掩体"——此处的掩体属于**场景固有属性**这一象限。

## 地图编辑规范

### 拓扑 Linter

| 检查项 | 规则 |
|--------|------|
| 度数检查 | 小场景 ≤ 3 连接，中场景 ≤ 4 连接，大场景 ≤ 5 连接 |
| 连通性检查 | 所有节点必须可达，无孤岛 |
| 出生点检查 | 至少有一个大场景作为出生点 |
| 平衡性预警 | 各出生点到关键资源的距离差距 > 2 AP 时警告 |

### 最佳实践

**DO**：
- ✅ 用门户系统统一所有过渡
- ✅ 严格遵守五并列原则
- ✅ 为每个场景类型设计明确的战术意义
- ✅ 让空间本身讲述故事

**DON'T**：
- ❌ 创建超过上限的连接数
- ❌ 混淆小场景与微型场景
- ❌ 让小场景连接到 5 个地方（毁掉"一夫当关"的空间性格）
- ❌ 忽略 AP 距离平衡

## 归档恢复增补：拓扑、垂直空间与空间关系（2026-08-10）

> **来源追踪**：`docs/L_归档/03_空间系统设计.md`。
> **恢复原则**：以下内容是归档中被现行文档遗漏、且未被后续裁决废止的有效设计。涉及具体地图数值的部分明确标注为玩法层示例，不反向成为基类层固定值。

### 五并列拓扑原则的完整边界

**基类层唯一结构边界是：任一天然场景节点的连接数不得超过 5。** 大/中/小场景的 5/4/3 是标准玩法包可采用的默认平衡值，不是三种基类各自不可突破的结构边界（D-057）。玩法包可以在 1–5 内声明其他按档上限，但绝不能超过 5。

```text
结构硬上限（Class）：所有天然场景 ≤ 5
标准玩法默认（Play）：大场景 5 / 中场景 4 / 小场景 3
```

连接计数包含一切会把活体转移到另一个可行动位置的入口：普通通道、柜体入口、载具占用入口、翻窗、楼梯、梯子和通风口等。微型场景本身是附属关系，不作为第四种天然场景档位参与按档计数。

#### 为什么五并列约束至关重要

1. **控制脑力搜索深度**：平均 3 个出口时，下两步约有 3×3 种路线；平均 8 个出口时会膨胀为 8×8，玩家通常会放弃推演。
2. **保持拓扑可读性**：有限连接使地图能稳定呈现为接近平面的图，减少交叉与遮挡。
3. **形成空间张力**：大场景偏交通枢纽，中场景偏标准战场，小场景偏瓶颈与伏击点。
4. **通过通道而非房间容量节流**：天然场景不设活体容量；过渡点占用和阻挡让尸潮分批通过，避免瞬时围攻。

> 旧“接敌面”概念继续废止。正确约束对象是通道瓶颈和微型场景占用，不是“同时能被几个人攻击”。

### 过渡门户数据契约

门户统一表达楼梯、梯子、门、窗、舱口、阳台与通风口等连接。基类层声明字段和约束，玩法层实例填入具体 1–5 数值。

```json
{
  "id": "portal:window:floor-3-to-2",
  "kind": "window",
  "cost": 1,
  "checks": ["ref:check:agility"],
  "effects": ["ref:effect:fall-damage"],
  "directionality": "one-way-down",
  "losBridge": true,
  "floorDelta": -1
}
```

| 字段 | 语义 | 约束 |
|------|------|------|
| `id` | 稳定门户引用 | 全局稳定，不依赖显示名 |
| `kind` | 门户基类引用 | 必须能在目录解析 |
| `cost` | 玩法层通行成本 | 玩家可见时为 1–5；零费语义由附着动作类别表达，不以越界数值绕过 |
| `checks` | 通过前的检定引用 | 只引用已登记的检定/Expr |
| `effects` | 通过后的结构化效果 | 必须映射到现有 Op，不携带可执行代码 |
| `directionality` | 双向或明确的单向 | 方向枚举含 `bidirectional`/`unidirectional`/`one-way-down`/`one-way-up`；单向陷阱必须显式标注（D-074），不再压成布尔 `directed` |
| `losBridge` | 是否桥接视线、射击或感知 | 只建立影响关系，不等于可移动 |
| `floorDelta` | 楼层差 | 内部拓扑数据；必须与两端楼层声明一致 |

#### 梯子

- 双向通行，通常成本由玩法包配置为 1。
- 可声明占用双手或禁止携带重型物品的检定。
- 视线桥接可以是关闭、单向或受限，不与移动方向自动绑定。
- 梯子与楼梯不是同一基类：二者可以有不同的检查、效果和携带约束。

### 楼层与垂直空间

#### 叠层语义

楼层不是独立的距离体系，而是同一拓扑图上的分层呈现信息。表现系统可把当前层作为主视图、相邻层作为半透明上下文；规则计算仍只使用节点、连接、门户与影响关系。

- 竖向门户两端应有可对齐的表现锚点，保证跨层动画连续。
- 默认不常驻绘制跨层连线，悬停、移动预览、射击预览时再显示。
- 叠层也可以表达同一楼层的局部场景切换，不把“楼层”硬编码成唯一用途。
- 具体图层透明度、屏幕坐标和转场方式归 `docs/表现系统/01_图形化与UI.md`。

#### 垂直交互

- **跨层移动**：只能经门户发生；自由跳跃或飞行必须来自玩法包组合的移动模式。
- **跨层视线**：由 `losBridge` 或其他明确影响边声明；能看见不代表能移动过去。
- **跳窗距离**：按 D-051 平移后，到下层目标的等价距离为 2，且不再叠加楼梯式“离开 + 进入”两段。
- **楼梯等双向门户**：按拓扑路径逐边累加，不与跳窗的单向捷径规则混用。

### 三种空间关系必须分离

| 关系 | 核心语义 | 结构性质 | 示例 |
|------|----------|----------|------|
| **容纳关系（Containment）** | A 在 B 内或占用 B 的槽位 | 通常单父级、禁止成环 | 手枪在背包槽；玩家占用驾驶位 |
| **拓扑关系（Topology）** | A 与 B 通过某种通道相连 | 可成环、可单向、可带条件 | 教室经门连接走廊 |
| **影响关系（Influence）** | A 可影响 B，但不能据此移动到 B | 限定传播类型与方向 | 二楼窗口可看见并射击操场 |

禁止用一个 `parent` 或一个 Link 同时承担三种语义。尤其：`losBridge` 建立的是影响关系，不能被路径查找器自动当作移动边；载具座位是容纳/占用关系，不把载具伪装成微型场景。

### 无人场景的散落物清理

当物品被丢在天然场景地面，且**所有活体**都离开该天然场景后，散落物被删除。

- 判定主体是活体，不是所有实体；载具或环境实体不能意外阻止清理。
- 清理范围按整个天然场景判断；附属微型场景不单独延长地面物寿命。
- 正式放入容器的物品豁免：死亡背包、载具货舱、箱子和储物柜等。
- 该规则同时减少视觉垃圾和全局状态负担，并允许“丢弃后离开”成为销毁物资的战术选择。

### 隐蔽与潜行

- 柜体、角落等特定局部空间可以赋予隐蔽状态。
- 隐蔽不等于不存在；其可见性仍由知识与查询端口决定。
- 攻击、制造高强度声音等主动行为可以按玩法包规则解除隐蔽。
- “找到”是进入目标接触空间的移动语义，不自动绕过隐蔽或知识权限。

### 区域效果

区域效果挂在场景节点或由实体向场景授予，不另建空间类型。

- 燃烧房间：每回合对场景内目标产生结构化伤害请求。
- 辐射区：进入时施加状态。
- 黑暗区域：限制特定影响关系或可见性查询。

区域效果的具体数值与持续时间属于玩法层；基类层只定义可组合的附着、传播、进入/离开触发与清理契约。

### 地图平衡示例（玩法层示例，非基类固定值）

```text
路线 A：出生点 → 走廊 → 教室 → 取得标准武器
总成本：3 AP；收益稳定

路线 B：出生点 → 器材室 → 高风险小场景 → 取得高收益武器
总成本：3 AP；收益更高但存在瓶颈风险

路线 C：出生点 → 教学楼 → 楼梯 → 上层暴露点 → 取得远程武器
总成本：3 AP；获得射程优势但位置更易被观察
```

平衡目标不是让路线完全同质，而是让多个出生点到关键资源的最短成本大致相等（通常允许 ±1 AP），同时让风险、信息暴露、瓶颈和撤离条件不同，避免唯一最优路线。

### 特殊地点设计指导（供玩法层使用）

- **高价值区域**：放在高风险小场景，或设置钥匙/技能等网关；避免只有单一不可逆出口。
- **战略要点**：通常位于中/大场景交界，连接接近玩法包上限，能观察多个方向。
- **伏击点**：小场景连接主通道，具备单向或受限影响关系，并保留可计算的撤离路线。

### 完整拓扑 Linter

| 检查组 | 必须检查 |
|--------|----------|
| 结构硬边界 | 任一节点连接数不得超过 5 |
| 玩法包按档值 | 若玩法包声明 5/4/3 或其他 1–5 上限，则按其声明检查 |
| 连通性 | 所有要求可达的节点可从出生点到达；孤岛必须显式声明用途 |
| 出生点 | 至少一个合法出生点；出生点到关键资源的最短 AP 成本差异过大时警告 |
| 门户合理性 | 两端存在；方向合法；`floorDelta` 一致；单向陷阱显式标注 |
| 影响边 | `losBridge` 等影响关系不得进入移动图；传播类型必须受限 |
| 零费环 | 零费门户或附着动作不能形成可无限重复的状态增益环 |
| 微型场景 | 必须附属于合法天然场景；小场景个人空旷地禁令必须生效 |
| 关系成环 | 容纳关系禁止成环；拓扑关系允许成环；两者不得混判 |

诊断必须带稳定路径、原因和可执行的修正建议；错误阻止发布但不阻止保存半成品。具体编辑器交互归 `docs/创作系统/02_地图生产管线.md`。
