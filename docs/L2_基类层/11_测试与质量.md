# 测试与质量保证

---

## 核心目标

**零运行时错误保证**：玩家或 UGC 创作者只要按照 API 规范，无论填入多么诡异的东西，都不会在运行时造成错误。

**不打补丁原则**：发现问题 → 完全解决根因，而非局部修复。

---

## 测试层级

### 1. 单元测试（底层逻辑完备性）

**目标**：保证每个函数、模块在所有边界条件下正确工作。

**覆盖范围**：
- **距离范式**：所有节点类型组合的距离计算
- **AP 消耗**：所有动作的成本计算（包括负重、状态修正）
- **状态交互矩阵**：所有状态组合的效果叠加
- **投点分配**：所有可能的骰子结果 + 修正值组合
- **过渡阻挡**：所有过渡场景类型 + 占用情况组合
- **微型场景贴身**：边界容量、跨场景解除、小场景合并逻辑

**用例生成策略**：
```typescript
// 示例：距离范式的穷举测试
describe('DistanceCalculation', () => {
  const sceneTypes = ['large', 'medium', 'small'];
  const microSceneCases = [
    { sameNatural: true, sameMicro: true },
    { sameNatural: true, sameMicro: false },
    { sameNatural: false, sameMicro: false },
  ];
  
  for (const typeA of sceneTypes) {
    for (const typeB of sceneTypes) {
      for (const microCase of microSceneCases) {
        it(`${typeA} -> ${typeB}, micro: ${JSON.stringify(microCase)}`, () => {
          const result = calculateDistance(typeA, typeB, microCase);
          expect(result).toMatchSnapshot();
        });
      }
    }
  }
});
```

**边界用例清单**：
- AP 为 0 时能否执行动作
- 倒地者能否被倒地
- 小场景门被堵时能否从内部出门
- 死亡背包容量为 0 时的行为
- 体力为 0 时的强力骰
- 零挫败退还 + 多次强力骰
- 过渡场景双侧同时被占
- 垂直过渡下侧有人时上侧跳下
- 大场景 5 连接上限 + 微型场景
- 爬行跨微型场景但不跨天然场景

### 2. 集成测试（系统交互）

**目标**：验证多个模块组合时的正确性。

**关键场景**：
- **完整回合流程**：投点 → 行动 → NPC → 清理，检查状态一致性
- **载具系统**：上车 → 开车 → 下车 → 车辆被毁
- **精密交互中断**：撬锁中 → 受击 → 状态清除
- **小场景堵门**：进入 → 来到门边 → 外部尝试进入 → 攻击门边 → 进入
- **距离 DC 射击**：多层场景跨越射击 → DC 计算 → 命中判定
- **死亡背包生成**：死亡 → 生成背包 → 容量 = 物品数 → 搜尸 → 拾取

**集成测试框架**：
```typescript
class GameTestHarness {
  state: GameState;
  
  // 快捷设置场景
  setupScene(config: SceneConfig): void;
  
  // 模拟玩家动作
  playerAction(playerId: string, action: Action): ActionResult;
  
  // 模拟完整回合
  runTurn(): TurnResult;
  
  // 断言状态
  assertState(condition: (state: GameState) => boolean): void;
  
  // 快照对比
  snapshotState(): string;
}

// 示例：小场景堵门场景
test('small scene door blocking', () => {
  const harness = new GameTestHarness();
  
  harness.setupScene({
    type: 'small',
    entities: [
      { id: 'player1', position: 'shared' },
      { id: 'zombie1', position: 'shared' },
    ],
    portals: [{ id: 'door1', type: 'parallel' }],
  });
  
  // 僵尸主动来到门边
  harness.playerAction('zombie1', { type: 'move_to_portal', portalId: 'door1' });
  
  // 外部玩家尝试进入
  harness.setupEntity({ id: 'player2', scene: 'outside' });
  const result = harness.playerAction('player2', { type: 'enter_through', portalId: 'door1' });
  
  expect(result.blocked).toBe(true);
  expect(result.reason).toBe('portal_occupied');
  
  // 远程攻击门边僵尸
  harness.playerAction('player2', { type: 'ranged_attack', target: 'zombie1' });
  harness.assertState(s => s.entities['zombie1'].hp < 3);
});
```

### 3. 模糊测试（Fuzzing）

**目标**：发现未预料的边界情况和组合爆炸。

**策略**：
- **随机 UGC 输入**：生成合法但诡异的地图配置
- **随机动作序列**：AI 随机选择动作，运行数千回合
- **状态空间探索**：尝试触发所有状态组合

**模糊测试引擎**：
```typescript
class FuzzTester {
  // 生成随机但合法的地图
  generateRandomMap(): MapData {
    const nodeCount = randomInt(10, 50);
    const nodes = [];
    
    for (let i = 0; i < nodeCount; i++) {
      const type = randomChoice(['large', 'medium', 'small']);
      const maxConnections = { large: 5, medium: 4, small: 3 }[type];
      const connections = randomInt(1, maxConnections);
      
      nodes.push({
        id: `node_${i}`,
        type,
        connections: randomConnections(nodes, connections),
      });
    }
    
    return { nodes, validate: true };
  }
  
  // 运行随机游戏
  runRandomGame(turns: number): FuzzResult {
    const map = this.generateRandomMap();
    const game = new GameEngine(map);
    
    const errors = [];
    
    for (let turn = 0; turn < turns; turn++) {
      try {
        // 每个玩家随机选择动作
        for (const player of game.players) {
          const actions = game.getLegalActions(player.id);
          const action = randomChoice(actions);
          game.executeAction(player.id, action);
        }
        
        game.endTurn();
      } catch (e) {
        errors.push({ turn, error: e, state: game.snapshotState() });
      }
    }
    
    return { errors, totalTurns: turns };
  }
}

// 持续模糊测试
test('fuzz 10000 random games', () => {
  const fuzzer = new FuzzTester();
  const result = fuzzer.runRandomGame(10000);
  
  expect(result.errors).toHaveLength(0);
}, 60000); // 60 秒超时
```

### 4. 属性测试（Property-Based Testing）

**目标**：验证系统不变性（invariants）。

**不变性清单**：
- **AP 守恒**：每回合结束时，所有玩家的 AP 应为 0
- **位置一致性**：活体的 `location.naturalScene` 必须存在于地图中
- **微型场景附属性**：所有微型场景必须附属于某个天然场景
- **状态持续时间非负**：所有状态的 `duration` ≥ 0
- **生命值上限**：所有活体的 `hp` ∈ [0, maxHp]
- **背包容量**：槽位占用 ≤ 总容量
- **距离非负**：任意两节点间距离 ≥ 0
- **过渡场景连通性**：所有过渡场景的两侧必须是有效节点

**示例（使用 fast-check）**：
```typescript
import fc from 'fast-check';

test('AP conservation after turn', () => {
  fc.assert(
    fc.property(
      fc.record({
        playerCount: fc.integer({ min: 2, max: 6 }),
        rolls: fc.array(fc.integer({ min: 1, max: 6 })),
        modifiers: fc.array(fc.integer({ min: 0, max: 3 })),
      }),
      ({ playerCount, rolls, modifiers }) => {
        const game = setupGame(playerCount);
        
        // 模拟投点
        game.rollPhase(rolls.slice(0, playerCount), modifiers.slice(0, playerCount));
        
        // 模拟动作消耗
        game.players.forEach(p => game.spendAllAP(p.id));
        
        // 断言 AP 守恒
        const totalAP = game.players.reduce((sum, p) => sum + p.ap, 0);
        return totalAP === 0;
      }
    )
  );
});
```

### 5. UGC 静态验证器（Linter）

**目标**：在加载前拒绝不合法的 UGC 内容。

**检查项**：

#### 地图结构
- [ ] 所有节点 ID 唯一
- [ ] 连接数不超过类型上限（大 5 / 中 4 / 小 3）
- [ ] 出生点存在且可达所有节点
- [ ] 无孤岛节点（从出生点不可达）
- [ ] 过渡场景的两侧节点存在
- [ ] 循环引用检测（A → B → A 的门）

#### 物品配置
- [ ] 物品 ID 唯一
- [ ] 伤害值 ∈ [1, 5]
- [ ] 槽位占用 ∈ {1, 2}
- [ ] 谱型引用有效（对于枪械）
- [ ] 标签合法（`heavy`, `blocking`, `reach` 等）

#### 实体配置
- [ ] 实体 ID 唯一
- [ ] 初始位置存在于地图
- [ ] 生命值 ∈ [1, 5]
- [ ] 巡逻路线所有节点可达

#### 玩法包规则
- [ ] 事件触发条件可解析
- [ ] 引用的物品/节点存在
- [ ] 无死锁条件（如"必须拾取不存在的物品"）

**Linter 实现**：
```typescript
class UGCLinter {
  errors: LintError[] = [];
  warnings: LintWarning[] = [];
  
  validate(ugcData: UGCPackage): LintResult {
    this.checkMapStructure(ugcData.map);
    this.checkItems(ugcData.items);
    this.checkEntities(ugcData.entities);
    this.checkRules(ugcData.rules);
    
    return {
      valid: this.errors.length === 0,
      errors: this.errors,
      warnings: this.warnings,
    };
  }
  
  checkMapStructure(map: MapData) {
    // 检查节点 ID 唯一性
    const ids = new Set();
    for (const node of map.nodes) {
      if (ids.has(node.id)) {
        this.errors.push({
          type: 'duplicate_node_id',
          message: `Node ID ${node.id} is duplicated`,
          node: node.id,
        });
      }
      ids.add(node.id);
      
      // 检查连接数上限
      const maxConnections = { large: 5, medium: 4, small: 3 }[node.type];
      if (node.connections.length > maxConnections) {
        this.errors.push({
          type: 'connection_limit_exceeded',
          message: `${node.type} scene can have at most ${maxConnections} connections`,
          node: node.id,
          actual: node.connections.length,
        });
      }
    }
    
    // 检查可达性
    const reachable = this.bfs(map, map.spawnPoint);
    const unreachable = map.nodes.filter(n => !reachable.has(n.id));
    
    if (unreachable.length > 0) {
      this.errors.push({
        type: 'unreachable_nodes',
        message: `${unreachable.length} nodes are unreachable from spawn`,
        nodes: unreachable.map(n => n.id),
      });
    }
  }
  
  bfs(map: MapData, start: NodeId): Set<NodeId> {
    const visited = new Set<NodeId>();
    const queue = [start];
    
    while (queue.length > 0) {
      const current = queue.shift()!;
      if (visited.has(current)) continue;
      visited.add(current);
      
      const node = map.nodes.find(n => n.id === current);
      if (node) {
        queue.push(...node.connections.map(c => c.target));
      }
    }
    
    return visited;
  }
}
```

### 6. 运行时沙盒

**目标**：即使 UGC 内容通过了 Linter，运行时仍可能触发未预料的组合。沙盒保证错误不会崩溃游戏。

**沙盒策略**：
- **指令计数器**：限制单次事件处理的最大指令数（防止死循环）
- **递归深度限制**：状态触发链最多 10 层
- **内存限制**：单个 UGC 包最大内存占用 100MB
- **超时保护**：单回合计算超过 5 秒 → 强制结束

**沙盒实现**：
```typescript
class UGCSandbox {
  instructionLimit = 100000;
  recursionLimit = 10;
  timeout = 5000; // ms
  
  executeUGCEvent(event: UGCEvent, context: GameState): Result {
    const startTime = Date.now();
    let instructions = 0;
    
    try {
      return this.runWithLimits(event, context, {
        checkInstruction: () => {
          instructions++;
          if (instructions > this.instructionLimit) {
            throw new Error('Instruction limit exceeded');
          }
          if (Date.now() - startTime > this.timeout) {
            throw new Error('Timeout');
          }
        },
      });
    } catch (e) {
      console.error('UGC execution error:', e);
      return { error: e.message, fallback: true };
    }
  }
}
```

## 测试驱动开发流程

1. **编写失败测试**：先写测试用例，断言期望行为
2. **实现最小功能**：让测试通过
3. **重构**：优化代码，测试保持通过
4. **回归**：确保其他测试仍然通过
