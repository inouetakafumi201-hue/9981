## 核心理念

### "较低的创作自由，创造了大多数人绝对的创造自由"

传统UGC平台的问题：
- **Roblox/Minecraft Mod**：自由度极高，但需要编程能力
- **结果**：99%的玩家只能消费，无法创作

本引擎的解决方案：
- **限制创作维度**：只能操作节点、实体、规则组合
- **降低创作门槛**：用自然语言描述，LLM自动转换
- **保证系统稳定**：无论怎么创作都不会崩溃

## UGC友好的报错与鲁棒性系统

### 报错分级

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| **系统级错误** | 底层基底出问题 | 直接终止 |
| **玩法包级错误** | 配置问题 | 计入警告日志，尽量继续运行；触发循环检测等监测器时升维为终止级 |

### 载入时审查

- 玩法包尝试载入时，逐项审查是否违反设计原则、是否与已加载内容冲突
- 一旦命中，**拒绝载入**，并**明确指出玩法包中具体是哪一部分出了问题**
- 载入监测模块与核心运行时**解耦**，后续可以持续追加更多辅助性警告规则

### 报错文案原则

- 无论系统级还是玩法包级，都要给出**详尽、设身处地**的错误原因解释和可行的解决建议
- **禁止只抛冷冰冰的错误码**——创作者大多不是程序员，看不懂就等于没有反馈

### 素材与字段缺失的鲁棒性兜底

| 情况 | 处理方式 |
|------|----------|
| 修改已有字段但新值缺失/损坏 | **换回原有值** |
| 新增字段缺失（如新增物品但没给素材） | **用同类型的默认值填充** |

**原则**：任何"半成品"都不应该让加载失败，而是尽可能优雅退化成已知可用的状态。

## 三层创作自由度

### 第一层：换皮（5秒完成）

选择已有实例，修改名字和数值。

```
示例：
- 将"手枪"改名为"激光手枪"
- 将伤害从2改为3
- 完成
```

### 第二层：组合（5分钟完成）

选择已有基类，组合出新的武器/技能。

```
示例（霰弹枪）：
基类组合：
- 枪类（gun_type）
- 散射属性（scatter_attribute）
- 枪械伤害（gun_damage）

参数配置：
- 散射范围：2
- 基础伤害：3
（命中范围内全部目标，不设固定人数上限）
```

> **2026-08-08 权威变更（本次会话裁决，已获项目所有者授权）**：废除"攻击形状/形状轴"设计
> （原三选一分类：单体/散射/范围）。散射改为武器属性（`scatter_attribute`），不再叫"谱型"；
> 且散射不设固定目标数上限——上例原"散射目标：3"已删除。详见
> `docs/L0_规范宪法.md`、`docs/L2_基类层/基类层定义.md` §4.3。

### 第三层：定义（5小时完成）

定义全新的基类或规则。

```
示例：
- 定义新的"冰冻谱型"
- 定义新的"护盾机制"
- 定义新的玩法包结构
```

## 规则描述语言

### DSL 规范（D-019 决策）

规则 DSL 为**纯声明式 JSON**。

```json
{
  "type": "game_rule",
  "version": "1.0",
  "name": "霰弹枪规则",
  "base": ["gun_type", "scatter_pattern", "gun_damage"],
  "params": {
    "range": 2,
    "targets": 3,
    "damage": 3
  },
  "constraints": {
    "ap_cost": 1,
    "min_distance": 1,
    "max_distance": 2
  }
}
```

### DSL 约束

- ❌ 不支持命令式逻辑
- ❌ 不支持循环
- ❌ 不支持变量赋值
- ✅ 纯声明式：定义"是什么"，不定义"怎么做"

## LLM辅助创作

### 自然语言 → DSL

创作者用自然语言描述，LLM 转换为 DSL：

```
创作者输入：
"一把霰弹枪，可以在近距离发射3颗子弹，每颗造成3点伤害"

LLM 输出：
{
  "type": "weapon",
  "base": ["gun_type", "scatter_pattern", "gun_damage"],
  "params": {
    "targets": 3,
    "damage": 3
  }
}
```

### LLM 辅助规则

| 功能 | 说明 |
|------|------|
| 语法检查 | 验证 DSL 格式正确性 |
| 语义检查 | 验证基类引用正确性 |
| 冲突检测 | 检测与现有规则的冲突 |
| 平衡建议 | 基于数值约束给出平衡建议 |
