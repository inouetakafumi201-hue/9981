## 一、架构总览（三层，已冻结的形状）

```
L1 引擎层 Kernel（src/core/kernel）——0 游戏知识，只认实体/状态/关系/动作/规则/事务/Hook
   └─ 铁律：0 追加。已接线 Hook 分发（wire-hooks）。是稳定基座。
        ↓ 上层只经公开 Op/Query/queryActions/Policy/Decision/Intent 消费
L2 基类层 Class（src/l2 规范模型+装载管线 · src/class 实例目录 · src/core/ugc UGC接入 · src/core/kernel/ai AI消费者）
   └─ 铁律：实例不含玩法数值、不含玩法规则；可组合/继承/扩展。
        ↓ 玩法层组合基类层实例 + 数值约束(1-5) + 玩法规则
L3 玩法层 Play（src/play）——具体数值、玩法包、玩法规则
   └─ 铁律：纯数据、高频迭代、不回溯改基类层。
```

**唯一写入通道**：所有状态改变经 `OpRegistry.invoke`。玩法层仅 `core-mechanics/load.ts` 可引用 `OpRegistry`。

## 三、每条线的可信断点（从哪往下写）

### L1 引擎层 — ✅ 完成，作为冻结基座
- 断点：无新增开发。仅在上层需要时**补公开契约**，且遵守 0 追加铁律。
- 风险：上层若绕过公开 Op 直接依赖内核内部形状 → 违规，须挡回。

### L2 基类·管线 (l2-base-layer-spec) — ✅ 高信任，待收敛执行
- 真实完成：`src/l2` 编译/校验/解析/注册/运行时提交 + `model/**` 规范常量；37 测试全绿。
- 断点：**执行 D-061**（把 `spec-compiler` 独有缺口迁入 `src/l2`、更名引擎级 JSON 原语、退役 `SpecificationCompiler`）。→ **PT-01**（🔒 等 D-061 批准 + PT-02 先行）。

### UGC (wakeup-ugc) — ⚠️ 主链路完整，跨 Spec 装配当前红灯
- 真实完成：主链路与机器可校验端口契约已存在，PT-02 也已交付 `src/l2/ugc/ports/`。
- 最新事实：新建 `src/core/ugc/integration/l2-adapter.ts` 直接导入 `src/l2/ugc/ports/index.js`，触发 `architecture-boundary.test.ts` 的“基类层未冻结时保持零耦合”断言；定向复测稳定为 1 失败/6 通过。
- 断点：先裁定 D-061 下的冻结状态与装配所有权，再由所属线选择稳定端口接线。不得放宽零耦合守卫、不得为当前内部形状 force-fit 适配器。

### AI (wakeup-ai) — 🟡 实现齐全，逐条证据混合
- 真实完成：`src/core/kernel/ai` 全套组件 + 9 个 AI 测试文件；design 明确 AI 落于此（受限引擎消费者）。
- PT-04 逐条审计：71 条验收标准为 **44✅/23◐/4⬜**。B-20 已把逐要求来源追踪机器化；B-19 已建立文档术语增量守卫，但仍保留 23 处既有违规精确基线。
- 断点：A-AI-01/02/03 需所有者裁决；延后提交与宏动作守卫仍是零覆盖分支。不要把“9 个文件全绿”等同于逐条高信任。

### L3 核心机制 (wakeup-core-mechanics) — ⚠️ 低信任，**冻结待裁决**
- 真实状态：机制内容有**两套并行实现**——`action-turn/playpack.json`（纯数据，30 测试，可信）与 `core-mechanics/*.ts`（TS，**零测试**，含装载期治理 Linter）。二者对 U-002 结论**相反**。

### L2 空间物品 (wakeup-space-items) — 🟢 tasks 已按 D-058 重写，实施待 PT-08b

## 七、信任缺口与本报告未覆盖的诚实边界

- ~~**`test/l2/**` 不在 `tsconfig` 默认 typecheck**~~ → **已闭合（PT-06，2026-08-09）**。`tsconfig.json` 的 `include` 改为 `["src", "test"]`（写目录而非枚举子目录，新增 `test/<子目录>` 自动进检查范围）；`lint` 改为 `eslint src test --ext .ts,.tsx`；`tsconfig.l2.json` 终于有脚本会跑它（`typecheck:l2`）。
  **闭合方式经过对照实证**，不是"命令退出码 0 所以认为覆盖到了"：在 `test/l2/` 放入引用不存在字段的探针，新范围 `tsc` 报 `TS2339` 且退出码 2，同一文件在旧范围（`["src","test/properties"]`）下退出码 0。
  **并且加了守卫防止回退**：`test/toolchain/gate-coverage.test.ts` 断言"磁盘上每个 `src/`、`test/` 下的 `.ts`/`.tsx` 都在 typecheck program 内"、"vitest include 的根都落在被检查的树里"、"lint 目标含 src 与 test 且 `--ext` 不漏 `.tsx`"、"lint 对 test/ 路径真的报 error"。把范围缩回旧配置会让该守卫直接变红（已反向验证：确实只有 G1、G4 两条失败）。

## 八、结论：可信设计的一句话总结

**L1 引擎与 L2 管线具备高信任证据；AI 实现齐全但逐条证据为混合状态（44✅/23◐/4⬜）；UGC 主链路完整但最新直接装配违反零耦合守卫，当前不能宣称全绿**；L3 核心机制仍受 D-062 与零测试阻塞。跨 Spec 集成必须先裁定稳定端口与所有权，不能放宽守卫或适配活跃内部形状。
