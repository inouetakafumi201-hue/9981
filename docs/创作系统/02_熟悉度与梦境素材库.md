## 一、定位与边界

本文档把世界观总纲 §十二「玩法与 UGC 的叙事统一」落成创作侧可实现的**世界内创作资格与素材契约**。

它回答的问题不是「编辑器长什么样」，而是：

> 玩家凭什么、按照什么规则，能在《起床》里把「在别人梦里见过的东西」变成「自己的梦境素材」，进而以某个梦为蓝本构建自己的梦境？

### 1.1 本文档拥有的东西

- 「熟悉度」作为**创作资格的判定**：每张梦境/地图一条，满则解锁该梦为可创作蓝本。
- 「学习（洞察）」作为**元素素材的获取动作**：把梦中见过、记住、学会的元素固化进素材库；可语义提炼的内容按 `docs/运营系统/06_素材记忆与消耗系统.md` 进入词条提取与合成链。
- 「蓝本 = 完整梦境模板（单一来源）」的契约语义。
- 「自建梦境 → 成为梦主」在创作侧的开房/主权方向。
- 上述机制消耗的点数使用「记忆巩固 / 训练」等**世界内理由**（不定义具体货币与币种；更细的提取、合成、塑形三环见运营/06）。

### 1.2 本文档不拥有的东西（明确不做）

| 不做 | 归属/原因 |
|---|---|
| **熟悉度的数值表**（每次进入涨多少、各行为权重、完整阶段边界的具体百分比） | 属于玩法层映射，本文只定结构；数值由玩法包提供 |
| **编辑器 / 素材库界面的图形化线框** | 表现系统后续专题 |
| **驻地的绘制 / 素材游览在局外的 UI 排布** | 表现系统后续专题 |
| **具体货币种类、汇率、产出与通胀控制** | 运营系统经济专题 |
| **完整主线剧情 / 结局 / 世界观解释** | 叙事设定总纲 |
| 复制世界观正文 | 只用总纲的稳定叙事 ID 交叉引用，不搬运 |

> **架构边界铁律（沿 L2/06 与 00 架构域）**：本文件描述的是「内容如何被创作出来」，属创作系统；它不定义运行期语义，不新增引擎原语，不绕过 `OpRegistry.invoke` 的注册校验。具体玩法数值、胜负规则与运行时行为一律归玩法层。

## 二、这个世界里的创作资格

### 2.1 熟悉度条

每张梦境/地图在玩家的局外档案里有一条独立的**熟悉度**。

> 熟悉度 = 你对这张梦的理解程度。它是创作资格，不是战力的刻度。

| 熟悉度 | 解锁能力 |
|---|---|
| 0%–10% | 只能作为普通访客进入，无法带走任何东西 |
| 10%–40% | 可以学习该梦境中的基础元素 |
| 40%–70% | 可以学习高级元素，并初步理解该梦境的结构逻辑 |
| 70%–100% | 可以复制该梦境的完整蓝图 |
| 100%（满） | 可以以该梦境为基底进行自由修改和再创作 |

**创作资格判定只依赖「熟悉度满」，不依赖战力等级或货币持有**。玩家不能掏钱跳过熟悉度；它只能通过进入、理解、生存来积累（见 §三）。这是 UGC 从「外包工坊」变成「成长关系」的关键：玩家想建一张「医院噩梦」，必须先在这张梦里活过、迷路过、快死过、看过隐藏通道，才能学会它。

### 2.2 为什么不是「拉官方图来改」

传统 UGC 的逻辑是「我打开编辑器 → 拉一张官方地图 → 改一改 → 发布」。

本作的逻辑是：

> 我在别人的梦里活下来 → 看懂了它 → 记住了它 → 学会了它 → 然后才能拿它当底子，建出我的版本。

这不是「加工」，而是「传承与再创造」。熟悉度让每张地图都成为值得反复游玩的**收集目标**而不是一次性关卡，也让玩家和每张地图之间产生不可替代的情感联系。

### 2.3 熟悉度的数据上限

熟悉度属于**搜集记录**（累计进展），不受玩法数值 1–5 约束，也不受任何战斗决策的「同时可选」约束。它是一张长期累计表，玩家会为它刷新而与单张地图建立长期关系。

> **语义**：熟悉度是「我在多懂这张梦」，是状态记录而非可被取舍的单回合资源。这里的放宽只针对数值记录（运营系统 §4.3），不针对同屏决策数。

## 三、熟悉度的获取来源

熟悉度没有统一的「刷分」来源，它是**你在融入一张梦的过程中自然积累的证据**。设计上应覆盖以下行为类别（具体权重留给玩法包定义）：

| 行为类别 | 示例 | 设计意图 |
|---|---|---|
| **探索** | 走到更深的区域、发现隐藏通道/房间 | 让探索有目的 |
| **战斗 / 生存** | 交手、存活回合数、从险境脱身 | 让这张梦的危险被亲历 |
| **发现隐藏要素** | 找到一般玩法不会注意的细节、彩蛋 | 让「看得仔细」有回报 |
| **提取词条** | 用「提取」动作固化某个元素的某个属性（见 §四） | 提取和熟悉互相喂养 |
| **失败也涨** | 在梦里被弹出/被杀，但死前看到的已记录 | 让挫败部分转化为收集满足感 |

### 3.1 失败也涨（死亡有价值）

在梦中被杀，任务失败。但死前看到的东西、走过的路、遇到的元素，已经计入熟悉度。所以玩家在败局里也会说：

> 「这局虽然输了，但我摸到了那个核心区，熟悉度涨了一大截。」

这避免「只有赢才涨」的挫败循环，也让熟悉度成为「我在理解这张梦」的记录而非「我在这张梦里赢了」的记录。

### 3.2 与「可进入/可学习阶段」的配合

熟悉度阶段会反过来影响**能在特定梦境里做什么**：

- 阶段 0–10%：作为访客看不到那些只有「理解结构的人」才能察觉的高级元素。
- 阶段 10–40%：开始能学习该梦境中的基础元素。
- 阶段 40–70%：开始能看清结构逻辑（布局、关键物、弱点关系）。
- 阶段 70–100%：能够复制完整蓝图。

这让「刷熟悉度」本身不是单调刷量，而是逐层解锁对同一张梦的**更深入理解**。

## 四、学习（洞察）→ 元素素材

### 4.1 梦中可以「学」什么

在别的梦里，你会看到各种**元素**：物件、场景局部、生物/敌人类型、机制、情绪氛围等。

这些元素**不是捡拾的装备**，而是**从别人的潜意识里固化的记忆碎片**。它们进入玩家的「梦境素材库」，用于之后构建自己的梦。

> **叙事**：你反复进入、熟悉、学习它，最后把它改造成你的据点。这和运营商进入普通人的梦、窃取资源、建立据点没有本质区别——只是玩家亲自上阵，运营商是雇人去做。

### 4.2 学习动作的成本、风险与语义提炼

「看到」不等于「能带走」。学习一个元素需要：

| 成分 | 说明 |
|---|---|
| **观察/刻录时间** | 必须持续注视或接触该元素一段时间，相当于「记忆刻录」 |
| **点数消耗** | 消耗洞察点数，代表投入的认知成本（点数的世界内理由见 §七） |
| **稀有度梯度** | 普通元素耗少，稀有元素耗多 |
| **记忆容量** | 玩家能稳定记住的素材数量有限，必须取舍 |

**风险回报**：学习行为本身可能惊动梦主，或吸引潜意识守卫。在别人的梦里「偷师」，别人是会察觉的（对应 `condition:dream-defender` 的守卫生成）。这让「抄东西」变成有风险、需要选时机的策略行为，而不是无脑右键收集。

> **与提炼/合成链的分工**：学到的东西里，可组合的「属性/词条类」内容（伤害类型、散射、穿透、状态等）在操作上走**提取词条 → 合成台（LLM 守门）** 的链（见 `docs/运营系统/06_素材记忆与消耗系统.md` §三/四）：提取烧掉原素材得纯语义词条，合成时由 LLM 翻译成合法 JSON。本文件只定「学习是获取动作、素材进梦境素材库」的落点，不重复定义词条结构。

### 4.3 素材元数据与分类维度

元素素材进入素材库时，必须具备以下元数据：

- `introduction`：列表和地图入口使用的一句话正式简介。
- `description`：详情页深入描摹、世界观讲述或可公开线索；无内容时允许为空。
- `iconAssetRef`：可选图标引用，用于缩略和快捷栏。
- `textureAssetRef`：必填贴图引用；场上实体使用严格正面俯视图，物品使用统一正视图。
- `quality`：玩家可见品级 1–5。
- `displayCategory`：素材库检索分类，不代替运行时实体分类。
- `runtimeEntityRef`：可选的物品、武器、载具、NPC、角色、交互实体或环境实体 profile 引用。
- `actorController`：角色素材可选 `player | ai-player | npc`；AI 玩家用于匹配和占位并参与玩家行动轮，NPC 由 NPC AI 驱动；二者不混用。

素材库分类分为三层：

1. **展示分类**：装置、照明、陈设、交互、线索、遮挡、物品、武器、载具、生物、角色、机制、氛围、蓝本。
2. **运行时实体语义**：`item | weapon | vehicle | npc | character | interactive | environment`。实体是否可交互由合法动作投影决定；物品、武器、载具、NPC、角色等通过稳定 profile 引用获得规则语义，不复制玩法数值。
3. **角色控制身份**：`player | ai-player | npc | unbound`。角色贴图和角色素材只表达外观，不表达控制器；AI 玩家使用玩家行动轮，NPC 使用 NPC 行动阶段，unbound 只用于肖像、对话、回顾或背景演出。

词条是独立的五类语义内容：属性、技能、状态、防御、机动。词条不可直接放置，不与实体或角色分类混合。AI 不是素材，也不是可单独放置的实例；AI 参数必须通过 PlayerAI 或 NpcAI 配置引用。蓝本是完整地图/梦境模板，不是普通元素素材，也不使用元素素材的贴图分类替代。

### 4.4 素材库 = 梦境素材库

玩家学到的元素进入**梦境素材库**——即一般 UGC 体系里的「仓库」，但现在有明确的叙事身份：库里存的是「我记住、学会、掌握的别的梦」。

> 素材库与「收藏室」（运营系统，长期纪念对象）严格区分：素材库服务于**创作**（构建梦境），收藏室服务于**长期推进与纪念**，两者不混装（见运营系统 §4.2 与本文 §6）。

### 4.4 元素素材 vs 整梦蓝图

为把「学元素」和「以梦为蓝本」区分清楚，本系统使用两档创作基础：

| 粒度 | 是什么 | 获取方式 |
|---|---|---|
| **元素素材** | 单一可重用的物件/生物/机制/氛围，可自由组合进自己造的梦 | 学习动作（见 §四） |
| **词条** | 从素材中提取的纯语义词条（品质 1-5），供合成台组合 | 提取动作（见 `运营系统/06` §三） |
| **蓝本** | 一整张现成梦境的可再创作模板（构成即该梦的完整蓝图） | 熟悉度满（见 §五） |

它们的分工：元素素材是「积木」，蓝本是「整套可改造的房子」，词条是「积木上的属性/词汇」。玩家既可以用积木从零搭自己的梦，也可以拿别人的整套房子当底子改造，还可以把素材提炼成词条去合成台组合新素材。

## 五、蓝本 = 完整梦境模板（单一来源）

### 5.1 定义

**蓝本**是某张现成梦境的**完整可再创作模板**。它通过把该梦的熟悉度刷满而解锁，存入梦境素材库，作为再创作的基底。

- 一张梦对应一个蓝本，蓝本来源是**熟悉度满的原梦**自身。
- 蓝本不是从多个素材拼出来的，而是「整张梦被复制下来再改造」。
- 在蓝本上派生/再创作，沿用创作系统 `derivedFrom` 的溯源语义：新作品是原蓝本的派生，对原蓝本可溯源，但不改变原蓝本自身。

### 5.2 与创作系统已有契约的衔接

`docs/创作系统/01_创作工具与产权.md` 已定义「派生 / 插槽引用 / 放置」三种关系与 `derivedFrom` 溯源；`docs/运营系统/06_素材记忆与消耗系统.md` 已定义词条语义解耦与合成台。蓝本在此处的落点：

- **蓝本 = 一张可派生、可再创作的基底**，属「存在完整模板」类创作依据。
- **元素素材 = 可自由组合的积木**，属「组合」类创作依据。
- **词条 = `placeable:false` 的实例**，属「词汇」类创作依据，只填合成台/工作台插槽、不进书架浏览（见 `创作系统/01` §五与 `运营系统/04` §四）。
- 三者都进入梦境素材库；建自己梦的时候，可以用纯元素拼，也可以用蓝本作为整体的底子，再叠加元素修改。

### 5.3 为什么「只能靠熟悉度满解锁蓝本」

如果不把「以某梦为蓝本」的资格卡在熟悉度上，退化的用法就是「拉官方图改一改」。熟悉度门槛保证：

- 玩家不是「打开地图直接抄」，而是**先真正理解这张梦的构成逻辑**（结构、关键点、潜在的手感）。
- 高级蓝本（稀有梦境、硬核地图）对应更高的熟悉度成本，形成长期收集目标。
- 玩家间形成专精与交易价值：不同玩家擅长不同类型的梦境（医院、工厂、学校、老城区），可交换素材、共享据点体系。

## 六、自建梦境 → 成为梦主

### 6.1 带着自己造的梦开房

玩家用自己的梦境素材库（元素 + 蓝本）构建梦境后，可以带着它开房间，让其他玩家进入。

这在叙事上就是（总纲 `role:dream-builder`）：

> 你成了一个「梦主」。其他玩家在你的梦里战斗、探索、死去。你看着他们，就像当初你看着别人的梦一样。

### 6.2 主权 / 中立两种模式（方向）

| 模式 | 叙事含义 | 方向 |
|---|---|---|
| **主权模式** | 你是这个梦的梦主，你的潜意识防卫（`condition:dream-defender`）会攻击入侵者 | 其他玩家必须完成任务或生存 |
| **中立模式** | 你提供一个稳定梦境作为竞技场 | 其他玩家在其中对抗，你作为旁观/仲裁 |

具体开房协议、房间权限、队伍规则属于后续联机专题；本文只把「开房 = 成为梦主」的创作侧方向定下来。实现不得在联机协议里凭空加一套「房主编辑器」——房主身份就是梦主身份，素材库就是他的梦境资产。

### 6.3 后座感（角色反转）

刚入行时玩家在被入侵的梦里当佣兵；建成自己的梦后，会亲历「为什么梦主会派守卫追杀入侵者、为什么梦主醒来后不记得、为什么梦境会排斥外来者」。这种角色反转不是硬加的道德说教，而是让玩家亲手重复资本行为后自然体会到的批判——**这是自建梦境在叙事上最高的价值**。

## 七、经济循环落点

### 7.1 循环形状

本文件把对话文件确定的探索→建梦循环落成方向：

```
探索收集 → 学习/提取素材 → 建梦 → 租用/维护 → 继续探索
```

即：

- 玩家在别人的梦里探索，学到素材、攒下熟悉度；可语义提炼的部分再按 `docs/运营系统/06_素材记忆与消耗系统.md` 进入提取词条与合成台。
- 用素材和蓝本构建自己的梦境。
- 维持自己梦境 / 扩充素材库需要投入（记忆巩固、租用锚定梦主空间等）。
- 赚取点数 / 资源的能力又取决于进一步探索和接单。

### 7.2 消耗的世界内理由

点数 / 货币在叙事上是玩家作为梦境专业人员的「认知与训练投入」：

- **学习元素** = 花「洞察/记忆巩固」资源把梦里见的东西固化下来；可语义提炼的内容再按 `docs/运营系统/06_素材记忆与消耗系统.md` 走提取词条与合成台。
- **维持自己梦境** = 让梦境稳定存在（对锚定梦主空间租用、或自我清醒梦稳定）。
- **扩充素材库容量** = 提升自己能稳定记忆的素材上限。

> **为什么不在这里定义货币**：具体币种、来源、汇率与回收属于运营系统经济专题，也是「从可挂素材对局到 MVP」之间的攻坚战。本文只定消费者为什么消费的理由，不定用什么货币消费。

### 7.3 与世界观经济的关系（约定）

- UGC 的「创作研发」消费与世界观内「经营驻地/推进主线」货币**可互通、但心智独立**。
- 玩家应能区分：我现在是「在做创作研发」还是「在经营驻地」。
- 互通不等于实时一比一换算。具体交换方向、损耗、门槛与来源留给运营系统（见 `docs/运营系统/01_运营与局外养成.md` §五）。
- 禁止用默认汇率、赠送货币或替身余额宣称经济集成已完成。
