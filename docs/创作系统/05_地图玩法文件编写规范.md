# 地图玩法文件 MapPlay 2.0 编写规范

> **状态**：权威定案（2026-09-05）
> **实现真身**：`src/play/content/map-play-file.ts`
> **适用范围**：所有可运行的局内、局外地图包
> **不适用**：通用 `PlayFile 1.0`、可拆分玩法层 Def、素材登记文件

## 一、主权关系

一张可运行地图由两个不可互相替代的核心共同定义：

```text
Canonical MapData = 空间事实主权
MapPlay 2.0      = 地图逻辑主权
```

`MapData` 唯一拥有 SVG 关联、图层、节点、边、放置和空间关系。`MapPlay` 唯一拥有该地图专属的局部状态、规则组合、生命周期、地图元素绑定、结果和表现时间线。其他实体、规则原语和表现组件都可模块化复用；只有这两个文档与具体地图绝对绑定。

地图包必须为每张 `MapData` 提供且只提供一个完整 MapPlay JSON。读取器不合并分片，不处理 `includes`，也不从多个根文件推断顺序。普通素材、玩法层定义和规则定义仍可自由拆分或合并，单文件限制不得外溢。

## 二、分层职责

| 层/内容 | 必须提供 | 禁止 |
|---|---|---|
| 基类层 | 可组合状态、事件、条件、动作和结果的类型边界 | 为单张地图写具体流程 |
| 玩法层 | 可复用 `ruleRef`、`conditionRef`、`actionRef`、`stateRef`、`outcomeRef` 及参数 Schema | 依赖具体地图坐标或具体渲染组件实现 |
| MapData | SVG、图层、节点、边、放置、门户等空间事实 | 规则流程和结果裁决 |
| MapPlay | 参数化组合已登记原语，定义本地图状态、规则、绑定、结果和语义时间线 | 新 Effect op、可执行代码、直接写 `WorldState`、空间覆写 |
| 表现层 | 稳定 `presentationRef`、时间线播放器、取消/跳过/降级/静态终态 | 裁决规则结果 |
| 渲染交互层 | 足够可配置的任务清单、倒计时、提示、转场、遮罩、镜头、动画、音频组件 | 暴露写规则状态的后门 |

地图专属机制不是地图私有代码。例如“30 秒倒计时，到零 Game Over，并同步任务栏”可在 MapPlay 中声明专属状态和规则组合；计时 tick、归零条件、任务栏同步和 Game Over 必须调用已登记原语。若缺少可复用原语，应先修改玩法层和公开 API，再编写 MapPlay。

## 三、固定根结构

```ts
interface MapPlayFileV2 {
  schemaVersion: '2.0';
  kind: 'map-play';
  mapPlayId: string;
  mapId: string;
  mapDataEntryId: string;
  entryNodeId: string;
  capabilities: MapPlayCapabilities;
  localState: MapPlayLocalState[];
  rules: MapPlayRule[];
  timelines: MapPlayTimeline[];
  outcomes: MapPlayOutcome[];
}
```

- `mapPlayId`：该逻辑文档的稳定 ID。
- `mapId`：必须精确等于对应 MapData 的 `id`。
- `mapDataEntryId`：必须精确等于包内 MapData 条目路径。
- `entryNodeId`：必须存在于对应 MapData。
- 根对象及所有子对象拒绝未知字段。
- ID 必须非空；同类声明内不得重复。
- 只允许 JSON 值，不允许函数、脚本、模块路径或动态求值文本。

## 四、能力声明

`capabilities` 是 MapPlay 使用能力的闭包清单：

```ts
interface MapPlayCapabilities {
  rules: string[];
  conditions: string[];
  actions: string[];
  states: string[];
  outcomes: string[];
  presentations: string[];
}
```

每个调用必须先出现在对应数组，并在装载环境的相应注册表中存在。声明本身不创造能力。路径、显示名和临时资源 URL 不能充当能力 ID。

## 五、地图局部状态

```ts
interface MapPlayLocalState {
  id: string;
  kind: 'flag' | 'counter' | 'timer' | 'objective';
  initial: JsonValue;
  lifecycle: 'map' | 'visit' | 'phase';
  stateRef: string;
  numericOwnerRef?: string;
}
```

- `map`：从 load 到 unload 存活。
- `visit`：每次 enter 重建、exit 释放。
- `phase`：由已登记阶段原语管理。
- `counter` 与 `timer` 必须填写 `numericOwnerRef`，进入设计货币/数值归属审计。
- `initial` 只是初值，不得夹带表达式或直接状态路径。
- 状态变化只能通过 `actionRef`；禁止 `world.*`、`state.*` 等直接写入引用。

## 六、规则与事件域

允许事件域固定为：

```text
map.load / map.enter / map.ready / map.pause / map.resume / map.exit / map.unload
node.enter / node.leave / edge.traverse
mechanic.event / outcome
```

规则结构：

```ts
interface MapPlayRule {
  id: string;
  ruleRef: string;
  event: MapPlayEventDomain;
  eventName?: string;
  targets: { kind: 'node' | 'edge' | 'placement' | 'layer' | 'portal'; id: string }[];
  conditions: { conditionRef: string; args: Record<string, JsonValue> }[];
  actions: { actionRef: string; args: Record<string, JsonValue> }[];
  timelineIds: string[];
}
```

`eventName` 只为 `mechanic.event` 等域提供已登记语义名，不是任意代码入口。`targets` 中的 ID 必须存在于绑定 MapData。参数可以引用业务 ID，但任何层级都禁止 `at/x/y/path/points/svg/topology/overrides/layerId` 等空间覆写字段。

规则先结算，表现后重演。`timelineIds` 不参与规则真假、数值变化或结果裁决；跳过全部时间线也必须得到相同游戏状态。

## 七、结果

```ts
interface MapPlayOutcome {
  id: string;
  outcomeRef: string;
  actionRef: string;
  behavior: 'terminate' | 'transition' | 'return';
  timelineId?: string;
}
```

结果必须调用已登记结果与动作能力。`terminate` 结束当前运行，`transition` 请求已登记转场，`return` 返回声明的上级流程。MapPlay 不得直接销毁世界、切换路由或修改内核状态。

## 八、语义时间线

```ts
interface MapPlayTimeline {
  id: string;
  skippable: boolean;
  cancelEvents: MapPlayEventDomain[];
  fallbackPresentationRef?: string;
  staticFinalState: string;
  cues: MapPlayCue[];
}

interface MapPlayCue {
  id: string;
  presentationRef: string;
  afterCueId?: string;
  delayMs: number;
  blocking: boolean;
  critical: boolean;
  fallbackPresentationRef?: string;
}
```

- `presentationRef` 只能引用已登记语义组件，不能直接内联 `RenderCommand`。
- `afterCueId` 表达局部偏序；不得悬空或成环。无 `afterCueId` 的 cue 从时间线起点计算 `delayMs`。
- `blocking` 只进入表现编排安全门，不阻塞规则结算；多人交权仍受表现层硬超时约束。
- `skippable` 表示用户可跳过视觉过程；无论是否可跳过，卸载和取消都必须可终止资源。
- `cancelEvents` 到达时停止未完成 cue，并应用 `staticFinalState`。
- 每条时间线必须有非空 `staticFinalState`。
- `critical: true` 的 cue 必须在 cue 或时间线级提供 fallback。关键表现及其 fallback 均不可解析时拒绝装载。
- 跳过、取消、资源失败和 reduced-motion 降级不得改变规则结果。

## 九、前端与表现组件的配套义务

为了使 UGC 创作者和开发者无需修改表现/渲染层，公共组件至少应提供：

1. 稳定 `presentationRef` 与版本化参数 Schema；
2. 任务清单条目增删、状态和进度绑定；
3. 倒计时/计数显示、警告阈值和静态终态；
4. 场景提示、遮罩、镜头、图层焦点和场景切换；
5. 动画、音频、全屏演出及 reduced-motion fallback；
6. 明确的 start/complete/cancel/timeout 生命周期；
7. 可跳过、可取消、可重放、可降级和卸载清理保证；
8. 参数越界、资源缺失和语义不存在的结构化诊断。

新增地图需求若只能靠改 React 组件或渲染命令实现，说明公共表现 API 不足。应先补表现组件及其登记/API，再回到 MapPlay 配置；不得把组件实现塞进地图包。

## 十一、编译顺序与拒绝条件

```text
严格 JSON 解析
→ MapData 规范化与结构校验
→ 每图恰好一个 MapPlay 配对
→ MapPlay 严格结构解析
→ mapId / mapDataEntryId / 地图元素引用校验
→ 能力声明与注册表校验
→ 局部状态和数值归属校验
→ 规则、结果和时间线图校验
→ 冻结为唯一 MapPlayProgram
→ 与地图 Prefab 一起进入可运行产物
```

以下任一情况必须拒绝，不得产生半成品运行产物：缺失或多个 MapPlay、错图绑定、未知字段、重复 ID、未解析能力/地图元素、直接状态写入、自定义 op、空间覆写、非法事件域、时间线悬空/成环、缺静态终态、关键表现无 fallback、数值无归属。

`PlayFile 1.0` 保持兼容，仅服务通用模式/剧情文件；不得用它规避地图包的 MapPlay 2.0 强制规则。
