## 一、定位：本文档描述的东西不是三层之一

三层架构（引擎层 / 基类层 / 玩法层）描述的是**一局游戏在运行期如何被组合出来**。它是运行期依赖链。

本文档描述的是**玩法层数据是怎么被创作出来的**。创作发生在运行期之外。

判据只有一条：

> **把它删掉，一局游戏还能不能跑起来？**

| 东西 | 删掉还能跑吗 | 归属 |
|------|-------------|------|
| `MapData` / 实例 profile / 玩法包 | ❌ 跑不了 | **玩法层数据** |
| 校验器 | ❌ 跑不了（载入时审查） | 基类层能力 |
| 地图编辑器 UI、工作台 UI | ✅ 照常跑 | **创作工具，不属于三层** |
| 仓库浏览界面 | ✅ 照常跑（但玩家买不了东西） | 对局外界面 |

依赖方向是单向的：

```
创作工具 ──产出──> 玩法层数据 ──被读取──> 一局游戏
   ↑                                        ↑
   └────── 复用渲染层与设计令牌 ─────────────┘

玩法层永远不 import 创作工具。反向 import 是架构违规。
```

### 代码位置

| 内容 | 路径 | 理由 |
|------|------|------|
| 实例 profile（JSON） | `src/play/profiles/**` | 已存在。玩法层数据 |
| `MapData` schema + 校验 | `src/play/map/` | 玩法层数据，游戏运行必需 |
| 曲线纯函数（RDP、重采样） | `src/play/map/curve.ts` | 纯函数，被运行期动画消费 |
| 地图编辑器 UI | `src/editor/map/` | 工具。**不在三层内** |
| 工作台 UI | `src/editor/bench/` | 工具。**不在三层内** |
| 仓库浏览 UI | `src/shell/stock/` | 对局外界面 |

`src/editor/**` 必须遵守一条 ESLint 约束（与 `src/core` 禁止 import React/DOM 同理，方向相反）：

```
src/play/**  禁止 import  src/editor/**
```

这条规则是"删掉编辑器游戏照常跑"的机械保证，不靠人记得。

> **文档归属已按 D-067 修正**：创作系统使用独立目录，不再采用“玩法层包含所有前端职责”的宽义读法。`docs/创作系统/**` 与 `docs/L3_玩法层/**` 分离；代码仍保持 `src/editor/**` 不被 `src/play/**` 反向依赖。

## 三、四个部件的职责边界

| 部件 | 能做 | **明确不能做** |
|------|------|---------------|
| **仓库** | 存放拥有的实例；按类别/类型浏览；标记归档 | 修改实例；存放地图自带的临时免费实例 |
| **工作台** | 修改实例属性；填插槽；派生变体；就地新建；与 LLM 协同 | 放置到地图；修改基类层（那只能由 LLM 直接改代码/数据） |
| **地图编辑器** | 导入人工 SVG；编辑节点、拓扑与空间关系；从统一资产登记中检索、选择和放置素材；试玩 | **修改任何实例本体**；生成或重绘地图 SVG；跨地图粘贴未拥有的实例 |
| **LLM / Agent 工具** | 生成玩法文件或带地图玩法包候选；采访式需求澄清；步骤 3 调用 V0 平台图像工具生成 AI/NPC/物品实体素材；步骤 6 完成内容和逻辑绑定 | 新增表现层实现；生成地图 SVG/底稿；决定或回写用户的地图空间布局；直接操作地图编辑器 |
| **玩法包** | 作为内容集合承载玩法层引用、玩法文件、地图包引用或表现资产引用 | 携带可执行代码；以包名替代 ContentKind；绕过统一校验 |

**地图包边界**：局内、局外地图都是目录/清单式地图包；“包”表示稳定内容边界，不要求压缩为 ZIP。局内地图玩法文件可深度接线场景生命周期和既有渲染组件，也可承载地图特有机制，但通用机制必须优先沉淀到玩法层复用。地图包与普通玩法内容保持独立，普通玩法文件只能引用和绑定，不能改写人工 SVG 或用户确定的空间关系。

### 地图编辑器为什么这么窄

它的右侧面板几乎是空的：放置参数只有坐标、朝向、挂哪条边、占哪个卡槽。所有"这个柜子里装什么"之类的设定都在实例本体上，由工作台设好。

想要三种不同装填的储物柜，就在工作台造三个实例，放置时选对应的那个。**选哪个实例本身就是分配设计。**

这是"清爽而非臃肿"的机械实现：编辑器没有检视器，所以它不可能长成第二个工作台。两者可快速切换，但逻辑上你始终在其中一个里。

### 工作台不做基类层图形化

这条是**永久性的**，不是 MVP 妥协。理由：基建的定义边界可以一路上升到与引擎层接壤，图形化它等于图形化引擎；而实例的数值与属性修改顶多就是最接近对局的那一层，边界清晰、可图形化。

普通玩家想动基类层，走 LLM。引擎已经为此预留了 `natural-language-adapter` 来源。

### 3.1 LLM 工具的玩法包生成管线

**定位**：LLM 工具是工作台的一个特殊协同模式，而非独立部件。它接入仓库、工作台、地图索引，产出的玩法包经由统一编译器验证（L2/06 §七）。

#### 能力边界

LLM 工具能理解既有基类层、玩法层、设计货币约束与公开 API，能写声明式内容并调用现有前端实现，但：

- ❌ **不能新增表现层实现**：只能调用已登记的视觉效果、UI 组件和动画编排
- ❌ **不能生成地图 SVG 或底稿**：全屏地图由人工产出并导入
- ❌ **不能直接操作地图编辑器或决定空间布局**：用户确定的坐标、拓扑与空间关系是权威设计意图，AI 不得回写或猜测替换
- ✅ **可以补齐玩法层复用缺口**：确有必要时，通过步骤 2 的规则/API 更新新增通用机制，而不是在每张地图重复实现
- ✅ **可以生成实体素材**：步骤 3 由 Agent 调用 V0 `GenerateImage` 等平台工具生成 AI/NPC/物品的视觉资源；仓库脚本只负责清单、确定性后处理、登记和挂载，不要求模型 API Key
- ✅ **可以新增实例并引用地图包**：玩法文件只保存稳定内容 ID、节点绑定和组件引用，不保存临时开发路径
- ✅ **可以完成高逻辑绑定**：步骤 6 按规划书、设计货币系统说明书和玩法设计说明书填充内容、流程和玩法文件

每张可运行地图必须读取且只读取一个完整 `MapPlay 2.0` JSON；它与 Canonical MapData 一一绑定，前者拥有地图逻辑，后者拥有空间事实。MapPlay 可组合已登记原语声明专属机制，并以语义时间线调用任务清单、场景提示、转场等既有表现能力；不得修改表现/渲染实现、发明 op、直接写状态或覆盖地图空间。缺少倒计时、计分等通用能力时，先扩充玩法层与公开 API，再由 MapPlay 参数化接线。详见 `05_地图玩法文件编写规范.md`。

#### 生成流程（采访 → 生成 → 验证 → 修正）

```
1. 玩家提出需求（自由文本 / 指定玩法包加工）
   ├─ 需求类型判定：是否形成完全无歧义的玩法逻辑？
   └─ 歧义补充：哪些需要澄清，哪些不够合理，违反了什么约束？

2. 采访循环（2-4 轮，注重高效）
   ├─ 单选 + 可补充的图形化问答（非固定问题树）
   ├─ 循循善诱：诱导其做出完善且合理的配置规范
   ├─ 调用工具：形象编辑器（左侧像素编辑器 / 样板库 / 上传）
   └─ 终止条件：已穷尽意图且可行（不可行则直接拒绝并说明）

3. 显示支付界面
   ├─ 价格按复杂度分档（实例数量 × 权重）
   ├─ 每档固定价格，不以强度而以层次为判定
   └─ 玩家确认支付

4. 生成并编译
   ├─ LLM 生成 JSON 清单（实例 profile / 规则配置 / 地图引用）
   ├─ 调用玩法包编译器（L2/06 §七）
   ├─ 收集诊断（error / warning / info）
   └─ 自动修正可修正诊断（autoFixable: true）

5. 展示与确认
   ├─ 玩法包简介 + 详细机制介绍（与房间查看界面相同）
   ├─ 玩家确认 / 继续加工（重新进入采访循环）
   └─ 保存最后一版
```

#### 必要信息清单（采访要收集的内容）

| 类别 | 必要信息 | 缺省行为 |
|------|----------|----------|
| **玩法类型** | 大逃杀 / 夺旗 / 团队竞技 / 自定义 | 无缺省，必须明确 |
| **初始装备** | 空手（D-041 默认）/ 指定武器 / 随机抽取 | 空手 |
| **胜利条件** | 最后一人存活 / 击杀数 / 占领点 / 自定义 | 最后一人存活 |
| **特殊规则** | 缩圈（D-049 用毒素伤害）/ NPC / 时间限制 | 无特殊规则 |
| **数值配置** | 伤害表 / AP 成本 / 血量上限 | 继承官方默认值 |
| **地图引用** | 官方地图 / 玩家地图 / 无地图（纯规则包） | 无地图 |

#### 违反约束的处理

| 违反类型 | 处理方式 |
|----------|----------|
| **五并列原则**（同时可选项 >5） | 警告，但不硬拦截（编译器可能拦截） |
| **1-5 数值约束** | 警告，编译器会报 `PLAY-NUM-OUT-OF-RANGE`（autoFixable） |
| **三层架构**（试图修改引擎层） | LLM 写不出来，物理上不可能 |
| **已确认决策**（如试图绕过骰点机制） | 警告，说明为何不符合设计意图 |

所有违反都**不是硬拦截**——LLM 给出警告，但仍生成 JSON，交给编译器验证。编译器的 `error` 才是真正的闸门。

#### 风控机制

1. **关键词计分风控**
   - 敏感词库（政治、色情、暴力、欺诈）
   - 每个词有权重，累积超过阈值 → 标记 Steam ID
   - 风控池供人工审查
   - 所有对话留档

2. **提示词注入检测**
   - 一旦检测到疑似注入（关键词"忽略""上下文""系统提示"等）
   - 拉便宜模型（如 GLM-5）二次校验：只传玩家输入，判断是否为注入
   - 触发二次校验时风控权重大幅提升

3. **单次加工循环 token 硬上限**
   - 防止恶意消耗算力
   - 超出上限直接终止，不影响已生成部分

4. **���格的 Prompt 结构隔离**
   - 系统提示与用户输入物理隔离
   - 用户输入不进入函数名、参数名、控制流

#### 素材处理

必须区分地图图像与实体素材：

- **地图图像**：Agent/LLM 不生成。用户导入人工 SVG，并在编辑器中亲自确定空间关系。
- **实体素材**：AI、NPC、物品的图片允许由 Agent 通过 V0 `GenerateImage` 等平台工具生成；默认入口不调用仓库内外部模型适配器，也不要求模型 API Key。
- **完整素材**：图片还必须绑定稳定实体/定义、渲染描述和编辑器目录元数据，并通过表现层实例化、渲染层消费、编辑器可选三道验收。
- **仓库代码**：只承接清单校验、确定性后处理、登记、引用校验与挂载报告。
- **形象编辑器**：仍可作为玩家手工修改入口；它与 V0 批量生成入口并存。
- **编译器检查**：引用必须指向官方库、玩家拥有内容或已完成登记挂载的生成素材。

## 四、三种关系（最容易混淆，必须逐条区分）

同样是"A 和 B 有关联"，语义完全不同：

| 关系 | 语义 | 母本更新时 | 用在哪 |
|------|------|-----------|--------|
| **派生** | 复制作为起点 | **不跟随**（向下兼容） | 工作台造变体 |
| **插槽引用** | 包含 | 跟随（是同一个对象） | 工作台填插槽 |
| **放置** | 快照内联 | 不跟随 | 地图编辑器放东西 |

### 派生 = 快照，不跟随

派生时把母本内容**完整复制**一份，`derivedFrom` 只记录出处，不参与解析。

```typescript
{
  id: 'police_shotgun_7f3a',        // 玩家命名 + 随机 key
  derivedFrom: 'official_shotgun',   // 仅溯源，不解析
  description: '……',                 // 派生时复制自母本，之后独立
  damage: 4,                          // 我改的
}
```

三个后果：

- 母本修 bug **不会**传播到派生物。这是"向下兼容"的代价，接受。
- **不需要**版本通知机制，也不需要覆写集与级联解析。
- 高阶创作者「保留官方介绍」自然成立——派生时就复制了官方文案，什么都不用做。

### 母本一旦被派生过就不可删，只���归档

不是为了解析（派生物已经是快照，不依赖母本），而是为了**保住购买记录与派生权凭证**。删掉母本，你在该小类上的派生资格就失去了证明。

归档 = 从选择器隐去，引用仍可解析。产权系统里"真删"没有任何好处。

### 插槽引用 = 活引用

```
储物柜 #7f3a { contents: → 警用霰弹枪 #a3f2 }
                          ↑ 同一个对象，不是副本
```

改了「警用霰弹枪 #a3f2」，所有插槽引用它的实例一起变。这是词汇该有的行为——修一个词的定义，用到这个词的地方全部生效。

与派生不冲突：派生是"以它为起点造一个新的"，插槽引用是"我包含它"。

### 引用/快照的分界线就是地图边界

| 位置 | 语义 |
|------|------|
| 工作台插槽 | 引用（活的） |
| 地图放置 | 快照内联 |

地图必须自包含，所以过地图边界时一律内联。这条同时解决了"插槽引用了我不拥有的实例"——内联后视为临时免费。

## 五、三个正交标记位

三个布尔值，各管一件事，互不重叠。全部**在基类层声明**，实例继承。

### `placeable` —— 管界面出现在哪

| 值 | 含义 | 例子 |
|----|------|------|
| `true` | 能摆到节点上 | 储物柜、僵尸、载具、门 |
| `false` | 只能填进别人的插槽 | 中毒、散射属性、穿透伤害 |

两者**都进仓库**——都是词汇，都受经济门禁（状态类甚至是最值钱的创作词汇）。区别只在界面：

- 地图编辑器面板：只列 `placeable: true`
- 工作台插槽选择器：两者都列，按插槽 `accepts` 过滤

心智矛盾就此消解：玩家从不"摆一个中毒"，他给一把枪装上中毒。拥有它是拥有词汇，不是拥有物件。这类 `placeable:false` 的实例即**词条**——它们承载"属性"（伤害类型、散射、穿透等）这类非自由文本属性，经工作台插槽填充，交给 LLM 翻译成合法 JSON（见 `docs/运营系统/06_素材记忆与消耗系统.md` §三）；它们**不在书架浏览**，归属工作台/研究台的词条类分区（见 `docs/运营系统/04_局外养成的保险箱与素材库交互.md` §四）。

**仓库界面必须为词条设独立分区**，否则购买后第一反应是"我买的东西呢"。

### `playerFacing` —— 管要不要写介绍

| 值 | 含义 | 要求 |
|----|------|------|
| `true` | 玩家在对局中会看到它 | 必须有名字、介绍、图标 |
| `false` | 只影响内部计算 | 免除 |

玩家能看见的东西必须能被理解；看不见的不勒索创作者写文案。散射属性是 `false`，中毒是 `true`。

> **2026-08-08 权威变更**：本节"散射谱型"改称"散射属性"，与已废止的"攻击形状/形状轴"设计
> 无关——散射本身作为武器属性一直有效，只是命名从"谱型"改为"属性"以避免与被废止的形状分类
> 混淆。详见 `docs/L0_规范宪法.md`、`docs/L2_基类层/基类层定义.md` §4.3。

### `derivable` —— 管派生权边界

```
枪类        derivable: false   ← 买一把霰弹枪不该解锁狙击枪
霰弹枪      derivable: true    ← 派生锚点
```

买一个实例 = 获得它**最近的上层派生锚点**的派生权。

层级超过两级时"最近的上层小类"会歧义，所以锚点必须显式标记。现在加是零成本，将来加是破坏性变更（所有已售实例的权限范围会变）。

它同时是**经济分段器**：词汇量增长是分区的、可控的。

## 六、数据流

```
基类层声明（插槽、约束、三个标记位）
    │  LLM 可改，图形化永不可改
    ▼
实例（工作台产出，targetOwnership: 'play-layer'）
    │  派生 = 快照 / 插槽 = 活引用
    ▼
仓库（产权边界 + 质量闸门）
    │  只有过了校验器的才能进
    ▼
放置（地图编辑器，快照内联进 MapData）
    │
    ▼
对局
```

### 仓库入口是质量闸门，不只是产权闸门

进仓库前必须过 `src/core/ugc` 的校验管线：不死循环、不违反不变式、不软锁。过不了 → 进不了仓库 → 放不到地图上。

于是白拿一个别处没有的能力：**UGC 内容在发布前被属性测试轰过十万次。**

### 临时免费

地图自带的节点与实例可任意复制使用，但：

- ❌ 不能进仓库
- ❌ 不能在工作台修改
- ✅ 在本地图内视为免费
- **标记位随复制传染**（数据结构里带标记，不靠推导）

**剪贴板是地图作用域的。** 跨地图粘贴要求仓库产权，否则拒绝并说明原因——否则打开别人地图 Ctrl+C、回自己地图 Ctrl+V，产权系统当场绕过。

### 便利性系统，不是密码学系统

`MapData` 是内联的 JSON，任何人都能读出完整实例规格。手抄一遍能重建，改存档能白拿。

**这不防死，是明确立场**：破解只让你跳过自己的难度曲线，损失内化在自己身上，不外溢到别人的对局平衡。

唯一的例外线：若将来出现 UGC 排行或竞技，"谁的仓库更丰富"会变成实质优势，届时才需要服务端权威。**现在不做。**

## 七、经济

### 定价原则

> **仓库不是能力等级，是表达词汇量。**

价值锚在**创作门槛与负担**，不在强度。新手用 5 个词写出比老手用 200 个词更好的东西是允许的、也是好的——说明经济没有污染玩法。

安全属性：**买了用不好没有任何危害。** 花大钱买复杂实例、不理解就乱放，结果只是做出一张不好玩的地图，损失全部内化。这就是这套经济可以不做强度约束的原因。

### 三条内容通道

| 通道 | 成本 | 可编辑 | 可购买 | 谁能用它做地图 |
|------|------|--------|--------|---------------|
| **官方包** | 打包出售（同时装包模式） | ✅ | ✅ | 任何购买者 |
| **高阶创作者包** | 免费上传 | ❌ | ❌ | **只有作者自己** |
| **地图自带** | 免费 | ❌ | ❌ | 只在本地图内 |

高阶创作者包是**平行内容通道**（类 mod）：能遇见，不能拥有。

三个后果：

1. **不冲击官方包经济** —— 免费的高质量词汇不会挤掉付费词汇，因为它不进任何人的仓库。
2. **依赖问题消失** —— 包与作者的地图同生共死，不存在"作者删了包，我的地图打不开"。
3. **代价**：高阶作品是孤岛，图形化创作者无法复用，社区共享词汇池不因他们增长。这是保护经济的对价，接受。

### 黑箱的三个精确含义

| 对谁 | 黑箱？ |
|------|--------|
| 对人 | ✅ 界面不提供打开入口 |
| **对校验器** | ❌ **完全透明，必须过全量校验** |
| 对密码学 | ❌ 不是加密 |

第二条由引擎保证而非约定：`CandidateSourceKind` 的 `kind` **不改变 Schema、配额、severity 或任何验证规则**。免费上传的黑箱包和官方包走完全相同的校验管线。

**人看不见，机器全看见。** 质量控制与黑箱不冲突。

而这条只有因为基建是数据（Op/Expr/Hook 树，D-019 已定为纯声明式 JSON）才可能。若基建是 TS 代码，"免费上传 + 黑箱 + 在别人机器上跑"就是任意代码执行漏洞。

### 介绍继承与质量信号

派生时复制母本介绍（见第四节）。所以：

- 校验器**不强求**每个派生实例重写介绍
- 大部分高阶创作者保留官方介绍 → 官方词汇仍在被传播 → 玩家打不开机制但认得零件
- 深度创作者补全介绍 → 「介绍完备度」可作为排序加权项，**不做硬门槛**（会挤走轻量创作者）

免费上传本会招垃圾内容，但货币来自点赞与游玩，排序机制天然存在，**不需要准入审核**。

### 货币来源

竞技、他人点赞与游玩等，可多币种服务不同目的。**属于后期设计，本文档不定。**

一个方向性判断：若创作者收入来自自己地图被玩，则形成闭环——创作 → 被玩 → 得币 → 买更复杂的词汇 → 创作更复杂的东西。价值与收入锚在同一个东西上。

## 八、工作台交互契约

### "怎么把一个实例塞进设定中"

这是工作台的核心交互，逐步定：

```
1. 点击插槽
2. 弹出选择器：只列仓库里符合 accepts 的实例
     accepts: '物品类'  → 类型约束承担全部搜索压力
     predicate?: Expr   → 可选进一步过滤（"体积 ≤ 2"），复用已有 Expr 树
3a. 选一个 → 回填
3b. 点「新建…」 → 在当前上下文里嵌套一层 → 确认后回填、回到原处
```

第 3b 条避免的是最糟的默认行为：为填一个槽被踢出当前编辑、去别处造完、再回来找回原来在改什么。

**类型约束是搜索问题的解**：新手仓库里符合条件的可能只有 3 个，老手 200 个但过滤后仍是十几个。全局注册表搜索因此可以延后（见第十一节）。

### 嵌套呈现：左树右详情

```
储物柜 #7f3a                    │  capacity  [==●===] 2
├ contents: 警用霰弹枪 #a3f2     │  contents  [警用霰弹枪 #a3f2] ⊙
│  └ onHit: 中毒 #b81c          │  locked    [✓]
└ locked: true                  │  lockDC    [====●=] 12
```

左树永远显示完整结构（你在哪、整体长什么样），右侧只编辑当前选中的一层。**任意深度都不迷路，因此不设深度上限。**

数值参数用推杆式滑块，范围由基类声明夹紧——超范围在控件层面即不可能，校验器只兜底。

### 环路在选择器层面消除

填槽时遍历引用图，会造成环的候选**直接不列出**。错误从"能犯但会被抓"变成"犯不了"。

### undo 按编辑上下文分层

嵌套里的 Ctrl+Z 只撤嵌套里的；退出嵌套后，整个嵌套编辑作为**一个**可撤销单元。否则一次深层编辑会污染上层 20 步历史。

## 九、地图编辑器交互契约

### 状态机

```
Select（默认，Esc 永远回得来）
  ├─ PlaceNode  （N，Esc 退出）
  ├─ DrawEdge   （E，Esc 退出）
  ├─ Sample     （I 或按住 Alt，松开即退）
  └─ Playtest   （P，Esc 退出，编辑状态保留）
```

只有三个创造性动作有模式。模式越多越容易迷路。

**默认态是 Select 而非造物**，因为主流用法是改已有地图（上面已有基础划分与拓扑），不是从白纸描图。

### Select 态裸输入

| 输入 | 空白 | 节点 | 边 | 道具 |
|------|------|------|-----|------|
| 左键单击 | 清空选择 | 选中 | 选中 | 选中 |
| 左键拖拽 | 框选 | 移动 | 拖控制点 | 移动 |
| 双击 | **不创建** | 聚焦 | 插入控制点 | — |
| 右键 | 画布菜单 | 元素菜单 | 元素菜单 | 元素菜单 |
| 悬停 | — | 白色描边 | 白色描边 | 白色描边 |

**双击空白不创建节点** —— 误创建是编辑器第一号烦人事。造节点按 N 或走右键菜单。

左键拖空白给框选而非平移，因为平移有空格与中键两条路，框选没有替代。

### 全局输入

| 输入 | 动作 |
|------|------|
| 空格+拖 / 中键拖 | 平移（走 SVG viewBox，不走浏览器滚动） |
| 滚轮 | 以光标为中心缩放 |
| Ctrl+Z / Ctrl+Shift+Z | 撤销 / 重做 |
| Delete | 删除选中 |
| Esc | 退出模式；已在 Select 则清空选择 |
| Ctrl+S | 保存 |
| Tab | 开合面板 |
| N / E / I / P | 节点 / 边 / 取样 / 试玩 |
| 1/2/3 | 楼层切换 |

平移缩放走 `viewBox` 而非浏览器滚动，与 `killWebFeel` 禁用滚动缩放的策略天然一致，不打架。

### 拉边流程

```
1. 按 E
2. 悬停节点 → 蓝色（合法起点）
3. 节点上按下 → 开始描线
4. 自由拖动 → 实时预览折线，原始点全收
5. 进入其他节点吸附半径 → 那个节点亮蓝
6. 在节点上松手 → 端点精确吸附节点中心 → RDP 简化 → 建边
7. 在别处松手 → 整条丢弃 + 红色一闪
8. 保持 E 模式可连画，Esc 退出
```

第 7 条是设计过的行为。未设计的默认要么建出悬空边（脏数据），要么静默失败（用户以为手抖）。

**只有松手点吸附，中间点永不吸附** —— 否则曲线绕过某节点旁边时会被它抢走。

端点吸附不是可选项，是正确性要求：浮点近似会让校验器判出"边端点不存在"。

### 拉线后的塑形：平滑样条线（不是贝塞尔）

> **术语正名**：这条边是**平滑样条线（Spline，工程上即经过全部样本点的 Catmull-Rom 样条）**，不是贝塞尔。贝塞尔是"控制点在外面把线吸过去"，线不经过手的落点，违反"指哪打哪"；样条**绝对穿过**每个必经点，拖拽直觉直接成立。全程只叫"样条线"，不再用"贝塞尔"。

样条线的编辑是三态合一的最小动作集，全部发生在**显式连线**（人层唯一有权增删的图元，见§八图元），不需要任何控制柄状态机：

```
┌───────────────────────────── 样条线塑形 ─────────────────────────────┐
│  [A] 拉伸建线     [B] 折点调整      [C] 拉弯塑形      [D] 折点删除       │
│  遇末端 → 拉出新  按住中间折点     按住线段主体      选中折点 Delete     │
│  线段（折线）     拖动改位置       往外拖 → 生成      或拖至邻近折点     │
│  松手生成新折点   左右连线跟随     隐藏样条点         重叠融化           │
└─��─────────────────────────────────────────────────────────────────────┘
```

动作对数据的映射（都发生在 `path: readonly Vec2[]` 这一个数组上，见下）：

| 触发操作 | 目标 | 交互行为 | 数据响应 |
|---|---|---|---|
| 末端按下→拖 | 末端折点 | 橡皮筋拉伸新折线，松手生成新折点 | `path` 末尾追加新折点 |
| 按住 | 中间折点 | 移动该折点位置 | 更新该折点坐标，左右连线跟随 |
| 按住并外拖 | 任意线段主体 | **拉弯成平滑样条**，松手定型 | 在鼠标落点**追加一个隐藏样条点**进该线段 |
| 双击 | 已拉弯的线段 | 恢复为直线 | 清空该线段内全部隐藏样条点 |
| `Delete` | 选中的折点 | 移除该折点 | 删点，前/后折点直接连成直线 |
| 拖至邻近折点 | 折点 | 触发"融合删除"吸附提示，松手删除 | 同上，删点即拍直两侧 |

逐条关键语义：

- **拉弯即追加（Fire-and-Forget）**：每对一条线段拖一次，就在鼠标落点追加**一个隐藏样条点**，样条穿过它。你拖多少次就塞多少，没有上限；S 型就是你在一段上拖两次。**隐藏点不可见、不可选中、不可二次编辑**——你觉得丑，只能把它们**整体**清空重拉，不存在"选中某个样条点微调"。这正是"所见即所得，不爽就重来"的极简流。
- **双击线段拉直**：清空该线段内全部隐藏样条点，瞬间绷直回直线。是唯一的重塑入口。
- **折点删除即拍直**：删除一个折点，不论其左右线段之前拉得多弯，都直接重连成一条**绝对直线**。因为重连是新建的线段、隐藏样条点天然为空，这是"安全降级"——避免"幽灵曲线"：两段不同曲率强行拼接大概率变成乱线，拍直最符合人类预期。
- **吸附删除**：拖某折点距左右任一邻折点小于阈值（约 10px）时，目标折点高亮提示"松手即融合删除"；松手后该折点消失，左右重连成直线。折叠阈值与 RDP epsilon 一样**不暴露给创作者**。
- **单击只高亮，不参���逻辑**：单击线段仅触发高亮（表现层反馈"当前操作焦点在这条线"），**不选中任何控制点、不弹菜单**。任何编辑开始/持续期间线段恒为高亮，但它只是镀层，不与任何逻辑纠缠——选中与否都不改变数据的增删改查。

**RDP 简化在拉边阶段做一次**（见「拉边流程」第 6 步），把录制的大量原始点压成少量折点；之后的样条点是创作者主动追加的，**不再简化**。直线段 `path` 为空数组时按线性插值渲染，非空即切换 Catmull-Rom 逐段穿过样本点。`path: readonly Vec2[]` 直接喂进已有的 `jumpMotion(path)` 运动核，引擎侧零改动。

### 图元穷举：双分层坐标系的最小闭合集（D-074）

地图编辑器的图元必须是**尽量少的框/线/点覆盖全部逻辑**（D-074）。任何新增图元先过核减审查：是否必要、能否被既有图元表达。当前闭合集如下——一个图元同时回答「人怎么画」（人层涂鸦）与「AI 怎么读」（逻辑层严格语义），这就是编辑器的**双分层坐标**：编辑时是人性化涂鸦，储存时翻译为拓扑层严格声明（D-072 ∕ D-074）。

| 图元 | 颜色 / 表现 | 人层交互（涂鸦式） | 逻辑锚点（AI 读编码） |
|---|---|---|---|
| **场景框**（原「节点框」，更准） | 灰白 | 多重叠加、旋转、融合；同类型重叠合并为一块、边界消失 | 场景节点；多个场景框聚合 = 一个场景；「最大距离矩形中心」= 高光点 |
| **连线**（平滑样条行动线） | 半透明白色 + 阴影 | 从场景高光点拖到目标场景边缘点；按住线段外拖拉弯（见§九样条塑形） | 拓扑连接 + 方向性 + 行动线路 |
| **视觉遮挡框** | 黄（半透明）；未来其他感官也黄，用纹理区分 | 阴影框选中、Delete、滚轮 10°/格旋转 | 视觉遮挡隔离：框覆盖其经过的样条线，翻译为「视觉遮挡」严格语义 |
| **物理遮挡框** | 红（半透明，醒目 + 不可通行） | 阴影框选中、Delete、滚轮 10°/格旋转 | 物理遮挡隔离：框覆盖的连线为「物理遮挡」，进入场景框被认可、融入寻路可通行判定 |
| **高地框** | 深绿 | 阴影框选中、Delete、滚轮旋转 | 地形锚点：玩家进入时阶梯式轻微放大 |
| **洼地框** | 浅绿 | 阴影框选中、Delete、滚轮旋转 | 地形锚点：玩家进入时阶梯式轻微缩小 |
| **过渡窗口** | 素材库组件（贴图可不同、效果可不同） | 不吸附到节点，独立拖到任意位置；一旦经过一条线即成为该线过渡窗口 | 过渡场景：在该样条线的过渡点上切分场景（切分，不自我创造） |

> **高地 / 洼地与楼层无关**：楼层严格使用分层地图（多图叠加）；高地和洼地**没有任何断层**，不存在从高地到洼地需要跳窗等高差逻辑，目前无任何玩法逻辑加持——**只做表现层的阶梯式缩放微调**，保留逻辑锚点供玩法包未来挂功能。

> **框 vs 点**：节点用框而不用点，因为框可以**吸附**。各种图形（组件素材）可随意摆放，只要不想用其功能、只作贴图（像素 / 全息投影光层背景的画风不同、有装饰作用）也允许；一旦拖拽的组件边缘**碰到**场景框边即生效。这允许在节点活动框内自由摆放，符合"大部分天然场景有相当大面积、内有多个微型场景"的认知。

#### 涂鸦式交互（拒绝 PS 式 4 点拖拽框）

所有矩形 / 线用**同一种**涂鸦式交互，避免 Photoshop 恼人的 4 角控制点拖拽：

- **同类型框重叠 = 合并**：像涂鸦一样多拖几个矩形，同类型重叠不报错，效果一致；所有同类型框重叠后**合并为一个���形、边界消失**。选中时选中整个阴影，整体删除或整体旋转。
- **点击选中**：四个角没有控制点，而是**阴影提起**的感觉。按 Delete 删除。鼠标拖拽**不能拖边框变形状**（框的形状只在造的时候定，之后整体拖动/旋转）。
- **滚轮旋转**：一次小滚 = 10°。
- **线同理**：一条线也是一个整体图元，同样阴影选中、整体删除/旋转，不逐控制点拖变形；**线自带一整条可整体拉弯/拍直的平滑样条**（塑形走第九节「拉线后的塑形」，不引入逐控制点微调）。
- 视觉遮挡框黄、物理遮挡框红、高地深绿、洼地浅绿——颜色就是图元身份的直观载。

#### 场景框聚合 = 场景，最大距离矩形中心 = 拖线锚点

- **多框聚合 = 一个场景**：`场景框`可以拉出多个框糊在一起构建一个场景；可以旋转后再拖新框融合。连在一起的多个框视为**一个场景**。
- **高光点**：创建一个或多个场景框构成一个场景后，选择其**「最大距离矩形中心」**创建一个**高光点**——可用它拖出直线；单点高光点可设置该场景属性（大 / 中 / 小等场景档位）。
- **空洞全填（仅对场景框生效）**：本条**只针对场景框**，不适用于其他方框图元（视觉遮挡框 / 物理遮挡框 / 高地 / 洼地等——它们没有「封闭区域归属」语义，不参与填充判定）。若**场景框**形成内部封闭空洞（如 4 个矩形围成一个矩形空洞），视觉上**像油漆桶一样被填充**（像没有这个空洞），逻辑上该区域也是场景的一部分、**不可在其中放置其他场景节点**；储存逻辑仍是多个矩形拼成，**不会用虚假矩形填补空洞**。

  **为什么必须填死、且只对场景框生效**（本条的推导依据）：
  - **跨场景寻路依赖外��交点定位**：离开一个场景前往另一个场景寻路时，以「**连接点**（连线端点，即高光点 / 目标场景边缘点，见本节连线图元）」与「**封闭图形场景外框**」的**交点**，作为离开场景这一段**阶段寻路的终点**。外框必须是一条无分叉、连续闭合的确定边缘，这个交点定位才成立。
  - **内部空洞破坏该定位**：若封闭区域内残留空洞，外框会在该翻折处失去唯一连续边缘，交点不再唯一，跨场景阶段寻路终点随之失准——空洞直接破坏这条逻辑。
  - **空洞若不锁死会崩坏寻路算法**：若内部空间不属于场景、可被再次放入新图元，设计者理论上**能把另一个场景塞进空洞**（见图元可自由摆放的合理认知）。场景被嵌套进其他场景的内部封闭区域，将使该场景的边界归属与「可走性由连接决定」的可通行判定彻底崩坏。因此必须把被完全包围的内部区域**预先并入所属场景并禁止再放场景节点**，从源头杜绝嵌套。
- **粘连判定**：若一次场景框拖拽/创建**把两个已创建的节点连接了起来**，则这两个场景**不合并**，此次操作被**拒绝**（拖了没效果），并给淡出提示。违反上述任一原则的操作都被拒绝并返回违反原则的提示。

> 允许**撤销 / 重做**（成熟问题，见第九节必要性）。

## 十、基类完备性测试

### 原则

> 在工作台想给实例设一个属性，却在基类里找不到插槽 —— 那是**基类设计缺陷**，不是需要新架构层的信号。

容器的初始物品和基类的其他设定没有任何区别，同样是引用其他类。找不到槽说明这个基类没有被好好思考过。

### 语料格式

创作者撞到"想设但没槽" → 报一条 → 变成一条失败测试 → 补基类。

```typescript
// 基类设计完备性测试。语料只增不减。
test('容器类能表达「初始装着某物」', () => {
  expectSlot('container.*', 'contents', { accepts: '物品类' });
});
test('网关类能表达「需要某物才能通过」', () => {
  expectSlot('gateway.*', 'requires', { accepts: '物品类' });
});
test('武器类能表达「命中时施加某状态」', () => {
  expectSlot('weapon.*', 'onHit', { accepts: '状态类' });
});
```

**基类层的完备性因此变成可度量的东西**，不靠谁记得。这条语料库是宪法 3.3「遇到未在清单中的新概念」流程的可执行版本。
