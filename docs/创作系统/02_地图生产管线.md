# 地图生产管线规范（V0 新标准版）

> **状态**：已正式确立标准六步工作流
> **最后更新**：2026-09-06
> **归属**：创作系统；局内局外地图本质上都是地图包，编译后的地图原数据属于独立内容类型，经地图包规范装载；玩法文件与地图玩法文件负责与玩法层绑定
> **核心原则**：全屏底图采用人工产出的高质量 SVG；AI 不再介入初稿底图生成，聚焦于素材整体挂载、规则部署与高逻辑玩法绑定

---

## 一、标准六步生产工作流

地图的生产不再是盲目的程序化生成或位图切片修补，而是严格遵循以下六个阶段，实现人类空间意图与 AI 高逻辑生成的精准配合：

```
第一步：规划书起草
  ↓ 明确玩法主题、胜负条件、阵营对抗、经济流转与特殊玩法文件逻辑
第二步：部署玩法层新规则与更新 API 文档
  ↓ (a) 面向非素材拓展玩法层玩法机制
  ↓ (b) 补齐复用逻辑缺口与微量新增机制
  ↓ (c) 维护更新面向 UGC 开发者与 AI 的 API 契约文档
第三步：利用素材管线生成全套 AI、NPC、物品实体素材
  ↓ (a) 挂载整体：不仅是美术贴图，而是包含 Manifest / Profile / 表现层配置的完整实体包
  ↓ (b) 在编辑器、素材库与渲染层中即时可选可用（覆盖 8 大标准类别）
第四步：地图生成（人类主导拓扑编辑）
  ↓ (a) 用户在编辑器中直接导入人工精绘的 SVG 全屏矢量底图
  ↓ (b) 选用新生成的全套素材与旧有素材，完成节点、连线、场景框的拓扑标定
  ↓ (c) 固化底图空间关系与创作者基础设计意图，输出规范 MapData
第五/六步：AI 高逻辑绑定与玩法流程填充
  ↓ (a) AI 按照设计货币系统说明书与玩法设计说明书进行逻辑绑定
  ↓ (b) 自动填充关卡流程、行为触发、事件链条与特殊玩法文件
  ↓ (c) 最终编译校验并输出完整可运行的地图包
```

---

## 二、六个步骤的详细契约与权责

### 第一步：规划书起草
- **输入**：关卡创意、情境设定或任务需求。
- **输出**：完整的玩法规划书（Markdown）。
- **内容要求**：
  1. 关卡核心循环与空间尺度（大/中/小天然场景分布）。
  2. 关卡特有的特殊机制逻辑（例如：氧气泄露、倒计时撤离、警报轮转）。
  3. 阵营与 NPC 行为倾向、关键物品与资源费目分配。

### 第二步：部署玩法层新规则，更新 API 文档
- **目标**：为规划书中的特殊玩法提供底层支撑，保持引擎对新机制的承载力。
- **具体实施**：
  1. **面向非素材的玩法拓展**：新增 Op / Expr / Effect 规则定义，拓展通用玩法层机制。
  2. **微量机制更新**：补齐逻辑复用缺口，确保规则具备无状态、可重入和可验证性。
  3. **更新 API 文档**：将新函数、新操作符与事件签名写入开发者文档，供 UGC 创作者与 AI 阅读。

### 第三步：利用素材管线生成全套素材
- **目标**：为关卡提供完整挂载的实体数据包（美术 + 逻辑）。
- **素材 8 大类别**：
  1. `weapon-melee`（近战武器）
  2. `weapon-ranged`（远程武器）
  3. `weapon-firearm`（枪械武器）
  4. `item-consumable`（消耗品）
  5. `item-tool`（工具）
  6. `item-equipment`（装备）
  7. `device`（装置设施）
  8. `environment`（环境组件）
- **挂载完整性**：
  - 产出不仅是 PNG/SVG 贴图，而是包含 `manifest.json`、`gameplay profile`（数值属性、可用动作、互动消耗）和 `presentation` 挂载配置的完整实体包。
  - 生成后即可在编辑器素材库、背包以及空间表现层中直接检索和选取。

### 第四步：地图生成（用户在编辑器中导入 SVG 并标定拓扑）
- **取消 AI 生成底稿**：整张地图的背景直接使用人工产出的 SVG 矢量底图，确保美学质量与清晰的空间透视。
- **编辑器操作**：
  1. 用户直接拖入 `.svg` 文件作为全屏底图层。
  2. 创作者通过拖拽选用第 3 步生成的实体素材与既有素材。
  3. 标定天然场景节点（`MapNode`）与移动连接（`MapEdge`），划定归一化场景框（`SceneFrame`）。
- **核心宗旨**：由人类创作者在底图上固化空间意图（哪些路能通、哪些门能走、建筑内外层级关系），输出纯净的 `MapData`。

### 第五/六步：AI 高逻辑绑定与玩法流程填充
- **输入**：第四步生成的 `MapData`、设计货币系统说明书、玩法设计说明书。
- **AI 任务**：
  1. **实体放置与状态配置**：将 NPC、宝箱、交互装置合理摆放至场景内的微型场景（泛光圈）。
  2. **高逻辑与玩法文件编写**：编写关卡专属的玩法逻辑（Event Triggers、胜利判定、AI 巡逻路线与对峙规则）。
  3. **地图包概念**：无论局内地图还是局外地图，统一视作独立地图包进行依赖加载与运行时实例化。

## 三、数据契约核心：几何与拓扑的解耦

`MapData` 的核心公式保持不变：

$$\text{MapData} = \text{PrefabDef} + \text{几何}$$

- **拓扑部分**：节点 ID、连接关系、方向性、放置实体、场景嵌套。编译后进入引擎生成 `PrefabDef`。
- **几何部分**：归一化坐标 `at`、楼层 `floor`、贝塞尔曲线 `path`、底图 `backdrop`。编译时全部剥离，仅供编辑器和表现层渲染。
- **SVG 底图优势**：矢量无损缩放，不受特定屏幕分辨率限制，完美对齐 `[0,1]²` 归一化坐标系。
