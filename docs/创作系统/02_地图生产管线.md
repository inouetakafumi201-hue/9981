## 一、定位

地图生产不再包含 Agent、LLM 或仓库脚本生成地图图片、底稿或初始拓扑。全屏地图视觉使用**人工产出的 SVG**；用户把 SVG 导入地图编辑器，再亲自表达拓扑、空间关系和基础设计意图。

`MapData` 仍是地图拓扑的数据契约，但它不再意味着“脚本能生成 JSON，所以地图生产管线已经跑通”。现有 `asset:generate` 样例仅用于开发期契约自测，不是正式地图创作入口，也不替代编辑器。

核心分工：

- 人负责难以由 AI 精确控制的视觉空间关系、拓扑和放置意图。
- V0 Agent 通过平台图像工具生成 AI、NPC、物品实体素材，不生成地图 SVG。
- AI 在空间意图稳定后，根据规划书、设计货币系统说明书、玩法设计说明书与 API 文档完成高逻辑绑定。
- 校验器与编译器负责发布闸门，不负责创作地图。

## 二、现行六步生产链

| 步骤 | 责任与动作 | 阶段产物 | 阶段门 |
|---|---|---|---|
| 1. 规划书 | 起草完整玩法、内容、流程、特殊机制与玩法文件逻辑 | 玩法设计说明书、设计货币约束、内容清单、特殊机制清单 | 玩法目标、复用边界和地图需求无关键歧义 |
| 2. 玩法层规则与 API | 优先扩展非素材玩法；只为复用缺口和必要新机制做微量实现；同步更新面向 UGC 开发者和 AI 的 API 文档 | 新增/复用规则、稳定 API 与示例 | 新机制不能由既有规则组合时才新增；文档与接口同步 |
| 3. V0 原生素材生成 | 依据资产清单，由 Agent 调用 V0 `GenerateImage` 等平台工具批量生成 AI、NPC、物品实体素材；仓库侧登记稳定 ID 与关联 | 待挂载的完整实体/表现资产集合 | 不能只有图片；必须具备实体关联、渲染描述、编辑器目录元数据和稳定引用 |
| 4. 人工地图编辑 | 用户导入人工 SVG，使用新旧素材编辑场景、拓扑、空间关系与初始放置 | SVG + 表达用户基础设计意图的 `MapData` | AI 不生成底稿，不猜测或回写用户确定的空间关系 |
| 5. 素材挂载 | 把素材接入运行与创作界面，验证其可被实际消费 | 可运行、可检索、可选择、可放置的挂载结果 | 表现层能实例化，渲染层能消费，编辑器能检索/选择/放置，缺一不可 |
| 6. AI 高逻辑绑定 | AI 按设计货币系统说明书和玩法设计说明书填充主要内容、流程、节点绑定与玩法文件 | 完整地图包候选 | 玩法文件通过校验；通用机制复用玩法层，地图特有逻辑才留在地图玩法文件 |

步骤 4 与步骤 6 不可倒置。步骤 4 固化用户的空间设计意图；步骤 6 只能在此基础上做内容和逻辑绑定。

## 三、地图包边界

### 3.1 地图包不是 ZIP

局内地图与局外地图本质上都是**目录/清单式地图包**。“包”描述逻辑内容边界和稳定引用关系，不要求物理压缩为 ZIP。传输形式不能反过来定义内容类型。

地图包至少可关联：

- 人工 SVG 全屏地图；
- `MapData` 拓扑、几何和放置声明；
- 新旧素材的稳定引用与挂载清单；
- 与地图节点、边、场景生命周期关联的玩法文件；
- 发布校验与版本元数据。

地图包与普通玩法内容保持独立边界：普通玩法文件可以引用地图包，但不能以自身替换地图原数据或偷偷重写人工空间关系。

### 3.2 局内地图玩法文件

局内地图玩法文件的特殊性来自它与地图表现及场景生命周期的深度连接，而不是“它只能做演出”或“它可以复制实现所有玩法”。它可以：

- 调用既有渲染层组件，例如任务清单、场景提示和过渡组件；
- 绑定场景切换、节点/边触发、局部演出与地图生命周期；
- 承载确实只属于该地图的特殊机制。

复用原则：倒计时、计分、通用任务状态等可跨地图使用的机制，应优先在玩法层实现，再由渲染层和地图玩法文件接线。只有无法合理复用、确属单地图语义的机制，才留在地图玩法文件中。地图玩法文件不得新增表现层实现，只能调用已登记组件。

## 四、人工 SVG 与 `MapData`

SVG 是全屏视觉地图的人工原稿，`MapData` 是拓扑与逻辑空间的权威声明。两者通过归一化坐标关联：

- SVG 负责空间构图和视觉关系；
- `MapData.nodes` / `edges` 负责场景和通行拓扑；
- `MapData.placements` 负责已登记素材的放置；
- 几何字段服务编辑器、表现与运行期寻路数据面；
- `compileMap` 产生引擎可消费的 `PrefabDef` 拓扑面。

地图编辑器必须保留用户导入 SVG 和亲自标注的空间关系。AI 可以建议绑定，但不得重新推导坐标、重绘 SVG，或用生成底稿覆盖人工结果。

## 五、素材挂载验收

图片文件存在不等于素材完成。一个素材只有同时满足以下条件，才算通过步骤 5：

1. **表现层实例化**：可以从稳定实体/定义引用创建可见实例，并进入既有生命周期。
2. **渲染层消费**：渲染描述、资源引用和必要状态可被现有渲染路径读取。
3. **编辑器可选**：进入统一资产索引，可搜索、浏览、选择和放置。
4. **引用完整**：图片、实体定义、渲染描述、目录元数据之间无悬空引用。
5. **不依赖开发目录**：运行时和浏览器不扫描 `run/`，挂载产物使用稳定副本或稳定引用。

步骤 3 只产生“待挂载素材”，步骤 5 才证明它真正可用于地图生产。目前这条从批量清单到 V0 出图、登记、表现层实例化和编辑器可选的闭环**尚未实现完整**。

## 六、数据契约与发布闸门

现有能力继续作为地图包发布闸门：

| 能力 | 作用 | 状态 |
|---|---|---|
| `MapData` | 表达节点、边、放置与几何 | 已实现 |
| `validateMapStructure` | 无 IO 的结构校验；可在编辑器持续调用 | 已实现 |
| `validateMapAgainstClasses` | 校验跨目录类型、尺度和可放置性 | 已实现 |
| `compileMap` | 将拓扑编译为 `PrefabDef` | 已实现 |
| `prefab.spawn` 二次闸门 | 防止绕过友好校验后生成损坏世界 | 已验证 |

诊断必须一次报告全部问题并携带 `message` 与 `correction`。`error` 阻止发布但不阻止保存半成品。

仍有效的关键约束：

- 曲线端点必须吸附节点；
- 场景嵌套尺度必须合法；
- 连接数按场景档位限制；
- `path` / `op` / `call` / `q` / `var` 等 Expr 判别键不得被放置覆写遮蔽；
- 几何不推导行动代价，作者不逐边填写代价。

`npm run asset:generate`、`asset:pipeline`、`asset:view` 仍可验证样例 MapData 的校验、编译、spawn 与可视化，但只属于**开发期契约自测**，不生成正式地图。

## 九、明确废止

- Agent、LLM 或脚本生成地图 SVG、PNG 底稿或初始空间构图。
- AI 地图草图 → 人工局部重绘 → 图片纯化/切片 → 登记的旧入口。
- 把脚本生成样例 `MapData` 当作正式地图生成。
- 把“图片已生成”当作“素材已挂载”。
- 让 AI 改写用户在编辑器中确定的地图空间关系。
- 在单张地图玩法文件里重复实现本应进入玩法层的通用机制。
