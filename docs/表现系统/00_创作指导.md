## 一、画风基调（做任何视觉前先对齐的底色）

> 权威来源：`01_图形化与UI.md` §视觉风格定位 + §五条视觉定律。这里是浓缩成"画什么之前先想一遍"的基调。

### 1. 像素前景 + 全息投影背景

一句话：**前景像素、背景全息光层、叠层分离**。

- **交互组件 / 实体（活的、可点的）**：像素艺术，高饱和，32×32 或 64×64。
- **背景 / 氛围**：全息投影光层——低饱和、半透明、发光、微微泛光/闪烁，由代码层生成（渐变 + 发光 + 透明度函数），不是贴图。
- **两者分层渲染**（前景像素 + 背景全息光层），视觉层次必须清晰、一眼能分开。

> **2026-08-19 升级（D-083）**：背景从「低饱和简笔画贴图」升级为「全息投影光层」（对齐地图编辑器全息游戏风，**不是暗黑科技终端**——暖光浮层 + 克制发光）。「简笔画」为历史基线。创作界面偏暖（琥珀光），对局棋盘保持低饱和略冷暗调。权威见 `01` §视觉风格定位。

为什么这么组合（不可突破的理由）：

1. **梦核一致**——清醒梦里一切都像投影，创作界面与对局棋盘同一种光层语言，不割裂；
2. **数据更轻**——背景光层是代码层、零贴图资产，一张地图 < 1MB 更稳；
3. **对比鲜明**——高饱和像素在低饱和暗光层上一目了然（低心智性）；
4. **工具支持**——游戏内创建工具只画前景像素（像素填充 + 缩放），背景光层由模板生成，不需要画背景；
5. **风格统一**——前景像素网格约束 UGC 内容，背景光层由同一套 token 光层模板生成。

### 2. 颜色是语义，不是装饰（五条视觉定律第一条）

全局颜色语义**不许因切换界面改义**，做任何素材第一件事是"这个对象在视觉上最可能被玩家猜成什么功能"，取那个主色。读法（给设计者）→ 见 `01` §1 全局颜色映射表与 `01` §1 双重分类裁决例。浓缩速记：

- 红=生命减损/致命，蓝=清醒/体力/处决/科技，黄=感官/警戒，橙=AP/消耗/进度，绿=正面/安全/免费，紫=关系约束/远程，珊瑚=近战/格斗，青=社交/UGC/创作，灰=冷却/延迟，灰白=可交互但受制于状态（高光材质，悬停才亮起），纯白/奶白=梦境边界与过载，金/银=品级高光。
- **金银只作高光/描边，不构成评级阶梯、不覆盖主色。**
- 次要语义用局部徽章/边缘/文字承载，**不混成第三种主色**。

### 3. 交互语法统一：边缘发光，不用传统按钮

悬停高亮 + 边缘发光（白光=可通行/黄=警戒/橙=进行中/红=致命/蓝=可处决/紫=网关/珊瑚=近战/绿=安全/青=UGC）。可点击对象必须**高光 + 凸起 + 材质**，不可点击**扁平无高光**。做可交互物就照这套来，别发明新交互形态（见 `01` §视觉定律 2）。

### 4. 姿态物理拓扑

站立/蹲下/倒地（濒死蓝闪可变处决）/睡眠都是**视觉可识别的像素姿态**（高度/占位各有值，见 `01` §4）。新增一种"姿态类"新形态前先查这里，能复用就复用。

### 5. 数值铁律在表现的投影

所有玩家可见数值严格 1–5；表现层只读规则投影，动画/配色不反推、不发明数值（见 `02` §一、`01` §玩家可见数值归属分类）。

## 二、动态图形化的五条原则（新机制/新单位的演出怎么想）

> 权威来源：`01` §前端动态图形化——活体运动与对峙 + §对局动态图形化的标准模型；`03` §成本序修正与全屏认知判据。这里是判断新演出的五把尺子。

### 原则一：动画是"规则结果的视觉重演"，不是规则本身

任何动画都不改变结算、不提交 AP/状态、不泄露隐藏信息。失败/跳过 → 静默跳过、直接显示规则结果，**永不拒绝合法规则对象、永不伪造规则事实**（`02` §一确定性降级，`01` §动画与规则结算的解耦）。

> 抓手：拿一个"机制后果"来，问"它有没有一个 `after:*` 事件可挂？"——有，才是表现该做的；没有，就别在表现层硬造后果。

### 原则二：克制序 = 帧 > 全屏 > 粒子 > 曲线

四类动画按**成本/克制**排的取舍序（`03` §成本序修正，2026-08-14 定案）：

- **帧动画 = 最贵**。它是 UGC 的持续负担（每帧都要维护、创作难度高），**只能维持一个小集**，只留给"确需角色身体/姿态细节"的地方。**无注册帧的地方一律默认曲线兜底**；帧=未来可选增强，不是初始必备。
- **全屏动画 = 次贵**。它是**复杂交互的"逃课"**——某交互逻辑复杂到"画帧没法画、还要跟几何交互、合理实现太可怕"时，一张全屏富视听质感的演出比逐帧省。但全屏有**认知判据**（见原则三），不是随意用。
- **粒子 = 百搭但不过度**。粒子几乎能叠加在任何效果上"加体积感"，但**它自己不会做动作**（粒子不代替攻击/移动/状态），且**不铺满、不承载关键结果**。关键结果必须靠图标/文字/音频（`02` §七.2）。
- **曲线 = 主力、最放开、零素材**。对图标做挤压/旋转/缩放/位移/变色/蒙版，不用任何资源、扩展性最强、让游戏独特而灵动（`03` §曲线配方库）。

### 原则三：全屏动画必须过"认知判据"

人们认知里的全屏动画 = **漫画风的特殊动作/特殊演出**。使用前自问一次：这是不是"正常游戏里会有一格漫画特写的那种对象"？符合认知才上全屏，否则用别的手段。

- 符合（可上）：破窗、破门、翻窗/跳窗、处决/令其长眠、招架触发、出生/入睡、传送。
- 不符合（改用别的手段）：**载具爆炸**（物理常态，用通用爆炸贴帧 + 破坏后帧更省更对味）、普通破坏、换弹（闪烁图标 + 音频）、各类常态反馈。

### 原则四：动画与规则结算、"演出"与"交权"解耦

- **行动结算**（玩法层）不等动画——选项/高亮立刻可用，恢复对峙可能没停完；
- **行动演出**（表现层）可滞后，不阻塞下一步；
- **轮权交接**（交给下一个玩家/NPC）必须等所有动画结束——这是唯一硬同步点；
- **单人模式无此限制**，可直接推进不等动画（`01` §回合制与动态图形化的并发权责）。

> 核心权衡：回合制能接受"戛然而止"，接受不了"我离这么近却打不到"。动画没停但可交互=节奏连贯（接受）；交权必须等=逻辑正确（安全）。

### 原则五：新单位/新机制按"标准模型"套进既有编排

一个机制的演出是「机制后果 → 一段可解耦动画序列」的映射，标准套路（`01` §对局动态图形化的标准模型 + §三动画攻击模型）：

```
机制动作（例如 1 AP 近战攻击同微型场景目标）
  ├─ 朝向对象
  ├─ 跳跃动画移动到面前（幅度比走路大；迟缓/重物各一条跳跃曲线）
  ├─ 身体前倾 → 武器倒下 → 前戳
  ├─ 对方受击（帧）→ 往后退 + 可能撞物理遮挡
  └─ 移动沿途可能把别的活体挤开（ORCA 避让）→ 攻击/受击后恢复对峙归位
```

**关键解耦**：让开和归位是**两个分离机制**——中间人让开是**一次性瞬态**（不需要挤回来），动作完成才执行**恢复对峙**调整队形。新单位接入时照这个模型把"机制后果"拆成可演出的子动作，套进既有舞蹈编排（declarative timeline / 命令式控制 + ORCA + 恢复对峙）。**活体移动/对峙的一切高层表现都只是站位/位移结果的视觉重演，不参与规则（`01` §前端动态图形化）。**

## 二·六、UI 的动态：Image 2 认知循环（子系统一，本轮攻下）

> **权威升级（2026-08-15 项目所有者推进）**：此前"UI=记方案不采购"（见 `asset-pipeline` 记忆）的裁决，在本轮收窄并前移为"**用 Image 2 做 UI 设计时的认知具现、实现仍走代码**"。逐字分工如下。

### 一句话定位

**Image 2 是"认知具现器"，不是"素材工厂"。** 它的价值在于：UI 难在"虚空造物"——设计师和 AI 在动笔前对"对局画面到底会有哪些 UI 要素、长什么样"没有共同画面。把全部图形化设计汇成一份提示词扔给 Image 2（它的 UI 审美较好），多迭代几版供人挑选，让 **AI 与开发者双方都对同一张参考图建立明确认知**，不再是凭空想象。**但它的游戏内容（角色、场景、战斗画面）不能看，只看 UI。**

### 为什么还是代码，Image 2 只做认知

1. **动态做不好靠素材**：UI 的动态（画一次动效、悬停、展开、冷却填充、轮次流转）是**关系与时间**，静态贴图表达不了；Image 2 出的是静态画面，只能给出"布局/层次/氛围"的定妆照，动效仍要代码（曲线/状态机/声明式组件树）实现。
2. **素材只是提上限**：极少数**零渲染继承不到**的静态精密细节——即代码（几何/着色器）够不着的精细纹理、材质——才考虑用素材补位；这正好接回 `§二` 克制序与 `01` 视觉定律（颜色/发光/凸起都由代码语义驱动，不靠素材）。
3. **一致性靠 token，不靠素材**：实现仍用声明式组件树 + token 注册表（颜色/圆角/阴影/字体**严格映射语义色与视觉定律**，禁自由样式），保证全 UI 风格统一且随语义色冻结一起收敛。

### 五步循环（迭代者可套）

1. **汇要素清单**：读完 `01_图形化与UI` 全部对局 UI 要素——轮次栏（核心组件）、两套动作菜单（付费/附赠）、状态图标栏、物品栏与负重、头顶弱点、距离 DC、门户、UGC/高级角标、圆圈导航——列成"对局画面有哪些 UI"。
2. **编参考提示词**：把清单 + 画风基调（§一：像素前景/素描背景、色语义映射、边缘发光语法）+ `01` 各 UI 组件职责，编成一张"对局 UI 定妆照"的 prompt。
3. **多迭代出几版**：扔给 Image 2，出 3–5 版供项目所有者挑选。
4. **只取认知、不取资源**：选中版作为设计师/AI 的共同参考蓝图，落到代码（声明式组件树 + token），素材不进入产品。
5. **真必要才补位**：只有代码够不着的静态精密细节才考虑局部素材，且走 `§四` 自主创作纪律。

> **边界（对 Image 2 产物的态度）**：产物是**参考，不是权威**。布局/层级/色彩氛围可以被采纳，但最终以 `01` 视觉定律与本文 `§一` 基调为裁定依据；Image 2 的任何"新增主色 / 发明交互形态 / 数值"一律不采纳（接 `§四` 硬边界）。

3. **从已知配方到新配方**：`03` §Ⅳ曲线配方库把意图穷举成零件（P/S/R/C/M 组），任何新机制对得上某个物理/情绪意图就能立刻套用；配方可参数化复用（换 duration/弧度表达不同强度）、可叠加（粒子盖在曲线上）。
4. **减法（读表做取舍）**：`03` §Ⅺ交叉编目表把常见动作一次过，"需帧/值得全屏"列告诉你要不要上高成本手段——**默认一律曲线 + 粒子；做到"让玩家一眼看懂机制后果"就停。** 帧一律曲线兜底，全屏严格过认知判据。

> 省力杠杆（先用，再谈高成本）：一个动作能否用一个**闪烁图标 / 抖动曲线 + 一点音频**就表达清楚？能 → 不做帧、不做全屏（`03` §成本序的两个省力杠杆）。抽象化 + 音频 = 换弹的答案。

## 四、迭代自主创作规范（保证开发连贯的关键规则）

> 本条是本文件**真正新增的制度**，满足"开发连贯 + 覆盖无法穷举的新东西"（2026-08-14 项目所有者指示）。其余各节是从既有表现文件提炼，本节给迭代者明确的自主空间与边界。

### 4.1 自主创作设计是**允许且被鼓励**的

本作迭代中必然会出现设计文档与灵感索**没穷举到**的新东西——新的载具、新的僵尸/NPC 种类、新的物品种类、新的机制演出。只要满足下列纪律，迭代者**可以自主进行创作设计**，不必每做一样都停下等裁决：

1. **可以自己创作素材**，或用素材管线（`asset-pipeline` / `sprite-forge` skill、Nano Banana、本地后处理）产出素材；
2. **可以仿照既有实现**——照 `01/02/03` 已经定案的做法来，不另起炉灶发明一套新风格；
3. **成品质量对对齐既有画风**——指"达成高质感"：既符合 §一画风基调，又遵循 §二五条原则，且落在查表路径（§三）里。

### 4.2 自主创作的五条硬边界（不可越线）

自主是**在既定基调内自由**，不是无限自由。以下越线动作必须先提请项目所有者裁决：

| 边界 | 判定 | 处置 |
|---|---|---|
| **碰权威规则/数值** | 是否改变规则结算、伤害/AP/清醒/距离等 1–5 数值、隐藏信息 | 不可。表现层只读投影，不反推机制（`02` §一） |
| **新增主色/改颜色语义** | 是否发明全局主色，或让某色换域换义 | 不可。颜色语义是宪法级冻结（`01` §五条视觉定律 1）；新增/该义须裁决 |
| **新增高成本动画类型** | 是否新增"帧/全屏/粒子"某类的注册范围、突破克制序 | 不可。成本序是定案（`03` §成本序修正）；要上高成本手段须裁决 |
| **改变既有交付物** | 是否跨 Spec/跨文档改别人已定案的实现或文字 | 不可。遵守"不跨 Spec 改交付物"（AGENTS.md 专项纪律）；需要对方改是写交接项 |
| **打破解耦契约** | 是否让表现层写规则状态、依赖内部形状、绕过唯一写入通道 | 不可。三命令门禁 + 单调重定义唯一写入通道 + 原子验证是铁律 |

### 4.3 自主创作必须回写文档（连贯的本体）

自主做的新东西**不能只停在代码/临时会话里**。落地后要回写到表现文档，让后续迭代者能看到、能接着做，这才是"保证开发连贯"：

- **新单位/新机制的演出** → 回补 `03` 灵感索对应小节（尤其 Ⅳ 曲线配方库、Ⅴ~Ⅹ 逐机制清单、Ⅺ 交叉编目表）——这是灵感索"越攒越厚、前端用时挑"的用法。
- **新的单元色/素材** → 记到 `01`（若真的开辟了新素材语义）或创作系统对应文档，且过门禁术语/废用词。
- **新做法若与已定案冲突** → 不静默覆盖，按并行纪律登记 + 提请裁决（D-060）。

### 4.4 完成一件自主创作的检查清单

落地一件新表现时，对着打勾：

- [ ] 符合 §一画风基调（像素前景/素描背景、颜色语义、边缘发光、姿态拓扑、数值 1–5）；
- [ ] 符合 §二五条原则（重演不越权、克制序、全屏过认知判据、演出/交权解耦、套标准模型）；
- [ ] 走通了 §三查表路径（从既有配方/编目里取，而不是凭空发明）；
- [ ] 未越 §4.2 硬边界；
- [ ] 已回写 `03` 灵感索 / 相关文档（§4.3）；
- [ ] 三命令门禁 + `verify:docs` 通过。

## 五、常见"新东西"参考走一遍（示例）

以项目所有者点名的两个必然出现、必然无法穷举的新东西为例，示范 §二~§四怎么落到判断：

**新载具（例如叉车、摩托车）**：先判它是不是"载器"（引擎基元，内部承载活体且无微型场景，见引擎层立项 L-01/L-02）。是 → 表现上套 §九载具专项：驾驶=可动实体（参与 ORCA）、无人=不可动实体（行动轮结束静默归位）；损毁走"通用爆炸贴帧 + 破坏后残骸帧"，**不上全屏**（载荷爆炸不符合全屏认知判据）；移动=重装跳跃曲线 + 轮下尘；上车/下车=淡入淡出到车内。全部能在 `03` §九 + 交叉编目找到现成做法，只换参数。

**新僵尸/NPC 种类**：先判它的 AI 状态机（`03` §八警戒动画：睡眠→巡逻→寻声→追逐→攻击）能不能复用。能 → 头顶状态气泡 + 路径 + 追逐射击 + 朝最近玩家移动 + 死亡淡出。追逐=追踪速度明显快于巡逻（节奏差异用曲线参数表达，不新画帧）。若新种类带全新行为（例如会钻管子的怪），先查 `03` 配方库有无对应曲线（`P2 拖拽位移`/`R4 滚动旋转`/`S3 阶梯缩放` 这类零件）拼得出来；拼出来了就自主做并回写 `03`；拼不出/要上帧或全屏 → 按 §4.2 提请裁决。
