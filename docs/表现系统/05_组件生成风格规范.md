# 组件生成风格规范（sprite-forge 组件管线）

> **归属**：表现系统（正交域）。**性质**：组件生成管线的**风格权威**——`sprite-component.py`
> 的提示词组装逻辑直接引用本规范，任何组件生成都输出同一种美学。它不新增视觉定律，
> 只把 `01_图形化与UI.md`（视觉定律/语义色）与 `00_创作指导.md`（画风基调）蒸馏成
> 「生成组件时该长什么样」的固定参数表。
> **状态**：已定案（2026-08-16）。**最后更新**：2026-08-16
> **依赖 / 引用**：`docs/表现系统/01_图形化与UI.md`（权威：视觉定律/语义色）、`00_创作指导.md`（权威：画风基调）、
> `.agents/skills/sprite-forge/tools/sprite-component.py`（脚本实现）、`PLT-01`（角色画风，同源不同域）

---

## 〇、定位：组件管线 vs 角色管线

| | 角色管线（PLT-01 / master） | **组件管线（本规范）** |
|---|---|---|
| 对象 | 会动的形态（角色/NPC） | **静态件**（武器/物品/设备/环境交互件） |
| 帧 | 固定 16 姿态 | **由调用方决定**：1 帧（钥匙）或多帧（箱子三态） |
| 风格 | 角色专属（紫衣侦探母版） | **全局统一**（语义色 + 固定光影 + 固定视角） |
| 心智负担 | 迭代者要盯细节 | **外包**：AI 只传参数，直接拿成品 |
| 权威 | PLT-01 + master sheet | **本规范** + sprite-component.py |

**核心原则**：
1. **极其稳定**：提示词高度结构化、风格参数硬编码、后处理固定，不做随机发挥。
2. **外包化**：不消耗 AI 心智。调用方只提供 类型 + 描述 + 状态；其余全由脚本决定。
3. **风格锁定靠提示词**：语义色表 + 本规范写死在脚本里，任何组件生成都输出同一种美学。
4. **帧数由 AI 决定**：AI 觉得有必要多状态（箱子要 closed/open/broken）就传 `--states`，
   脚本自动排网格并切格。

> **真实流程（2026-08-16 起）**：调用后**不是「直接拿成品」**。脚本按**实际检测到的品红
> 分隔带**切格（推理真实行列，不受提示词期望约束），并经**成品质量闸门**校验——任一帧
> 过小或非品红内容占比过低（疑似纯色块）就整体失败，在输出目录保留 `raw.png`/`sheet.png`
> 供重跑或人工排查，绝不把损坏切格写进 `manifest.json`。切图布局由检测结果确认，模型未遵守
> 提示词布局时按检测到的分隔带切，而不是静默产出 1×1 单色块。

## 一、固定风格参数（全局统一，任何组件不许突破）

### 1. 视角 = 正面俯视视图

与角色/地图同一法则（`01` §正面俯视视图）。

从物体正前方的上方观看组件，采用固定的正面高位等轴镜头：**顶部平面与前立面同时可见**，并用平面形状、可读剪影、地面阴影表达识别；**不允许侧面、后部、纯平面俯视或纯正面**。地图实体与背包/UI 图标**统一同一视图**，只在构图留白与识别优先级上区分（地图件要有可辨识的落地轮廓和前部体积，UI 件可以更强调剪影对比）。

- **固定英文口令**：`front-top axonometric view`（同义 `front-top orthographic view`）
- **必须是**：`front-top axonometric view, elevated camera directly in front, top face and front face visible, side and rear faces hidden, fixed conventional elevated angle, orthographic projection.`
- **禁止**：`pure top-down plan view`、`bird's-eye view`、`flat overhead icon`、`side profile`、`rear view`、`three-quarter side`、`visible side face`、`all three faces`、`perspective rotation`，以及以第三方游戏名作为视角名称或提示词类比（D-025）。
- **不是** 纯俯视、**不是** 纯侧影、**不是** 立体积木三面拼。

### 2. 像素规格

- **原生** 64×64 像素网格美学（生成时 1024×1024，后处理重建到 64×64）
- **硬边色块**：每个表面 2-3 阶明暗（亮/中/暗为独立纯色区域，边界干净）
- **禁止**：抗锯齿、渐变、抖动、模糊、柔边
- **轮廓**：干净硬边，64×64 下可读

### 2.5 视角规则（语境决定，统一正面俯视，铁律）

组件分两种语境，**都在正面俯视视图内，只是识别侧重不同；视角口令统一注入提示词**：

| 语境 | 用途 | 视角要求 |
|---|---|---|
| `--context map`（**默认**） | **地图上的实体** | **正面俯视视图**——唯一允许的视角 |
| `--context ui` | 背包/界面图标 | **同样正面俯视视图**（强调剪影对比与人眼可读，仍是正面俯视，无立面、无倾斜纵深） |

**正面俯视视图表述（已锁定进脚本，任何组件生成都带这段）**：

> TOP-DOWN PLAN VIEW (STRICT, THE ONLY ALLOWED VIEW): overhead plan-view sprite. The object reads as a flat top-down outline and readable silhouette, with a ground shadow to show where it sits on the map. NO front face, NO side face, NO top face, NO oblique depth, no three-quarter depth, not isometric, not a side profile. Every generated object MUST use this exact flat top-down plan view - never any other angle.

**关键设计**：旧"正面斜投影/Cabinet/Cavalier"要求"正面朝镜头 + 右侧面 + 顶面三面可见"，这是**一个误解**——本项目是正面俯视打法，地图与实体没有立面可画；那个规则只会诱导模型画出立体积木。因此统一改为正面俯视视图（见上文 `01` §正面俯视视图 的"为什么"）：

旧的方体物件靠"三面可见"才能稳定——那是斜投影的错误前提。正面俯视下，方体/箱体改为**平面轮廓 + 顶面结构线/材质划分 + 方向偏移的落地阴影（ground shadow）**表达"这是个结实的箱子"，不画任何侧立面。角色（`PLT-01`）与物件（本规范）同一正面俯视法则。

**何时必须 `map`（默认，不用改）**：箱子、门、锁、武器实体、设备、环境交互件等一切**会显示在地图上**的东西。

**何时用 `ui`**：背包图标、物品栏缩略图、UI 上的展示图标——不在世界里出现的；仍是正面俯视，只更强调识别。

> 地图实体必须以正面俯视视图生成。这是宪法级视觉规则（`01` §视觉风格定位·正面俯视视图），组件管线用 `--context` 把这条规则显式传给 AI。

### 3. 光影（统一方向，不许随意发挥）

- 光源 = **左上**（恒定）
- **正面俯视下的光影** = 平面明暗分区 + 统一方向落影：亮度按**材质/层次**分层（亮/中/暗为独立纯色区域），落影按光源方向成一侧偏移，帮助"贴地"与形体辨识；不再逐"面"各画一套明暗（因为没有立面）。
- 小件可 2 阶；高光（金银）只作**边缘 / 局部材质**，不覆盖主语义色、不构成评级阶梯

### 4. 背景 = 品红底

- 生成时 `100% solid flat magenta (#FF00FF)`，无渐变无阴影无文字
- 后处理把近品红像素归一到纯品红（消除抗锯齿残边）
- 输出即可色键抠图（品红 → 透明）

### 5. 材质基调

- **现代都市低饱和写实**：接地气的日常物件，muted palette
- **禁止**：奇幻铠甲、血腥、赛博发光、科幻质感

## 二、语义色表（组件类型 → 主色/次色/高光）

> 权威：`01` §五条视觉定律 1。主色不许因界面切换改义；金银只作高光。

| 组件类型 | 主语义色 | 次色/材质 | 高光 |
|---|---|---|---|
| `weapon-melee`（近战武器） | **珊瑚**（近战/格斗身份） | 深钢灰、磨旧皮革握把 | 银边 |
| `weapon-ranged`（非枪远程） | **紫**（远程/关系约束） | 哑光深灰复合材料、棕带 | 银 |
| `weapon-firearm`（枪） | **枪灰蓝** + **橙**（AP/弹药消耗） | 深聚合物、黄铜细节 | 银滑套 |
| `item-consumable`（消耗品） | **绿**（正面/安全）或 **橙**（消耗）按主功能 | 白绷带/琥珀液体/纸包 | 亮绿点缀 |
| `item-tool`（工具） | **橙**（进行中）或 **黄**（感官/注意）按主功能 | 黑橡胶握把、钢 | 银 |
| `item-equipment`（装备） | **蓝**（科技/清醒域） | 灰织物、深带 | 青蓝边缘 |
| `device`（设备） | **灰白**（可交互受制状态）+ **蓝** 科技点缀 | 暗屏、金属壳 | 白边亮起（激活时） |
| `environment`（环境件） | **低饱和灰/棕**（匹配低饱和全息光层背景，D-083） | 木/混凝土/金属 | 克制、几乎无 |

## 三、状态网格（帧数由 AI 决定）

- **单帧**：不传 `--states` → `single.png`
- **多帧**：`--states closed,open,broken` → 每个状态一帧，自动排网格并切格
- 网格排法（竖排优先，规避上游明令禁止的 1×N 水平漂移）：
  - 1 → 1×1；2 → 2×1；3 → 3×1；4 → 2×2；5-6 → 3×2；7-9 → 3×3；10-16 → 4×4
- 帧与帧之间：同一对象、同一比例、同一像素尺度、居中、不越格、仅品红连接

## 四、产物契约（调用方拿到的形状）

```
<out>/
  raw.png         后端原始网格 sheet
  raw.json        提示词留档（含状态表）
  sheet.png       背景纯化后的整 sheet（品红底）
  frames/         N 个 64×64 成品帧（single.png / closed.png ...）
  contact.png     各帧拼版总览
  manifest.json   组件登记（kind/type/states/frames/contact）
```

- 所有帧 = 64×64 RGBA，品红底，可直接色键抠图挂载
- `manifest.json` 是挂载时读的登记（文件名/状态/路径）
- **质量闸门**：任一帧尺寸过小或非品红内容占比过低即整体失败，保留 `raw.png`/`sheet.png`，
  不产出 manifest——损坏资产不会进登记，需重跑或人工排查

---

## 四·5、成品质量闸门（防御层）

脚本对每个切出的源帧做两重校验，一律失败即拒绝产出并保留原始素材：

1. **尺寸**：切帧宽度/高度 < 8px 视为退化（防反向/零宽裁剪框产出 1×1 单色块）。
2. **内容**：非品红内容占比 < 2% 视为纯色块（防模型没画该状态、只剩品红底）。

切格布局以**检测结果**为准：检测到的真实状态格数与调用状态数一致时，直接按真实行列切格；
只有格数不一致时才退回安全的等分策略。切出的帧用**原生分辨率**喂 proper-pixel-art（`-s 1` 不放大），不做
1024 预放大以免放大掩盖问题。

## 五、调用方式（AI / 迭代者直接抄）

```bash
# 单帧（地图实体，默认 map 语境 = 正面俯视视图）
python .agents/skills/sprite-forge/tools/sprite-component.py \
  --type item-tool --desc "old brass door key" --out run/assets/key

# 多帧（箱子三态，地图实体 = 正面俯视视图）
python .agents/skills/sprite-forge/tools/sprite-component.py \
  --type environment --desc "wooden supply crate" \
  --states closed,open,broken --out run/assets/crate

# 背包/UI 图标（ui 语境 = 同样正面俯视视图，强调剪影识别）
python .agents/skills/sprite-forge/tools/sprite-component.py \
  --type item-consumable --desc "bandage" --context ui --out run/assets/bandage-icon

# 指定后端
python .agents/skills/sprite-forge/tools/sprite-component.py \
  --type weapon-firearm --desc "revolver" --provider gemini --out run/assets/revolver

# 只打印提示词（校对）
PRINT_PROMPT_ONLY=1 python .agents/skills/sprite-forge/tools/sprite-component.py \
  --type item-consumable --desc "bandage" --out /tmp/x
```

**AI 用它的规则**：
- 需要组件时**先查** `run/assets/` 有没有现成的（复用优先）
- 没有 → 用上面的命令生成，**拿到 manifest.json 直接挂载**，不用盯贴图
- 若脚本报质量闸门失败：保留的 `raw.png`/`sheet.png` 需**重生成或人工处理**，且此时没有
  manifest——不要手动补写 manifest 挂载未切好的帧
- **默认就是 `map` 语境**（地图实体 = 正面俯视视图），只有明确是背包/UI 图标才传 `--context ui`（仍是正面俯视，只强调剪影识别）
- 只有"生成效果不符合预期"时才需要人工裁决/重生成

## 六、边界（不自越）

- **不碰权威**：本规范不改视觉定律/颜色语义/数值；只做"组件该长什么样"的固定参数化。
- **不碰实现**：不进 `src/`，产物落在 `run/assets/`。
- **不背美术选型**：组件生成是外包工具，最终挂载哪些组件、用不用，由玩法/场景迭代者决定。
- **风格锁定靠提示词**：不在脚本里硬编码图片、不训练模型；统一性靠本规范 + 提示词模板保证。
