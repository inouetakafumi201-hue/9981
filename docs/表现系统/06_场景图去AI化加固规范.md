# 06 · 场景图去 AI 化加固规范

## 问题定义

AI 生成的场景图 / 背景图存在大量抗锯齿杂色（万级色彩数），混入 ship 包无法举证「像素艺术」特征。64×64 角色组件不在此列（已通过 proper-pixel-art 管线处理）。

## 资产核验结果

| 资产 | 尺寸 | 输入色数 | 量化后色数 | 状态 |
|------|------|----------|------------|------|
| `residence-room.png` | 1024×1024 | 76,959 | 10 | **已纯化** |
| `bench/backdrop.png` | 1024×1024 | 69,888 | 6 | **已纯化** |
| `library/backdrop.png` | 1024×1024 | 62,380 | 8 | **已纯化** |
| `painter/backdrop.png` | 1024×1024 | 79,860 | 11 | **已纯化** |

量化后色数远低于 32 目标调色板，说明这些图的实际主色调本就很少（6-11 色），
纯化后色数与量化后一致，说明边清 / 投票 pass 没有进一步抹平细节（原始图本身接近硬边）。

## 工具：Hashi-Dither Purifier

位置：`.agents/skills/sprite-forge/tools/hashi-dither-purifier.py`

### 算法原理

三段式：

1. **降色**：PIL `quantize(colors=32)` 将万色 → 目标调色板
2. **边清**：逐像素分析——同色邻居 ≤2 方向且被 ≥2 种异色包围 → 替换为相邻主色
3. **硬边投票**：3×3 窗口投票，若某色得票 ≥4 且中心不是该色 → 吞并中心

### 用法

```bash
# 单文件
python hashi-dither-purifier.py single input.png --output output.png --colors 32

# 批处理（加 -purified 后缀）
python hashi-dither-purifier.py batch input1.png input2.png --colors 32

# 覆盖原文件
python hashi-dither-purifier.py batch input1.png input2.png --colors 32 --inplace

# 验证（只打印统计）
python hashi-dither-purifier.py inspect input.png
```

### 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--colors` | 32 | 目标调色板色数（建议 16/32/48） |
| `--passes` | 3 | 边清+投票混合通过数 |

### 调色板

内置 WakeUp 场景专用 48 色调色板（墨 / 深蓝黑 / 冷灰蓝 / 暖棕 / 冷绿 / 暗紫 / 暗橙 / 冷青），覆盖所有场景图主色调。16/32/48 三档可选。

## 决策规则

| 场景 | 是否需要纯化 | 原因 |
|------|-------------|------|
| 角色精灵（64×64 / 32 色） | 否 | 已有 proper-pixel-art 管线 |
| 组件（64×64 / 32 色） | 否 | sprite-component.py 已处理 |
| 场景图（≥512px / 万色） | **是** | 必须纯化才能举证像素艺术特征 |
| 地图背景图 | **是** | 必须纯化且要从零建立新管线 |
| UI 界面图 | **是** | ≥512px / 万色需要纯化 |

## 与现有管线的关系

- **sprite-pixelate.py**：角色 / 组件（64×64 网格）
- **sprite-component.py**：组件生成（含 proper-pixel-art 后处理）
- **hashi-dither-purifier.py**：场景图 / 背景图（尺寸灵活 512~2048）

三者互不重叠，各管各的资产类型。
