# 表现层生命周期与交互桥设计

> **状态**：设计定案（2026-08-26）
> **定位**：本文补全表现层与规则/运行期/渲染交互层之间的生命周期、交互目标、事件顺序和安全边界。本文不实现 ORCA、A* 或具体渲染组件。
> **依赖**：`表现系统/01_图形化与UI.md`、`表现系统/11_ORCA寻路与移动系统设计补全.md`、`表现系统/14_表现层架构设计.md`、`L2_基类层/03_空间系统.md`、`工程治理/11_游戏整体交互流程设计.md`。

## 一、核心裁决

### 1. 场景框与地面承载椭圆是两条交互轨道

- **跨天然场景**：玩家点击当前可达的高亮场景框，提交跨场景移动意图。
- **同一天然场景内移动**：玩家点击目标实体脚底的椭圆地面承载面，提交移动到该微型场景的意图。
- 移动选择态同时高亮当前天然场景内全部可进入的地面承载椭圆；悬停或聚焦只增强当前目标。
- 场景框和地面承载椭圆都是投影出的交互目标，不是普通网页按钮。
- 目标点击先经过合法动作投影和权威动作通道；表现层不得点击即移动。

### 2. 空旷地不是交互目标

个人空旷地不是动作、按钮、场景框、泛光圈或玩家可主动选择的目标。运行期在实体从其他场景进入大/中天然场景时，根据容纳和微型场景规则自动创建或复用个人微型场景。实体离开后，UI 不提供主动返回个人空旷地的入口。

### 3. 泛光圈是脚底地面承载面

泛光圈同时表达当前微型场景和可点击落脚目标，但它不是悬浮特效，不是正圆，不位于实体头顶。它是固定正面俯视镜头下的椭圆地面承载面，中心落在实体脚底或微型场景地面锚点。

```ts
interface GroundGlowFootprint {
  readonly footprintId: string;
  readonly microSceneId: string;
  readonly center: Vec2;
  readonly radiusX: number;
  readonly radiusY: number;
  readonly rotation: 0;
  readonly occupantIds: readonly string[];
  readonly visibility: 'weak' | 'highlighted' | 'selected' | 'fading';
  readonly interactive: boolean;
  readonly revision: number;
}
```

- `radiusX > radiusY`，长短轴体现地面接触面。
- 默认始终弱可见，不在移动模式外消失。
- 移动选择态高亮全部可进入目标。
- 悬停、键盘聚焦和手柄聚焦必须有非颜色反馈。
- 点击命中使用椭圆区域。
- ORCA 使用等效圆半径；表现椭圆只负责视觉和交互命中，不成为规则或 ORCA 的椭圆碰撞体。

## 二、跨层对象和生命周期

### 1. 规则/运行期对象

玩法层和运行期维护：

```text
天然场景节点
微型场景节点
实体归属
occupants
容量
进入/离开
最后实体离开后的拓扑销毁
```

表现层不得读取内核私有微型场景结构，也不得自行改变实体归属。

### 2. 表现投影对象

整合层向表现层提供已收窄的投影事件：

```ts
interface MicroScenePresentationProjection {
  readonly microSceneId: string;
  readonly hostNodeId: string;
  readonly creatorEntityId?: string;
  readonly occupantIds: readonly string[];
  readonly lifecycle: 'created' | 'updated' | 'destroyed';
  readonly revision: number;
}
```

事件类型：

```text
presentation:micro-scene-created
presentation:micro-scene-occupants-changed
presentation:micro-scene-destroyed
```

表现层只消费事件和投影，不从事件推断未声明的规则字段。

### 3. Cluster / GroundGlow 生命周期

```text
micro-scene-created + 至少一个 occupant
→ Cluster created
→ GroundGlowFootprint created

occupants-changed + occupantIds 非空
→ Cluster 更新
→ GroundGlowFootprint 更新
→ 等效圆 ORCA 输入更新

occupantIds 变为空
→ 逻辑 Cluster/Footprint/Glow 立即从活动投影注销
→ 可选视觉淡出 200–300ms
→ 淡出期间不可点击、不参与 ORCA、不参与重叠检测
→ 淡出完成后释放视觉实例

micro-scene-destroyed
→ 幂等注销 Cluster/Footprint/Glow
```

活动状态不允许空 Cluster。重复 destroy、对象已经不存在或过期 destroy 必须幂等处理并记录必要诊断，不得恢复已注销对象。

### 4. 最后实体离开

最后一个注册实体离开时，必须同时完成两条注销：

```text
运行期/玩法层：微型场景拓扑注销
表现层：Cluster + GroundGlowFootprint + Glow 投影注销
```

表现淡出不是逻辑驻留。淡出对象不能被交互、ORCA、空间目标查询或新事件继续引用。

## 三、移动交互生命周期

### 1. 跨天然场景

```text
读取可见天然场景和合法动作投影
→ 高亮可达场景框
→ 玩家点击场景框
→ 生成移动 intent
→ 权威动作确认
→ 新空间 projection committed
→ 旧 Cluster 移除实体并按归零规则注销
→ 新天然场景/微型场景投影更新
→ CollisionRegistry 更新
→ ORCA 注册当前实体
→ MoveChoreographer 播放移动演出
→ 到达静态终态
```

### 2. 同场景微型场景

```text
读取当前天然场景内可进入微型场景投影
→ 所有可进入 GroundGlowFootprint 高亮
→ 玩家点击目标椭圆
→ 生成移动 intent
→ 权威动作确认
→ 新微型场景投影 committed
→ 更新旧/新 Cluster 和地面承载椭圆
→ CollisionRegistry 更新
→ ORCA 使用等效圆半径计算站位
→ MoveChoreographer 播放场内移动演出
→ 到达静态终态
```

玩家看不到“进入空旷地”动作；运行期如需创建个人微型场景，该创建是 `entity.place` 容纳过程的副作用。

### 3. 等待不由渲染层表达

渲染层不显示“等待表现层确认”的内部中间态。渲染层只接收：

```text
projection committed 后的表现事件
```

并开始演出。Intent pending、projection pending、route pending 属于整合层/UI 状态，不由渲染组件猜测或提前移动实体。

## 四、ORCA 与空间责任

### 1. ORCA 输入

ORCA 只消费已确定的：

```text
实体位置
CollisionBox
可动性
目标速度
可通行域
Cluster/Footprint 的等效圆约束
```

ORCA 不决定：

```text
天然场景归属
微型场景创建/销毁
容量是否合法
玩家是否可以选择目标
AP 成本
规则结果
```

### 2. 不可动实体

不可动实体不移动，但仍作为 ORCA 静态障碍参与空间计算。车辆有人驾驶/无人驾驶的可动性变化通过投影事件更新 CollisionRegistry，不由渲染层自行判定。

### 3. Cluster 不自行创建

表现层不得因为两个实体距离接近就创建具有玩法意义的 Cluster。Cluster 只能由微型场景表现投影和实体空间投影派生；表现层可以维护内部缓存，但缓存不构成规则事实。

## 五、动画、命令和回合交权

### 1. RenderCommand 生命周期

```ts
interface RenderCommandRequest {
  readonly commandId: string;
  readonly semanticId: string;
  readonly sourceRevision: number;
  readonly targetPageId?: string;
  readonly trigger: 'after-event' | 'projection' | 'local-input';
  readonly advancesJourney: false;
  readonly payload: Readonly<Record<string, unknown>>;
}

type RenderCommandOutcome =
  | 'accepted' | 'completed' | 'skipped' | 'degraded'
  | 'failed' | 'timeout' | 'cancelled' | 'stale';
```

命令执行器必须支持 requestId/commandId、revision、取消、超时、跳过、降级、资源失败和 dispose。命令完成不等于规则完成。

### 2. 单人模式

单人模式下任何表现动画不阻塞玩家输入：

```text
规则结算完成
→ 动作卡片可按规则投影发放/高亮
→ 玩家可继续输入
→ ORCA 恢复对峙和视觉演出并行
```

表现层不得为了等待动画阻止下一次输入。

### 3. 多人模式

多人模式下，轮次结束必须等待本轮所有必要演出完成后才允许：

```text
发放下一轮动作��
高亮下一轮可用动作
自动滑动镜头
结束当前轮次并交权
```

等待是表现层编排器/整合层的安全门，不是渲染组件自行阻塞。为防止死循环，交权等待设置硬上限：

```text
3000ms
```

超过上限后：

```text
记录演出超时诊断
取消或降级未完成命令
落入最终静态状态
释放表现锁
继续发放/高亮/镜头交权
```

规则事实不回滚，玩家输入不重复提交。

## 六、视觉状态降级

### reduced-motion

- 保留场景框、椭圆承载面、标题、焦点、状态和最终位置。
- 禁用复杂移动、旋转、连续脉冲和 comic beat，或替换为静态姿态。
- 不把承载面从页面中删除。

### low-performance

- 减少粒子和装饰数量。
- 保留所有可交互场景框和地面承载椭圆。
- 保留实体位置、Cluster 关系、焦点和错误状态。
- 低性能不是空白 fallback。

### 资源失败

```text
资源失败
→ 记录资源诊断
→ 使用语义贴图/静态承载面/文字 fallback
→ 保留交互和最终状态
```

### 4. MapPlay 语义时间线

`MapPlay 2.0` 只声明 `presentationRef`、cue 偏序、延时、blocking、跳过、取消事件、fallback 与 `staticFinalState`。表现层负责把这些语义解析为真实命令，并保证：跳过/取消/超时统一收敛到静态终态；关键 cue 必须有 fallback；规则先结算、表现后重演；卸载后不残留动画、音频或锁。时间线不能成为计时器 tick 或规则状态的事实源。

## 七、验收不变量

1. 玩家可通过点击高亮场景框完成跨天然场景移动。
2. 玩家可通过点击实体脚底椭圆完成微型场景移动。
3. 玩家可见动作列表不包含“进入空旷地”。
4. 空旷地只能由运行期自动创建或复用。
5. 泛光圈始终是脚底椭圆，不是正圆或浮空特效。
6. ORCA 使用泛光圈等效圆半径，不把视觉椭圆直接当碰撞体。
7. 活动 Cluster 不存在空 occupant 状态。
8. 最后一个实体离开时，逻辑投影立即注销，视觉最多短暂不可交互淡出。
9. 表现层不得自行创建玩法 Cluster 或改变实体归属。
10. 单人模式的演出不阻塞输入。
11. 多人模式的轮权交接等待演出，最长 3000ms。
12. 超时后表现进入静态终态并释放交权锁。
13. 动画、粒子、音频和命令在卸载后不残留。
14. 规则结算、动作卡片和表现演出互不伪造对方完成状态。

## 八、实现前置交接

表现层实现开始前必须从整合层获得：

```text
Canonical MapData v2 空间投影
合法移动动作投影
MicroScenePresentationProjection
实体位置/可动性投影
after:* 收窄事件及 revision
资源 AssetAdapter
RenderCommandApi 宿主注入点
```

如果任一输入缺失，表现层返回 Pending Convergence 或静态安全状态，不创建第二套规则推断。
