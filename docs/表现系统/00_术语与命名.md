# 表现系统术语与命名规范

> **性质**：表现系统正交域的术语权威登记处。
> **用途**：消除"表现层"一词在项目中的歧义，统一所有层级的命名使用。
> **状态**：定案（2026-08-26）
> **维护规则**：任何人在项目中引入"表现"相关术语，必须先查本表；本表是 `verify:docs` 术语一致性校验的权威基准。

---

## 一、"表现层"5 义对照表

> 项目中"表现层"一词存在 **5 种不同语义**，混用会导致 L2 契约层与前端层通讯障碍。以下为权威对照：

| # | 术语 | 层级 | 定义 | 所在位置 | 举例 |
|---|---|---|---|---|---|
| 1 | **表现系统**（Presentation System） | 正交域 | L0 规范宪法第十三条定义的"不改变规则位阶"的游戏正交域：动画、特效、声音、UI 反馈 | `docs/L0_规范宪法.md` §13 | "表现系统负责把结算结果翻译成玩家可感知的形式" |
| 2 | **PresentationDescriptor** | 数据类型 | L2 语义投影中的只读数据结构，承载 `resources[]` / `paidActions[]` / `attachedActions[]` | `src/l2/model/projection.ts:213` | `PresentationDescriptor.paidActions` |
| 3 | **表现层**（Presentation Layer） | 运行链位置 | 14_ 文档定义的新分层，位于"整合层之上、渲染交互层之下"，负责节点关系/ORCA/编排/端口面 | `docs/表现系统/14_表现层架构设计.md` §1.1 | "表现层不持有权威写权，只消费只读投影" |
| 4 | **渲染交互层**（Render/HCI Layer） | 运行链位置 | 表现层之上的薄壳层，零游戏逻辑，只消费表现层暴露面、生成 UI 组件和动效 | `docs/表现系统/14_表现层架构设计.md` §一.1 §四 | "渲染交互层是 V0 偷师前端的定位" |
| 5 | **src/ui/presentation/** | 代码子目录 | `src/ui/presentation/` 目录下的纯函数工具集，负责 accessibility / gameplay-value / salience / descriptor-validator | `src/ui/presentation/` | `descriptor-validator.ts` 校验 `ActionDescriptor` 格式 |

### 命名纪律

- **写作文档时**必须用语义名（全称），不得用"表现层"泛指
  - ✅ "表现系统正交域"、"渲染交互层"、" PresentationDescriptor "
  - ❌ "表现层统一处理"（哪层？）
- **写作代码时**严格按类型名
  - ✅ `PresentationDescriptor`（L2 投影类型）、`UiActionView`（UI 模型类型）
  - ❌ `"presentation"`（不指代任何代码实体）
- **跨层通讯时**用端口名（`projection` / `actionQuery` / `revision`），不用"表现层"

## 二、相关正交术语对照

| 术语 | 层级 | 定义 | 权威来源 |
|---|---|---|---|
| **整合层**（LoadingRuntime） | 运行链位置 | 组合根 + 对局外壳 + UI 宿主 + 事件出口的已装载生产面 | `docs/工程治理/04_整合层_装载运行期_规划设计.md`（归档） |
| **基类层**（Class） | 运行链位置 | 实例库：可枚举、可组合、不含具体玩法语义的定义集合 | `docs/L0_规范宪法.md` |
| **玩法层**（Play） | 运行链位置 | 规则组合：1-5 数值、流程、胜负、地图数据、策略的具体实现 | `docs/L0_规范宪法.md` |
| **引擎层**（Kernel） | 运行链位置 | ECS / Op / Query / Expr / Hook / 事件 / 持久化的原语集合 | `docs/L0_规范宪法.md` |
| **L2 语义层** | 运行链位置 | 基类层与玩法层之间的契约层，定义家族契约（Family Contracts）和投影规范 | `docs/L0_规范宪法.md` §7 |

## 三、表现层 5 义与本项目的双轨制

> 以下记录本项目在实施"高亮轨 + 卡片轨"（双轨制）时，各术语所对应的具体落地：

| 双轨制概念 | 对应的语义层级 | 说明 |
|---|---|---|
| **高亮轨** | 运行链中的渲染交互层 | `track: 'highlight'` 的 ActionDef → 地图上直接点实体的交互模式 |
| **卡片轨** | 运行链中的渲染交互层 | `track: 'card'` 的 ActionDef → 发牌器渲染的卡牌 UI |
| **卡片实例** | 渲染交互层 | `CardData` 是 Value Object（B 方案），不是 ECS Entity，由 ActionDef 投影生成 |
| **CardPresentationDef** | 基类层 | 新增的卡片元数据 Def，存于 `defRegistry`，纯前端渲染服务 |
| **双轨切池** | 渲染交互层 | 前端按 `UiActionView.track` 把动作分为 `highlightPool` / `cardPool` |
| **发牌动画** | 渲染交互层（纯前端） | 订阅 `UiView` 变更 → diff → `AnimatePresence`；玩法层不设计触发时机 |
| **表现层端口面** | 运行链中的表现层 | `ActionQueryPort` / `ProjectionPort` / `ActionPort` 共同承载双轨数据流 |

## 四、已废弃的同义混淆词

以下词汇在本项目中**不再使用**，已在历史文档中逐步清除：

| 废弃词 | 正确替代 | 废弃原因 |
|---|---|---|
| `表现层 ActionDef` | `CardPresentationDef` | ActionDef 是引擎层类型，与表现层无直接关联 |
| `渲染层 action` | `InteractionIntent` | 避免与引擎层 ActionDef 混淆 |
| `UI 层 action` | `UiActionView` | UI 层是渲染交互层的子集 |
| `前端 action` | `UiActionView` / `InteractionIntent` | 前端范围过大，不精确 |
