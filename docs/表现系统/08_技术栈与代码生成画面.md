## 〇、一句话定位

**用前端框架 + 代码特效生成一切画面，零或极少美术素材依赖——这是 AI 原生的独立游戏质感，不是页游感。**
> 这里的 TypeScript 指实现语言，不是玩法包表达。玩法包 authoring 在 L2/06 中分成官方 TS 对象字面量与 UGC JSON，两者最后都进入同一条 `PlaypackLoader.load` / `PlaypackActivator.activate` 管道。

## 一、核心理念：代码生成画面

### 1.1 什么是"代码生成画面"

| 传统游戏开发 | WakeUp 的"代码生成画面" |
|------------|----------------------|
| 美术画素材 → 程序拼接 | AI 写代码 → 代码生成视觉 |
| 依赖美术团队产能 | 零或极少美术素材 |
| 修改需要重画 | 修改只需改参数 |
| 美术风格由人决定 | 美术风格由 design-tokens 决定 |
| AI 难以参与美术环节 | AI 直接写代码产出画面 |

**核心优势**：
1. **AI 原生**：AI 能直接写 CSS/JS/React 代码，不需要"理解美术语言"
2. **迭代速度快**：改一个参数就能看到效果，不需要等美术重画
3. **风格一致性强**：所有视觉由统一的 design-tokens 控制，不会出现"这张图和那张图风格不搭"
4. **独立游戏质感**：精雕细琢的代码特效（缓动曲线/多层材质/动态光影），不是页游的"平涂 + 线性淡入淡出"

### 1.2 "零素材"≠"完全没有图片"

**实际情况**：
- **零素材依赖** = 不依赖美术团队产能，AI 能独立完成 90% 的视觉产出
- **极少美术素材** = 只有少量基础素材（像素字体、几何图形库、噪声纹理）
- **代码生成为主** = UI 元素、动画、特效、粒子全部用代码生成

**素材清单**（极少量）：
| 素材类型 | 数量 | 用途 | 生成方式 |
|---------|------|------|---------|
| **像素字体** | 1-2 款 | 所有文字显示 | 开源字体（例如：Press Start 2P） |
| **几何图形库** | ~10 个 | 按钮、边框、装饰 | SVG 代码生成（圆/矩形/多边形） |
| **噪声纹理** | 2-3 张 | 材质叠加（磨砂玻璃/金属） | Perlin Noise 算法生成 |
| **地图背景** | 按地图数量 | 全息投影光层（代码生成优先；确需美术底图经底图管线产出后按光层处理，D-083） | AI 图片生成（Nano Banana API）可选 |
| **角色精灵** | 按角色数量 | 64×64 像素小人 | agent-sprite-forge 生成 PNG |

**其他全部用代码生成**：
- UI 元素（对话框、菜单、按钮）→ React + Tailwind CSS
- 动画效果（滑入、弹性、震动）→ Framer Motion / GSAP
- 粒子特效（火花、烟雾、碎片）→ 程序化粒子系统
- 光影效果（边缘光、辉光、阴影）→ CSS filter / SVG filter
- 材质效果（磨砂玻璃、金属反光）→ CSS backdrop-filter / 多层叠加

## 二、技术栈选型

### 2.1 前端框架与库（已确定，见 2.3 定稿清单）

| 层级 | 选型 | 理由 |
|------|------|------|
| **UI 框架** | React 18（函数组件 + hooks） | JSX 是纯表达式，AI 重构时上下文不碎片化；声明式组件树天然契合"状态 → 视图"的数据流 |
| **样式框架** | Tailwind CSS + design-tokens + tailwindcss-animate | 原子类内联在标签上，AI 改样式不需要跨文件对齐；design-tokens 锁死审美方向，防止 AI 随意配色 |
| **动效引擎** | **Framer Motion（唯一，已确定）** | 声明式 spring 动效，AI 写起来和写 Tailwind 一样自然；P5 风格斜切滑入/弹性/偏移变换直接声明，不需要 GSAP |
| **粒子/特效** | **@tsparticles（JSON 配置，已确定）** | 粒子参数就是 JSON 配置，与玩法包"声明式数据"哲学同构；火花/烟雾/碎片/光尘开箱即用，避免"GIF 贴图"式页游感 |
| **UI 原语** | **Radix UI（无样式原语，已确定）** | 提供正确的可访问行为（焦点陷阱/键盘导航/ARIA），视觉全由 Tailwind + tokens 自定义，AI 组合成本低 |
| **图标** | **lucide-react（已确定）** | 纯 SVG 图标，图标名直白（map-pin/swords/heart-pulse），AI 猜名字几乎不会错；零素材图标来源 |
| **状态管理** | **Zustand（唯一，已确定）** | 少样板、无 Provider 嵌套，AI 写起来最接近普通函数 |
| **路由** | React Router | 标准选型 |
| **音频** | **Howler.js（已确定）** | 游戏音频标准库：BGM 交叉淡入、音效分层、音量控制；API 简单，AI 友好 |
| **3D/2D 渲染** | Three.js（3D）/ PixiJS（2D，后置） | 只在需要大量粒子、全屏 shader、或 SVG 性能瓶颈时才引入，作为叠加层 |
| **SVG 操作** | 原生 SVG + React 绑定 | 地图拓扑、连线、几何图形全部用 SVG，Chrome DevTools 能直接选中查看，比 Canvas/WebGL 透明 |
| **前端测试** | **Testing Library + jsdom（已确定）** | 组件行为测试（渲染/交互/动效后状态），与 Vitest 同一条流水线 |
| **打包工具** | Vite | 与 Vitest 同源，配置零摩擦 |
| **桌面端** | Electron | 内置固定版本 Chromium，"Chrome 调成什么样，打包出来就是什么样" |

### 2.2 不选的技术与理由

| 不选 | 理由 |
|------|------|
| **Vue** | JSX 比模板语法更接近 TS 表达式，AI 重构时不需要跨文件对齐 |
| **原生 CSS / CSS Modules** | 样式分散在多个文件，AI 改样式时容易遗漏；Tailwind 的原子类更适合 AI 操作 |
| **Unity / Unreal** | 黑盒太多，AI 难以精确控制；JS/CSS 架构让 AI 和人类都能看懂每一行代码 |
| **Phaser / Cocos** | 游戏引擎适合传统"美术画素材 → 程序拼接"的流程，不适合"代码生成画面" |
| **WebGL 为主渲染** | 过早优化；SVG 足够用，性能瓶颈出现后再引入 WebGL 作为叠加层 |

### 2.3 已定库清单（写死，AI 实现时必须用）

**这条清单是硬性约束，不是参考**。AI 在表现层写 UI / 动效 / 粒子时，默认从下面这些库里拿能力；**禁止只写原生 CSS 过渡做出线性淡入淡出**（那是页游感的第一来源）。库表达不了的需求（如复杂演出 timeline、全屏后处理）先登记到「后置」档，不临时造轮子。

#### 必装（现在起必须存在、必须使用）

| 库 | 用途 | AI 使用要点 |
|----|------|------------|
| `framer-motion` | 一切 UI 动效：滑入/弹性/偏移/微交互 | `motion.div` + `initial/animate/exit` + `transition={{type:'spring'}}`；P5 风格斜切用 `skewX` |
| `@tsparticles/react` + `@tsparticles/slim` | 粒子特效：火花/烟雾/碎片/光尘 | 用 JSON 配置对象（`options`）声明粒子，改参数即调效果，不写手动画布循环 |
| `@radix-ui/react-dialog` 等子包 | 可访问行为原语：对话框/提示/菜单/滑条 | 视觉全用 Tailwind + tokens 覆盖，Radix 只管行为与 ARIA |
| `lucide-react` | 全部图标 | 图标名直白（`MapPin`/`Swords`/`HeartPulse`），不需要自绘 icon |
| `zustand` | 表现层状态（UI 状态机、通知队列、对话框栈） | `create<State>()(...)` 一个函数，无 Provider |
| `react-router-dom` | 对局外界面路由（驻地/商店/任务日志等） | 标准路由，仅用于表现层页面跳转 |
| `howler` | 音频：BGM 交叉淡入、音效分层、音量 | `new Howl({src, volume, loop})`，一个实例一个声音 |
| `@testing-library/react` + `jest-dom` + `user-event` + `jsdom` | 组件测试 | 在 Vitest 里给 `environment: 'jsdom'` 的测试文件测组件行为 |
| `tailwindcss` + `tailwindcss-animate` | 原子样式 + 动效工具类 | tokens 挂进 `tailwind.config`，组件类名内联 |

#### 可选（按需安装，同样写死用法）

| 库 | 用途 | 何时引入 |
|----|------|---------|
| `@fontsource/press-start-2p` | 英文像素字体 | 需要像素文字时（中文像素字体另行评估） |
| 更多 `@radix-ui/react-*` 子包 | 新 UI 原语 | 遇到新的可访问交互组件时按 `@radix-ui/react-<name>` 命名装 |
| `canvas-confetti` | 一次性庆祝特效（成就/任务完成） | 需要轻量庆祝彩带时（比 tsparticles 轻） |

#### 后置（明确不现在装，登记给未来）

| 库 | 用途 | 引入条件 |
|----|------|---------|
| `gsap` | 复杂时间轴编排（多段演出序列） | Framer Motion 的 `useAnimate`/variants 表达不了时 |
| `three` / `@react-three/fiber` | 3D 镜头/全屏 shader | 出现 3D 需求或全屏后处理时 |
| `pixi.js` | 2D 高性能批量渲染 | SVG 同屏 DOM 节点数成为性能瓶颈时 |
| `dnd-kit` | 拖拽排序（编辑器二期） | 编辑器需要拖拽列表/排序时 |
| `@xstate/xstate` | 复杂状态机 UI | 表现层出现超过 3 层嵌套状态时（目前 UI 状态机优先 zustand 手写） |

**纪律**：
1. 动效一律走 Framer Motion，不用手写 CSS keyframes 做 UI 动效（CSS 过渡只允许用于 `hover`/`focus` 等微状态切换）。
2. 粒子一律走 tsparticles，不贴 GIF、不用静态图片冒充。
3. 图标一律 lucide-react，不手绘 SVG path。
4. 可访问行为（弹窗焦点/键盘/ARIA）一律 Radix，不自己实现。
5. 音效一律 Howler，不用 `<audio>` 裸标签。
6. 新库进必装档需要项目所有者裁决；文档不改，代码不许偷偷引入新依赖。

## 三、独立游戏质感 vs 页游感

### 3.1 核心区别

| 特征 | 独立游戏质感（目标） | 页游感（避免） |
|------|-------------------|---------------|
| **动效** | 精雕细琢的缓动曲线（elastic/spring） | 线性淡入淡出（`ease-in-out`） |
| **材质** | 多层叠加（磨砂玻璃/金属反光/噪声纹理） | 纯色平涂 |
| **光影** | 动态光影（边缘光/环境光遮蔽/辉光） | 无光影或假光影（单层阴影） |
| **粒子** | 程序化粒子（火花/烟雾/碎片，物理模拟） | GIF 动图或静态图片 |
| **UI 层次** | 多层景深（近景模糊/远景虚化） | 全部平铺在同一平面 |
| **响应** | 微交互（悬停/点击/拖拽的细腻反馈） | 按钮变色而已 |
| **字体** | 像素字体 + 抗锯齿控制 | 系统字体（Arial/微软雅黑） |
| **配色** | 统一色板 + 语义映射（见 `01` 五条视觉定律） | 随意配色（蓝紫粉橙一锅炖） |
| **细节** | 每个元素都有细节（纹理/描边/高光） | 大面积留白/空洞 |

### 3.2 实现手段示例

#### 示例 1：独立游戏质感的 UI 卡片

```tsx
// React + Tailwind + 手写 CSS 特效
<div className="
  relative
  bg-black/10
  backdrop-blur-xl
  backdrop-saturate-180
  rounded-lg
  border border-white/20
  shadow-[inset_0_1px_0_rgba(255,255,255,0.3),0_8px_32px_rgba(0,0,0,0.4)]
  transition-all duration-300 ease-[cubic-bezier(0.68,-0.55,0.265,1.55)]
  hover:translate-y-[-2px] hover:scale-[1.02] hover:shadow-[0_12px_48px_rgba(0,0,0,0.5)]
"
style={{
  backgroundImage: `
    linear-gradient(135deg, rgba(255,255,255,0.1) 0%, transparent 50%),
    url('/noise.png')
  `,
}}>
  {/* 内容 */}
</div>
```

**效果分析**：
- `backdrop-blur-xl`：磨砂玻璃效果
- `backdrop-saturate-180`：颜色增强
- `shadow-[inset_0_1px_0_...]`：顶部边缘光（高光）
- `shadow-[0_8px_32px_...]`：投影（营造悬浮感）
- `ease-[cubic-bezier(...)]`：弹性缓动（悬停时有回弹）
- `backgroundImage`：多层纹理（渐变 + 噪声）

#### 示例 2：P5 风格的斜切滑入动画

```tsx
import { motion } from 'framer-motion';

<motion.div
  initial={{ x: -100, opacity: 0, skewX: -5 }}
  animate={{ x: 0, opacity: 1, skewX: 0 }}
  exit={{ x: 100, opacity: 0, skewX: 5 }}
  transition={{
    type: 'spring',
    stiffness: 300,
    damping: 30,
  }}
  className="relative bg-black/80 border-l-4 border-red-500"
>
  {/* 红色条纹装饰 */}
  <div className="absolute top-0 right-0 w-2 h-full bg-gradient-to-b from-red-500 to-red-700 animate-pulse" />
  
  {/* 对话框内容 */}
  <div className="p-4">
    <h2 className="text-white font-pixel">艾琳 · 侦探</h2>
    <p className="text-gray-300">这个案子不简单。</p>
  </div>
</motion.div>
```

**效果分析**：
- `initial`：入场前状态（左侧 -100px，透明，斜切 -5°）
- `animate`：入场后状态（归位，不透明，斜切 0°）
- `exit`：出场状态（右侧 +100px，透明，斜切 +5°）
- `type: 'spring'`：弹性缓动（有回弹）
- `border-l-4 border-red-500`：左侧红色边框（P5 风格）
- `animate-pulse`：红色条纹脉冲动画

#### 示例 3：程序化粒子系统（火花）

## 四、Design Tokens（美学真相源）

### 4.1 什么是 Design Tokens

**定义**：所有视觉参数（颜色/字体/间距/阴影/动画曲线）的唯一真相源，所有代码从这里读取参数。

**为什么需要 Design Tokens**：
- **防止 AI 随意配色**：AI 不能"觉得红色好看就用红色"，必须从 tokens 里选
- **保证风格一致**：所有组件用同一套参数，不会出现"这个红和那个红不一样"
- **快速迭代**：改一个 token，所有用到这个 token 的地方都会更新

### 4.2 Design Tokens 结构

```typescript

export const tokens = {
```


## 五、核心逻辑层零前端依赖

### 5.1 什么是"核心逻辑层零前端依赖"

**定义**：`src/core/` 目录下的所有代码不能 import React/DOM/SVG 相关内容，保证核心逻辑可以在 Node.js 无头环境运行。

**为什么需要这条约束**：
- **前后端同构**：服务器和客户端用同一套逻辑，不需要维护两份代码
- **测试友好**：核心逻辑可以在 Vitest 中测试，不需要启动浏览器
- **AI 协作友好**：AI 写核心逻辑时不需要理解前端概念，只需要理解状态机

**实现方式**：
```json
// .eslintrc.json
{
  "overrides": [
    {
      "files": ["src/core/**/*.ts"],
      "rules": {
        "no-restricted-imports": ["error", {
          "patterns": [
            "react",
            "react-dom",
            "framer-motion",
            "*svg*",
            "*dom*",
            "*browser*"
          ]
        }]
      }
    }
  ]
}
```

### 5.2 分层架构

```
src/
├── core/                    # 核心逻辑（纯 TS 状态机）
│   ├── entities/            # 实体/物品/节点定义
│   ├── rules/               # 基类层规则
│   ├── modes/               # 玩法层规则
│   └── __tests__/           # Vitest 测试
│
├── components/              # React UI 组件
│   ├── panels/              # 物品栏、动作面板
│   └── primitives/          # 按钮、进度条
│
├── scene/                   # SVG 渲染层
│   ├── NodeMap.tsx          # 节点拓扑图
│   └── EntitySprite.tsx     # 实体精灵
│
└── design/
    └── tokens.ts            # Design Tokens
```

**数据流**：
```
src/core（状态机）
    ↓ 状态变化
src/components（React 监听状态）
    ↓ 渲染 UI
src/scene（SVG 渲染地图）
```

## 六、AI 原生的开发流程

### 6.1 AI 如何参与开发

| 传统流程 | AI 原生流程 |
|---------|-----------|
| 美术画原画 → 程序切图 → 拼接到游戏 | AI 写代码 → 代码生成画面 → 人类审查 |
| 改动需要重走流程 | 改动只需改参数 → 立即看到效果 |
| 美术和程序需要反复沟通 | AI 一个人完成"设计 + 实现" |

**AI 的优势**：
1. **写 CSS/JS 代码比"理解美术语言"简单**
2. **Design Tokens 给了 AI 明确的约束**（不会随意配色）
3. **声明式 UI（React）让 AI 只需要描述"要什么"，不需要描述"怎么做"**

**人类的角色**：
1. **定义 Design Tokens**（美学方向）
2. **审查 AI 产出**（质量把关）
3. **调整参数**（微调动效/配色）

### 6.2 开发迭代示例

**任务**：实现 P5 风格的对话框

**步骤 1**：人类写设计文档（`06_叙事对话框系统.md`）
- 定义对话框的功能（立绘/名字/文本/选项）
- 定义动效（斜切滑入 + 弹性）
- 定义配色（黑色背景 + 红色边框）

**步骤 2**：AI 写代码
```tsx
<motion.div

  transition={{ type: 'spring', stiffness: 300, damping: 30 }}

>
  {/* ... */}
</motion.div>
```

**步骤 3**：人类审查
- 在浏览器里看效果
- 微调参数（例如：`stiffness: 300 → 400`）

**步骤 4**：迭代
- 人类说"弹性太强了，改弱一点"
- AI 改代码：`stiffness: 400 → 250`
- 立即看到新效果

## 七、性能优化策略

### 7.1 优化原则

**过早优化是万恶之源**：先做出独立游戏质感，性能瓶颈出现后再优化。

**优化顺序**：
1. **先用 SVG + React**（最简单）
2. **性能瓶颈出现 → 局部用 Canvas**（例如：粒子系统）
3. **仍然不够 → 引入 WebGL**（例如：全屏 shader）

### 7.2 常见性能瓶颈与解决方案

| 瓶颈 | 解决方案 |
|------|---------|
| **同屏大量 DOM 节点** | 虚拟化（只渲染可见部分） |
| **复杂动画导致卡顿** | 用 `will-change: transform` 提示浏览器优化 |
| **粒子系统性能差** | 改用 Canvas 批量渲染 |
| **全屏特效性能差** | 改用 WebGL shader |
| **状态更新频繁** | 用 `useMemo` / `useCallback` 避免重复计算 |

### 7.3 性能监控

```tsx
// 开发环境启用性能监控
import { Profiler } from 'react';

<Profiler id="DialogBox" onRender={(id, phase, actualDuration) => {
  if (actualDuration > 16) {
    console.warn(`${id} took ${actualDuration}ms to render`);
  }
}}>
  <DialogBox />
</Profiler>
```

## 九、总结

WakeUp 的"代码生成画面"方案：

**核心技术栈**：
- React + Tailwind CSS + Framer Motion
- SVG（主渲染）+ Canvas/WebGL（性能瓶颈时引入）

- AI 原生（AI 能直接写代码产出画面）

- 风格一致性强（Design Tokens 统一控制）
- 独立游戏质感（精雕细琢的代码特效）

**核心约束**：
- 核心逻辑层零前端依赖（`src/core/` 不能 import React/DOM）
- Design Tokens 是唯一美学真相源（不能硬编码颜色/间距）
- 过早优化是万恶之源（先用 SVG，瓶颈出现后再优化）
