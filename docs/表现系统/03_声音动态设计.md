> **归属**：表现系统 · 子系统三（五条动态子系统之三）  
> **性质**：自主创作设计（基于 `00_创作指导.md` §二·五战略分工）

## 〇、一句话定位

**声音是"省力杠杆"——换弹 = 音效 + 曲线，不做帧/全屏。**

音频系统的职责是**通过声音增强游戏反馈、建立情绪氛围、减轻视觉动画负担**。声音不改变规则、不泄露隐藏信息（除非规则本身允许"听到声音"），且遵循 `00` §二·原则二"克制序"——声音是成本最低、扩展性最强的表现手段之一。

## 一、声音系统的五大职责

| 职责 | 一句话 | 典型场景 | 与视觉的关系 |
|---|---|---|---|
| **1. 动作反馈** | 让玩家"听到"动作结果 | 攻击命中、拾取物品、开门、换弹 | **代替视觉**：换弹只用音效 + 曲线，不做帧 |
| **2. 状态提示** | 用声音告知状态变化 | 体力耗尽、过载、濒死、冷却完成 | **辅助视觉**：声音 + 图标闪烁 |
| **3. 环境氛围** | 建立场景情绪与沉浸感 | 风声、雨声、脚步声、环境音乐 | **独立于视觉**：声音营造氛围，视觉聚焦玩法 |
| **4. 空间定位** | 用立体声告知方向与距离 | 敌人脚步、枪声、爆炸 | **补充视觉**：声音告知"屏幕外发生了什么" |
| **5. 叙事语音** | 角色对话、旁白、提示 | NPC 对话、教程提示、剧情语音 | **配合视觉**：语音 + 字幕 |

## 二、音频分层架构（四层混音）

> **设计原则**：基于 `00` §二·原则一"动画与规则结算解耦"——声音也不阻塞规则，但多个声音可能叠加，需要分层混音避免混乱。

### 2.1 四层混音架构

| 层级 | 优先级 | 职责 | 典型音量 | 允许叠加数量 |
|---|---|---|---|---|
| **第一层：关键反馈** | 最高 | 玩家自己的动作反馈（攻击/拾取/换弹） | 100% | 最多 3 个同时播放 |
| **第二层：战斗音效** | 高 | 其他玩家/NPC 的动作音效（枪声/脚步/受击） | 70% | 最多 8 个同时播放 |
| **第三层：环境氛围** | 中 | 风声/雨声/环境音乐/远处枪声 | 40% | 无限制（但自动衰减） |
| **第四层：UI 反馈** | 低 | 按钮点击/菜单切换/冷却完成提示 | 50% | 最多 2 个同时播放 |

### 2.2 混音规则

**当同层声音超过上限时**：
- **第一层**：最新的声音顶掉最旧的声音（保证玩家自己的动作总能听到）
- **第二层**：最近的声音顶掉最远的声音（优先播放屏幕内/附近的声音）
- **第三层**：自动衰减（所有环境音同时播放，但音量按距离衰减）
- **第四层**：最新的声音顶掉最旧的声音

**跨层叠加**：
- 四层可以同时播放（总音量不超过 100%）
- 当总音量 > 100% 时，自动压缩（Compression）：第一层保持 100%，其他层按比例降低

## 三、动作反馈音效（第一层 + 第二层）

> **核心设计**：每个动作都有对应的音效，遵循 `03` §成本序修正的"省力杠杆"——能用音效解决的，不做高成本视觉动画。

### 3.1 动作音效库（按语义分类）

| 动作类型 | 音效描述 | 时长 | 音量 | 音高变化 | 典型场景 |
|---|---|---|---|---|---|
| **攻击类** | | | | | |
| - 近战命中 | 钝击声（拳/棍/刀） | 0.2s | 100% | 无 | 近战攻击命中 |
| - 近战落空 | 轻微破风声 | 0.15s | 60% | 无 | 近战攻击未命中 |
| - 枪械射击 | 枪声（手枪/步枪/霰弹枪/狙击枪） | 0.3s | 100% | 武器特定 | 射击 |
| - 换弹 | 弹匣抽出 → 插入 → 拉栓 | 1.5s | 80% | 无 | 换弹动作（`03` §省力杠杆：音效 + 曲线，不做帧） |
| - 爆炸 | 低频爆炸声 + 碎片飞溅 | 1.0s | 120% | 无 | 手榴弹/载具爆炸 |
| **移动类** | | | | | |
| - 脚步声 | 脚步声（轻/中/重） | 0.3s | 50% | 随机 ±5% | 移动时每步触发 |
| - 跳跃 | 起跳 + 落地 | 0.5s | 60% | 无 | 跳跃动画 |
| - 门开关 | 木门/金属门开关声 | 0.8s | 70% | 无 | 开门/关门 |
| - 破坏 | 玻璃破碎/木板断裂 | 0.6s | 90% | 无 | 破窗/破门（配合全屏动画） |
| **交互类** | | | | | |
| - 拾取 | 轻快的"叮"声 | 0.2s | 80% | +20% | 拾取物品 |
| - 使用物品 | 撕开包装/吞咽/注射 | 0.5s | 70% | 无 | 使用消耗品 |
| - 装备切换 | 金属碰撞/布料摩擦 | 0.4s | 60% | 无 | 切换武器/装备 |
| **状态类** | | | | | |
| - 受击 | 肉体撞击 + 痛苦呻吟 | 0.3s | 80% | 随机 ±10% | 受到伤害 |
| - 倒地 | 重物倒地 + 沉重呼吸 | 1.0s | 90% | -20% | HP 归零倒地 |
| - 濒死 | 急促呼吸 + 心跳声（循环） | 循环 | 60% | 无 | 濒死状态（可处决） |
| - 死亡 | 最后一口气 + 身体倒下 | 1.5s | 100% | -30% | 死亡 |
| **UI/系统类** | | | | | |
| - 轮次开始 | 提示音（上升音阶） | 0.5s | 70% | 无 | 轮次开始 |
| - AP 消耗 | 轻微"咔哒"声 | 0.1s | 40% | 无 | 消耗 AP |
| - 冷却完成 | 提示音（明亮） | 0.3s | 60% | 无 | 动作冷却完成 |
| - 按钮点击 | 轻柔"咔" | 0.1s | 50% | 无 | UI 按钮点击 |

### 3.2 音效触发时机

**与动画的关系**（遵循 `00` §二·原则四"动画与规则结算解耦"）：
- **音效触发 = 规则事件发生时**（不等动画播放到某一帧）
- 例如：攻击命中 → 立刻播放"近战命中"音效，不等攻击动画播放到"武器接触目标"那一帧
- 例外：**换弹**音效需要与曲线动画同步（音效分三段：抽出 0.5s → 插入 0.5s → 拉栓 0.5s，配合 `03` §M组曲线"枪口下倾 → 抖两下 → 回正"）

**触发代码示例**（伪代码）：
```typescript
// 规则层触发音效，不依赖表现层动画
onActionResolved(action: Action) {
  if (action.type === 'melee_attack' && action.hit) {
    Audio.play('melee_hit', { volume: 1.0, layer: 'key_feedback' });
  }
}
```

### 3.3 音高随机化（避免重复感）

**为什么需要**：同一个音效反复播放会让人感觉机械、单调

**实现方式**：
- 每次播放时，音高随机 ±5%（例如：脚步声、受击声）
- 某些音效不随机（例如：枪声、爆炸——这些声音的"特征音高"是识别度的一部分）

## 四、空间音频（3D 定位）

> **设计原则**：基于 `00` §二·原则一"动画不泄露隐藏信息"——声音遵循规则的"听觉范围"，不泄露屏幕外的隐藏敌人（除非规则允许"听到"）。

### 4.1 立体声定位

**左右声道**：
- 根据音源的 X 坐标计算左右声道比例
- 音源在屏幕左侧 → 左声道音量高
- 音源在屏幕右侧 → 右声道音量高
- 音源在屏幕中央 → 左右声道平衡

**前后感（混响）**：
- 远处的声音 → 增加混响（Reverb），音量衰减
- 近处的声音 → 减少混响，音量正常

### 4.2 距离衰减

**衰减公式**：
```
音量 = baseVolume × (1 - distance / maxHearingRange)²
```

**参数**：
- `baseVolume`：音效的基准音量（见 §三·3.1 表格）
- `distance`：音源到镜头中心的距离（单位：格子）
- `maxHearingRange`：最大听觉范围（默认 20 格）
  - 枪声：30 格
  - 爆炸：40 格
  - 脚步声：10 格
  - 对话：5 格

**超出范围**：
- `distance > maxHearingRange` → 不播放音效（完全听不到）

### 4.3 隐藏信息规则

**不泄露规则不允许的信息**：
- 如果规则规定"玩家听不到这个声音"（例如：敌人在隔音墙后、敌人潜行中），则**完全不播放音效**，即使视觉上看到了动画
- 如果规则规定"玩家能听到但看不到"（例如：敌人在屏幕外开枪），则播放音效 + 3D 定位（让玩家通过声音判断方向）

**触发代码示例**（伪代码）：
```typescript
onActionResolved(action: Action) {
  if (action.type === 'gunshot') {
    // 检查规则：玩家能否听到这个枪声
    if (Rules.canPlayerHear(action.source, player)) {
      const distance = Vector.distance(action.source.pos, camera.pos);
      const volume = calculateVolumeByDistance(distance, 30); // 30 = 枪声最大听觉范围
      const pan = calculatePanByPosition(action.source.pos); // 左右声道
      Audio.play('gunshot', { volume, pan, layer: 'combat' });
    }
  }
}
```

## 五、环境氛围音（第三层）

> **设计原则**：环境音是"独立于玩法的情绪层"，不与动作音效竞争注意力，音量较低、持续播放、营造沉浸感。

### 5.1 环境音分类

| 类型 | 描述 | 音量 | 循环 | 触发条件 |
|---|---|---|---|---|
| **环境音乐** | 背景音乐（无歌词、低调） | 30% | 是 | 对局开始 |
| **自然环境** | 风声、雨声、鸟叫、虫鸣 | 20% | 是 | 根据地图类型 |
| **室内环境** | 空调声、电流声、水滴声 | 15% | 是 | 室内场景 |
| **远处战斗** | 远处枪声、爆炸、喊叫（模糊） | 25% | 否 | 随机触发（营造紧张感） |
| **脚步回声** | 玩家自己的脚步在空旷空间的回声 | 10% | 否 | 大型空旷场景 |

### 5.2 环境音的动态调整

**根据游戏状态调整**：
| 游戏状态 | 环境音乐音量 | 自然环境音量 | 远处战斗音量 |
|---|---|---|---|
| **平静探索** | 30% | 20% | 0% |
| **警戒状态** | 20% | 15% | 25% |
| **激烈战斗** | 10% | 5% | 40% |
| **濒死状态** | 5% | 0% | 60%（心跳声取代） |

**为什么这样设计**：
- 战斗时降低环境音乐音量 → 让玩家更专注于动作音效（枪声/脚步）
- 濒死时只保留心跳声 → 营造紧张感

### 5.3 环境音的空间化

**室内 vs 室外**：
- **室内**：增加混响（模拟封闭空间），低频增强
- **室外**：减少混响，高频清晰

**根据镜头位置动态调整**：
- 镜头移动到室内 → 环境音逐渐切换到"室内模式"（0.5秒淡入淡出）
- 镜头移动到室外 → 环境音逐渐切换到"室外模式"

## 六、状态提示音（辅助视觉反馈）

> **设计原则**：基于 `03` §成本序修正的"省力杠杆"——状态变化用"音效 + 图标闪烁"，不做复杂视觉动画。

### 6.1 关键状态提示音

| 状态 | 音效描述 | 时长 | 音量 | 触发时机 | 配合视觉 |
|---|---|---|---|---|---|
| **体力耗尽** | 沉重喘息 + 低频"咚" | 0.8s | 90% | SP 归零 | 体力条闪烁（蓝色） |
| **过载** | 高频尖锐声 + 电流声 | 1.0s | 100% | 过载触发 | 屏幕白光闪烁（`00` §一·5 纯白=过载） |
| **濒死** | 心跳声（循环，逐渐加快） | 循环 | 80% | HP ≤ 1 | 屏幕边缘红光脉动 + 蓝闪可处决高光 |
| **冷却完成** | 明亮提示音（上升音阶） | 0.3s | 60% | 动作冷却完成 | 动作卡片边缘绿光闪烁 |
| **AP 不足** | 低沉"咚"（负面） | 0.2s | 70% | 尝试使用 AP 不足的动作 | AP 计数器红光闪烁 |
| **负面状态获得** | 不和谐音（下降音阶） | 0.5s | 80% | 中毒/流血/眩晕 | 状态图标出现 + 角色头顶红色气泡 |
| **正面状态获得** | 和谐音（上升音阶） | 0.5s | 70% | 治疗/增益 | 状态图标出现 + 角色头顶绿色气泡 |

### 6.2 循环音效的管理

**濒死心跳声**：
- 进入濒死状态 → 开始循环播放心跳声（1 次/秒）
- 心跳声逐渐加快：1 次/秒 → 1.5 次/秒 → 2 次/秒（随时间推移）
- 退出濒死状态（恢复 HP）→ 心跳声淡出（0.5秒）
- 死亡 → 心跳声停止（0.2秒骤停）

**体力耗尽喘息**：
- SP 归零 → 播放一次沉重喘息
- SP 恢复 > 0 → 播放一次轻松呼气

## 七、叙事语音与对话

> **设计原则**：语音是"高成本内容"（需要配音演员或 AI 语音生成），优先级低于音效，MVP 可用字幕代替。

### 7.1 语音分类

| 类型 | 描述 | 优先级 | MVP 是否必须 |
|---|---|---|---|
| **角色对话** | NPC 与玩家的对话 | 高 | ❌ 否（字幕代替） |
| **战斗喊话** | 角色在战斗中的短句（"换弹！""小心！"） | 中 | ❌ 否（可省略） |
| **教程提示** | 游戏机制的语音讲解 | 低 | ❌ 否（文字提示代替） |
| **剧情旁白** | 过场动画的旁白 | 高 | ❌ 否（字幕代替） |

### 7.2 语音生成方案

**MVP 阶段**：
- **不做语音**，只用字幕（节省成本）
- 重要对话显示字幕 + 打字机效果（0.05秒/字）

**后期增强**：
- 使用 **ElevenLabs API** 生成 AI 语音（`00` §二·五表格提到）
- 语音缓存：同一句话只生成一次，缓存到本地
- 用户设置：语音音量、语速、是否启用语音

### 7.3 字幕显示规则

**位置**：
- 屏幕底部居中（黑色半透明背景 + 白色文字）
- 角色名字用颜色区分（玩家=青色、NPC=灰白）

**显示时长**：
- 短句（< 10 字）：2 秒
- 中句（10-20 字）：4 秒
- 长句（> 20 字）：6 秒
- 或者：用户按 Space 跳过

**多人对话**：
- 对话框左侧显示说话者头像（32×32 像素）
- 头像边缘用颜色语义高亮（青色=玩家、灰白=NPC）

## 八、音效资源管理

> **设计原则**：音效文件轻量、快速加载、支持流式播放

### 8.1 音效文件格式

**推荐格式**：
- **短音效**（< 2 秒）：`.ogg`（Vorbis 编码，压缩率高）
- **长音效/音乐**（> 2 秒）：`.ogg`（流式播放）
- **语音**：`.mp3`（兼容性好）

**不使用 `.wav`**（文件过大，不适合 Web）

### 8.2 音效文件大小约束

| 类型 | 时长 | 比特率 | 文件大小上限 |
|---|---|---|---|
| **短音效** | < 2s | 96 kbps | 50 KB |
| **中等音效** | 2-5s | 128 kbps | 150 KB |
| **环境音乐** | 2-5 分钟 | 128 kbps | 5 MB（流式播放） |

### 8.3 预加载策略

**对局开始时预加载**：
- 所有第一层/第二层音效（动作反馈 + 战斗音效）
- 当前地图的环境音
- UI 反馈音效

**延迟加载**：
- 语音文件（需要时才加载）
- 非当前地图的环境音

**卸载策略**：
- 对局结束后，卸载所有音效（释放内存）
- 只保留 UI 反馈音效（主菜单也需要）

## 九、用户设置（无障碍支持）

> **设计原则**：音频设置必须支持无障碍需求（听力障碍、敏感度等）

### 9.1 音量设置

**分层控制**：
- **总音量**：0% ~ 100%（默认 100%）
- **音效音量**：0% ~ 100%（默认 100%，控制第一层 + 第二层）
- **环境音量**：0% ~ 100%（默认 100%，控制第三层）
- **UI 音量**：0% ~ 100%（默认 100%，控制第四层）
- **语音音量**：0% ~ 100%（默认 100%）

**静音快捷键**：
- 按 `M` 键 → 总音量静音/取消静音

### 9.2 无障碍设置

**听力障碍支持**：
- **视觉音效提示**：开启后，所有音效都会在屏幕上显示视觉指示
  - 枪声 → 屏幕边缘显示方向箭头（红色）
  - 脚步声 → 屏幕边缘显示方向箭头（黄色）
  - 对话 → 强制显示字幕
- **振动反馈**：开启后，关键音效触发时手柄振动
  - 受击 → 轻微振动
  - 爆炸 → 强烈振动
  - 濒死 → 心跳节奏振动

**敏感度设置**：
- **减少突发音效**：开启后，降低爆炸/枪声等高音量音效（避免惊吓）
- **单声道模式**：开启后，禁用立体声定位（适合单侧听力障碍用户）

## 十、与现有系统的衔接

### 10.1 与动画系统的解耦

**音效不等动画**（遵循 `00` §二·原则四）：
- 音效由**规则事件触发**，不依赖动画播放到某一帧
- 例外：换弹音效需要与曲线动画同步（分三段播放）

**代码示例**（伪代码）：
```typescript
// 规则层触发音效
onActionResolved(action: Action) {
  Audio.play(action.soundId, { layer: 'key_feedback' });
}

// 表现层播放动画（独立）
onActionResolved(action: Action) {
  Animation.play(action.animId);
}
```

### 10.2 与镜头系统的协同

**音效音量受镜头距离影响**：
- 镜头距离音源越远 → 音量越低（见 §四·4.2 距离衰减）
- 镜头缩放不影响音量（音量只与实际距离有关，不与视觉大小有关）

**镜头切换时的音效处理**：
- 镜头快速切换到新焦点 → 音效立刻按新距离重新计算音量
- 不需要淡入淡出（避免音效延迟）

### 10.3 与 UI 系统的协同

**UI 音效（第四层）**：
- 按钮点击、菜单切换、冷却完成提示等
- 不受距离衰减影响（始终按基准音量播放）

## 十三、待验收问题（提请项目所有者裁决）

1. **四层混音架构**：第一层"关键反馈"最多 3 个同时播放，第二层"战斗音效"最多 8 个——这个上限是否合适？
2. **距离衰减公式**：`音量 = baseVolume × (1 - distance / maxHearingRange)²`——平方衰减是否太快？要不要改为线性衰减？
3. **换弹音效与曲线同步**：这是唯一一个"音效必须与动画同步"的例外——是否违反了"音效与动画解耦"的原则？（我的判断：不违反，因为换弹本身就是"音效 + 曲线"的省力杠杆，音效是主角）
4. **濒死心跳声逐渐加快**：这是否会让玩家感到过度紧张/焦虑？要不要保持恒定节奏？
5. **视觉音效提示**（无障碍支持）：屏幕边缘显示方向箭头——这是否违反了"音效不泄露隐藏信息"的原则？（我的判断：不违反，因为这是用户主动开启的无障碍功能，相当于"规则允许看到"）
6. **MVP 音效数量**：54 个音效（5.5 MB）——这个数量是否太多或太少？
