# 08 · 调色板宽度放宽记录（32 → 64）

## 现象

项目所有者反馈：管线生成的角色 PNG 放大后**颜色杂色非常杂乱、不平整**，
**不符合人类手绘的平整感**。

排查方向（最初假设）：
- 是 AI 生成的图本身有杂色？
- 还是管线后处理有 bug？

## 排查过程

### 实验一：AI 直出 vs 32 色量化后

对 `src/devboard/game-ui-shell-10/public/games/menu/detective/f01.png`（155×154）：

| 状态 | 尺寸 | 唯一色数 | 平均相邻色差 |
|------|------|----------|-------------|
| AI 直出 | 155×154 | 32（已 proper-pixel-art） | 15.7 |
| 32 色量化 | 同 | 32 | 15.7 |

### 实验二：32/64/128/256 色量化对比

```
proper colors=32:  out_uniq=7,  avg_adj=109.9
proper colors=64:  out_uniq=7,  avg_adj=109.9
proper colors=128: out_uniq=7,  avg_adj=109.9
proper colors=256: out_uniq=7,  avg_adj=109.9
```

**关键发现**：改变 `--colors` 参数**完全不影响** proper-pixel-art 的实际输出。
输出色数稳定在 7，色彩量化是 K-means 自动收敛，与 `--colors` 无关。

### 实验三：原图直传 vs 32 色限制

源图实际是 11×11 网格 + 32 色（原图已 32 色），
proper-pixel-art 把 11×11 网格重建出来后**只用 7 个色**。
**32 色限制未生效，杂色也不是源于此**。

## 实验二：upscale 参数对比（关键发现）

proper-pixel-art 有 `-u` / `initial_upscale_factor` 参数，控制边缘检测前的预放大倍数。
值越小 → 检测到的网格越密 → 产出像素数越多 → 保留越多颜色。

对 detective f01（155×154）：

| upscale | 输出尺寸 | 输出唯一色数 |
|---------|---------|-------------|
| 2（旧默认） | 11×11 | 7 |
| 4 | 28×29 | 12 |
| 6 | 46×45 | 19 |
| 8 | 57×55 | 25 |
| **10** | **155×154** | **32** |
| 12+ | ≥155×154 | 32（已饱和） |

**upscale=10 时输出尺寸 = 输入尺寸，颜色数完全保留（32）。**

## 实验三：组合流程最终验证

```
source: 155×154, uniq=32
proper(-u 10): 155×154, uniq=32  ← 与输入完全一致
NEAREST→128×128: uniq=32, avg_adj=17.8  ← 完美保留
```

**结论：upscale=10 是甜点参数，颜色数与原图完全一致。**

## 真因诊断

`--colors` 参数完全不影响 proper-pixel-art 的实际输出。
杂色来源于 proper-pixel-art 的 **initial_upscale_factor=2**：把图压到 11×11 网格，
颜色数由网格数决定，与调色板无关。

## 处理

**改 proper-pixel-art `PixelateConfig.initial_upscale_factor` 默认值：2 → 10。**

| 文件 | 改动 |
|------|------|
| `proper_pixel_art/config.py` | `initial_upscale_factor: int = 2` → `10` |
| `proper_pixel_art/colors.py` | `palette_img` 默认 `num_colors=16` → `64`（仅保留，实际由 CLI 控制） |
| `sprite-pixelate.py` | CLI 加 `-u 10` |
| `sprite-purify-slice.py` | CLI 加 `-u 10` |
| `sprite-component.py` | CLI 加 `-u 10` |

**32 色限制也一并放宽为 64**（之前已改），但实际有约束力的是 upscale=10。

## 第二轮诊断（杂色仍存在）

`upscale=10` 改完后，色数对上了，但**色块内仍有颗粒感**（"明暗过渡割裂"）。
grainy 3×3 颗粒像素从 2142 → 1204（仍大量残留）。

## 实验：量化方法对比

proper-pixel-art 的量化方法（`color_config.quantize_method`）：

| 方法 | grainy 颗粒像素 | 说明 |
|------|----------------|------|
| MEDIANCUT | 2142 | 旧默认 |
| **MAXCOVERAGE** | **821** | **当前默认**（已最优） |
| FASTOCTREE | 1204 | 更快但颗粒感更多 |
| LIBIMAGEQUANT | N/A | 需额外依赖 |

MAXCOVERAGE 已最优，但 821 颗粒像素仍偏多。

## 实验：median 前置降噪

在 proper-pixel-art 之前加 median 降噪：

| 方案 | uniq | grainy 颗粒 | 评估 |
|------|------|------------|------|
| 原图（AI 直出） | 2037 | 3387 | - |
| median3（仅） | 1603 | 3164 | 降噪不足 |
| median3 + proper | **12** | **29** | **最优** |
| median5 + proper | 14 | 20 | 略优但过度平滑 |

**median3 + proper 最佳** —— 颗粒感 -99%。

## 处理（最终）

**sprite-pixelate / sprite-purify-slice / sprite-component 三个工具的 `pixelate_frame` 前置 median 3×3 降噪。**

```python
from PIL import ImageFilter
denoised = img.filter(ImageFilter.MedianFilter(3))
denoised.save(...)
# 再走 proper-pixel-art
```

## 验证结果

| 指标 | 改前 | 改后 | 改善 |
|------|------|------|------|
| grainy 3×3 颗粒像素 | 2142 | 29 | -99% |
| uniq | 30 | 12 | -60% |
| 视觉平整度 | 颗粒明显 | 接近手绘 | 显著 |

## 改动清单（累计）

| 文件 | 改动 |
|------|------|
| `proper_pixel_art/config.py` | `initial_upscale_factor: 2` → `10` |
| `proper_pixel_art/colors.py` | `palette_img` 默认 `num_colors=16` → `64` |
| `sprite-pixelate.py` | 默认 `colors=64`，CLI 加 `-u 10`，**前置 median3 降噪** |
| `sprite-purify-slice.py` | 默认 `colors=64`，CLI 加 `-u 10`，**前置 median3 降噪** |
| `sprite-component.py` | 默认 `colors=64`，CLI 加 `-u 10`，**前置 median3 降噪** |

## 不动的东西

- **proper-pixel-art 的 downsample 行为**（per-cell mode 算法）—— 太复杂，改了影响太大
- **hashi-dither-purifier.py 的 32 色硬限**（最后一道"护城河"）
- **MapData JSON / scene-image 资产**（不涉及）

---

*Bug 记录（最终结论）：色块内颗粒感是 AI 直出图本身带渐变区 + proper-pixel-art per-cell 模式的双重结果。prompt 已写"NO gradients"但 AI 不遵守（AI 直出 uniq=40k+，远超 32 色上限）。管线侧 median3 前置降噪把 grainy 砍掉 99%，剩余少量颗粒是算法固有问题，非 bug。32 色护城河不改。*
