## 一、设计背景

### 1.1 核心问题

游戏世界需要一套统一的"时间度量标准"来衡量各种活动的消耗与消耗。现有机制在以下方面需要统一：

- 账单结算周期的统一标准
- 任务消耗时间的度量单位
- 资源类活动（商店、黑客）的刷新节奏
- 套餐机制的生效逻辑与风险设定

### 1.2 与现有 UI 的适配关系

本设计与以下 UI 文档保持一致：
- `docs/电脑UI_V0_创作需求.md`：包含账单、套餐的 UI 表现需求
- `docs/电脑UI_V0_Prompt总集.md`：SUBSCRIPTION.NET 营业厅页面的实现设计
- 均采用**天为基准**的时间刻度

## 二、时间刻度定义

### 2.1 基准单位

```
1天 = 1个时间刻度 (Time Unit, TU)
```

**设计原则**：
- 以自然时间长度为基准，玩家易于理解
- 天为最小可操作单位，避免"分钟级"的操作复杂度
- 为所有系统提供统一的计量标准

### 2.2 体力运作

时间刻度是**被动消耗资源**，而非主动消耗。玩家：
- 无法"存档时间"来用
- 无法"加班熬夜"加速
- 只能"安排活动"在不同刻度中进行

## 三、账单系统（压力核心）

### 3.1 核心机制（对应 UI：运营商B 账单展示）

| 属性 | 定义 | UI 体现 |
|------|------|---------|
| **周期** | 7天一个完整账单周期 | 营业厅顶栏"订阅截至：2026-09-15"风格 |
| **到期** | 每7天一个账单一次性到期 | 账单倒计时条显示剩余天数 |
| **延期** | 到期后3天内可主动延期提醒 | UI显示"延期提醒"选项 |
| **超时** | 超过7天+1天（即8天）上门执行失败，游戏结束 | UI警示红色闪烁"账单超时" |
| **换套餐** | 换套餐立即生效（本月即时生效） | 套餐卡片"立即换牌"按钮 |
| **最后一天换套餐风险** | 当日即使用，需支付整个账单 | UI提示"最后一天换套餐需支付全额" |

### 3.2 账单节奏图（对应 UI 营业厅）

```
D1  D2  D3  D4  D5  D6  D7  D8
[------账单周期------]  超时失败
↑                       ↑
到期                   强制上门
```

- **D1-D7**：玩家可自由操作+套餐使用窗口
- **D8**：超时上门，游戏失败

### 3.3 账单的设计哲学（对应 UI：运营商B"莫名其妙的高额支出"）

账单是**唯一的硬性死线**，其7天周期决定：
- 游戏的整体紧迫感
- 主线任务的节奏设计
- 玩家资源规划的核心目标

## 四、玩家活动系统（消耗链）

### 4.1 主线任务

| 特征 | 说明 |
|------|------|
| **消耗** | 不定时消耗时间刻度 |
| **触发** | 由事件/剧情节点推动 |
| **时长** | 单个任务1-3天不等 |
| **压力** | 随账单节奏推进，形成层层推进的紧迫感 |

### 4.2 入梦消耗（对应 UI 概念）

| 特征 | 说明 |
|------|------|
| **最小消耗** | ≥1天时间刻度 |
| **设计意图** | 足够制造压力，使玩家必须权衡收益与代价 |

### 4.3 时间消耗性行动

所有需要"消耗时间"的玩家行动，以天为单位计耗，计入玩家当日可支配的时间资源。

## 五、资源性活动（补给链）

### 5.1 商店刷新（对应 UI：营业厅商店刷新）

| 特征 | 说明 |
|------|------|
| **周期** | 1~2天一个循环 |
| **频率** | 较为频繁，保证玩家有"期待感" |
| **类型** | 补充类资源，非必须经济来源 |
| **UI体现** | 商品池周期性刷新，玩家有期待感 |

### 5.2 黑客任务（对应 UI 黑客模块）

| 特征 | 说明 |
|------|------|
| **周期** | 7天一个周期 |
| **刷新机制** | 消耗完当日提前刷新 |
| **设计呼应** | 与账单周期形成呼应，周期性但非硬性约束 |
| **UI体现** | 黑客任务7天一刷新，玩家需在账单前完成 |

## 六、套餐机制（软约束调节器）

### 6.1 核心定义（对应 UI：营业厅套餐卡片）

套餐是**低心智负担的全局辅助系统**：

- **本质**：即时生效的提升效果
- **心智负担**：玩家无需理性计算，感知"整体提升"即可
- **生效**：换套餐当日即刻激活
- **权益可见**：在界面清晰展示提升效果

### 6.2 换套餐风险计算（对应 UI：最后一天换牌的风险提示）

```
换套餐时间线分析：

D1-D6：  传统换牌窗口
  └─ 换套餐：当日生效，无额外代价

D7（账单最后一天）： 风险窗口
  └─ 换套餐：當日即使用，需支付整個賬單
  └─ 风险：玩家若在最后一天"仓促换牌"，将承担全额费用

D8（超时）： 
  └─ 游戏结束，无换牌可能
```

### 6.3 设计哲学（对应 UI：运营商B"被坑的感觉，但又想升级"）

套餐是**情感缓冲器**而非**经济缓冲器**：

- **低消耗**：不会破坏经济平衡（对应 UI 中"低心智负担"）
- **高频可用**：玩家遇到紧急情况可随时求助
- **隐形调节**：在不破坏核心节奏的前提下，提升玩家"被关心"的体验

### 6.4 与现有 UI 规范的对应关系

| 功能 | 设计文档定义 | UI 文档实现 |
|------|--------------|-------------|
| **当前套餐** | 低消耗即时生效 | SUBSCRIPTION.NET 中"当前套餐：专业版" |
| **账单记录** | 7天周期、超时警告 | 营业厅底栏"最近账单（5项）" |
| **换套餐风险** | 最后一天需支付全额 | 套餐升级弹窗"确认支付 $X,XXX？" |
| **订阅截至** | 7天倒计时 | 顶栏"订阅截至：2026-09-15" |

## 七、平衡设计总结

### 7.1 压力与补给的平衡

```
[压力源]
  └─ 账单7天：硬死线，核心节奏
  └─ 主线任务：不定时推进，持续压力

[补给源]
  └─ 商店1-2天：频繁期待感
  └─ 黑客7天：周期性补给

[软调节]
  └─ 套餐：低消耗即时生效，情感缓冲
```

### 7.2 设计意图

1. **玩家始终在"被时间推着走"的状态**
2. **账单7天是玩家经营的主要节奏标尺**（对应 UI 订阅截至倒计时）
3. **副本/商店作为补充来源，不抢占核心压力**
4. **套餐提供情感缓冲，防止绝望感**（对应 UI 中"低心智负担"的设计）

### 7.3 关键平衡点

- **时间紧迫感**：主线+账单形成核心节奏
- **资源期待**：商店/黑客保持一定期待感
- **情感安全**：套餐提供"被懂得"的安心感
