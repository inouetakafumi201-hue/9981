## 一、定位：本文档描述的东西不是三层之一

三层架构（引擎层 / 基类层 / 玩法层）描述的是**一局游戏在运行期如何被组合出来**。它是运行期依赖链。

本文档描述的是**玩法层数据是怎么被创作出来的**。创作发生在运行期之外。

判据只有一条：

> **把它删掉，一局游戏还能不能跑起来？**

| 东西 | 删掉还能跑吗 | 归属 |
|------|-------------|------|
| `MapData` / 实例 profile / 玩法包 | ❌ 跑不了 | **玩法层数据** |
| 校验器 | ❌ 跑不了（载入时审查） | 基类层能力 |
| 地图编辑器 UI、工作台 UI | ✅ 照常跑 | **创作工具，不属于三层** |
| 仓库浏览界面 | ✅ 照常跑（但玩家买不了东西） | 对局外界面 |

依赖方向是单向的：

```
创作工具 ──产出──> 玩法层数据 ──被读取──> 一局游戏
   ↑                                        ↑
   └────── 复用渲染层与设计令牌 ─────────────┘

玩法层永远不 import 创作工具。反向 import 是架构违规。
```

### 代码位置

| 内容 | 路径 | 理由 |
|------|------|------|
| 实例 profile（JSON） | `src/play/profiles/**` | 已存在。玩法层数据 |
| `MapData` schema + 校验 | `src/play/map/` | 玩法层数据，游戏运行必需 |
| 曲线纯函数（RDP、重采样） | `src/play/map/curve.ts` | 纯函数，被运行期动画消费 |
| 地图编辑器 UI | `src/editor/map/` | 工具。**不在三层内** |
| 工作台 UI | `src/editor/bench/` | 工具。**不在三层内** |
| 仓库浏览 UI | `src/shell/stock/` | 对局外界面 |

`src/editor/**` 必须遵守一条 ESLint 约束（与 `src/core` 禁止 import React/DOM 同理，方向相反）：

```
src/play/**  禁止 import  src/editor/**
```

这条规则是"删掉编辑器游戏照常跑"的机械保证，不靠人记得。

> **文档放在 `docs/L3_玩法层/` 下**，不新建目录——玩法层作为"包含玩法在内的前端"这个宽义读法可接受。但代码位置按上表，`src/editor/**` 与 `src/play/**` 分离。

## 三、四个部件的职责边界

| 部件 | 能做 | **明确不能做** |
|------|------|---------------|
| **仓库** | 存放拥有的实例；按类别/类型浏览；标记归档 | 修改实例；存放地图自带的临时免费实例 |
| **工作台** | 修改实例属性；填插槽；派生变体；就地新建；与 LLM 协同 | 放置到地图；修改基类层（那只能由 LLM 直接改代码/数据） |
| **地图编辑器** | 放置节点与实例；拉边画曲线；填放置参数；试玩 | **修改任何实例本体**；跨地图粘贴未拥有的实例 |
| **玩法包** | 提供实例与 MVP 所需基建（Op/Expr/Hook 数据树） | 携带可执行代码 |

### 地图编辑器为什么这么窄

它的右侧面板几乎是空的：放置参数只有坐标、朝向、挂哪条边、占哪个卡槽。所有"这个柜子里装什么"之类的设定都在实例本体上，由工作台设好。

想要三种不同装填的储物柜，就在工作台造三个实例，放置时选对应的那个。**选哪个实例本身就是分配设计。**

这是"清爽而非臃肿"的机械实现：编辑器没有检视器，所以它不可能长成第二个工作台。两者可快速切换，但逻辑上你始终在其中一个里。

### 工作台不做基类层图形化

这条是**永久性的**，不是 MVP 妥协。理由：基建的定义边界可以一路上升到与引擎层接壤，图形化它等于图形化引擎；而实例的数值与属性修改顶多就是最接近对局的那一层，边界清晰、可图形化。

普通玩家想动基类层，走 LLM。引擎已经为此预留了 `natural-language-adapter` 来源。

## 四、三种关系（最容易混淆，必须逐条区分）

同样是"A 和 B 有关联"，语义完全不同：

| 关系 | 语义 | 母本更新时 | 用在哪 |
|------|------|-----------|--------|
| **派生** | 复制作为起点 | **不跟随**（向下兼容） | 工作台造变体 |
| **插槽引用** | 包含 | 跟随（是同一个对象） | 工作台填插槽 |
| **放置** | 快照内联 | 不跟随 | 地图编辑器放东西 |

### 派生 = 快照，不跟随

派生时把母本内容**完整复制**一份，`derivedFrom` 只记录出处，不参与解析。

```typescript
{
  id: 'police_shotgun_7f3a',        // 玩家命名 + 随机 key
  derivedFrom: 'official_shotgun',   // 仅溯源，不解析
  description: '……',                 // 派生时复制自母本，之后独立
  damage: 4,                          // 我改的
}
```

三个后果：

- 母本修 bug **不会**传播到派生物。这是"向下兼容"的代价，接受。
- **不需要**版本通知机制，也不需要覆写集与级联解析。
- 高阶创作者「保留官方介绍」自然成立——派生时就复制了官方文案，什么都不用做。

### 母本一旦被派生过就不可删，只能归档

不是为了解析（派生物已经是快照，不依赖母本），而是为了**保住购买记录与派生权凭证**。删掉母本，你在该小类上的派生资格就失去了证明。

归档 = 从选择器隐去，引用仍可解析。产权系统里"真删"没有任何好处。

### 插槽引用 = 活引用

```
储物柜 #7f3a { contents: → 警用霰弹枪 #a3f2 }
                          ↑ 同一个对象，不是副本
```

改了「警用霰弹枪 #a3f2」，所有插槽引用它的实例一起变。这是词汇该有的行为——修一个词的定义，用到这个词的地方全部生效。

与派生不冲突：派生是"以它为起点造一个新的"，插槽引用是"我包含它"。

### 引用/快照的分界线就是地图边界

| 位置 | 语义 |
|------|------|
| 工作台插槽 | 引用（活的） |
| 地图放置 | 快照内联 |

地图必须自包含，所以过地图边界时一律内联。这条同时解决了"插槽引用了我不拥有的实例"——内联后视为临时免费。

## 五、三个正交标记位

三个布尔值，各管一件事，互不重叠。全部**在基类层声明**，实例继承。

### `placeable` —— 管界面出现在哪

| 值 | 含义 | 例子 |
|----|------|------|
| `true` | 能摆到节点上 | 储物柜、僵尸、载具、门 |
| `false` | 只能填进别人的插槽 | 中毒、散射属性、穿透伤害 |

两者**都进仓库**——都是词汇，都受经济门禁（状态类甚至是最值钱的创作词汇）。区别只在界面：

- 地图编辑器面板：只列 `placeable: true`
- 工作台插槽选择器：两者都列，按插槽 `accepts` 过滤

心智矛盾就此消解：玩家从不"摆一个中毒"，他给一把枪装上中毒。拥有它是拥有词汇，不是拥有物件。

**仓库界面必须为依附类设独立分区**，否则购买后第一反应是"我买的东西呢"。

### `playerFacing` —— 管要不要写介绍

| 值 | 含义 | 要求 |
|----|------|------|
| `true` | 玩家在对局中会看到它 | 必须有名字、介绍、图标 |
| `false` | 只影响内部计算 | 免除 |

玩家能看见的东西必须能被理解；看不见的不勒索创作者写文案。散射属性是 `false`，中毒是 `true`。

> **2026-08-08 权威变更**：本节"散射谱型"改称"散射属性"，与已废止的"攻击形状/形状轴"设计
> 无关——散射本身作为武器属性一直有效，只是命名从"谱型"改为"属性"以避免与被废止的形状分类
> 混淆。详见 `docs/L0_规范宪法.md`、`docs/L2_基类层/基类层定义.md` §4.3。

### `derivable` —— 管派生权边界

```
枪类        derivable: false   ← 买一把霰弹枪不该解锁狙击枪
霰弹枪      derivable: true    ← 派生锚点
```

买一个实例 = 获得它**最近的上层派生锚点**的派生权。

层级超过两级时"最近的上层小类"会歧义，所以锚点必须显式标记。现在加是零成本，将来加是破坏性变更（所有已售实例的权限范围会变）。

它同时是**经济分段器**：词汇量增长是分区的、可控的。

## 六、数据流

```
基类层声明（插槽、约束、三个标记位）
    │  LLM 可改，图形化永不可改
    ▼
实例（工作台产出，targetOwnership: 'play-layer'）
    │  派生 = 快照 / 插槽 = 活引用
    ▼
仓库（产权边界 + 质量闸门）
    │  只有过了校验器的才能进
    ▼
放置（地图编辑器，快照内联进 MapData）
    │
    ▼
对局
```

### 仓库入口是质量闸门，不只是产权闸门

进仓库前必须过 `src/core/ugc` 的校验管线：不死循环、不违反不变式、不软锁。过不了 → 进不了仓库 → 放不到地图上。

于是白拿一个别处没有的能力：**UGC 内容在发布前被属性测试轰过十万次。**

### 临时免费

地图自带的节点与实例可任意复制使用，但：

- ❌ 不能进仓库
- ❌ 不能在工作台修改
- ✅ 在本地图内视为免费
- **标记位随复制传染**（数据结构里带标记，不靠推导）

**剪贴板是地图作用域的。** 跨地图粘贴要求仓库产权，否则拒绝并说明原因——否则打开别人地图 Ctrl+C、回自己地图 Ctrl+V，产权系统当场绕过。

### 便利性系统，不是密码学系统

`MapData` 是内联的 JSON，任何人都能读出完整实例规格。手抄一遍能重建，改存档能白拿。

**这不防死，是明确立场**：破解只让你跳过自己的难度曲线，损失内化在自己身上，不外溢到别人的对局平衡。

唯一的例外线：若将来出现 UGC 排行或竞技，"谁的仓库更丰富"会变成实质优势，届时才需要服务端权威。**现在不做。**

## 七、经济

### 定价原则

> **仓库不是能力等级，是表达词汇量。**

价值锚在**创作门槛与负担**，不在强度。新手用 5 个词写出比老手用 200 个词更好的东西是允许的、也是好的——说明经济没有污染玩法。

安全属性：**买了用不好没有任何危害。** 花大钱买复杂实例、不理解就乱放，结果只是做出一张不好玩的地图，损失全部内化。这就是这套经济可以不做强度约束的原因。

### 三条内容通道

| 通道 | 成本 | 可编辑 | 可购买 | 谁能用它做地图 |
|------|------|--------|--------|---------------|
| **官方包** | 打包出售（同时装包模式） | ✅ | ✅ | 任何购买者 |
| **高阶创作者包** | 免费上传 | ❌ | ❌ | **只有作者自己** |
| **地图自带** | 免费 | ❌ | ❌ | 只在本地图内 |

高阶创作者包是**平行内容通道**（类 mod）：能遇见，不能拥有。

三个后果：

1. **不冲击官方包经济** —— 免费的高质量词汇不会挤掉付费词汇，因为它不进任何人的仓库。
2. **依赖问题消失** —— 包与作者的地图同生共死，不存在"作者删了包，我的地图打不开"。
3. **代价**：高阶作品是孤岛，图形化创作者无法复用，社区共享词汇池不因他们增长。这是保护经济的对价，接受。

### 黑箱的三个精确含义

| 对谁 | 黑箱？ |
|------|--------|
| 对人 | ✅ 界面不提供打开入口 |
| **对校验器** | ❌ **完全透明，必须过全量校验** |
| 对密码学 | ❌ 不是加密 |

第二条由引擎保证而非约定：`CandidateSourceKind` 的 `kind` **不改变 Schema、配额、severity 或任何验证规则**。免费上传的黑箱包和官方包走完全相同的校验管线。

**人看不见，机器全看见。** 质量控制与黑箱不冲突。

而这条只有因为基建是数据（Op/Expr/Hook 树，D-019 已定为纯声明式 JSON）才可能。若基建是 TS 代码，"免费上传 + 黑箱 + 在别人机器上跑"就是任意代码执行漏洞。

### 介绍继承与质量信号

派生时复制母本介绍（见第四节）。所以：

- 校验器**不强求**每个派生实例重写介绍
- 大部分高阶创作者保留官方介绍 → 官方词汇仍在被传播 → 玩家打不开机制但认得零件
- 深度创作者补全介绍 → 「介绍完备度」可作为排序加权项，**不做硬门槛**（会挤走轻量创作者）

免费上传本会招垃圾内容，但货币来自点赞与游玩，排序机制天然存在，**不需要准入审核**。

### 货币来源

竞技、他人点赞与游玩等，可多币种服务不同目的。**属于后期设计，本文档不定。**

一个方向性判断：若创作者收入来自自己地图被玩，则形成闭环——创作 → 被玩 → 得币 → 买更复杂的词汇 → 创作更复杂的东西。价值与收入锚在同一个东西上。

## 八、工作台交互契约

### "怎么把一个实例塞进设定中"

这是工作台的核心交互，逐步定：

```
1. 点击插槽
2. 弹出选择器：只列仓库里符合 accepts 的实例
     accepts: '物品类'  → 类型约束承担全部搜索压力
     predicate?: Expr   → 可选进一步过滤（"体积 ≤ 2"），复用已有 Expr 树
3a. 选一个 → 回填
3b. 点「新建…」 → 在当前上下文里嵌套一层 → 确认后回填、回到原处
```

第 3b 条避免的是最糟的默认行为：为填一个槽被踢出当前编辑、去别处造完、再回来找回原来在改什么。

**类型约束是搜索问题的解**：新手仓库里符合条件的可能只有 3 个，老手 200 个但过滤后仍是十几个。全局注册表搜索因此可以延后（见第十一节）。

### 嵌套呈现：左树右详情

```
储物柜 #7f3a                    │  capacity  [==●===] 2
├ contents: 警用霰弹枪 #a3f2     │  contents  [警用霰弹枪 #a3f2] ⊙
│  └ onHit: 中毒 #b81c          │  locked    [✓]
└ locked: true                  │  lockDC    [====●=] 12
```

左树永远显示完整结构（你在哪、整体长什么样），右侧只编辑当前选中的一层。**任意深度都不迷路，因此不设深度上限。**

数值参数用推杆式滑块，范围由基类声明夹紧——超范围在控件层面即不可能，校验器只兜底。

### 环路在选择器层面消除

填槽时遍历引用图，会造成环的候选**直接不列出**。错误从"能犯但会被抓"变成"犯不了"。

### undo 按编辑上下文分层

嵌套里的 Ctrl+Z 只撤嵌套里的；退出嵌套后，整个嵌套编辑作为**一个**可撤销单元。否则一次深层编辑会污染上层 20 步历史。

## 九、地图编辑器交互契约

### 状态机

```
Select（默认，Esc 永远回得来）
  ├─ PlaceNode  （N，Esc 退出）
  ├─ DrawEdge   （E，Esc 退出）
  ├─ Sample     （I 或按住 Alt，松开即退）
  └─ Playtest   （P，Esc 退出，编辑状态保留）
```

只有三个创造性动作有模式。模式越多越容易迷路。

**默认态是 Select 而非造物**，因为主流用法是改已有地图（上面已有基础划分与拓扑），不是从白纸描图。

### Select 态裸输入

| 输入 | 空白 | 节点 | 边 | 道具 |
|------|------|------|-----|------|
| 左键单击 | 清空选择 | 选中 | 选中 | 选中 |
| 左键拖拽 | 框选 | 移动 | 拖控制点 | 移动 |
| 双击 | **不创建** | 聚焦 | 插入控制点 | — |
| 右键 | 画布菜单 | 元素菜单 | 元素菜单 | 元素菜单 |
| 悬停 | — | 白色描边 | 白色描边 | 白色描边 |

**双击空白不创建节点** —— 误创建是编辑器第一号烦人事。造节点按 N 或走右键菜单。

左键拖空白给框选而非平移，因为平移有空格与中键两条路，框选没有替代。

### 全局输入

| 输入 | 动作 |
|------|------|
| 空格+拖 / 中键拖 | 平移（走 SVG viewBox，不走浏览器滚动） |
| 滚轮 | 以光标为中心缩放 |
| Ctrl+Z / Ctrl+Shift+Z | 撤销 / 重做 |
| Delete | 删除选中 |
| Esc | 退出模式；已在 Select 则清空选择 |
| Ctrl+S | 保存 |
| Tab | 开合面板 |
| N / E / I / P | 节点 / 边 / 取样 / 试玩 |
| 1/2/3 | 楼层切换 |

平移缩放走 `viewBox` 而非浏览器滚动，与 `killWebFeel` 禁用滚动缩放的策略天然一致，不打架。

### 拉边流程

```
1. 按 E
2. 悬停节点 → 蓝色（合法起点）
3. 节点上按下 → 开始描线
4. 自由拖动 → 实时预览折线，原始点全收
5. 进入其他节点吸附半径 → 那个节点亮蓝
6. 在节点上松手 → 端点精确吸附节点中心 → RDP 简化 → 建边
7. 在别处松手 → 整条丢弃 + 红色一闪
8. 保持 E 模式可连画，Esc 退出
```

第 7 条是设计过的行为。未设计的默认要么建出悬空边（脏数据），要么静默失败（用户以为手抖）。

**只有松手点吸附，中间点永不吸附** —— 否则曲线绕过某节点旁边时会被它抢走。

端点吸附不是可选项，是正确性要求：浮点近似会让校验器判出"边端点不存在"。

### 曲线二次编辑

选中边 → 控制点显示为小方块 → 拖动调整 → 双击曲线插入控制点 → 选中控制点 Delete 删除。首尾两点不可删。

RDP 的 epsilon **不暴露给创作者**，固定值即可，不满意用控制点手调。

`path: readonly Vec2[]` 直接喂进已有的 `jumpMotion(path)` 运动核，引擎侧零改动。

### 取样

`Alt+点击` / `I`：指着地图上已存在的东西说"再来一个这样的"。

```
Alt+点击 已配置好的储物柜 → 样本槽 = 该实例引用 → 点其他节点即套用
```

零注册表、零打标、零搜索。对"已有基础划分与拓扑的地图"是最优匹配。

**不存在信息泄漏**：对局中只能购买，参数要退出到仓库才看得见。取样在编辑器上下文中进行，不涉及对局内信息可见性。

### 校验反馈

底栏显示问题计数（错误/警告分色）。点问题 → 摄像机飞到元素 → 元素红色脉冲。

**错误不阻止保存，只阻止发布。** 阻止保存会弄丢半成品工作。

### 视觉语言零新增

编辑器状态直接映射霓虹边交互语法（L2/08 视觉法则二），不发明新颜色：

| 编辑器状态 | 颜色 | 复用的原语义 |
|-----------|------|-------------|
| 悬停可选 | 白 | 可移动/可交互 |
| 已选中 | 黄 | 精确 |
| 校验错误 | 红 | 敌对/危险 |
| 拖拽合法落点 | 蓝 | 可执行 |

`tokens.ts` 不增长；创作者在编辑器学到的颜色含义进游戏直接通用。

### 必要 vs 延后

| 必要（改图闭环） | 延后 | 理由 |
|-----------------|------|------|
| 载入既有地图 | 全局注册表搜索 | 需打标基建；类型约束已够用 |
| 选中 / 放置 / 移动 / 增删节点 | 多选批量改 | 好用，非必要 |
| 拉边 + 曲线 + 端点吸附 | 跨地图复制粘贴 | 需 ID 重映射 + 产权检查 |
| 挂实例（取样或仓库面板） | 区块多边形 + spriteScale | 视觉润色 |
| 撤销/重做 | 网格吸附 | post-MVP 拓扑 |
| 校验显示 | 对齐辅助线 | 纯效率 |
| 存档/读档、平移缩放、楼层切换、试玩 | 图层锁定 | 元素量不大 |

撤销/重做在必要列且不可延后——它是让所有破坏性交互变安全的前提，没它每个删除都得弹确认框。

### 新手的第一张地图就是教程

空仓库新手编辑内置地图，满地临时免费实例：可复制、可摆放、可试玩，改不了。**玩到喜欢的，去买。**

从"用别人的东西"到"拥有自己的东西"是同一条曲线的自然延续，不需要额外引导关。

推论：**内置地图应故意做得实例丰富** —— 它们是货架。

## 十、基类完备性测试

### 原则

> 在工作台想给实例设一个属性，却在基类里找不到插槽 —— 那是**基类设计缺陷**，不是需要新架构层的信号。

容器的初始物品和基类的其他设定没有任何区别，同样是引用其他类。找不到槽说明这个基类没有被好好思考过。

### 语料格式

创作者撞到"想设但没槽" → 报一条 → 变成一条失败测试 → 补基类。

```typescript
// 基类设计完备性测试。语料只增不减。
test('容器类能表达「初始装着某物」', () => {
  expectSlot('container.*', 'contents', { accepts: '物品类' });
});
test('网关类能表达「需要某物才能通过」', () => {
  expectSlot('gateway.*', 'requires', { accepts: '物品类' });
});
test('武器类能表达「命中时施加某状态」', () => {
  expectSlot('weapon.*', 'onHit', { accepts: '状态类' });
});
```

**基类层的完备性因此变成可度量的东西**，不靠谁记得。这条语料库是宪法 3.3「遇到未在清单中的新概念」流程的可执行版本。

## 十一、明确不做

| 不做 | 理由 |
|------|------|
| 基类层图形化 | 永久。定义边界可上升至与引擎层接壤 |
| 基建的图形化编辑 | 同上。只给 LLM |
| 基建树的只读树状视图 | 纯粹性。是基类层图形化的开头 |
| 母本更新级联到派生物 | 向下兼容，不跟 |
| 版本通知机制 | 派生是快照，无需通知 |
| 覆写集 / 字段级继承 | 同上，派生即完整复制 |
| 实例插槽嵌套深度上限 | 左树右详情下无结构必要 |
| 全局注册表搜索 | 延后。类型约束 + 取样已覆盖 |
| 打标基建 | 延后。商城由卖家自己打标 |
| 服务端 ID 鉴权 | 玩家命名 + 随机 key 已足够 |
| 分配规则族独立层 | 已塌回实例插槽 |
| 地图售卖 | 建议免费分享 + 按被玩次数得币 |

## 附：ID 规范

```
玩家命名 + 随机 key        police_shotgun_7f3a
```

- **key 是身份，命名是显示。** 改名不改 key，因此改名不破坏任何引用。
- 显示名允许重复，ID 必须唯一。
- 不需要服务端鉴权。

与引擎 `isStableIdentity`（非空、无前后空白）兼容。
