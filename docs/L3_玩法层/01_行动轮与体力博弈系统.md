## 一、设计背景

### 1.1 问题的提出

原版游戏的策略深度较浅，玩家决策主要考验"对规则的理解"（读盘），而非"把理解转化为让人惊叹的具体执行"。具体表现为：

- 投点定序是一次性结果，无持续经营价值
- 体力仅用于强力骰，无风险-收益悖论
- 单步决策为主，缺乏"强制连锁"结构

### 1.2 解决方案概述

| 问题 | 解决方案 |
|------|----------|
| 行动轮无意义 | 行动轮资源化，可通过逆转/处决争夺 |
| 体力无风险 | 体力过载机制，高体力=高能力+高风险 |
| 战斗扁平 | 弱点系统，增加属性克制策略 |
| 防守无代价 | 招架增加对方体力，防守也有代价 |

## 二、行动轮系统

### 2.1 行动轮的本质

**行动轮是回合内所有玩家的执行顺序排名。**

| 属性 | 定义 |
|------|------|
| **规则** | 无并列，排名交换制 |
| **更新时机** | 立即生效（详见2.3节） |
| **已行动者可见性** | 已行动者保留在排名中，标记为已行动（具体表现见 `../表现系统/01_图形化与UI.md`） |
| **依赖基类** | 无（纯规则层） |

> **注意**：行动轮是玩法层定义的概念，基类层不感知"行动轮"。行动轮由玩法层规则在引擎层原语之上构建。

### 2.2 排名获取

```
回合开始 → 投点阶段 → AP结算 → 行动轮排名确定

排名规则：
1. AP多者排名靠前
2. AP相同时，投骰点数（修正后）高者排名靠前
3. 仍相同 → 完全随机
```

#### 按人数裁剪档位（D-037）

投点 AP 分配**严格按既有算法执行**，不因参与人数少而改用特例。裁剪规则：

| 场上人数 | 可用档位 | 说明 |
|----------|----------|------|
| **3 人及以上** | 0~3 AP 全档位 | 按算法完整计算 |
| **仅 2 人** | **取消 3 AP 档** | 其余逻辑不变 |
| **仅 1 人（单人投掷）** | 同样取消 3 AP 档 | → 该玩家**获得 2 AP** |

> **设计理由**：3 AP 是"唯一领先且优势 ≥2"的奖励档，其博弈前提是存在被拉开的对手。人数不足时该档失去意义，但没有必要为此改写整套算法——只需屏蔽该档，其余逻辑不变，单人情形自然落到 2 AP。这保证了规则的一致性，不引入"人数特例"这类额外心智负担。
>
> **实现要求**：AP 结算需读取当前存活参与人数作为档位上限参数。

### 2.3 行动轮的争夺与变化

#### 逆转（常规逆转）

```
时机：上一回合行动开始后，下一回合投点开始前（窗口期）
成本：1 AP（注意：消耗AP，非SP）
效果：自身行动轮排名提升1位
```

**与强力骰互斥**：同一回合内，不可同时使用逆转和强力骰。

> **术语修正**：原文档使用"SP"，现统一为"AP"。体力系统使用"SP"表示体力值。

#### 超逆转

```
成本：2 SP（体力值）
效果：行动轮排名提升2位
备注：实际上是"消耗2体力换+2排名"，而非"强力骰+逆转叠加"
```

> **数值验证**：2 ≤ 5（体力上限），符合五并列原则。

#### 处决后行动轮提升

```
触发：[1 AP] 令其长眠成功后
效果：行动轮排名提升1位
时机：立即生效（详见2.4节）
```

> **注意**：此处"令其长眠"为具体玩法技能实例，基类层不定义此技能。

### 2.4 立即生效机制

**核心规则**：每次行动轮变化后，立即重新排序，执行队列永远指向排名最高（最前）的未行动者。

> **实现要求（D-035）**：已行动者（AP 耗尽者）**不从列表中移除**，只标记为已行动。因此实现应为"**遍历列表找第一个未行动者**"，而不是"从队列中弹出"。
>
> 已行动者的视觉呈现语义是"他这回合已经行动过了"，具体表现方式见 `../表现系统/01_图形化与UI.md`（D-036 轮次栏规范）。行动排名本身是持续存在的公开信息——谁快谁慢很重要——把已行动者移除会导致列表长度在回合内不断变化，反而增加认知负担。

```
执行流程：
1. 初始化行动轮队列（按排名排列所有玩家）
2. 从队首开始执行
3. 该玩家完成行动后：
   a. 检查是否有行动轮变化（处决、逆转等）
   b. 若有，重新排序
   c. 返回队首，继续执行
4. 队列为空则回合结束
```

**示例**：

```
初始状态：
1. 玩家A
2. 玩家B
3. 玩家C

执行序列：
1. A行动（消耗1 AP）
2. A处决了D → 行动轮+1 → B被顶到后面
   新队列：B、玩家C、A
3. 重新从B开始执行
4. ...
```

### 2.5 行动轮排名变化表

| 触发条件 | 变化幅度 | 生效时机 |
|----------|----------|----------|
| 逆转 | +1位 | 立即 |
| 超逆转 | +2位 | 立即 |
| 处决成功 | +1位 | 立即 |
| 弱点命中（对方） | -1位 | 立即 |
| 招架成功（对方） | -1位 | 立即 |

## 三、体力系统（扩展）

### 3.1 体力值(SP)定义

体力是玩家的第二核心资源，同时具备双重性质：

| 性质 | 说明 |
|------|------|
| **能力资源** | 体力越高，强力骰底气越足 |
| **风险标记** | 体力越高，接近过载线的风险越大 |
| **数值范围** | 0-5（体力上限，D-007确认） |
| **恢复速率** | 每回合自然恢复1点（上限5） |

> **术语说明**：SP（Stamina Point）表示体力值，与AP（Action Point）是两种独立资源。

### 3.2 体力消耗途径

| 消耗方式 | 体力消耗 | 备注 |
|----------|----------|------|
| 强力骰（+1） | 1 SP | — |
| 强力骰（+2） | 2 SP | — |
| 超逆转 | 2 SP | 详见2.3节 |
| 常规恢复 | +1 SP | 每回合自然恢复 |
| 超量恢复 | +N SP | 睡眠、处决恢复满 |

> **数值验证**：
> - 强力骰+1：1 ≤ 5 ✓
> - 强力骰+2：2 ≤ 5 ✓
> - 超逆转：2 ≤ 5 ✓

### 3.3 体力博弈核心：让他人变强=让他人变危险

**体力增加的来源不只有"对自己有利"一种。**

| 触发条件 | 体力变化目标 | 博弈意义 |
|----------|--------------|----------|
| 招架成功 | 对方 +1 | 防守有代价——你在"养蛊" |
| 弱点命中 | 对方 +1 | 进攻有代价——对手强力骰底气更足 |

**这是一个精妙的博弈闭环**：
- 你削弱了对手的行动轮（排名下降）
- 你脱掉了对手的装备
- 但你也让对手的体力增加了
- 对手必须决定：要不要赌强力骰？还是继续蓄力等过载？

### 3.4 过载机制

```
触发条件：体力严格大于5（即尝试增加体力但已达上限）
效果：
  1. 体力保持在5（不会涨到6）
  2. 失去本回合行动权（如果还未行动）
  3. 下下回合重新加入投点
  4. 触发过载状态（视觉反馈见 `../表现系统/01_图形化与UI.md`）
```

**设计意图**：
- 高体力=高能力（强力骰底气）但高风险（容易过载）
- 即使过载，体力仍然高——残血反杀是可能的
- 对手可以"反制"：用体力压制换强力骰优势，拉开差距2以上废掉你本回合AP

### 3.5 体力流博弈示例

```
第1回合：
- 你弱点攻击对手 → 对手体力0→1，行动轮下降1位
- 对手强力骰+2 → 底气十足

第2回合：
- 对手攻击你，你招架 → 你体力+1（接近过载线）
- 对手强力骰+2 → 拉开差距，废掉你这回合AP

第3回合：
- 你行动轮很低，只能被动挨打
- 你必须决定：要不要逆转抢回行动权？
- 但逆转消耗2AP，你的行动成本更高
```

## 四、弱点系统

### 4.1 设计背景

弱点系统的目标：
- 增加战斗的"属性克制"策略深度
- 让战斗不只是比数值，而是有意识地针对对手的弱点
- 提供"高光时刻"——用弱点武器打出致命一击

### 4.2 伤害类型清单

| ID | 名称 | 示例 |
|----|------|------|
| DMG_01 | 锐器 | 刀具、电锯 |
| DMG_02 | 钝器 | 棍棒冲击、拳头（空手不进行弱点攻击） |
| DMG_03 | 穿刺 | 枪械、迅捷剑、钻头 |
| DMG_04 | 烈焰 | 打火机、喷火器、电焊枪 |
| DMG_05 | 冰冻 | 液氮、二氧化碳灭火器 |
| DMG_06 | 电流 | 电击枪、直流电 |
| DMG_07 | 毒素 | 毒药、毒圈 |
| DMG_08 | 凋零 | 窒息、过敏、核辐射、饥饿、腐坏 |
| DMG_09 | 侵蚀 | 强酸强碱 |
| DMG_10 | 精神 | 震爆弹、感官干扰 |

### 4.3 弱点类型清单

| ID | 名称 | 对应伤害类型 |
|----|------|--------------|
| WKN_01 | 精密 | 锐器 |
| WKN_02 | 缝隙 | 钝器 |
| WKN_03 | 密闭 | 穿刺 |
| WKN_04 | 易燃 | 烈焰 |
| WKN_05 | 冷脆 | 冰冻 |
| WKN_06 | 感电 | 电流 |
| WKN_07 | 活性 | 毒素 |
| WKN_08 | 活体 | 凋零 |
| WKN_09 | 易蚀 | 侵蚀 |
| WKN_10 | 感官 | 精神 |

### 4.4 弱点判定规则

#### 4.4.1 判定时机

弱点判定与伤害判定**独立进行**。

```
步骤1：伤害判定
  - 命中检定（距离DC等）
  - 命中 → 造成基础伤害（可为0）
  
步骤2：弱点判定（独立于伤害）
  - 攻击方伤害类型 vs 防守方暴露弱点
  - 有克制关系 → 触发弱点效果
  - 无克制关系 → 无弱点效果
```

#### 4.4.2 弱点效果

| 效果类型 | 说明 |
|----------|------|
| **装备脱落** | 手部/身上的物品或武器掉落（背包内不算） |
| **体力变化** | 对方体力 +1 |
| **行动轮下降** | 对方行动轮排名 -1 |
| **伤害数值** | **不受影响——弱点不会使伤害翻倍** |

**弱点效果不可被招架或其他方式弹反，独立直接生效。**

> **关键边界（D-049）**：**弱点不使伤害翻倍。** 伤害翻倍只来自"**骰点超出 DC 2 点及以上**"，与弱点系统无关。弱点系统的产出是上表三项**非伤害效果**——用用户的话说，弱点"只是会使得这个东西落地而已"。
>
> **为什么这条重要**：如果弱点也参与伤害计算，两套独立机制就会在数值上叠乘（超出 DC 翻倍 × 弱点翻倍 = 4 倍伤害），破坏平衡。两者必须严格分离：
>
> | 机制 | 触发条件 | 产出 |
> |------|----------|------|
> | **伤害翻倍** | 骰点超出 DC 2 点及以上（每 2 点翻一次） | 伤害数值 ×2 |
> | **弱点效果** | 伤害类型克制暴露弱点 | 装备脱落 / 体力+1 / 行动轮-1 |

#### 4.4.3 弱点暴露规则

**暴露条件**：弱点物品在**手部或身上**时，该弱点暴露。

```
暴露的弱点 = 玩家自身的弱点（不是物品的弱点）
- 左手武器的弱点
- 右手武器的弱点
- 身上防具的弱点
- 身上其他装备的弱点
```

**背包内物品的弱点不暴露**。

#### 4.4.4 弱点物品示例

| 物品类型 | 可能弱点 | 说明 |
|----------|----------|------|
| 金属武器 | 精密（WKN_01）、感电（WKN_06） | 导电、可被精密器械攻击 |
| 塑料制品 | 易燃（WKN_04）、冷脆（WKN_05） | 可燃、低温易碎 |
| 橡胶制品 | 易蚀（WKN_09） | 可被强酸碱腐蚀 |
| 衣物/防具 | 易燃（WKN_04）、易蚀（WKN_09） | 燃烧、腐蚀 |
| 玻璃制品 | 冷脆（WKN_05） | 低温易碎 |
| 电池设备 | 感电（WKN_06） | 导电 |

> **弱点定义**：弱点是基类层定义的属性（见基类层定义.md 4.4节），玩法层实例通过组合基类并设置参数来定义具体物品的弱点。

#### 4.4.5 零伤害弱点效果

部分武器/物品的伤害为0，但**弱点效果仍然生效**。

| 示例 | 伤害 | 弱点效果 |
|------|------|----------|
| 打火机 | 0 | 可能触发"易燃"弱点 |
| 催眠瓦斯 | 0 | 降对方行动轮 |
| 催泪瓦斯 | 0 | 降对方行动轮 |

### 4.5 弱点系统与防御的交互

```
攻击流程（含弱点）：
1. 攻击判定（命中/未命中）
2. 伤害结算（可被格挡/招架挡住伤害数值）
3. 弱点判定（独立于伤害，不可被任何方式阻挡）
   - 弱点效果：装备脱落、体力+1、行动轮-1
```

**关键规则**：
- 招架/盾牌只能挡**伤害数值**，**无法阻挡弱点效果**
- 弱点效果一旦触发，直接生效，不存在弹反
- 弱点攻击的伤害数值可被盾牌/招架挡住，但[失衡]状态会破除举盾（详见5.4节）

## 五、招架系统

### 5.1 招架动作

```
[1 AP] 招架

前置条件：
- 必须在最后一个AP使用（可选限制）
- 手持非重型武器或空手

效果：
- 挡住本回合内下一次近距离伤害
- 对方获得 [失衡] 状态
- 对方体力 +1
```

### 5.2 招架与格挡的区别

| 属性 | 招架 | 格挡（盾牌） |
|------|------|--------------|
| 成本 | 1 AP | 1 AP |
| 可用装备 | 非重型武器或空手 | 盾牌 |
| 防御范围 | 近距离伤害 | 近距离伤害 |
| 弱点效果 | **不可挡** | **不可挡** |
| 体力影响 | 对方+1 | 无 |
| 特殊属性 | 无 | 盾牌无弱点、数值超标 |

### 5.3 盾牌的优势

盾牌是几乎最强力的防具，因为：

1. **无弱点**：盾牌自身没有弱点，不会被弱点攻击脱落
2. **数值超标**：防御数值高于普通防具
3. **举盾状态持续**：举盾后状态保持到受伤后的回合结束（不是立即放下）

**但盾牌无法挡弱点效果**——弱点攻击产生的[失衡]状态会破除举盾（详见5.4节）。

### 5.4 弱点攻击与举盾

**弱点攻击不能直接破除举盾状态。**

```
弱点攻击 vs 举盾：
1. 攻击方使用弱点武器
2. 盾牌挡住伤害数值（举盾有效）
3. 弱点效果触发 → 对方获得 [失衡] 状态
4. [失衡] 状态破除举盾/防御/招架等准备动作状态
```

**这是盾牌被破解的唯一路径**——弱点攻击 → [失衡] → 破除举盾。

### 5.5 招架的博弈价值

招架的核心价值在于**双刃剑效应**：

| 你的收益 | 你的代价 |
|----------|----------|
| 挡住本次伤害 | 消耗1 AP（可能在最后一个AP） |
| 对方获得失衡 | 对方体力+1（对手强力骰底气更足） |
| 限制对方准备动作 | 自身无直接代价 |

**这是一个权衡**：
- 招架可以救命
- 但对手体力增加 = 对手下回合强力骰更有底气
- 对手可能直接拉开差距废掉你这回合AP

## 六、失衡状态

### 6.1 触发条件

| 触发方式 | 来源 |
|----------|------|
| 被招架 | 攻击被对方招架 |
| 被弱点命中 | 弱点效果之一 |
| 其他待定义 | — |

**[失衡]状态会破除以下状态**：
- 举盾状态
- 防御状态
- 招架状态

### 6.2 效果

**失衡状态下，以下"准备动作"全部失效**：

| 动作类型 | 失衡时是否可用 |
|----------|----------------|
| 招架 | ❌ 失效 |
| 举盾/格挡 | ❌ 失效 |
| 瞄准/蓄力 | ❌ 失效 |
| 其他待定义 | 待定 |

> **规则说明**：[失衡]状态是玩法层定义的规则状态，基类层不感知此状态。

### 6.3 持续时间

**失衡持续到当前回合结束**。

```
效果结算时（如持续伤害等触发），失衡状态解除。
```

### 6.4 弱点攻击与招架

**弱点攻击无法被招架，不存在弹反机制。**

```
弱点判定（独立于伤害） → 直接生效
  ├─ 装备脱落
  ├─ 体力+1
  ├─ 行动轮-1
  └─ 获得[失衡]状态 → 破除举盾/防御/招架等准备动作状态
```

**盾牌不能被弱点直接破除，但弱点产生的[失衡]状态会破除举盾。**

## 七、隐藏动作系统

### 7.1 设计背景

回合制下，动作执行的顺序是明确的。为了增加博弈深度，部分动作对对手**不可见**，直到动作发生。

**设计原则**：
- 隐藏动作增加"预判"博弈
- 隐藏动作不是"作弊"，而是一种合理的策略
- 隐藏动作必须在视觉上有所表现（让玩家知道"发生了某事"）

### 7.2 已确认的隐藏动作

| 动作 | 可见性 | 规则语义 |
|------|--------|----------|
| 招架 | **对他人完全不可见** | 仅被近战攻击时触发结算（D-032，表现方式见 `../表现系统/02_动画音效与反馈.md`） |
| 隐藏动作B | 待扩展 | — |
| 隐藏动作C | 待扩展 | — |

#### 招架的三种结算情况（D-032）

招架状态是**完全隐藏信息**——对手在 UI 上看不到任何"待机"标识。其结算分三种：

| 情况 | 结果 | 规则效果 |
|------|------|----------|
| **被近战攻击** | 招架**生效** | 触发招架效果（表现方式见 `../表现系统/02_动画音效与反馈.md`） |
| **被远距离伤害命中** | 招架**失效** | 静默失效，无特殊效果 |
| **受到无法招架的伤害** | 招架**失效** | 静默失效，无特殊效果 |

> **设计理由**：如果对手能看到"待机"标识，招架就退化成公开的威慑，预判博弈消失。静默打断则保证招架不会因为一次远程流弹，就给对手提供免费的信息反馈。

### 7.3 隐藏动作的设计指导

**适合作为隐藏动作的特性**：
1. **反击/防守类**：等待对方先动
2. **设置类**：提前布置陷阱/阵地
3. **观察类**：不改变状态，但获取信息

**不适合作为隐藏动作**：
1. **主动进攻**：过于依赖"先手优势"
2. **移动**：移动方向是重要的公开信息
3. **交互**：交互结果需要明确可见

### 7.4 隐藏动作的可见性规则（D-032 修订）

**隐藏动作对自己可见，对他人完全不可见。**

| 视角 | 可见性 |
|------|--------|
| **执行者自己** | 可见（自己知道自己在招架） |
| **其他所有人** | **完全不可见**，无任何"待机/准备"标识 |

结算时才生效（且仅在被近战攻击这一种情况下触发招架效果）。具体视觉反馈见 `../表现系统/02_动画音效与反馈.md`。

**参考概念**：《热血无赖》中的反击系统
- 敌人保持常态（不给预警标识）
- 主角攻击时，敌人触发擒拿反击
- 玩家在攻击前完全不知道敌人是否会反击

> **修订说明（D-032）**：本节原写"玩家看到对手在待机/准备，但不知道具体是什么"，这与真隐藏定位冲突——任何"准备中"标识都会让招架退化为公开威慑。现更正为对他人零标识。

## 八、信息分层系统

### 8.1 设计背景

完全信息对称可能导致"读盘"式博弈，缺乏信息获取的策略性。部分信息需要**主动获取**。

### 8.2 信息可见性分类

| 类别 | 可见性 | 获取方式 |
|------|--------|----------|
| 位置信息 | 完全可见 | 直接查看 |
| 行动轮排名 | 完全可见 | 行动轮排名列表（D-036，呈现方式见 `../表现系统/01_图形化与UI.md`） |
| 手部物品 | 可见 | 直接查看 |
| 身上装备 | 可见 | 直接查看 |
| 背包内容 | 模糊可见 | 需要展开 |
| 弱点属性 | **完全可见** | 常驻显示（D-031，呈现方式见 `../表现系统/01_图形化与UI.md`） |
| 瞄准中状态 | **可见但低显著性** | 悬停显示（D-033 可见性 + D-066 颜色，呈现方式见 `../表现系统/01_图形化与UI.md`） |
| 招架状态 | **完全不可见** | 真隐藏（D-032） |
| 目标意图 | 不可见 | — |

### 8.3 背包信息处理

**手部/身上**：完全可见
**背包内**：玩家只能看到物品槽的数量变化（格子变暗/变亮），具体物品需要展开查看。

具体视觉呈现见 `../表现系统/01_图形化与UI.md`。

### 8.4 弱点信息的可见性（D-031）

**弱点信息对所有人完全公开。** 不需要消耗 AP 侦察，也不需要把"悬停查询"作为唯一获取途径。

| 层级 | 规则语义 |
|------|----------|
| **玩家暴露的弱点** | 常驻公开，所有人直接可见（呈现方式见 `../表现系统/01_图形化与UI.md`） |
| **弱点的详细克制关系** | 悬停时显示补充说明 |

> **设计理由**：弱点系统的价值在于"有意识地针对"。把弱点做成需要额外获取成本的隐藏信息，会让针对性攻击退化为运气；同时也违背低心智性——玩家不该为了查一个静态属性反复操作 UI。

### 8.5 三种可见性档位的对照（D-031 / D-032 / D-033）

本作的信息设计使用三个明确档位，避免"半可见"这类模糊表述：

| 档位 | 定义 | 实例 | 规则语义 |
|------|------|------|----------|
| **完全公开** | 无需操作即可获知 | 弱点属性、行动轮、血量体力 | 常驻显示，所有人可见 |
| **低显著性公开** | 可获知但需主动看一眼 | `[瞄准中]` 状态 | 悬停时可见（D-033），无强提示 |
| **真隐藏** | 对他人完全不可见 | 招架 | 无任何标识，直到结算 |

具体视觉呈现见 `../表现系统/01_图形化与UI.md`。

> **为什么瞄准是低显著性而非真隐藏**：两步流程的远程武器必须让对手有机会反应（见 D-014），否则"反应窗口"名存实亡。但用强提示（感叹号）会让规避变成无脑操作，改为"需要主动看一眼"保留了观察成本，同时不构成信息壁垒。

## 九、回合结构（更新版）

### 9.1 完整回合流程

```
┌─────────────────────────────────────────────────────────┐
│ 1. 投点阶段                                              │
│    - 所有玩家同时投d6                                    │
│    - 承诺强力骰/逆转（窗口期）                           │
│    - 结算AP，确定行动轮排名                              │
└─────────────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────────────┐
│ 2. 行动执行阶段                                          │
│    - 从行动轮排名最高者开始执行                           │
│    - 执行完一个玩家后：                                  │
│      a. 检查行动轮变化                                   │
│      b. 重新排序                                        │
│      c. 继续执行下一位                                  │
│    - 直到所有玩家行动完毕                                │
└─────────────────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────────────────┐
│ 3. 清理阶段                                              │
│    - 所有玩家恢复1点体力（上限5）                        │
│    - 状态效果倒计时-1                                   │
│    - 触发持续效果                                        │
│    - 缩圈判定（如适用）                                  │
└─────────────────────────────────────────────────────────┘
```

### 9.2 窗口期动作

**窗口期**：上一回合行动开始后，下一回合投点开始前

**窗口期可选动作**：
| 动作 | 成本 | 效果 |
|------|------|------|
| 逆转 | 1 AP | 行动轮排名+1 |
| 超逆转 | 2 SP | 行动轮排名+2 |

**与强力骰互斥**：窗口期选逆转/超逆转，则本回合不能选强力骰

> **数值验证**：
> - 逆转成本：1 ≤ 5 ✓
> - 超逆转成本：2 ≤ 5 ✓
> - 与强力骰互斥：确保资源不重复消耗

### 9.3 过载玩家的处理

```
触发过载时：
1. 体力保持在5
2. 失去本回合行动权（如果还未行动）    ← D-055 更正：原写"行动权保留"为离群陈述，与 §3.4、§11 及第 2 项下的"跳过本回合"矛盾，已按多数一致读法改为"失去"
3. 如果过载时还未行动：
   - 跳过本回合
   - 下下回合重新加入投点
4. 过载期间：
   - 仍参与其他玩家的回合
   - 可以观察局势
```

## 九补、NPC 的资源与轮次定位（D-052）

### 9b.1 NPC 不参与行动轮

NPC **没有轮次**。他们有 AP，但**全部在玩家轮次结束之后顺序行动**。AI 玩家视同玩家（参与行动轮）。

### 9b.2 NPC 资源配置

| 资源 | 默认值 | 可配置 |
|------|--------|--------|
| **AP** | **1 AP** | ✅ 可配置 |
| **SP 上限** | **3** | ✅ 可配置 |
| **开局 SP** | **0** | ✅ 可配置 |
| **是否主动使用体力** | — | ✅ 可配置 |

### 9b.3 为什么给 NPC 配体力

**NPC 的体力系统纯粹是为了让玩家能在 PVE 中打出弱点甚至过载而生。**

如果 NPC 没有体力，弱点攻击的"对方体力 +1"和过载压制就在 PVE 中完全失效——玩家既学不到这套机制，也无法在打僵尸时练习。

体力上限 3（低于玩家的 5）意味着 **NPC 更容易被压到过载**，这正是"去杀僵尸"的收益之一。

### 9b.4 硬性限制

**NPC 的体力不可能用来抢轮次**（不可用于逆转/超逆转）——因为 NPC 本身就没有轮次。

> **对下游影响**：弱点系统与过载机制在 PVE 场景下全部有效，需在 NPC 侧实现体力池与过载判定。NPC 过载时的表现（跳过其行动）需在 `05_NPC行为配置.md` 中定义。

## 十、未来扩展方向

### 10.1 异步决策（未来玩法包）

**概念**：玩家可以在他人回合内消耗资源执行某些动作，这些动作在轮到自己时生效。

```
示例：
- 消耗1 AP，在自己回合+1 AP（预支）
- 消耗体力，预设强力骰
- 消耗道具，获得额外信息
```

**注意**：此机制不在MVP范围内。

> **规划说明**：异步决策是玩法层的扩展机制，需等待基类层支持相关基类后实现。

### 10.2 有限视野玩法包

未来可引入"视野限制"机制：
- 玩家只能看到一定范围内的信息
- 需要主动侦查获取远程信息
- 与隐藏动作形成策略配合

#### 观战状态的定位（D-034）

在当前**全信息**规则下，观战状态与在局状态的**信息权限没有实质差别**，唯一区别是**观战可以自主移动视角**。

即使未来引入视野规范，观战也只是"**去掉视野可见范围这一限制**"，本质仍是全信息状态。

| 项目 | 结论 |
|------|------|
| **信息权限** | 与在局玩家一致 |
| **唯一差别** | 视角可自主移动 |
| **是否需要独立信息过滤层** | **不需要** |

具体观战界面实现见 `../表现系统/01_图形化与UI.md`。

> **对 MVP 的影响**：观战功能实现范围收窄为"**自由视角 + 复用在局 UI**"，不需要独立的观战数据通道或信息过滤层。为观战单独做信息裁剪属于无必要的实体增加。

### 10.3 更多隐藏动作

待游戏机制完善后，持续扩展隐藏动作清单。
