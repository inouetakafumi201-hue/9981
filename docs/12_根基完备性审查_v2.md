# 根基完备性审查（重做）

> **定位澄清（访谈决策 D-001，2026-08-03）**：本文档列出的 11 项内容不是内核实现缺口。内核（`src/core/kernel/`）提供的是通用数据型计算原语（查询引擎、事件分发器、光环/聚合引擎等），理论上已足以表达这些场景的绝大部分需求，且均有测试用例覆盖。但内核不实现任何具体玩法语义——不定义"物品拆分"这样的具体动作，不定义"阵营"这样的具体数值维度。本文档实际梳理的是**玩法包层必须用内核原语拼装实现的设计维度清单**，不是"内核要不要补功能"的问题。下文沿用的"根基缺失""需要实现""补全"等措辞，均指玩法包层的设计与实现工作，不代表对内核本身的缺口诊断。详见 `访谈决策记录.md` D-001。

> **目标**：找出当前根基的结构性缺失，而非功能清单。
> 
> **原则**：
> - 不问"需要什么功能"，而问"什么底层结构缺失导致 N 种机制无法实现"
> - 一个根基结构应该能承载 3+ 种表层机制
> - 优先整合，避免专用系统

---

## 审查方法论

### 什么是"根基缺失"？

**判断标准**：
1. 当前数据拓扑无法表达这种关系
2. 需要修改核心数据结构才能支持
3. 影响 3 个以上不相关的表层机制

**不是根基缺失**：
- 可以用现有结构组合实现
- 只是缺少具体数值/配置
- 仅影响单一机制

## 当前根基盘点

### 已有的底层结构

#### 1. 三大数据类型
```
节点 (Node)      - 空间拓扑
物品 (Item)      - 可携带对象
实体 (Entity)    - 具有位置的对象
```

#### 2. 关系与容纳
```
实体 → 位于 → 节点
物品 → 携带于 → 实体（背包/手）
实体 → 创建 → 微型场景
实体 → 所有者关系（owner）
```

#### 3. 状态与时序
```
状态效果 (StatusEffect)  - 持续时间、效果
回合流程                 - 投点、行动、清理
AP 消耗                  - 1 AP 铁律
```

#### 4. 查询与计算
```
距离范式    - 节点间距离
拓扑查询    - 路径查找
估值函数    - 局面评估（AI 用）
```

## 根基缺失清单

### 缺失 1：物品堆叠

**无法实现的机制**：
- 货币系统（金币 ×100）
- 弹药系统（子弹 ×30）
- 材料收集（木材 ×50）
- 消耗品堆叠（绷带 ×5）

**当前问题**：
```typescript
interface Item {
  id: string;     // 每个物品独立 ID
  type: string;
  slots: number;
}

// 10 个金币 = 10 个独立物品 = 占 10 个槽位 ❌
```

**根基需求**：
```typescript
interface Item {
  id: string;
  type: string;
  stackable: boolean;    // 是否可堆叠
  stackSize?: number;    // 堆叠数量（stackable=true 时有效）
  maxStack?: number;     // 最大堆叠数（默认 99）
  slots: number;         // 每堆占用槽位（1）
}

// 100 个金币 = 1 个物品（stackSize=100） = 占 1 个槽位 ✓
```

**承载的表层机制**：
1. 货币系统
2. 弹药系统
3. 材料收集
4. 消耗品批量使用
5. 商店交易（检定堆叠数量）
6. 合成系统（消耗 N 个材料）
7. 投掷物（手雷 ×3）

**设计细节**：
- 分堆：100 个金币可拆成 60 + 40 两堆
- 合并：两堆金币自动合并（不超过 maxStack）
- 转移：转移 N 个堆叠物品
- 使用：消耗堆叠中的 1 个（stackSize - 1）

### 缺失 2：条件网关（资源检定）

**无法实现的机制**：
- 商店购买（检定金币）
- 门锁（检定钥匙）
- 技能消耗（检定法力值）
- 任务交付（检定任务道具）
- 资源转换（检定材料 → 输出产品）

**当前问题**：
过渡场景只能定义"消耗 AP"，无法定义"检定资源"。

```typescript
interface Connection {
  from: NodeId;
  to: NodeId;
  cost: { ap: number };  // 只能检定 AP ❌
}
```

**根基需求**：
```typescript
interface Condition {
  type: 'has_item' | 'has_resource' | 'has_status' | 'check_stat';
  params: any;
}

interface Gateway {
  conditions: Condition[];  // 前置条件
  cost?: Cost;              // 消耗（可选）
  effects?: Effect[];       // 效果
  onSuccess?: Effect[];     // 成功后效果
  onFailure?: Effect[];     // 失败后效果
}

// 应用到过渡场景
interface Connection {
  from: NodeId;
  to: NodeId;
  gateway?: Gateway;        // 可选的网关检定
}
```

**示例**：
```typescript
// 上锁的门
{
  conditions: [{ type: 'has_item', params: { item: 'key_red' } }],
  cost: { ap: 1 },
  onSuccess: [{ type: 'consume_item', item: 'key_red' }]  // 钥匙消耗
}

// 商店购买
{
  conditions: [{ type: 'has_resource', params: { resource: 'gold', amount: 50 } }],
  cost: { resources: { gold: 50 } },
  onSuccess: [{ type: 'transfer_item', from: 'shop', to: 'player', item: 'sword' }]
}

// 合成台
{
  conditions: [
    { type: 'has_item', params: { item: 'iron', count: 3 } },
    { type: 'has_item', params: { item: 'wood', count: 2 } }
  ],
  cost: { items: ['iron:3', 'wood:2'], ap: 1 },
  onSuccess: [{ type: 'create_item', item: 'iron_axe' }]
}
```

**承载的表层机制**：
1. 上锁的门（检定钥匙）
2. 商店（检定货币）
3. 合成台（检定材料）
4. 任务 NPC（检定任务道具）
5. 技能消耗（检定法力/体力）
6. 等级限制（检定等级）
7. 声望门槛（检定声望值）
8. 过桥费（检定金币才能过桥）

### 缺失 3：资源池（非物品资源）

**无法实现的机制**：
- 货币（金币、钻石）
- 经验值
- 技能点
- 声望/好感度
- 法力值（如果不复用体力）
- 建材（木材、石头）

**当前问题**：
只有 HP、Stamina、AP 三种资源，都是硬编码的。

```typescript
interface LivingEntity {
  hp: number;
  stamina: number;
  // 无法添加 gold, exp, mana...  ❌
}
```

**根基需求**：
```typescript
interface Entity {
  resources: Map<string, number>;  // 通用资源池
}

// 预定义资源（核心机制）
const CORE_RESOURCES = ['hp', 'stamina', 'ap'];

// 扩展资源（玩法包定义）
player.resources.set('gold', 100);
player.resources.set('exp', 0);
player.resources.set('mana', 50);
player.resources.set('reputation_merchant', 5);
```

**与物品堆叠的关系**：
- 物品堆叠：有实体的对象（可交易、可掉落）
- 资源池：抽象数值（不占背包、可溢出）

```
金币作为物品 = 可交易、可掉落、占背包
金币作为资源 = 不占背包、账户余额

示例：
- Minecraft：金币是物品（可掉落）
- WoW：金币是资源（账户绑定）

两者都用资源池表示：
- 物品堆叠 → resources['item:gold']
- 抽象资源 → resources['currency:gold']
```

**承载的表层机制**：
1. 货币系统
2. 经验/等级
3. 技能点
4. 声望/好感度
5. 特殊资源（法力、怒气、能量）
6. 建材资源
7. 积分/荣誉
8. 任何数值统计

### 缺失 7：被动触发系统

**无法实现的机制**：
- 荆棘反伤（受击时触发）
- 击杀回血（击杀时触发）
- 反击（格挡后触发）
- 进入陷阱（移动时触发）
- 装备耐久（使用时触发）

**当前问题**：
只有主动动作，没有被动响应。

```typescript
// 当前：玩家主动攻击
player.attack(target);

// 缺失：敌人被动反伤
// 谁来调用？在哪触发？
```

**根基需求**：
```typescript
interface PassiveTrigger {
  event: string;           // 触发事件（on_damaged, on_kill, on_move）
  condition?: Condition;   // 触发条件
  effect: Effect;          // 触发效果
  consumed?: boolean;      // 是否一次性
  cooldown?: number;       // 冷却时间
  priority: number;        // 优先级
}

interface Entity {
  passives: PassiveTrigger[];
}

// 执行流程
function onEntityDamaged(target: Entity, damage: number, source: Entity) {
  // 1. 应用伤害
  target.hp -= damage;
  
  // 2. 触发被动
  for (const passive of target.passives.filter(p => p.event === 'on_damaged')) {
    if (checkCondition(passive.condition)) {
      applyEffect(passive.effect, { target, source, damage });
    }
  }
  
  // 3. 触发攻击者的被动（击杀回血）
  if (target.hp <= 0) {
    for (const passive of source.passives.filter(p => p.event === 'on_kill')) {
      applyEffect(passive.effect, { source, target });
    }
  }
}
```

**触发链保护**：
```typescript
interface TriggerContext {
  depth: number;           // 当前深度
  maxDepth: number;        // 最大深度（3-5）
  chain: string[];         // 触发链记录
}

// A 攻击 B → B 反伤 A → A 反伤 B → 超出深度，停止
```

**承载的表层机制**：
1. 荆棘反伤
2. 击杀回血/回蓝
3. 反击/连击
4. 装备耐久消耗
5. 陷阱触发
6. 进入区域效果
7. 死亡触发（遗言技能）
8. 连锁反应（元素爆炸）

```typescript
interface Node {
```

```typescript
interface EnvironmentStatus {
```

```typescript
// 每回合更新
function updateVision(player: Player) {
  const controlled = getControlledEntities(player);
  player.visibleNodes.clear();
  player.visibleEntities.clear();
  
  for (const entity of controlled) {
    const nodes = findNodesInRange(entity.location, entity.visionRange);
    nodes.forEach(n => {
      player.visibleNodes.add(n);
      player.exploredNodes.add(n);  // 同时标记为已探索
    });
    
    const entities = findEntitiesInNodes(nodes);
    entities.forEach(e => {
      if (canDetect(entity, e)) {
        player.visibleEntities.add(e.id);
      }
    });
  }
}
```

```typescript
  findEntities(filter: EntityFilter): EntityId[];
  countEntities(filter: EntityFilter): number;
}

interface EntityFilter {
  location?: { node?: NodeId, radius?: number };
  category?: EntityCategory;
  status?: string[];
  tags?: string[];
  faction?: string;
  hp?: { min?: number, max?: number };
}
```

**测试用例**：
- 查询"教室内所有玩家"
- 查询"半径 3 内的僵尸"
- 查询"HP < 2 的敌人"
- 查询"带有'可燃'标签的实体"

**风险点**：
- 性能（100+ 实体时的过滤）
- 缓存策略（位置查询结果缓存）
- 距离范式的正确实现
