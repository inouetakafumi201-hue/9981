# 核心设计理念

---

## 项目定位

**《起床》（WakeUp）** 是一个基于童年石头剪刀布叙事游戏演化而来的**离散策略引擎**，旨在创造一个：
- 极简但深度的策略体验
- 零门槛的 UGC 创作平台
- 通用的战术博弈框架

---

## 核心设计哲学

### 1. 极简离散系统

- **一次一个行动**：不存在"半步"或"同时做两件事"
- **铁律**：一个动作永远消耗 **1 AP**
- **信息完全公开**：没有手牌、没有迷雾、没有隐藏属性
- **数值极小**：所有玩家可见数值不超过 5，没有小数
- **不会数 6**：公开规则中的数字上限是 5，6 只是骰子的物理上限

### 2. 棋类的广义化

本质上是将 RPG 游戏乃至各种游戏形式纳入到棋类概念中，用完全节点化的方式构建了一个循环，使得它可以将各种玩法纳入到同一个心智模型中。

**关键特征**：
- 离散节点拓扑（不是连续坐标）
- 回合制时序（不是即时反应）
- 状态透明（不是信息不对称）

### 3. 规则理解的验证

游戏的核心乐趣不在于单一的某个游戏模式，而在于：
- **"我读懂了这个局面"的验证感**
- 玩家做出一个行动，是因为他判断这是当前局面下的最优解
- 结果证明他对了（或者对手的应对让他意识到自己漏算了什么）

### 4. 设计原则金字塔

#### 顶层原则：四级否决层级（非并列加权）

顶层原则是四条**独立**准则，但它们之间构成**有先后否决权的层级**，不是简单加权：先保证玩家想得动，再保证玩家愿意想；然后保证学会一次能反复使用，最后才让结果尽量符合常识。

1. **低心智性**（玩家需要同时维护的独立信息越少越好，否决权最高）
   - 宁可砍掉有趣但复杂的机制
   - 护甲不增加抗伤值，因为增加隐性心智负担
   - 如无必要，不给武器加耐久值
   - 如无必要，勿增实体 / 状态 / 属性（一个动作固定 1 AP，任何变体自己变通；车撞人不减耐久；死亡不化床，避免破坏出生点神圣性）
   - 五并列原则：任何时刻玩家面对的选项不超过 5 个（场景连接数上限：大 5 / 中 4 / 小 3；背包槽位上限：6 格 [2 手 + 4 格背包]；生命值上限：5 点；体力上限：5 点）

2. **可玩性**
   - 在满足低心智性的前提下，机制应保留足够的策略深度与博弈趣味
   - 与"规则理解的验证"（见上文第 3 节）呼应：玩家的乐趣来自"读懂局面并做出正确判断"

3. **复用性**
   - 枪械共享距离 DC 表（不是每把枪独立属性）
   - 近战武器遵循 2×4 范式（不是每把武器独立机制）
   - 接敌面数量 = 场景连接数上限（复用同一套 5/4/3）

4. **常识性**
   - 配件系统不需要过度简化（PUBG 配件概念广为人知）
   - 背包中的可乐可以直接喝（常识）
   - 铁锤装进包里仍然有负重 buff（常识）

**层级含义**：即使一个机制非常符合常识、复用程度很高，只要它持续增加玩家必须维护的状态或污染行为菜单，就应优先删除。

#### 实现原则

1. **解耦再解耦**：层层外包的接口系统
   - 节点 / 物品 / 实体三者平级，不是继承关系
   - 估值函数属于内核层，不属于 AI 模块
   - 玩家 AI 与 NPC AI 彻底分离

2. **维护下棋一般的纯洁性**
   - 所有被动选择都不经过分支（自动结算）
   - 零费动作不产生搜索分支
   - 禁止回合外选择、回合外反击

## 与现有游戏的定位对比

### 不是传统意义的"大逃杀游戏"

虽然可以包含大逃杀玩法，但本质是：
- **一种可以模拟万物的、可无限拓展的"战术沙盒棋"（Tactical Sandbox Chess）**
- **一个离散物理世界的模拟器**
- **用棋类逻辑解构一切冒险故事的通用框架**

### 与其他 UGC 平台的区别

| 平台 | 创作门槛 | 自由度 | 系统一致性 |
|------|---------|--------|-----------|
| Roblox | 需要编程 | 极高 | 低（每个游戏不同） |
| Minecraft Mod | 需要编程 | 极高 | 低 |
| **本引擎** | 自然语言 | 受限但完备 | 极高（统一心智模型） |

**核心差异**："较低的创作自由，创造了大多数人绝对的创造自由"

## 设计验证标准

### 底层范式判定

一个机制是否属于底层，可以用这个问题判断：
> 去掉"战斗"和"最后存活者获胜"以后，它是否仍然是一个有意义、可复用的世界操作？

例如：
- ✅ "实体从一个容器转移到另一个容器"是底层范式
- ❌ "死亡后全部装备掉落"只是某个玩法包的规则

### 机制验证清单

添加新机制前检查：

1. ✅ **五并列原则**：是否符合"不超过 5 个并列选项"？
2. ✅ **常识映射**：是否有现实或游戏常识支撑？
3. ✅ **AP 等价**：1 AP 价值是否等价于标准动作？
4. ✅ **零费合理**：零费动作是否真的不产生搜索分支？
5. ✅ **状态必要性**：是否可以用已有状态组合实现？
6. ✅ **复用优先**：是否可以复用已有流程而非新增？
7. ✅ **1 AP 铁律**：是否真的需要"2 AP 动作"，还是可以拆成两个 1 AP？

### UGC 友好性检验

一个机制是否 UGC 友好：
> 如果一个实现要求 UGC 创作者附加额外创作（如与原版武器伤害之间的优先级选择），要很怀疑是否要砍掉它。除非是自洽的优秀机制（如让其选择伤害类型）。

## 废案档案

**这些机制曾被提出，但经验证后废弃。记录于此以避免重复讨论。**

### 已明确否决的机制

| 废案名称 | 否决理由 | 教训 |
|---|---|---|
| **死后化床** | 与出生点床冲突，破坏床的神圣性，无端增加实体 | 不要为了"有趣"破坏基础概念的纯洁性 |
| **多米诺长眠** | 太反常识，连锁击败超标 | 反直觉的传导机制难以平衡 |
| **霸体** | 用户自认坏点子，为了解决拓扑混乱引入新概念 | 用新概念修补旧问题是设计债务 |
| **感知衰减表** | 过于复杂，改用场景类型影响衰减程度 | 表格越多，心智负担越重 |
| **噪音残影** | 无效设计 | 不要为了"拟真"添加无玩法意义的复杂度 |
| **尸体系统** | 搜尸、拖拽尸体增加心智负担 | 改为死亡背包（只出不进的容器实体） |
| **护甲增加抗伤值** | 隐性心智负担 | 护甲改为直接减伤规则（轻 -1 到 0，中 -1 到 1，重型特殊） |
| **耐久系统** | 如无必要，勿增属性 | 武器、载具不需要耐久值 |
| **体积分类** | Small/Medium/Large 三档废弃 | 改为"占 1 格 / 占 2 格"二分 |
| **口袋槽位** | 删除，改为初始背包 2 格 | 槽位类型越少越好 |
| **已发现关系系统** | "找到"不是关系，是进入微型场景 | 不要为简单的空间操作创建关系系统 |
| **回合外反击 / Overwatch** | 违反回合制纯洁性 | 保持时序纯洁性优先于战术丰富性 |
| **意图机作为顶层决策** | 改为 αβ 剪枝搜索 + 随机选择器 | 通用算法优于特化启发式 |
| **曼哈顿距离（AI 估值）** | 节点非网格，不存在坐标系 | 用拓扑距离（距离范式） |
| **替身使者拓展** | 引入第二状态源，心智负荷翻倍 | 超出五并列原则的扩展必败 |

### 待定但暂不实现的候选机制

| 机制 | 状态 | 原因 |
|---|---|---|
| 攻击形状细节 | 概念存在，具体定义待补充 | 框架已定（单体/散射/范围），数值待测试 |
| 配件效果数值 | 待测试 | 瞄准镜/握把/弹夹的具体加成待平衡 |

> **已从候选机制表移出**：资源转换网关、检定网关、条件网关三种网关**已确认为 MVP 标配机制**，不再是"特殊地图专属、暂不纳入标配"的候选项。原因：12_根基完备性审查_v2.md 已指出条件网关是阻塞商店、上锁门、合成台等玩法的根基缺失项，而这些玩法在 MVP 中大概率需要出现，网关机制不应停留在"可选扩展"层级。三种网关的具体规则（门槛定义、呈现方式、AP 成本等）作为标配机制在 02_游戏机制系统_v2.md 中正式设计。详见访谈决策记录 D-006。

## 术语纯洁性原则

**统一术语是降低心智负担的基础。**

### 禁止混用的术语对

| 正确术语 | 错误/废弃术语 |
|---|---|
| 天然场景 | 自然场景、场景节点 |
| 小场景 | 微型节点、Micro Scene |
| 微型场景 | 接触空间、局部场景 |
| 活体 | 角色、单位（保留"实体"用于底层） |
| 死亡背包 | 尸体、掉落物 |
| 令其长眠 | 处决、终结、击杀（保留"死亡"用于系统） |
| 距离 | 跨度、射程（保留"范围"用于 AOE） |
| 流程 | 行动坐标系、动作链 |
| 谱型 | 枪械类型、武器分类 |
| 感知阈值 | 触发条件、警觉度 |

### 强制统一的数值表述

| 正确 | 错误 |
|---|---|
| 1 AP | 一个 AP、1ap、1 行动点 |
| 5 点生命 | 5HP、5 血、五点生命 |
| 距离 3 | 3 格距离、三个节点 |
| 伤害 2 | 2 点伤、两点伤害 |

## 世界观：零和睡眠协议

**叙事原则**："谜语人"风格，不过度强调措辞，让玩家主动探寻。

**MVP 阶段定位**：世界观在 MVP 阶段做**基础呈现**——不是完全略过，也不要求完整叙事系统落地。MVP 的物品描述、场景文本等内容需要预留世界观呈现的轻量位置（见下文"表现方式"），但不需要对话树、剧情章节等重系统。呈现的具体形式和范围（如道具描述/环境文本的实现细节）待后续物品系统、UI 设计阶段细化。

### 核心设定

- **睡眠守恒**：睡眠时间和清醒时间全球守恒，一人入睡 → 地球另一端一人被强制唤醒
- **定向导流器**：科学家武器化这一效应，制造单向唤醒攻击（跨洲狙击敌方领导层睡眠）
- **床位经济**：床成为稀缺战略资源，控制谁能休息 = 控制组织运转
- **清醒特工**：玩家扮演的特种兵单位，管理 VIP 睡眠周期，利用这一机制执行各种衍生的战略行动。例如黑入对方导流机房等等。
- **僵尸真相**：底层民众被迫使用边缘服务器，睡眠质量极差，渴望安眠

**批判力**：
> "睡眠是每个人都有的东西啊" = "劳动力是每个人都有的东西啊"

**表现方式**：
- 不贴脸宣讲
- 细节散布（道具描述、NPC 对话、环境文本）
- 允许玩家完全忽略世界观也能正常游玩

## 设计债务管理

### 已知债务（需后续验证）

| 债务项 | 风险等级 | 缓解措施 |
|---|---|---|
| 多人载具内复杂交互 | ⚠️ 中 | 汽车只能坐两人，两扇门。汽车有四格槽作为容器可在车上直接访问；车旁边花 1 AP 打开后备箱。后备箱不可上锁，偷窃可能。在车上的玩家进入一种网关。主座玩家能开车，副座不行。为节省菜单，不支持一次性坐到副座，要坐到主座然后在网关内换座（如未占），但假如主座被占则自动副座。电瓶车有二格槽。车门属性：活体希望对车内交互前，需将门的属性修改（如砸破，钝锐器伤害皆可）。车门一般挡不住远程武器，除非防弹玻璃，直接穿透且不会破坏车门。**两扇门设定已解决**：保留为两个独立属性（主驾/副驾，分别占索引 1、2），日常体验中基本等同于只有一扇门；车辆交互范围以"是否站在车辆旁"判定，不区分具体在哪一侧/哪扇门旁——位置优先于索引，两个索引仅在"针对性破坏车门"等场景下才有区分意义（详见访谈决策记录 D-012、D-030；规则落地于 04_物品与装备系统_v2.md 载具章节）。 |
| 跨楼层垂直战斗 | ⚠️ 中 | 一般而言跨楼层都是二楼架枪瞄准楼下的人。不设定架枪动作，必须来到接近某场景的窗边。窗户是过渡场景创造的微型场景。窗户过渡场景与翻窗使用的过渡场景是同一个。垂直过渡（跳窗）仅上侧创建微型场景，来到窗边即可对楼下射击。**距离计算已解决**：常规楼层过渡（如楼梯）按"离开 +1、进入 +1"叠加计算；跳窗微型场景到下层天然场景统一按距离 1 计算（体现居高临下优势），不与常规楼层过渡叠加（详见访谈决策记录 D-013；规则已落地于 03_空间系统设计.md 垂直交互规则）。 |
| 大规模 NPC（100+ 僵尸） | ⚠️ 高 | 守卫范式 + 状态机（非搜索） |
| UGC 内容恶意攻击 | ⚠️ 高 | 静态 Linter + 运行时沙盒 |

### 已偿还债务（已解决）

| 债务项 | 原问题 | 解决方案 |
|---|---|---|
| 物品 vs 实体混淆 | 折叠自行车能否直接骑 | 明确为两个不同对象，需转换 |
| 小场景 vs 微型场景混淆 | 车内是什么空间 | 定义为两套正交坐标 |
| 2 AP 动作的实现 | 违反 1 AP 铁律 | 拆成两个 1 AP + 中间状态 |
| 尸体系统复杂度 | 搜尸、拖拽、容器 | 简化为死亡背包实体（只出不进） |

## 未来愿景

### 成为"离散策略博弈的通用浏览器"

**长期目标**：
- AI Agent 能用自然语言描述玩法，系统自动生成地图 + 规则
- 玩家能像浏览网页一样浏览不同玩法
- 社区沉淀的优质内容成为新的"棋谱库"

**技术路径**：
1. 完成底层引擎（力求 0 追加）
2. 开发 LLM 辅助 UGC 工具
3. 建立标准化协议（地图 JSON + 规则包）
4. 开放 API 给 AI Agent 生成内容

**可持续性保证**：
- 统一心智模型（所有玩法遵循同一套规则语法）
- 范式复用（新武器只需定义谱型，不需要新代码）
- 扩展性架构（见 05 文档的扩展性保证）
