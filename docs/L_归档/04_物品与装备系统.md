# 物品与装备系统

## 背包与携带系统

### 槽位结构

玩家的携带系统基于严格的槽位限制：

```
左手（Hand_L）      - 单手物品
右手（Hand_R）      - 单手物品【双手物品无特殊情况只是要求在空一只手中才可主动使用，占一格】
左口袋（Pocket_L）  - 
右口袋（Pocket_R）  - 【改为初始背包，2个槽位，方便解释部分占两格物品。无口袋概念】
背包槽1（Backpack_1）- 【这二者是拓展的，出生没有】
背包槽2（Backpack_2）- 
```

**核心原则**：
- 人是双利手（左右手功能完全相同）
- 初始背包只有两格
- 重型物品放入背包仍然有负重buff
- 数值严格控制：4个背包槽位正好不超过"五并列"认知负担

### 物品体积分类

#### Small（小型）
- **可放入**：手、背包
- **示例**：钥匙、子弹、绷带、硬币
- **特点**：不影响移动，易于管理

#### Medium（中型）
- **可放入**：仅手、背包
- **示例**：手枪、防暴盾、工具
- **特点**：标准战斗装备

#### Large（大型/双手）
- **可放入**：双手同时、背包
- **示例**：电锯、加特林、长枪
- **特点**：占用双手，通常附带重型buff

### 物品管理操作

#### 整理背包（1 AP）
- 消耗1 AP，可以任意重排所有槽位
- 进入"暂停整理模式"，自由拖拽物品
- 确认后扣除1 AP，原子提交整个事务
- AI使用语义意图而非穷举排列

#### 拾取物品（每件1 AP）
- 每拾取一个物品消耗1 AP
- 设计意图：防止"一次全拿"贪婪行为
- 场景：房间有3把枪，捡完需要3 AP，期间可能被偷袭
- 自动放入合适的空槽位（手优先，然后背包）

#### 丢弃物品（0 AP，依附）
- 不消耗AP，但必须依附于一个付费动作【附赠动作是讨论深入点3，这里一种交互可能是严格规定在ap结束后才能执行，表现为ap消耗完后下方框出现可执行的附赠，部分附赠不限次数，一些防止乱玩如开关门限制一次。这个的弊端是不够灵活，如多ap压缩策略性，如丢弃武器近战等迅捷操作。也可在ap未耗尽时设菜单切换按钮】
- 例如：移动时顺便丢掉手里的武器
- 防止无限丢弃/刷屏漏洞
- 保持操作流畅性

### 使用规则

#### 武器使用限制
- **必须在手上**：武器必须装备在手部槽位才能使用
- **背包武器不可直接使用**：需要先整理背包（1 AP）拿出
- 设计意图：打落武器机制有意义

#### 消耗品例外
- **可从背包直接使用**：药品、食物等消耗品
- 常识映射：背包侧面的可乐可以顺手拿起来喝
- 不需要先拿到手上

### 负重系统

#### 重型标签
物品带有`[heavy]`标签时：
- 在大场景移动消耗+1 AP（2 AP per node）【具体实现可能是获得"前往xx"状态，任何其他位移检测或者成功到达会清除它】。【】特定过渡场景如楼梯、窗户也会让通过它前往另一场景+1ap】
- **即使放入背包，负重效果仍然存在**
- 常识：铁锤装进包里也不会变轻

#### 负重聚合
- 沿携带关系树向上聚合所有重型标签
- 只要实体栏位里有重型物品，就受影响
- 无法通过"放入背包"避税

### 特殊容器扩展【玩家死亡后留下的背包也是容器。有2-4个格子】

#### 载具容器
- 汽车/电瓶车可以有货物槽
- 独立于角色的携带系统
- 车辆被毁时，货物掉落到当前节点

#### 箱子/储物柜
- 地图上的静态容器节点
- 可以存放/取出物品【不需要ap打开，除非上锁。上锁的破开/撬开是精密行动，2ap。有钥匙是普通行动。】
- 通常在安全区域

## 武器系统

### 武器分类

#### 按体积分类

##### 轻型单手武器【大中小标准范式忘了？没有那么多分类，2*4而已，枪械系统另算】
- 体积：Medium
- 占用：单手
- 移动：无惩罚
- 示例：手枪、短刀、棍棒

##### 重型双手武器
- 体积：Large【没有体积概念，一般都占一格，少量两格，例如电锯】
- 占用：双手
- 移动：大场景+1 AP
- 示例：电锯、加特林、霰弹枪

#### 按攻击距离分类

##### 近战武器
- 范围：同一微型场景
- 攻击：1 AP
- 优势：无需瞄准，可车上使用（电瓶车）
- 示例：刀、棒球棍、电锯

##### 远程武器
- 范围：可跨节点攻击
- 攻击流程：瞄准（1 AP）→ 对方可反应 → 开枪（1 AP）
- 劣势：两步流程，给对手反应时间
- 示例：手枪、步枪、狙击枪

#### 按伤害类型分类

##### 标准伤害
- 伤害值：1-3
- 无特殊效果
- 可被护甲减免

##### 特殊伤害
- 附带状态效果
- 例如：电击枪（造成1伤害+眩晕1回合）
- 例如：火焰喷射器（造成1伤害+燃烧状态）

### 武器平衡原则

#### 伤害与获取难度
- 1伤武器：容易获取，大量分布
- 2伤武器：标准武器，需要规划路线
- 3伤武器：稀有，通常在危险区域或需要特殊条件

#### 射程与伤害权衡
- 近战：高伤害（2-3），但需要贴身
- 中距离：中等伤害（1-2），平衡选择
- 远距离：中高伤害（2-3）。

#### 成本与收益
```
手枪：
- 获取：3 AP
- 伤害：2【废案】
- 使用：2 AP（瞄准+射击）
- 总成本：5 AP杀死5血目标（理论上）

电锯：
- 获取：3 AP（危险路线）
- 伤害：2
- 使用：1 AP（近战）
- 移动惩罚：+1 AP per 大场景
- 总成本：看情况，高风险高回报
```

## 防具系统

### 防具类型

#### 主动防御
**防暴盾**：
- 需要花费1 AP举盾
- 提供1回合的格挡状态
- 可被破甲武器无视
- 可被"扒盾"动作移除

#### 被动防御
**护甲/防弹衣**：
- 装备后自动生效
- 减少受到的伤害（-1或转换为特定类型）
- 可能有耐久度机制
- 占用特定装备位

### 防御机制设计

#### 格挡（Blocked）状态
```
效果：免疫下一次直接伤害
持续：1回合
克制：
  - 破甲标签武器可穿透
  - 扒盾动作可移除
```

#### 掩体机制
在特定节点提供防御加成：
- 在掩体后：远程伤害-1
- 离开掩体：效果消失
- 不占用装备槽位

## 载具系统

### 载具作为可占用容器

载具不是特殊移动代码，而是：
- 一个可占用的实体
- 拥有若干角色槽位（驾驶位、乘客位）
- 对外提供移动或撞击动作
- 权限由特定槽位的占用者获得

### 载具类型

#### 汽车（Car）【所有构思阶段的代码全是伪代码且很可能不是正确实现】

### 载具操作

#### 上车/下车（各1 AP）
```
上车：
- 移动到载具所在节点
- 花费1 AP进入载具（占用驾驶位或乘客位）
- 获得载具提供的动作

下车：
- 花费1 AP离开载具
- 移动到载具当前节点
- 失去载具提供的动作
```

#### 驾驶移动
```
在大/中场景：
- 消耗1 AP，移动2个节点
- 相当于普通移动的加速版

限制：
- 汽车不能进入微型场景和过渡场景
- 电瓶车可以被推过过渡场景（不在车上时）
```

#### 撞击机制
```
流程：
1. 瞄准目标（1 AP）【深化4，场景掩体属性，不可被撞击，可能继承。如一个实体让所在的微型场景具有掩体属性）】
2. 目标可反应（躲开/离开节点）【这里不是被动选择，是自己回合】
3. 如果目标未躲开，造成伤害

伤害：
- 汽车：3点
- 电瓶车：2点

失败：
- 如果目标躲开，浪费了瞄准的1 AP
```

### 载具防御与破坏

#### 爆胎机制
```
远程武器爆胎：
- 直接判定，消耗1 AP
- 效果：失去移动修正（变成1 AP移动1节点）

近战武器爆胎：
- 需要1 AP蹲下
- 然后1 AP攻击轮胎
- 设计意图：给车内的人1 AP反应时间
```

#### 车辆损毁
```
汽车：5点生命值
电瓶车：3点生命值

损毁流程：
1. 生命值归零
2. 进入燃烧状态（持续1回合）
3. 下一回合爆炸（同微型场景3点伤害）
4. 乘员需要提前下车避免伤害
```

### 载具特殊规则

#### 汽车锁门
- 可以锁门防止被拽下车
- 其他玩家需要：
  - 1 AP破窗/撬门
  - 1 AP拽下驾驶员
  - 1 AP自己上车

#### 电瓶车推车
```
条件：不在车上
动作：花费1 AP，带着电瓶车一起移动
应用：
- 可以推过楼梯（过渡场景）
- 可以推进微型场景
- 常识映射：电瓶车轻便可推
```

#### 车上近战（电瓶车独有）
- 借鉴《骑马与砍杀》机制
- 可以在驾驶时使用近战武器
- 平衡：无法锁门，容易被拽下车

## 格斗系统（可选模块）

### 对峙状态网关

格斗系统通过"对峙"状态网关收束复杂性：

#### 进入对峙（1 AP）
```
前置条件：
- 至少一只手空闲
- 在同一微型场景
- 对方没有重型buff（或对方虚弱/倒地时单向对峙）

效果：
- 双方进入[对峙]状态
- 菜单切换为格斗动作列表
- 无法执行移动、远程攻击等动作
```

#### 格斗动作
```
重拳（1 AP）：
- 造成2点伤害
- 解除对峙状态

过肩摔（1 AP）：
- 前置条件：对方没有重型buff
- 造成1点伤害 + 倒地状态
- 解除对峙状态

夺取武器（1 AP）：
- 从对方手中移除一件装备
- 解除对峙状态

挣脱（1 AP）：
- 离开对峙状态
- 移动到相邻节点【还有拖着】
```

### 空手价值强化

格斗系统的设计意图：
- 让空手玩家有反击重装玩家的手段
- 提供近距离的战术博弈深度
- 平衡武器流派

### 为什么格斗系统不常驻

原因：
- **无法容忍属性状态爆炸**【已被网关思维解决】
- 过多的格斗机制会导致行为菜单繁杂
- 违反五并列原则

解决方案：
- 作为赛季特殊内容或特定地图规则
- 或者极度简化为2-3个核心动作【这个MVP可以考虑】

## 物品设计最佳实践

### DO
- ✅ 严格遵守体积分类
- ✅ 每个物品都有明确的AP成本权衡
- ✅ 复用现有能力组件
- ✅ 让常识驱动物品行为
- ✅ 数值控制在1-5范围

### DON'T
- ❌ 创建需要特殊状态管理的物品
- ❌ 让物品绕过标准动作系统
- ❌ 设计"必拿"的超模装备
- ❌ 忽略携带重量对移动的影响
- ❌ 让背包成为负重避税天堂
