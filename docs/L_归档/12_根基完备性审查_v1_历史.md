# 根基完备性审查

> **目标**：通过大量 RPG 机制测试用例，找出当前根基的结构性缺失，做整合而非打补丁。

**审查原则**：
- 不问"大逃杀需要什么"
- 而问"什么机制会让当前根基崩溃"
- 每个缺失必须影响 3+ 个不同场景
- 优先整合，避免碎片化 API

---

## 审查方法

### 测试用例分类

**控制与视角类**：
- 远程操控（无人机、随从）
- 多段变身（人→狼人→巨狼）
- 旁观模式、回放系统

**状态与查询类**：
- 延时 Buff/Debuff
- 状态查询（"附近中毒的敌人"）
- 复合状态（冰冻+燃烧→蒸汽）

**归属与关系类**：
- 召唤物/随从
- 陷阱与触发器
- 队伍系统、阵营关系

**资源与进度类**：
- 资源系统（金币、经验、声望）
- 条件胜利（收集 3 个钥匙）
- 物品合成（铁+木→斧头）

**时空与动态类**：
- 时间回溯（倒带 3 回合）
- 动态地图（房间随机生成）
- 传送门、飞行

**叙事与交互类**：
- 对话树（NPC 对话分支）
- 任务系统（接取、追踪、完成）
- 剧情触发点

## 第一部分：控制与视角类

### 用例 1.1：远程操控（无人机）

**场景描述**：
玩家部署无人机，切换视角到无人机，移动侦察另一个房间，然后切回本体。

**根基需求拆解**：

#### 需求 A：观察视角分离
```typescript
interface GameState {
  viewpoint: Map<PlayerId, EntityId>;  // 玩家观察的实体
}
```

**影响范围**：
- 无人机/侦察机器人
- 旁观模式（观战）
- 回放系统
- 安全摄像头（查看其他房间）
- 水晶球（远程观察）

#### 需求 B：控制权转移
```typescript
interface Entity {
  controller?: EntityId;  // 当前控制者
  defaultController?: EntityId;  // 默认控制者（断线后恢复）
}
```

**影响范围**：
- 远程操控
- 魅惑/控制技能（夺取敌人控制权）
- 多角色切换（战棋式）
- 载具驾驶

#### 需求 C：受击打断框架
```typescript
interface LivingEntity {
  activeAction?: {
    type: 'controlling' | 'lockpicking' | 'channeling';
    target?: EntityId;
    interruptOnDamage: boolean;
    interruptOnMove: boolean;
  };
}
```

**影响范围**：
- 远程操控受击打断
- 精密交互（撬锁中）
- 持续施法（引导技能）
- 吟唱读条

**判断**：这 3 个需求是**独立正交的**，不是一个需求的变体。

---

### 用例 1.2：多段变身

**场景描述**：
玩家白天是人类（5 HP），月圆之夜变狼人（7 HP，+2 伤害），满月变巨狼（10 HP，+5 伤害但失去理智）。

**根基冲突点**：

#### 冲突 A：生命值上限变化
当前铁律：生命值上限 5 点。

变身后 7 HP 违反了"不会数 6"原则。

**可能的解决方案**：

方案 1：**变身不增加 HP 上限**
- 狼人仍然 5 HP
- 但获得其他 buff（+1 伤害、+1 移动）
- 保持数值纯洁性

方案 2：**变身是"更换实体"**
- 人类实体 HP=5
- 变身 = 创建狼人实体（HP=5，但有不同技能）
- 不是数值变化，是实体替换

方案 3：**允许临时 HP**
```typescript
interface LivingEntity {
  hp: number;           // 当前生命
  baseMaxHp: number;    // 基础上限（5）
  tempMaxHp: number;    // 临时上限（变身+2）
}
```
- 临时 HP 只在变身期间有效
- 变身结束，超出部分削减到基础上限

**判断**：方案 1 最符合设计哲学，方案 2 干净但复杂，方案 3 打破纯洁性。

#### 冲突 B：变身状态的多阶段
```typescript
// 当前状态系统
interface StatusEffect {
  type: string;
  duration: number;
}
```

狼人变身是**状态链**：
```
人类 --(月圆之夜)--> 狼人 --(满月)--> 巨狼 --(黎明)--> 人类
```

这不是单一状态，是**状态机**。

**可能需要**：
```typescript
interface TransformationState {
  currentForm: string;       // 'human' | 'werewolf' | 'giant_wolf'
  availableTransitions: {    // 可用的变身路径
    to: string;
    condition: Condition;
    cost?: Cost;
  }[];
}
```

**影响范围**：
- 多段变身（人→狼→巨狼）
- 进化系统（史莱姆→史莱姆王）
- 装备切换形态（普通模式→战斗模式）

### 用例 1.3：旁观模式

**场景描述**：
玩家死亡后进入旁观模式，可以自由切换视角观看其他存活玩家。

**根基需求**：

#### 需求 A：自由视角移动
旁观者的视角不绑定任何实体，可以移动到任意节点。

```typescript
interface Player {
  controlledEntity?: EntityId;  // null = 旁观模式
  viewpoint: EntityId | NodeId;  // 可以是实体或节点
}
```

**影响范围**：
- 旁观模式
- 上帝视角（GM 模式）
- 过场动画镜头

#### 需求 B：受限观察范围
旁观者能看到什么？

- 方案 A：全知视角（可以看到整个地图）
- 方案 B：只能观察存活队友
- 方案 C：只能观察最后看见你的敌人

需要**观察权限系统**：
```typescript
interface ViewPermission {
  canViewEntity: (viewer: PlayerId, target: EntityId) => boolean;
  canViewNode: (viewer: PlayerId, node: NodeId) => boolean;
}
```

**影响范围**：
- 旁观模式权限
- 迷雾系统（未探索区域不可见）
- 反侦察（隐身、潜行）

## 第二部分：状态与查询类

### 用例 2.1：延时 Buff

**场景描述**：
玩家喝下"延时毒药"，3 回合后发作，持续 5 回合，每回合 -1 HP。

**根基需求**：

#### 需求 A：延时生效机制
```typescript
interface StatusEffect {
  type: string;
  delay: number;      // 延迟回合数（负数 = 未生效）
  duration: number;   // 生效后持续回合数
  stacks?: number;    // 可叠加层数
}
```

**影响范围**：
- 延时药水
- 诅咒（3 回合后死亡）
- 充能技能（蓄力 2 回合，释放）

#### 需求 B：状态叠加规则
玩家连续喝 3 次延时毒药，如何叠加？

- 方案 A：**延长持续时间**（3+3+3=9 回合毒）
- 方案 B：**增加层数**（毒 ×3，每回合 -3 HP）
- 方案 C：**独立计时**（3 个独立毒素状态）

**可能需要**：
```typescript
interface StatusEffect {
  stackBehavior: 'extend' | 'intensify' | 'independent';
  maxStacks?: number;
}
```

**影响范围**：
- 毒素叠加
- 护甲叠加
- Buff 叠加规则

### 用例 2.2：状态查询

**场景描述**：
NPC AI："优先攻击中毒的敌人"。
UGC 规则："当所有僵尸死亡时，生成 Boss"。

**根基需求**：

#### 需求 A：空间查询
```typescript
interface QueryService {
  findEntitiesInRange(center: NodeId, radius: number): EntityId[];
  findEntitiesInScene(scene: NodeId): EntityId[];
  findPath(from: NodeId, to: NodeId): NodeId[];
  getDistance(a: NodeId, b: NodeId): number;
}
```

**影响范围**：
- AI 寻找目标
- 范围伤害（爆炸影响附近所有人）
- 任务目标（"杀死房间内所有敌人"）

#### 需求 B：状态查询
```typescript
interface QueryService {
  findEntitiesWithStatus(statusType: string): EntityId[];
  findEntitiesWithTag(tag: string): EntityId[];
  hasStatus(entity: EntityId, statusType: string): boolean;
}
```

**影响范围**：
- AI 行为（攻击中毒者）
- 条件触发（"当有人中毒时..."）
- UI 显示（标记中毒玩家）

#### 需求 C：组合查询
```typescript
interface EntityFilter {
  location?: { scene?: NodeId, radius?: number };
  status?: string[];
  tags?: string[];
  category?: EntityCategory;
  hp?: { min?: number, max?: number };
  owner?: EntityId;
  faction?: string;
}

findEntities(filter: EntityFilter): EntityId[];
```

**影响范围**：
- 复杂 AI（"攻击附近血少的中毒敌人"）
- UGC 规则（"当区域内所有玩家都中毒时..."）
- 统计系统（"存活的队友数"）

**判断**：查询服务是**根基缺失**，几乎所有系统都需要它。

### 用例 2.3：复合状态交互

**场景描述**：
玩家同时中了"冰冻"和"燃烧"，两者互相抵消产生"蒸汽"状态（视野模糊）。

**根基需求**：

#### 需求 A：状态交互矩阵
```typescript
interface StateInteraction {
  stateA: string;
  stateB: string;
  result: 'cancel' | 'transform' | 'amplify' | 'none';
  resultState?: string;
}

// 示例
const INTERACTIONS = [
  { stateA: 'frozen', stateB: 'burning', result: 'transform', resultState: 'steam' },
  { stateA: 'wet', stateB: 'electric', result: 'amplify' },  // 电击伤害翻倍
];
```

**影响范围**：
- 元素反应（冰+火、水+电）
- 疾病组合（感冒+中毒→重症）
- Buff 冲突（狂暴+虚弱→抵消）

#### 需求 B：状态优先级
玩家有"眩晕"和"加速"，哪个先生效？

```typescript
interface StatusEffect {
  priority: number;  // 优先级（高优先级覆盖低优先级）
  exclusive?: string[];  // 互斥状态组
}
```

**影响范围**：
- 控制技能优先级（眩晕>减速>缓慢）
- Buff 覆盖规则
- 状态免疫（"免疫控制"覆盖所有控制状态）

**判断**：状态交互矩阵在 02/05 文档中提到，但没有详细设计。需要补充。

## 第三部分：归属与关系类

**场景描述**：

```typescript
interface Entity {
```

#### 需求 B：数量限制
玩家最多同时拥有几个召唤物？

```typescript
interface Player {

```

**影响范围**：
- 召唤物上限

**影响范围**：

### 用例 3.2：阵营系统

**场景描述**：
地图上有 3 个阵营：玩家、僵尸、野生动物。玩家和僵尸互相敌对，野生动物中立（除非被攻击）。

**根基需求**：

#### 需求 A：阵营定义
```typescript
enum Faction {
  Player = 'player',
  Zombie = 'zombie',
  Wildlife = 'wildlife',
  Neutral = 'neutral',
}

interface Entity {
  faction: Faction;
}
```

**影响范围**：
- 敌我识别
- AI 目标选择
- 队伍系统（多人模式）

#### 需求 B：阵营关系矩阵
```typescript
interface FactionRelations {
  [factionA: string]: {
    [factionB: string]: 'hostile' | 'neutral' | 'friendly';
  };
}

const RELATIONS: FactionRelations = {
  player: { zombie: 'hostile', wildlife: 'neutral' },
  zombie: { player: 'hostile', wildlife: 'hostile' },
  wildlife: { player: 'neutral', zombie: 'neutral' },
};
```

**影响范围**：
- 攻击判定（能否攻击队友）
- AI 行为（不攻击中立单位）
- 游戏规则（杀死队友扣分）

#### 需求 C：动态改变阵营
野生动物被攻击后，对攻击者变为敌对。

```typescript
interface Entity {
  factionOverrides?: Map<EntityId, 'hostile' | 'friendly'>;  // 针对特定实体的关系
}
```

**影响范围**：
- 野生动物激怒
- 魅惑技能（敌人变友军）
- 背叛机制（NPC 叛变）

**判断**：阵营系统是**根基缺失**，当前只有"玩家 vs NPC"二分。

## 第四部分：资源与进度类

### 用例 4.1：资源系统

**场景描述**：
玩家收集金币购买武器，获得经验升级，提升声望解锁商店。

```typescript
interface Player {

// 示例
player.resources.set('gold', 100);
```

**影响范围**：
- 货币系统
- 经验系统

#### 需求 B：资源消耗
```typescript
interface Cost {
  resources?: Map<string, number>;
  items?: ItemId[];
  hp?: number;
  stamina?: number;
}

interface Action {
  cost: Cost;
}
```

**影响范围**：
- 购买物品
- 升级技能
- 制造/合成
- 特殊技能（消耗生命施法）

#### 需求 C：资源上限
```typescript
interface ResourceLimit {
  resource: string;
```

**影响范围**：

## 第五部分：时空与动态类

### 用例 5.1：时间回溯

**场景描述**：
玩家使用"时间倒流"技能，倒带 3 回合，恢复到之前的状态（位置、HP、背包）。

**根基需求**：

#### 需求 A：游戏状态快照

#### 需求 B：伤害吸收顺序
```typescript
function applyDamage(entity: LivingEntity, damage: number, type: DamageType) {
  // 1. 按优先级排序护盾
  const shields = entity.shields.sort((a, b) => b.absorbPriority - a.absorbPriority);
  
  // 2. 逐层消耗护盾
  for (const shield of shields) {
    if (shield.type === 'all' || shield.type === type) {
      const absorbed = Math.min(shield.value, damage);
      shield.value -= absorbed;
      damage -= absorbed;
      if (shield.value <= 0) removeShield(entity, shield);
    }
  }
  
  // 3. 剩余伤害扣血
  entity.hp -= damage;
}
```

**影响范围**：
- 多层护盾
- 护盾破碎

```typescript
}
```
