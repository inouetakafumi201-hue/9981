> 与 `L11_TEST_REPORT.md` 的分工：那份记录第一轮属性测试的**规模与结论**（42 万次、12/12 全绿、4 处 severity 修复）。
> 本份记录第二轮——**验证这套验证本身有多少判别力**，以及据此重建的套件。
> 两份都有效，前者是被本份复核的对象，不是被它取代的对象。

## 一、起点：42 万次全绿之后，探针测出大片空转

第一轮 420,006 次运行零失败。问题是：零失败有两种成因——产品真没缺陷，或**测试根本没走到缺陷所在的分支**。
两者在报告上长得一样，区别只能靠测量得到，不能靠读代码推断。

于是不改产品、不改测试，先写探针（`mutation/probes/probe.ts`）逐条复刻原生成器，统计每类分支的实际命中次数：

| 观测项 | 实测 | 含义 |
|--------|------|------|
| 3000 条**合法** API 序列命中的检查器子句 | **0 条** | 8 条子句在合法状态下全部返回空——删掉任意一条都不可观测 |
| 随机串撞注册码（属性 3，5000 次） | **0 命中** | "码未注册"这条路走的全是前缀也非法的样本 |
| 带 `E_` 前缀的样本比例 | 约 12% | "前缀合法、码未注册"这一类实际未被测到 |
| 29 个注册码中 prefix 非法的 | **0 个** | `BAD_PREFIX` 子句在合法状态下永不可达 |
| emit 的 catch 块触发次数 | **0 次** | 属于死代码，不是被验证过的路径 |
| 两条属性的实际输入空间 | **29** | 10 万次跑的是同 29 个值的重复 |

**关键结论（决定了后面全部设计）**：合法状态下 `checkInvariants()` 恒返回 `[]`。
所以"删掉一条不变量子句"这件事，**在结构上不可观测**——不是我们没测到，是没有任何合法输入能让它显形。
造违规态因此不是"附加的测试手段"，而是**观测的前提条件**。

## 二、发现的产品缺陷：12 个（另有 4 处设计钉子）

编号沿用探针的 C01~C20，每条都有最小复现（`test/l11-regression.test.ts`）。

| # | ID | 缺陷 | 要害 |
|---|----|------|------|
| 1 | C01 | 合法 API 建的长因果链被判为数据损坏 | 100 条合法 emit 报出 36 条违规。根因是 `checkInvariants` 复用了 `chainOf`，把调用方的**展示预算** `maxDepth` 当成了**数据完整性**边界 |
| 2 | C02 | `emit` 未复制 `source`，事后改调用方对象会追改已发诊断 | 诊断是事实记录，事实不该能被事后编辑 |
| 3 | C04 | `col.all` 外泄内部数组 | `readonly` 只在编译期成立，运行期 `.length = 0` 直接清空内部状态 |
| 4 | C05 | `sealed=true` 而无 fatal 未被检出 | 单向检查让**完全取反**的实现也能通过，故补为双向子句 |
| 5 | C06 | 注册表写入面未封死 | 错误码表是唯一真相源，可写就不是真相源 |
| 6 | C07/C08 | `CodeSpec` 未冻结，`severity` 与 `recoverable` 脱钩 | 前提破了，所有查 spec 的子句一起失去意义 |
| 7 | C09 | 跨 collector 的因未被拒 | 两个 collector 各有独立时间轴，混用直接导致因果时间倒挂 |
| 8 | C10 | 伪造的因未被拒 | 未注册码可借因果链混进来隐身 |
| 9 | C11 | `clear()` 后可复用旧世代诊断作因 | 跨世代因果是断的 |
| 10 | C13 | `maxDepth` 非法时报 `CHAIN_TOO_DEEP` | 入参错误伪装成数据错误，排查方向被带偏 |
| 11 | C18 | 纯空白 `message` 未退回 `code` | `??` 只挡 `null`/`undefined`，空串与空格会被留下 |
| 12 | C19 | 无因时仍写入 `causedBy: undefined` 键 | "键不存在"与"键存在但值为 undefined"是两回事 |

**4 处设计钉子**（不是缺陷，是容易被后人"顺手改掉"的刻意选择，故用测试钉住）：

- **C12** `clear()` 刻意不重置 `time`。跨世代的时间戳唯一性是 `NON_MONOTONIC_TS` 与 `CAUSE_NOT_EARLIER` 赖以成立的前提。
- **C14** `emit` 返回内部对象**本体**。因果链的身份依赖它，返回副本会让链断裂。
- **C15** `sealed` 不阻断后续 `emit`（Spec 缺口，行为在此钉住而非擅自改变）。
- **C16** 前缀合法但未注册的码必须被拒——不能靠前缀放行。

## 三、重建的套件

原 `test/l11-property.test.ts` **一字未改**，全程保留（42 万次，12/12）。
新增三个文件，各自承担一种原套件结构上做不到的判别：

| 文件 | 用例数 | 承担什么 |
|------|--------|----------|
| `test/l11-shadow.test.ts` | 3 | 影子模型逐字段对照。断言不是"某个性质成立"，而是"产品与独立实现的每个字段都相等" |
| `test/l11-invariant-checker.test.ts` | 28 | 每条子句一个注入用例。这是唯一能让子句显形的办法（见第一节） |
| `test/l11-regression.test.ts` | 21 | 12 个缺陷的最小复现 + 4 处设计钉子 |
| 合计（含原属性测试 12） | **64** | 全部通过 |

池子的设计是从探针结论倒推的，不是凭感觉：

- 码池刻意**极小且跨 severity 取齐**（fatal/error/warn 各有代表），再加"合法前缀但未注册"与"前缀非法"两个负例。池子小了之后，重复码、重复实体、跨 severity 混排才都成为高频事件——原套件用 uuid 撞码，5000 次 0 命中。
- 实体 id 池只有 `e0`/`e1`，让"同一实体连发多条"进入样本空间。
- `message` 池含 `undefined`/空串/纯空白：`??` 与 `trim() !== ''` 的差别只在这两个值上可见。
- `maxDepth` 池含 `0`/负数/非整数/`NaN`：入参校验的每个分支各一个代表。

### 两个观测面的刻意分离

`walkChainForCheck` 与 `chainOf` 不合并，是 C01 的直接结果：

- `chainOf` 的 `maxDepth` 是**调用方的展示预算**——传小了只说明调用方不想看那么深；
- `walkChainForCheck` 的上限是 `diags.length + 1`，是**数据完整性边界**——超了才真的意味着链坏了。

合并这两者，就等于让"调用方少看几层"和"数据损坏"共用一个判据。

同理，`members: Set<Diagnostic>`（供 emit 做 O(1) 身份检查）与 `diags: Array` 刻意并存：
合并成一个会让 `MEMBERS_SIZE_MISMATCH` 与 `MEMBERS_MISSING` 两条子句永久不可检测。

## 四、变异测试：全绿之后才是真正的开始

`npm run mutate`（`mutation/run.ts`）逐个注入变异体，跑收缩后的套件，非零退出即记为杀死。

```
变异体总数：116
无效（find 未唯一命中）：0
计分变异体：115   杀死：115   存活：0
预期等价（存活为正确）：1
变异得分：100.00%
```

三条驱动器纪律，都是前几层踩出来的：

1. **`find` 必须恰好命中 1 次**，否则记为 INVALID 并排除出得分。0 次意味着"改了个不存在的字符串"被静默算成击杀；≥2 次意味着实际改了多处，结论对不上 `desc` 写的那一处。
2. **超时、栈溢出、编译失败都算杀死**——它们同样是"测试发现了问题"。
3. **`finally` 中恢复 `src/`**，不论成败。

### 刻意排除原属性测试，代价写在明面上

`vitest.mutation.config.ts` 只跑新增的三个文件。理由不是原测试慢，而是它的规模**写死在文件里**（四个 `numRuns: 100000` 硬编码），收缩不了：一个变异体要跑 42 万次，116 个不可能在合理时间内完成。

代价是诚实的：只被原套件杀掉、新套件杀不掉的变异体会显示为**存活**。这是想要的方向——让新套件独立承担判别力，才能量出它自己的水平，而不是躲在 42 万次（已被证明有大片空转）的背后。

### 变异体清单的两条硬判据

- **替换物不得偶然重建被删掉的安全性质。** 想删环保护就彻底删，不要换成一个自带上限的写法——那样变异体与原实现等价，存活证明不了任何盲区（L12 称之为"去牙变异体"）。
- **标 `expectEquivalent` 必须在 `desc` 里写下理由和前提。** 等价结论不是永久的，是**有前提的**；前提不写下来，后人无法判断它还成不成立（L8 的 M14 教训）。

### M46：一条被撤销的等价声明

M46 原先标了 `expectEquivalent`。撤销的原因不是判断失误，而是**前提在测试现场不成立**：
`l11-invariant-checker.test.ts` 用 `Map.prototype.set.bind` 绕过封印注入注册表损坏，
这条路径正好让 M46 的两条判据不再等价。驱动器实测确认 M46 被杀死，故它回到计分池。

这正是"前提必须写下来"的用处——前提写在 `desc` 里，才有东西可以被后来的测试推翻。

## 五、等价变异体：存活也要给出证据

得分表里 M28 是**唯一**存活的变异体，标了 `expectEquivalent`（把 `!== undefined` 换成 `!= null`）。

问题在于：`expectEquivalent` 与"我们的测试没测到它"在得分表上**长得完全一样**，一个是结论，一个是盲区。
所以有了 `mutation/equivalence.ts`——差分模糊器，`npm run test:equiv` 驱动。

### 5.1 模糊器自己必须先过自检

"跑了 N 步没有反例"同样有两种成因：真等价，或**模糊器根本没走到变异点**。
故第一阶段先跑一批**已知不等价**的哨兵，全部被抓到才说明这个模糊器在这里有分辨力。

哨兵取 **M26**（成员判断取反）与 **M27**（`E_DIAG_FOREIGN_CAUSE` 换成通用码）——
它们与 M28 改的是**同一条语句**：

```ts
if (causedBy !== undefined && !this.members.has(causedBy)) {
```

同一条语句是刻意的。在别处抓到分歧，只能证明模糊器"能工作"，不能证明它"看得见这一行"，而后者才是等价结论的前提。

### 5.2 两阶段判定，以及"打破前提必须分歧"

M28 的前提是"类型面不允许 null，且套件不构造 null"。但模糊器的 null 探针**恰好就在构造 null**——
若两侧一起跑带 null 探针的观测面，M28 必然分歧；若一起跑不带的，则永远一致。任取一种都不足以下结论。

故判定拆成两半，两半都必须成立：

| 阶段 | 观测面 | 要求 | 含义 |
|------|--------|------|------|
| (a) | 无 null 探针 | 必须**处处一致** | 前提成立的输入空间内，确实等价 |
| (b) | 带 null 探针 | 必须**出现分歧** | 前提是**承重**的 |

(b) 不是补充验证，是让 (a) 有意义的那一半。若打破前提后两侧照旧一致，说明这条等价根本不依赖那个前提——
那 `desc` 里写的前提是**误记**，后人会照着一个不存在的条件去判断它将来是否还成立。
反过来，(b) 处的分歧就是那条前提的**量化**：它精确地标出等价在哪里终止。

实测输出：

```
观测规模：哨兵 300 序列 / 等价判定 2000 序列，每序列 ≤16 步；
         哨兵与判定跑前提内观测面（无 null 探针），破前提复核另跑带 null 探针的面。
哨兵 M26 已抓到（第 3 条观测串分歧）
哨兵 M27 已抓到（第 3 条观测串分歧）
等价体 M28 在前提内 2002 条观测串上无分歧
等价体 M28 打破前提即分歧（前提是承重的）：首处分歧 @4867
```

哨兵也跑**无 null 探针**的观测面——若哨兵靠 null 探针才被抓到，就只证明了"null 那条路看得见"，
而 M28 的正面判定跑在没有 null 的输入空间里，那份分辨力对它无效。

### 5.3 观测面由三部分构成，缺一不可

1. **损坏注入（20 例，每条子句一例）**——见第一节：合法状态下子句恒不可观测，注入是前提条件。
2. **注册表基线**——`checkRegistry()` 自身的 6 条子句。
3. **随机计划的全状态转储**——每步之后转储 collector 全字段，加上别名探针、定长深链探针、null/undefined 入参探针、封印面探针。

三条实现上的要害：

- **绕过封印必须还原。** `sealRegistry()` 遮蔽的是**实例**属性（`m['set']`/`delete`/`clear`），`Map.prototype.set.bind(REG)` 仍能写入。能绕过本身就是"封印只覆盖实例面"的证据。但 `CODE_REGISTRY` 是**模块级单例**，一例没还原干净，后面所有例的分歧都来自污染而非变异体——那种"发现不等价"是假阳性，比漏报更浪费时间。故每例之后立刻核对 size + 键集，发现残留就地报出。
- **观测函数必须全能（total）。** 变异体会让本该合法的调用抛错、会让本该被拦的 null 存进字段。抛错必须作为**数据**记进观测串，不能作为控制流逸出——逸出会让一处真分歧被读成基础设施故障。`shallow()` 因此对 `null` / `undefined` / 非对象**各印各的**：把 null 和 undefined 印成同一个值，等于亲手抹平 M28 唯一的观测点。
- **两侧喂同一个种子。** 输入必须逐位相同，否则分歧可能来自随机数而不是变异。

### 5.4 不动源文件

变异驱动器是**原地改写 `src/diagnostic.ts` 再还原**的——那条路径曾经真的毁掉过一次源文件。
模糊器改成另一种做法：把源码复制到 `mutation/.tmp/v<N>_<tag>.ts` 再改副本，两侧各 import 一份，
`src/diagnostic.ts` 全程只读。

可以这么做的前提是 `src/diagnostic.ts` **没有任何 import**（自足模块），换目录不会有相对路径失效问题。
用新文件名而不是 `?v=N` 查询串：文件名不同则模块 id 必然不同，两侧的 `CODE_REGISTRY` 单例天然隔离——
而隔离是整件事成立的前提，注入注册表损坏会污染整个模块。

本轮全程核对：`src/diagnostic.ts`、`test/l11-property.test.ts`、`L11_TEST_REPORT.md` 三个文件
在跑完变异测试与模糊器之后**哈希完全一致**，`mutation/.tmp/` 无残留。

## 六、本轮记录的空转形态

L11 复现了前几层已知的形态，并补上两种新的。
前四种（自指判据、去牙变异体、顺序依赖的模块态、未验证的区分性断言）的原始记录见 `kernel-l12-test/REPORT.md` 第六节。

**已知形态在 L11 的复现**：

| 形态 | L11 现场 |
|------|----------|
| ID 池不碰撞 | uuid 撞注册码，5000 次 0 命中 |
| 池不相交 | 只有 12% 样本带 `E_` 前缀，"前缀合法、码未注册"未被测到 |
| 观测面缺，不出可触发状态 | 3000 条合法序列命中子句 0 条 |
| 对称代码覆盖不对称 | `FATAL_NOT_SEALED` 有、`SEALED_WITHOUT_FATAL` 无（C05），全取反的实现能通过 |
| 顺序依赖的模块态造成假"不等价" | `CODE_REGISTRY` 是模块级单例，注入不还原就污染后续全部用例 |

**本轮新增的两种**：

### 6.1 判据复用造成的"合法即损坏"

C01 不是漏检，是**误检**：把调用方的展示预算（`chainOf` 的 `maxDepth`）当成了数据完整性边界，
于是 100 条合法 emit 被报成 36 条数据损坏。

这种缺陷比漏检更隐蔽——它**制造**违规而不是放过违规，因此在"全绿"的套件里也能长期存在：
没有测试会去断言"合法操作**不应**报违规"，因为那看起来像废话。

判据是"两个概念用同一个数值边界"时必须问：这两个边界的**语义单位**是否相同？
`maxDepth` 的单位是"调用方想看几层"，`diags.length + 1` 的单位是"链最多可能有多长"。单位不同，就不能共用。

### 6.2 等价声明缺少反向验证

只验证"前提成立时等价"是不够的。若不同时验证"打破前提就不等价"，那条前提可能纯属**误记**——
等价其实由别的原因保证，而 `desc` 里写的那条从来没起作用。

那样的记录比不记录更坏：它给后人一个假的判断依据，让人以为只要那个条件还在，等价就还成立。
解法就是 5.2 的两阶段判定：正面 (a) 与反面 (b) 都必须成立，缺一不可。
