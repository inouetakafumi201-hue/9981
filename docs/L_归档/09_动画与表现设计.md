# 动画与表现设计

---

## 核心原则

**像素风 + 程序化动效**：不依赖大量手绘动画帧，而是通过代码驱动的变换、粒子和震动创造质感。

---

## 移动表现

### 跳跃式移动（程序化非逐帧动画）

**实现方式**：
- 不使用逐帧动画
- 程序化旋转和缩放图标
- 添加粒子效果（灰尘、波纹）
- 可选的轻微震动反馈

**代码驱动示例**：
```typescript
// 伪代码
function moveAnimation(sprite: Sprite, from: Point, to: Point) {
  const duration = 300; // ms
  
  // 位置插值
  sprite.position = lerp(from, to, easeOutCubic(t));
  
  // 跳跃旋转
  sprite.rotation = sin(t * PI) * 5; // 摆动 ±5 度
  
  // 缩放（模拟跳起落下）
  sprite.scale.y = 1 + sin(t * PI) * 0.15;
  
  // 粒子发射（落地时）
  if (t > 0.8) emitDust(sprite.position);
}
```

**效果**：
- 视觉清晰：明确表达移动轨迹
- 性能友好：纯计算，无额外资源
- 风格统一：所有移动复用同一套逻辑

## 重要动作的全屏动画

### 方案 A：分离式动画（推荐）

**关键动作全屏分离式动画**：
- 地图上：图标瞬间替换（人形 → 尸体贴图）
- 全屏：播放预设骨骼动画（0.5-1 秒）

**适用动作**（仅限低频、仪式性动作）：
- 翻窗（带碎玻璃声）
- 跳窗（一跃而下 + 坠落伤害特效）
- 令其长眠（蓝插头插入动画）

**说明**：远程开枪、上车/下车、精密交互完成（撬锁成功）等高频动作改为原地效果（见下方"推荐：混合方案"），不再触发全屏动画，避免频繁打断节奏。

**优势**：
- **完全解耦**：地图逻辑与动画表现分离
- **UGC 友好**：创作者只需提供一张静态图 + 选择动画模板
- **不打断流程**：动画播放时，玩家可继续思考下一步
- **质感强**：全屏大动作比小图标更有冲击力

**劣势**：
- 频繁弹全屏可能打断节奏（缓解：快速动画 + 可跳过）

---

### 方案 B：硬做小图标动画

**直接在地图上播放帧动画**：
- 翻窗：人物图标连贯动作（跨越 → 落地）
- 射击：枪口闪光 + 弹壳抛出

**优势**：
- 观感连贯，不弹全屏

**劣势**：
- **场景交互技术难题**：窗户是过渡场景，图标如何平滑跨越？
- **资源需求高**：每个动作需要多帧像素画
- **UGC 门槛高**：创作者需绘制完整动画序列

---

### 推荐：混合方案

**常规动作**：程序化变换（移动、转身、待机、近战攻击、远程开枪、上车/下车）
**重要动作**：全屏分离式动画（翻窗、跳窗、令其长眠）
**次要动作**：简单图标切换（拾取物品、丢弃、精密交互完成如撬锁成功）

**说明**：远程开枪、上车/下车归入"程序化变换"，精密交互完成归入"简单图标切换"，均改为原地效果（如攻击：红色射线+目标闪烁 0.2 秒），与08_图形化与UI设计_v2.md的动画规范保持一致，不再触发全屏动画。

**动画模板库**（UGC 可选）：
- 近战攻击 A/B/C（挥砍、突刺、横扫，原地效果）
- 远程射击 A/B（手枪、步枪后坐力，原地效果）
- 翻窗 A/B（正面、侧面，全屏）
- 跳窗（一跃而下，全屏）
- 令其长眠（统一蓝插头动画，不可替换，全屏）

## 状态可视化

### 倒地动画

**零血倒地（濒死）**：
- 人物旋转躺下（0.4 秒）
- 蓝色边缘闪烁（可处决标记）
- 屏幕边缘轻微变暗

**普通倒地（击倒）**：
- 同样躺下动画
- 无蓝色闪烁
- 可爬行时显示移动箭头

### 爬行表现

**像素风爬行动画**：
- 2-3 帧循环（拖拽身体）
- 移动速度视觉上慢于正常移动
- 留下拖痕粒子（可选）

---

## 粒子效果

### 最小粒子集

**只实现高价值粒子**：
- 灰尘（移动落地）
- 血液飞溅（受击）
- 枪口火焰（射击）
- 碎玻璃（翻窗）
- 蓝光粒子（令其长眠）

**实现原则**：
- 程序生成，不用贴图
- 简单几何形状（圆点、线段）
- 短生命周期（< 0.5 秒）

---

## 音效与震动

### 触觉反馈（可选）

**轻度震动**：
- 移动落地：10ms 震动
- 受击：50ms 震动
- 射击：30ms 震动

**重度震动**：
- 倒地：100ms 震动
- 爆炸：150ms 震动

### 音效分层

**UI 层**：
- 按钮点击
- 菜单切换
- AP 消耗提示音

**游戏层**：
- 脚步声（按场景类型变化）
- 武器音效（射击、挥砍）
- 环境音（风、雨、僵尸呻吟）

## 技术实现建议

### 动画系统架构

```typescript
interface Animation {
  type: 'procedural' | 'fullscreen' | 'sprite';
  duration: number;
  skipable: boolean;
  
  // 程序化动画
  update?(sprite: Sprite, t: number): void;
  
  // 全屏动画
  template?: AnimationTemplate;
  
  // 精灵帧动画
  frames?: Texture[];
}

// 动作 → 动画映射
const ACTION_ANIMATIONS = {
  move: { type: 'procedural', update: moveAnimation },
  shoot: { type: 'procedural', update: shootAnimation }, // 普通开枪：原地效果，非全屏
  climb_window: { type: 'fullscreen', template: 'climb_window' }, // 翻窗
  jump_window: { type: 'fullscreen', template: 'jump_window' }, // 跳窗
  execute: { type: 'fullscreen', template: 'blue_plug', skipable: false }, // 令其长眠
  pickup: { type: 'sprite', frames: [frame1, frame2] },
};
```

### 性能优化

**批量渲染**：
- 同类粒子合并绘制
- 精灵表合图减少纹理切换

**LOD（细节层级）**：
- 远离镜头的实体减少动画帧率
- 屏幕外的粒子不更新

**动画池**：
- 复用动画实例，减少 GC

## UGC 创作指南

### 最低要求

创作者只需提供：
1. **静态图标**（32×32 或 64×64 像素）
2. **选择动画模板**（从预设库选择）

### 高级定制

可选提供：
1. **自定义帧动画**（需符合像素网格规范）
2. **自定义音效**（< 100KB，.ogg 格式）
3. **粒子颜色配置**（JSON 定义）

### 静态验证

Linter 检查：
- 图标尺寸是否符合规范
- 帧数是否在合理范围（2-8 帧）
- 文件大小是否超标
