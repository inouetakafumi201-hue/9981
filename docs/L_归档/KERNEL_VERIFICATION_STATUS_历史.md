## 二、已确认的具体缺陷（普查阶段静态发现，尚待逐层证实）

### 2.1 `fc.uuid()` 空转

UUID 碰撞概率为零，所有"重复 ID"代码路径不可达。

| 层 | 出现次数 |
|----|---------:|
| L8 | 3（已修） |
| L11 | 1（已修） |

（L4 原有 3 处、L7 原有若干处，均已在重建中改为小固定池。）

**L8 实测订正（2026-08-08）：这一层的危害比"重复 ID 路径不可达"严重得多。**
`fc.uuid()` 用在 `add` 侧，而 `del` 侧的 id 取自固定池 `REL_POOL`，
**两个池永不相交**，于是删除类 op 的实测生效次数是 **0/2000**——
不是"某条分支不可达"，是**整个 op 是死代码**。
`relation_del`、`attachment_del` 加上 uuid 造出的不可引用实体，
六种 op 里三种在整段 100,000 次运行中从未做过任何事。

判据升级：见到 `fc.uuid()` 时，不要只问"重复 ID 路径可达吗"，
要问"**这个 id 之后还有别的 op 会引用它吗**"。
若引用侧另有池子，那不是覆盖不足，是整条操作链断开。
排查方法是直接计数（probe 打印生效次数），不是读代码推断。

### 2.2 重言式断言（同一函数调用两次自比）

形如 `const r1 = f(x); const r2 = f(x); expect(r1).toEqual(r2)`。
**对任何确定性无副作用函数恒真**，连"完全不实现"也能通过。

| 层 | 函数 | 规模 |
|----|------|------|
| L12（已修） | `replay(seed, ops)` | 10 万次 |
| L12（已修） | `compareVersions(...)` | — |
| L4（已修） | `collectAndSortInstead(type)` | 10 万次 |

L12 的 `replay` 用例即使把实现改成"忽略 ops 直接返回 seed"也会全绿。
**已由 L12 重建证实**：该用例旁边的"快照隔离"属性还有第二层空转——
生成器产出的 Op 全是 `{...s}` 纯拷贝，永不原地写，
于是 BUG L12#9（`replay` 不克隆 seed）在那个样本空间里**不可能发生**。
补一个原地写的 Op 后第 1 步即暴露。**生成器的覆盖与断言的形状同等重要。**

### 2.3 自检式不变量断言

只断言 `checkInvariants()` 返回空，不配独立影子模型。
返回空可能是状态干净，也可能是**检查器本身漏检**。
调用了不变量检查但无影子模型的层：L1L2(6)、L9(1)、L10(6)。
（L11 原在此列（6 处），重建时已补影子模型 + 20 例损坏注入。
L11 实测把这条判据推进了一步：**它的 8 条子句在合法状态下命中数为 0**——
3000 条合法 API 序列一条也点不亮。也就是说"无影子模型"还不是最糟的情形，
最糟的是**连可触发状态都造不出来**，那时删掉子句在结构上不可观测，
补影子模型也照不出来，必须先注入非法状态才有观测面。）
（L8 原在此列且情况最重：它的 `checkInvariants` 不仅无影子模型，
**本身还是单向的**——只问"该有的在不在"，不问"在的都该在吗"。
把 `relation_del` 里清索引的两行整段删掉，原有 10 项断言全绿。
重建时补齐反向校验并以 24 项损坏注入证明每条子句真会报错。）

**由 L8 新增的判据：单向检查器查不出"多出来的东西"。**
凡是维护索引 / 缓存 / 派生表的层，检查必须**双向**：
既从主表查索引有没有，也从索引查主表还在不在。
只做一半时，残留项、重复项、错位项全部不可见。
排查方法：把清理索引的代码整段删掉，看有没有人喊。

### 2.4 完全没有不变量校验的层

L3、L5、L6、L13 — 需先确认是否存在应有的一致性约束而未校验。
（L12 原在此列，重建时已补 `checkWorldState` + 四个 `checkInvariants`，
并以 37 项损坏注入证明每条子句真会报错。）

## 三、重建方法（每层照此四步，顺序不可换）

1. **观测面**：给被测源码加纯观测方法（轨迹 / 快照 / `checkInvariants`），
   不改变任何既有行为。
2. **影子模型**：独立重写预期值，零共享代码，逐字段对照。
   优先对照**完整执行轨迹**而非最终结果。
3. **损坏注入**：向私有状态注入损坏，反向证明检查器每条分支真会报错。
4. **变异测试**：注入单点故障。存活者要么补测试，要么用**差分模糊 + 哨兵自检**
   证明其语义等价。

四个反复踩到的坑，写在这里避免重犯：

- **小固定池**：ID 生成器一律 `fc.constantFrom(...pool)`，不用 `fc.uuid()`。
- **池必须故意重叠**：两个池不相交时，"两者在该级并列"的情形永远构造不出来，
  末级 tiebreak 永远得不到表决机会。
- **身份必须唯一且不参与排序键**：末级 tiebreak 生效时前几级键必然并列，
  比对 id 数组会让顺序翻转逐字节不可见。用 `Map<Def, tag>`。
- **差分模糊器自己要过哨兵自检**：拿已知不等价的变异体当哨兵，且哨兵要选在
  待证变异体**同一代码块**内。"没发现分歧"可能是等价，也可能是没走到。

L12 重建时又撞见四种，一并记在这里（详见
[kernel-l12-test/REPORT.md](docs/L_归档/开发期杂项_2026-08/kernel测试工程/kernel-l12-test/REPORT.md) 第六节）：

- **自指判据**：测试 `import` 产品自己的常量表再拿它断言产品的输出，
  改常量时两侧一起变，差异恒不可见。破法：字面量钉死取值 **且** 断言两两互不相同。
- **去牙变异体**：替换物偶然重建了被删掉的安全性质（把 `visited` 换成长度上限，
  上限自己就恢复了终止性），变异体与原实现等价，其存活证明不了任何盲区。
  判据：替换物不得重建被删掉的性质。
- **顺序依赖的模块态造成假"不等价"**：模块级计数器跨步累积，
  基线与变异体起点不同，于是**任何**变异体都"第 1 步就不等价"。
  假"不等价"与假"等价"同样是错结论，且噪声会**掩盖真盲区**。
  差分比较必须两侧同起点。
- **区分性断言本身也要被验证**：为某个变异体专门写的用例，
  必须**手动打上那个变异体再跑一遍**确认它真会红。
  "断言通过"只说明它没失败，不说明它能失败。
  L12 的 M82 三条菱形用例方向写反，全是恒真断言，靠这一步才发现。

L8 重建时又撞见两种，一并记在这里（详见
[kernel-l8-test/REPORT.md](docs/L_归档/开发期杂项_2026-08/kernel测试工程/kernel-l8-test/REPORT.md) 第六节）：

- **观测面缺失可触发状态 → 假等价**：差分模糊器跑的全是**合法状态**，
  而合法状态下不变量检查器的每条子句都返回空，于是"删掉一条报违规的子句"
  在那个观测面里根本不可观测。L8 首版哨兵自检 11/14，漏掉的三个全是
  `checkInvariants` 子句。**检查器本身也是被测对象**，
  观测面必须包含能触发它每条子句的状态——对检查器而言，
  损坏注入不是"额外的测试"，而是"让它可观测"的前提条件。
  判据：若某段代码只在异常状态下执行，观测面就必须能造出异常状态。
- **对称代码的覆盖不对称**：`cloneEntityStub` 的 out 桶有测试守着、in 桶没有；
  反向校验的两侧同理。写法对称不代表覆盖对称。
  判据：见到 `out`/`in`、`from`/`to`、`left`/`right` 这类成对结构，
  逐个数断言，不要因为代码是复制粘贴的就认为测试也覆盖了两份。

L8 还再次踩了"区分性断言本身也要被验证"这一条：
M92 的用例初版写成 `expect(a.rel.in).not.toBe(b.rel.in)`，
而 Map 每次 clone 都新建，共享发生在**桶数组**那一层——断言恒真，
手动打上 M92 才发现位置写错了。这条坑连续两层复现，
说明它不是偶发失误，而是默认会犯的错。

L11 重建时又撞见两种，一并记在这里（详见
[kernel-l11-test/REPORT.md](docs/L_归档/开发期杂项_2026-08/kernel测试工程/kernel-l11-test/REPORT.md) 第六节）：

- **判据复用造成"合法即损坏"**：把调用方的**展示预算**（`chainOf` 的 `maxDepth`）
  当成了**数据完整性**边界，于是 100 条合法 emit 被报成 36 条数据损坏（BUG L11#1）。
  这比漏检更隐蔽——它**制造**违规而不是放过违规，所以在全绿的套件里也能长期存在：
  没有测试会去断言"合法操作**不应**报违规"，因为那看起来像废话。
  判据：两个概念共用一个数值边界时，先问它们的**语义单位**是否相同。
  `maxDepth` 的单位是"调用方想看几层"，`diags.length + 1` 的单位是"链最多可能有多长"；
  单位不同就不能共用。L11 据此把 `walkChainForCheck` 与 `chainOf` 分成两个函数。
- **等价声明缺少反向验证**：只验证"前提成立时等价"是不够的。
  若不同时验证"**打破前提就不等价**"，那条前提可能纯属误记——
  等价其实由别的原因保证，而 `desc` 里写的那条从来没起作用。
  那样的记录比不记录更坏：它给后人一个假的判断依据。
  判据：等价判定做两阶段，(a) 前提内必须处处一致，(b) 破前提必须出现分歧；
  (b) 处的分歧就是那条前提的**量化**，它精确标出等价在哪里终止。
  L11 的 M28（`!== undefined` → `!= null`）即用此法判定。

L11 也再次印证了 L8 那条"观测面缺失可触发状态"，且程度更深：
L8 是哨兵自检 11/14 漏三个，L11 是**3000 条合法序列命中子句 0 条**——
不是漏了几个，是整个检查器在合法输入下完全不可观测。
连续两层复现，可以确定：**凡是被测对象里有"只在异常态执行"的代码，
损坏注入就是必需项，不是可选项。**
