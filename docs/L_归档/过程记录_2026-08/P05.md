禁止使用“模板”“内容层”等废用术语。

## 必须完成的审查

1. UI 只能通过只读 Query、合法动作查询、Decision/Intent、Knowledge/visibleTo 和 Presentation Descriptor 获取规则与表现信息。
2. UI 和动画不得直接写引擎状态；用户操作必须表达为交互意图并走合法 Op 通道。
3. 动画是否加载、播放、跳帧或失败不得改变规则结果、随机结果、动作合法性或结算顺序。
4. 语义字段缺失必须拒绝；图标、纹理、音效、动画等非语义表现资源可以显式降级，但必须提供可诊断的替代行为。
5. 防止隐藏信息通过 HUD、预览、动画、日志、调试面板、可访问性文本或资源命名泄漏；投影结果必须服从当前 Agent 的可见性。
6. 动画时长、素材路径、视觉 mockup、帧率目标、性能候选值和具体布局不得成为基类层语义默认值。
7. 基类层可以定义可复用表现描述符；玩法专属 HUD、具体模式界面、具体美术资源和玩法提示归玩法层或表现资源。
8. 玩家可见数值必须保持 1-5；UI 不得通过二次换算显示违反规范的伪精确玩法值。内部技术指标必须明确隔离。
9. 覆盖输入禁用、过期 Decision、状态变化、异步动画、重放、回退、跳过动画、多窗口和无障碍模式下的规则一致性。
10. 每条需求必须有可判定验收标准和权威来源，明确依赖 core、space-items、AI 的只读契约，删除重复和不可测试陈述。
