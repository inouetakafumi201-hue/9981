## 权威优先级

规范宪法 → 已确认访谈决策 → 引擎层不变量与职责边界 → 基类层有效契约 → 玩法层定稿规则 → 历史示例或旧路线图。

禁止使用“模板”“内容层”等废用术语。

## 必须完成的审查

1. 将空间与物品概念按三层职责归属：
   - Node、Link、Entity、Item、Container、Slot 等运行时原语归引擎层。
   - 枪类、近战类、谱型类、伤害类、物品类、防具类、载具类、容器类和移动模式等可复用语义单元归基类层。
   - 具体地图、命名武器、具体 NPC、胜负规则、出生分布和具体玩法数值归玩法层。
2. 不得恢复已经废弃的“物品体积”等机制；发现旧文档冲突时，引用控制决策并移除其规范效力。
3. 枪械基础伤害表 T-001 和掩体机制 T-002 必须保持未决，不得自行给出默认实现或具体数值。
4. 所有玩家可见数值必须在 1-5 范围内；内部拓扑计数需明确标记。节点连接数必须遵守不超过 5 的约束。
5. 微型场景必须附属于天然场景；核对创建、归属、父场景、占用和生命周期语义，不得与当前锁定决策冲突。
6. 基类层实例不包含具体玩法数值约束和具体模式出现规则；具体武器应由武器类、谱型类、伤害类等组合形成，而不是错误建立按数值区分的继承树。
7. 对 core mechanics 的动作、伤害、状态、资源、网关等契约只建立类型化依赖，不复制定义。
8. 不得重定义引擎层 Op、Query、Relation、拓扑存储或事务机制；写入必须通过合法 Op。
9. 每条需求必须可测试、可追踪，并明确引用损坏、非法组合、越层数值和不变量冲突时的拒绝或诊断行为。
10. 明确本 Spec 提供给 UGC、UI 和玩法层物品实例配置的稳定接口及未决接口。

## 写入边界

- 只修改 `.kiro/specs/wakeup-space-items/requirements.md`。
- 不创建 `design.md`、`tasks.md` 或其他文件。
- 不修改 core requirements、规范宪法、访谈决策、审查报告和领域原始文档。
- 不写实现代码，不运行构建或测试。
- 开始时检查目标文件和 Git diff；保留人工改动。若发现其他会话正在修改目标文件，停止并报告，不得覆盖。
