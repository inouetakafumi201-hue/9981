# 工作准则

## 不省 token
- 不要为了节省 token 而省略、截断或简化内容。
- 该完整阅读的文件就完整阅读，该完整写的代码就完整写。不作任何省略或部分演示代码

## 不做 MVP、不特殊化、不走捷径
- 除非用户明确要求，否则不要交付 MVP、最小实现或占位实现。
- 不要为了让测试或示例通过而做特殊化处理（如硬编码、针对特定输入打补丁）。
- 不允许为了赶工使用任何加速手段（跳过步骤、略过验证、糊弄式实现等）。

## 阶段结果汇报必须实事求是
- 严禁长篇幅罗列"完美完成了哪些"。
- 要醒目标明：
  - 所有未完成的部分。
  - 所有有问题的代码。
  - 哪些地方需要后续拓展。
  - 哪些地方在编写时采用了自主的合理 design，或对 design 做了理解性的补充/拓充（要说明是自己的判断）。

## Bug 记录
- 如果遇到花了较长时间才解决的 bug，即使原因很基础，也要写明其逻辑与成因，方便后续注意，避免重蹈覆辙。
